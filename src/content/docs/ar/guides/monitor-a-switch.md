:::caution[تحقق قبل الاستخدام]
الرمز المصدري متاح، ولكن لا يوجد إصدار مدعوم من Kadupul أو مسار ترحيل. اختبر هذه الإجراءات على نسخة معزولة مع وجود نسخ احتياطية قبل الاعتماد عليها. راجع [حالة المشروع](/ar/project/status/).
:::

المحول هو حالة الاستخدام الكلاسيكية لاستعلامات البيانات. أنت لا تعرف مسبقاً عدد المنافذ الموجودة، ويمكن أن يتغير العدد، ويحتاج كل منفذ إلى مصدر بيانات خاص به. راجع [القوالب](/ar/concepts/templates/) لمعرفة كيفية عمل استعلامات البيانات؛ تتناول هذه الصفحة الإعداد الصحيح.

## قبل أن تبدأ

تأكد من استجابة الجهاز من المجمّع المعين، ويفضل أن يكون ذلك تحت مستخدم أداة الاستقصاء. استخدم بيانات الاعتماد المكونة للقراءة فقط. تتجنب معرّفات OID الرقمية الاعتماد على أسماء MIB المثبتة محلياً.

```bash
snmpwalk -v2c -c 'your-read-only-community' switch.example.net .1.3.6.1.2.1.31.1.1.1.1
```

استخدم SNMP v2c أو v3. عدادات الواجهة 64 بت هي كائنات SMIv2 ولا يمكن الاستعلام عنها عبر v1. سيمنحك جهاز v1 عدادات 32 بت فقط ولا شيء غير ذلك.

## اختيار قالب الجهاز

يحدد قالب الجهاز استعلامات البيانات وقوالب الرسوم البيانية المعروضة عند إضافة الجهاز. يرث Kadupul مجموعة القوالب التي توفرها Cacti، والتي تتضمن قالب جهاز SNMP عاماً ومجموعة من القوالب الخاصة بالموردين.

يأتي اكتشاف المنفذ من نفس المصدر بغض النظر عن اختيارك: استعلام بيانات الواجهة المحدد في `resource/snmp_queries/interface.xml`. إذا لم يتطابق أي قالب مع أجهزتك، فاختر القالب العام واربط استعلام الواجهة به.

## تشغيل استعلام البيانات

يجتاز الاستعلام `ifIndex` للعثور على المنافذ، ويقرأ `ifNumber` لمعرفة العدد المتوقع. ثم يجمع مجموعة من الحقول لكل منفذ.

| الحقل | OID | يُستخدم لـ |
|---|---|---|
| `ifIndex` | `.1.3.6.1.2.1.2.2.1.1` | الموضع في جدول SNMP |
| `ifName` | `.1.3.6.1.2.1.31.1.1.1.1` | اسم المنفذ القصير، `Gi1/0/3` |
| `ifDescr` | `.1.3.6.1.2.1.2.2.1.2` | وصف أطول |
| `ifAlias` | `.1.3.6.1.2.1.31.1.1.1.18` | وصف الواجهة الذي قمت بتكوينه |
| `ifHwAddr` | `.1.3.6.1.2.1.2.2.1.6` | عنوان MAC للمنفذ |
| `ifSpeed` | `.1.3.6.1.2.1.2.2.1.5` | السرعة بالبت/ثانية، 32 بت |
| `ifHighSpeed` | `.1.3.6.1.2.1.31.1.1.1.15` | السرعة بالميغابت/ثانية |
| `ifOperStatus` | `.1.3.6.1.2.1.2.2.1.8` | Up أو Down |
| `ifInOctets` / `ifOutOctets` | `.1.3.6.1.2.1.2.2.1.10` / `.16` | عدادات البايت 32 بت |
| `ifHCInOctets` / `ifHCOutOctets` | `.1.3.6.1.2.1.31.1.1.1.6` / `.10` | عدادات البايت 64 بت |

قم بتشغيل الاستعلام مرة واحدة على الجهاز. سيعيد جدولاً بالمنافذ المكتشفة. اقرأ هذا الجدول قبل إنشاء الرسوم البيانية، لأنه يشكل الأساس لكل قرار لاحق.

## اختيار عدادات 64 بت

يقدم استعلام الواجهة العديد من قوالب الرسوم البيانية لحركة المرور. أهمها:

| قالب الرسم البياني | ما يقرأه |
|---|---|
| In/Out Bits | `ifInOctets`, `ifOutOctets` |
| In/Out Bits (64-bit) | `ifHCInOctets`, `ifHCOutOctets` |
| In/Out Bits (64-bit, 95th) | الشيء نفسه، مع خط النسبة المئوية 95 |
| In/Out Bits (64-bit, BW) | الشيء نفسه، نسبة إلى سرعة الواجهة |
| Status (Up/Down) | `ifOperStatus` |
| In/Out (Errors/Discards) | `ifInErrors`, `ifInDiscards`, `ifOutDiscards`, `ifOutErrors` |

استخدم قالباً 64 بت ما لم يكن لديك سبب محدد لعدم القيام بذلك. يصل عداد الثمانيات (octets) 32 بت إلى الحد الأقصى عند 4294967295. منفذ جيجابت تحت الحمل الكامل يملأه في حوالي 34 ثانية. عند خطوة مدتها 300 ثانية، لا تستطيع أداة الاستقصاء التمييز بين تجاوز سعة واحد وسبعة تجاوزات، ويصحح `COUNTER` تجاوزاً واحداً فقط بين عينتين. لا يظهر الرسم البياني معطلاً بشكل واضح؛ إنه يعرض فقط قيماً منخفضة جداً بشكل دائم.

تحقق من ملء العدادات بالفعل قبل إنشاء مئات الرسوم البيانية.

```bash
snmpwalk -v2c -c 'your-read-only-community' switch.example.net .1.3.6.1.2.1.31.1.1.1.6
```

يتطلب أمر walk الفارغ أو الفاشل التحقيق: تحقق من الخطأ المبلغ عنه، وعرض الوصول، ودعم الوكيل.

## التحقق من الحد الأقصى المخزن بعد تغييرات السرعة

عندما يستخدم مصدر البيانات حداً أقصى بناءً على سرعة الاستعلام، يسحب الإنشاء السرعة من بيانات الاكتشاف المخزنة مؤقتاً. يُفضل `ifHighSpeed`، ويُستخدم `ifSpeed` إذا كان الأول مفقوداً، ويتم تطبيق الافتراضي المكون إذا كان كلاهما صفراً.

تتم كتابة هذه القيمة في الملف. قد يحتفظ المنفذ الذي تم اكتشافه بسرعة 100 ميجابت في الثانية ثم تم التفاوض عليه لاحقاً بسرعة أعلى بحد أقصى أقل من حركة المرور الحقيقية، وسيسجل RRDtool المعدلات الأعلى من هذا الحد كغير معروفة. قارن السرعة المخزنة مؤقتاً وتعريف مصدر البيانات والملف الفعلي باستخدام `rrdtool info`.

## قرار الفهرس

هنا يُفقد السجل التاريخي عند ارتكاب الأخطاء.

يخزن كل مصدر بيانات أمرين حول منفذه: الحقل الذي يحدده (نوع الفهرس) وقيمة ذلك الحقل. عند كل إعادة فهرسة، يعيد العثور على المنفذ من خلال السؤال عن فهرس SNMP الذي يحتوي حالياً على تلك القيمة في ذلك الحقل. يتبع مصدر البيانات القيمة، وليس موضع الجدول.

لذا فإن السؤال هو أي حقل يحمل القيمة.

يعلن استعلام الواجهة عن ترتيب تفضيل: `ifName`، ثم `ifDescr`، ثم `ifHwAddr`، ثم `ifIndex`. يختار Kadupul عادةً من بين المرشحين ذوي القيم المتميزة بما فيه الكفاية وبدون تكرارات.

| الحقل | ينجو من | يفشل عندما |
|---|---|---|
| `ifName` | عمليات إعادة التشغيل، استبدال البطاقات، إعادة الترقيم | يتركه الوكيل فارغاً أو يكرره عبر أعضاء المجموعة (stack) |
| `ifDescr` | مستقر عادة على أجهزة المحولات | على الخوادم، اسم نواة عرضة للتغيير |
| `ifHwAddr` | عمليات إعادة التشغيل | تحتوي البطاقة المستبدلة على عناوين MAC جديدة، وهي الحالة التي أردت الحماية منها بالضبط |
| `ifIndex` | لا شيء موثوق | يؤدي تبديل البطاقة أو إعادة التشغيل أو تغيير البرنامج الثابت إلى إعادة ترقيم الجدول |

إذا تراجع الاستعلام إلى `ifIndex`، فتعامل مع هذا كمسألة تحتاج للتحقيق وليس كنتيجة طبيعية. يرتبط سجل المنفذ الخاص بك بعد ذلك برقم يتمتع المحول بحرية إعادة تعيينه.

## طريقة إعادة الفهرسة

يتم تعيينها لكل جهاز لكل استعلام بيانات. وتحدد متى يعيد Kadupul قراءة حقول الفهرس.

| الطريقة | يتم تشغيلها عند | التكلفة |
|---|---|---|
| None | لا شيء؛ يدوياً أو عبر برنامج نصي فقط | لا شيء |
| Uptime | تراجع وقت تشغيل SNMP للجهاز إلى الوراء | مقارنة واحدة لكل دورة |
| Index Count | تغيير عدد الفهارس المكتشفة | عدّ واحد لكل دورة |
| Verify All | فشل فحص الهوية المخزنة مؤقتاً | يستعلم عن الفهارس المعروفة أثناء الاستقصاء |

Uptime هو الخيار الافتراضي ويناسب معظم المحولات، لأن إعادة التشغيل هي الحدث الذي يعيد ترقيم الفهارس. يلتقط Index Count البطاقات المضافة أو التي تمت إزالتها دون إعادة التشغيل. يمكن لـ Verify All اكتشاف الهويات المتغيرة على الفهارس المعروفة، ولكنه لا يضمن اكتشاف منافذ جديدة.

لإعادة تشغيل جهاز واستعلام محددين، استبدل كلا المعرفين بالمعرفات المثبتة. احذف `--qid` لإعادة تشغيل جميع الاستعلامات الخاصة بذلك الجهاز:

```bash
php cli/poller_reindex_hosts.php --id=42 --qid=16
```

يوسع `--id=all` التنفيذ ليشمل جميع الأجهزة الممكّنة. تجنب عمليات إعادة الفهرسة المتداخلة. يتجاوز `--force` تسجيل العمليات ويحدّث ذاكرة التخزين المؤقت للعناوين.

## عندما يختفي منفذ

لا تفترض أن المنفذ المفقود يوقف الجمع تلقائياً. يمكن لرمز إعادة الفهرسة الحالي إعادة تعيين علامة اليتيم والاحتفاظ بمعرّفات OID القديمة للاستقصاء عندما تكون الهوية غير محسومة ولا يغير أي مصدر الفهرس. قارن الهوية المخزنة بذاكرة التخزين المؤقت للاكتشاف الجديد وقم بتعطيل المصدر المتأثر حتى يتم تأكيد التطابق. راجع [استعلامات البيانات والفهارس](/ar/concepts/data-queries-and-indexes/).

## الهياكل الكبيرة (large chassis)

يصبح إعدادان لكل جهاز مهمين بمجرد زيادة عدد المنافذ: تحقق من معرّفات OID المكونة لكل طلب SNMP وعدد مسارات التنفيذ (threads) لكل جهاز. يعتمد دعم المعالجة بالدفعات والتوازي الفعلي على المجمّع والوكيل؛ لا يوفر PHP `cmd.php` و Spine سلوكاً متطابقاً في التوصيل.

غيّر إعداداً واحداً فقط في كل مرة ولاحظ مدة دورة أداة الاستقصاء.

## أنماط الفشل

| العَرَض | السبب |
|---|---|
| تم إنشاء الرسوم البيانية، وكل قياس غير معروف | لم يتم تنفيذ عدادات 64 بت، أو يستخدم الجهاز SNMP v1 |
| تقفز العدادات إلى قيم غير معقولة | يفيض عداد 32 بت أكثر من مرة في الفاصل الزمني |
| فجوات فقط تحت الحمل العالي | تم تثبيت الحد الأقصى لـ RRD على سرعة مكتشفة قديمة |
| تم تعيين سجل المنفذ إلى المنفذ الخاطئ بعد الصيانة | هوية غير مستقرة، أو تعيين قديم، أو معالجة يتيمة غير محلولة |
| تسجل أداة الاستقصاء تحذيرات حول فهارس SNMP غير صالحة | مصادر بيانات تركت بدون فهرس؛ أعد الفهرسة أو احذفها أو عطلها |
| تم اكتشاف المنافذ، ولم يتم جمع أي شيء | مصادر البيانات ذات الفهرس الفارغ لا تنشئ إدخالات في ذاكرة التخزين المؤقت لأداة الاستقصاء |
