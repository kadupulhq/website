## 项目概述

### 我今天可以安装使用它吗？

源代码可用于开发和独立环境测试。目前尚无受官方支持的正式版本，也无经过验证的生产安装路径。

安装指南与操作教程需要对照您实际使用的代码进行验证。详见[项目状态](/zh-cn/project/status/)。

### 它是否已具备生产可用性？

尚未具备。代码仓库明确将 Kadupul 定位为预预览（pre-alpha）阶段，尚未达到生产可用标准。发布状态并不能反映是否有用户在自行测试开发代码。

### 它是 Cacti 的直接替代品吗？

Kadupul 是一个独立的分支项目，拥有自己的开发优先级与技术支持渠道。目前处于预预览阶段；系统迁移需要针对实际使用的版本与扩展进行严格验证。详见[从 Cacti 迁移](/zh-cn/guides/coming-from-cacti/)。

### 为什么要建立独立的项目？

Kadupul 提供了一个平台，用于在自主的发布策略下重构子系统、提升语言基准版本并演进内部接口。详见[为什么创建此分支](/zh-cn/project/why-this-fork/)。

### 它基于哪个 Cacti 版本分叉？

应用程序衍生自 Cacti 1.2.31。代码仓库同时维护 `main` 与 `lts/1.2` 两条分支，各自具有不同的发布目标。详见[项目状态](/zh-cn/project/status/)。

### 谁在负责维护？

Kadupul 项目团队维护此代码仓库。请通过其问题追踪器与[贡献流程](/zh-cn/project/contributing/)参与项目工作。

### 是否有路线图、发布周期或支持政策？

代码仓库制定了发布目标、版本规范与贡献流程。目前尚未推出受官方支持的生产就绪版本。详见[项目状态](/zh-cn/project/status/)，了解规划版本与已发布产物之间的区别。

### 它是否隶属于 The Cacti Group？

不隶属。Kadupul 与 The Cacti Group 既无从属关系，亦未获得其官方背书。将其描述为 Cacti 的分支是对代码渊源的客观陈述。Cacti 是属于他们的项目与品牌。

### 这个名称有什么含义？

Kadupul 是僧伽罗语中一种夜间开花的仙人掌的名字。Cacti 源自整个仙人掌科植物；Kadupul 则是其中的一个具体物种。这一名称表明了项目的渊源，同时不企图代表其全部。详见[什么是 Kadupul](/zh-cn/start/what-kadupul-is/)。

## 从 Cacti 迁移

### 我的插件还能继续使用吗？

这正是我们的设计目标。插件 API 是四大兼容性目标之一。对于实际使用的具体版本，必须通过验证以确保 Cacti 插件无需修改即可加载与运行。

兼容性是一项工程目标，而非对所有插件的绝对担保。在规划迁移之前，请务必核实您实际依赖的插件及其版本。详见[与 Cacti 的兼容性](/zh-cn/project/compatibility-with-cacti/)以及[从 Cacti 迁移](/zh-cn/guides/coming-from-cacti/)。

### 我的 RRD 数据文件还能正常使用吗？

保留历史 RRD 数据是一项核心兼容性承诺。这些文件包含了无法重新生成的历史数据。在任何迁移操作之前，务必在副本上验证现有文件的读取功能。

任何要求废弃并重新创建这些历史数据的迁移方案都是不可接受的。详见[从 Cacti 迁移](/zh-cn/guides/coming-from-cacti/)。

### 模板和数据库结构能否顺利迁移？

模板的设计目标是无需修改即可导入。数据库结构力求保持易于识别，且无需导出为中间格式即可完成迁移。这些目标与插件及 RRD 文件一样，需要进行实际验证。

### 如果 Kadupul 与 Cacti 产生差异，我该如何获知？

通过清晰完备的文档记录。项目力求避免的并不是代码层面的分歧，这本就是创建分支的初衷；真正要规避的是未被记录的分歧，那会使每次升级都变成漫长的问题排查。

### 它能否与 Spine 配合运行？

Kadupul 将在维护 PHP 采集器的同时维护 Spine 分支。其代码仓库地址与经过验证的构建版本尚未在本站列出。Spine 需单独编译与安装。继承的集成机制包含 `poller_type` 和路径配置、父级采集器的命令行、Spine 读取的系统设置以及写入的数据表。

在系统切换前，请务必联合验证 Kadupul 与 Spine 的对应版本。如有异常请在 [Kadupul 问题追踪器](https://github.com/kadupulhq/kadupul/issues)中反馈。关于编译与配置指南，请参阅 [Spine（C 语言采集器）](/zh-cn/reference/spine/)。

### 它能否与 RRDtool 代理配合使用？

Kadupul 不使用 Cacti 组织的代理守护进程。请直接使用本地 RRDtool 存储。[RRDtool 代理参考](/zh-cn/reference/rrdproxy/)仅记录了继承的历史客户端协议，并不是受支持的部署方案。在正式记录代理部署方案前，必须先建立并验证 Kadupul 自研的替代方案。

### 运行环境有什么要求？

配置有 PHP、MySQL 或 MariaDB、RRDtool 的 Web 服务器，以及用于定时触发采集器的调度工具。具体的支持版本与扩展要求请参阅[环境要求](/zh-cn/reference/requirements/)。

## 许可证说明

### 该软件采用何种许可证分发？

GPL-3.0-or-later。

### Cacti 声明为 GPL-2，分支如何能采用 GPL-3？

继承的应用程序许可证明确允许采用 GPL 第 2 版或更高版本。Kadupul 选择了在分发中应用更高版本条款。第三方依赖仍遵循其各自的许可协议。详见[许可证](/zh-cn/project/license/)。

### 网站文档采用何种许可？

CC BY-SA 4.0。网站自身的程序代码与项目的其他部分保持一致，遵循 GPL-3.0-or-later。在注明项目出处并以相同方式许可衍生作品的前提下，您可以自由复用文档文本。

### 这些文档页面从何而来？

这些文档页面均根据应用程序源代码的实际行为编写。第三方文本资料在复用前必须单独进行许可证审查。

这一原则同样适用于社区贡献。文档修改必须以代码事实为依据。详见[参与贡献](/zh-cn/project/contributing/)。

## 参与项目

### 如何报告安全漏洞？

请在受影响的代码仓库中通过 GitHub 安全通告（Security Advisories）以私密方式提交。切勿提交公开问题。

未正式发布的代码也可能已被部署并存在漏洞。无论代码发布状态如何，均请以私密方式报告。详见[安全政策](/zh-cn/project/security/)。

### 若发现的漏洞可能同时影响 Cacti，该如何处理？

请私密报告给 Kadupul，并附上关于共享代码的已知细节。Kadupul 维护团队将依据[代码仓库安全政策](https://github.com/kadupulhq/kadupul/blob/main/SECURITY.md)对 Kadupul 进行问题分流与修复。

### 我该如何参与贡献？

请查阅[参与贡献](/zh-cn/project/contributing/)及目标分支上的贡献指南。实施重大变更前请先行沟通。

### 我在网站上发现了错误。

非常感谢。本站所有页面均直接根据源代码撰写，任何差错均有其具体事实依据。每个页面均附带有编辑链接。
