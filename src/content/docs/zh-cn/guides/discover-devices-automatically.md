自动化由两台容易混淆的独立机器组成。发现会遍历一系列地址并确定哪些是设备。一旦设备存在，规则就会决定为其构建什么内容。您可以独立运行其中任何一个，而人们在自动化方面造成的多数破坏都来自于同时启用两者并在事后才发现问题。

## 定义范围

网络范围是一个逗号分隔的列表。每个条目采用以下三种形式之一。

| 形式 | 示例 | 说明 |
|---|---|---|
| CIDR | `192.168.1.0/24` | 也接受点分掩码，`192.168.1.0/255.255.255.0` |
| 通配符 | `192.168.*.*` | 内部转换为等效的 CIDR |
| 单个地址 | `192.168.1.10` | 仅扫描该确切地址 |

写为 `192.168.1.10-192.168.1.50` 的起始至结束范围会被拒绝并报错。它们不受支持。

使用不重叠的范围，包括在可能并发运行的网络之间。工作表在 IP 地址上具有全局唯一键；重复项可能会拒绝整个插入批次，从而忽略该批次中的其他地址。参见[问题 #207](https://github.com/kadupulhq/kadupul/issues/207)。

所有内容均为 IPv4。范围计算全程使用 32 位整数转换，因此此处没有 IPv6 路径。

网络地址和广播地址被排除在外。一个 `/24` 扫描 254 个地址，从 `.1` 到 `.254`。单个地址条目扫描一个。在扫描期间，最后一个八位位组为 255 的地址也会被跳过。

在扫描开始之前，范围内的每个地址都会写入工作表中，每个地址一行，并且线程从中索取行。在第一次 ping 之前，一个 `/16` 会写入 65534 行。这是真正的开销，这也是为什么大型稀疏范围的扫描即使在没有任何响应时也很慢的原因。

为每个范围附加一个 SNMP 选项集。主控模式会记录错误并跳过 SNMP 集 ID 为零的范围。定向运行不应用相同的防护；直接启动它并不会使缺失的 SNMP 选项变得可用。

## 控制扫描节奏

| 设置 | 作用 | 默认值 |
|---|---|---|
| 发现线程数 | 索取地址的并行工作进程 | 1 |
| 运行限制 | 发现持续此时间后被终止 | 20 分钟 |
| 调度类型 | 手动、每日、每周、每月或某月某日 | 手动 |
| Ping 方法 | ICMP、TCP、TCP closed、UDP 或 SNMP | 来自全局设置 |
| Ping 重试次数、超时 | 每个地址的故障代价 | 来自全局设置 |

如果不加以考虑，线程与运行限制之间的相互作用会很糟糕。对于任何入侵检测系统而言，针对 `/16` 的五十个线程就相当于端口扫描。针对相同范围的一个线程将达到运行限制并在中途被终止，从而留下看起来像完整结果的部分结果。

调整范围大小，以便扫描在您的网络可承受的线程数下在限制时间内完成。多个小范围优于一个大范围，因为每个小范围都有自己的调度和自己的限制。

## 扫描对每个地址的操作

1. 解析名称。备用 DNS 服务器可以作为空格分隔的列表提供；如果未设置，则使用轮询器自身的解析器。当 DNS 未返回任何内容时，NetBIOS 查找是可选的回退方案。
2. 检查地址或该名称是否已是设备。如果是，该地址将被标记为已完成。这会抑制通过这些值找到的现有设备；这不是防止并发创建或不同别名的保证。
3. 使用配置的方法执行 ping。SNMP 方法会跳过单独的 ping。
4. 如果 ping 有响应，或者选择了 SNMP 方法，则尝试 SNMP 并收集 `sysDescr`、`sysObjectID`、`sysName`、`sysLocation`、`sysContact` 和正常运行时间。
5. 将收集的系统数据与设备规则进行匹配。

能够 ping 通但不响应 SNMP 的地址将被记录为已找到且存活。响应 SNMP 但不匹配任何设备规则的地址将被记录为已找到并带有其系统数据，且不会创建任何内容。两者都会进入已发现设备列表。

重复抑制默认开启。如果在该网络存储的发现记录中另一个地址上已见过 `sysName`，或者它存在于具有不同主机名的设备上，则跳过该地址。这对于具有许多寻址接口的路由器是正确的默认设置，但对于独立 NAT 地址后面的相同设备则是错误的设置，这正是同名 sysName 选项存在以用于关闭的原因。

现有设备可以在扫描期间重新运行其数据查询。这默认处于关闭状态，它适用于记录为正常运行或正在恢复的设备。发现使用其存储的状态进行此决定；它不会重新探测现有设备。

## 设备规则决定模板

设备规则将系统数据映射到设备模板。每个规则都包含针对 `sysDescr`、`sysObjectID` 和 `sysName` 的模式。匹配器会过滤设备作为非空返回的每个系统字段；空白规则模式匹配任何值。规则按顺序评估，首个匹配项生效。

使用简单的字面子字符串并在发现结果中验证所选模板。当前的 SQL 匹配器将正则表达式模式包装在字面 `/` 字符中，因此锚定模式（如 `^Linux.*fixture$`）即使数据库的正则运算符直接匹配它也会失败。子字符串回退无法修复该情况。参见[问题 #206](https://github.com/kadupulhq/kadupul/issues/206)。SQL `LIKE` 也将 `%` 和 `_` 视为通配符。

不匹配意味着没有设备。该地址将连同所收集的任何系统数据一起记录在已发现设备列表中，该列表正是您编写所缺失规则的地方。

将特定规则放在通用规则之上。匹配子字符串 `Linux` 并放置在供应商规则之上的规则将认领描述中提及 Linux 的每个设备。

## 在启用创建之前预览发现

新范围上的设备创建开关默认处于关闭状态。初始阶段请保持其关闭，并禁用重新运行现有设备数据查询的选项。此阶段仍会更新发现记录、扫描统计信息和日志，并可以发送配置的通知。它不会预览图形或树规则的执行。

运行扫描，然后阅读已发现设备列表。它显示记录的发现、它们收集的 SNMP 数据以及匹配的模板（如果有）。现有设备、被抑制的重复项和被跳过的地址无需出现在那里。检查每个地址的调试输出以及列表。

从命令行强制扫描，而不是等待调度：

```bash
php poller_automation.php --network=3 --force --debug
```

调试标志会实时打印每个地址的决策。启动调度已到期的已启用范围的主控进程是一个单独的模式：

```bash
php poller_automation.php -M
```

定向 `--force` 命令也会运行已禁用的网络。向主控模式添加 `--force` 会绕过调度检查，也可以启动已禁用的网络。验证单个范围时，请使用定向形式。

在开启创建之前，请在结果中检查三件事。

- 设备数量符合您的预期。数量远高于您的资产清单通常意味着范围比您想象的更宽。
- 选择的模板是正确的。所有设备上都有一列相同的通用模板意味着您的规则没有匹配。
- 没有重要内容缺失。对于缺失的设备，请检查范围扩展、工作进程完成情况、现有设备和重复项抑制、ping 策略和 SNMP 结果。仅仅不在列表中并不能确定它是不可达的。

## 图形和树规则

一旦设备存在，图形规则和树规则就会决定在其上构建什么。发现在创建设备后可以调用此自动化，CLI 也可以将其应用于现有设备。必须启用单个图形和树规则。全局图形/树自动化开关控制特定的创建钩子；它们不是对显式 CLI 自动化的全面禁止。

图形规则由三部分组成：它适用于哪些设备，它适用于数据查询中哪些已发现的索引，以及要创建哪种图形类型。两个匹配部分都是由规则项构建的，规则项是一个字段、一个运算符和一个模式，通过带有括号的 `AND` 或 `OR` 连接。

| 运算符组 | 成员 |
|---|---|
| 子字符串 | contains, does not contain, begins with, does not begin with, ends with, does not end with |
| 相等性 | matches, is not equal to |
| 数值 | is less than, less than or equal, greater than, greater than or equal |
| 存在性 | is unknown, is not unknown, is empty, is not empty |
| 模式 | matches regular expression, does not match regular expression |

这些将成为 SQL `WHERE` 子句。正则表达式运算符是数据库的正则表达式方言，而不是 PCRE，因此在 `preg_match` 中起作用的模式在此处不一定有效。针对数值模式的数值比较不加引号传递；其他所有内容都加上引号，并且数据库应用其类型转换规则。针对实际缓存的值测试数值过滤器；这些值通常存储为文本。子字符串运算符使用 SQL `LIKE`，其中 `%` 和 `_` 具有通配符含义。

在调试没有任何操作的规则之前，了解以下两种行为是值得的。

**空的设备/对象过滤器不匹配任何内容，但空的索引过滤器匹配所有缓存的索引。** 当设备选择过滤器没有匹配项时，它会回退到 false 条件。然而，一旦图形规则匹配了设备，删除其所有图形索引条件将使数据查询不受过滤。例如，删除 `ifDescr = eth0` 条件也会为 `lo` 创建图形。在编辑其索引条件时禁用该规则。

**引用设备尚未发现的字段的规则将被废弃。** 如果规则过滤设备缓存中不存在的数据查询字段，则运行会记录一条提及该字段的警告，并停止针对该设备处理该规则。常见原因是对一个数据查询编写的规则在查询返回不同字段集的设备上进行了评估。

规则编辑页面列出了候选对象和图形。在启用规则之前和编辑规则之后查看这些列表。它们是选择预览，而不是完整的执行空运行：数据源检查、现有图形检测、创建钩子和树插入仍会在执行期间发生。CLI 没有空运行选项。

树规则具有单独的设备和图形叶节点类型，以及选定的目标树和父节点。标头步骤可以使用固定字符串或来自设备/图形字段的值。派生自字段的标头应用不区分大小写的 PHP 正则替换；结果中的字面 `\n` 序列将其拆分为连续的嵌套标头。此替换语法与用于对象匹配的 SQL 正则表达式不同。现有的标头和叶节点在相同的树和父节点下被重用；更改路径可以添加另一个位置而不删除旧位置。

## 将规则应用于已存在的设备

发现不是唯一的入口。可以针对系统中已存在的设备运行规则，通过 ID、主机名或描述进行选择：

```bash
php cli/apply_automation_rules.php --ids="12 13 14" --debug
php cli/apply_automation_rules.php --hostname="^edge-" --debug
php cli/apply_automation_rules.php --description="branch office"
```

当值有效时，主机名和描述将作为正则表达式进行匹配，并且始终也作为子字符串进行匹配。三者中至少需要一个；在没有选择器的情况下调用它会退出并报错。组合选择器时，它们由 `AND` 连接。使用空格分隔的正设备 ID 进行精确选择；不支持逗号分隔的 ID。模式仍然可以很宽泛，SQL `LIKE` 回退将 `%` 和 `_` 视为通配符。

选择器查询不会自动排除已禁用的设备。`--debug` 会添加诊断信息，但仍会执行创建。没有匹配的设备是一个成功的空操作，因此仅凭退出状态并不能证明创建了任何内容。

对于每个匹配的设备，运行按顺序执行三件事：

1. 尝试为附加的且设备上没有图形的图形模板创建图形，但须通过模板合格性和数据源检查。
2. 使用存储的索引缓存针对附加的数据查询运行已启用的图形规则。此步骤本身不会重新运行发现；如果缓存缺失或陈旧，请先刷新数据查询。
3. 应用已启用的设备叶树规则。

启用全局树自动化后，新图形创建可以调用图形叶树规则。CLI 不会将这些规则重新应用于它发现已创建的图形。因此，仅仅因为重新运行了 CLI，新的或更改的图形叶规则不会回填现有图形。参见[问题 #211](https://github.com/kadupulhq/kadupul/issues/211)。单独验证它们的位置；不要仅仅为了触发创建钩子而删除并重新创建历史图形。

重复运行会按设备和图形模板抑制现有的非索引图形。索引图形按设备、数据查询、图形类型和索引进行检查。这可以防止连续运行中的重复创建；这不是并发保证。运行后检查图形列表和树，以及用于跳过图形、无效数据或创建失败的 `AUTOM8` 日志消息。

有一件事被静默跳过，足以令人困惑：具有标记为可覆盖但没有默认值的字段的图形模板不符合自动化条件。运行会记录未添加它是因为可覆盖字段没有默认值，然后继续。如果您期望的模板从未出现，那是首先要检查的事情。有关什么是可覆盖字段，请参见[模板](/zh-cn/concepts/templates/)。

## 陷阱

**禁用规则不会撤销其工作。** 它不会删除已创建的图形或树条目。设备删除具有单独的图形和数据源清理行为；在删除设备之前查看删除选项。

**被终止的扫描看起来像是一次干净的扫描。** 运行限制会终止发现，无论其进行到何处。记录的总数是已完成工作的总数，没有任何标记将结果标为部分结果。将扫描的地址数与范围大小进行比较。

**规则针对数据查询缓存运行，而不是针对设备。** 不匹配任何内容的图形规则通常意味着数据查询从未运行，或者运行了但未找到索引。在重写规则之前检查已发现的索引表。

**通知邮件包含现有发现和新发现。** 范围可以在完成时发送邮件，按每个 IP 是否出现在扫描前的快照中对其记录的发现进行分组。这并不是每个请求的地址都已扫描的证据。

## 故障模式

| 现象 | 常见原因 |
|---|---|
| 扫描在有主机的范围内未发现任何内容 | Ping 被阻止、SNMP 故障、排除项或重复项抑制 |
| 范围拒绝扫描，日志中报错 | 未附加任何 SNMP 选项集 |
| 发现设备但未创建任何设备 | 创建开关已关闭，或没有设备规则匹配 |
| 所有内容都获得相同的通用模板 | 规则顺序问题，通用规则位于特定规则之上 |
| 仅扫描了部分地址 | 达到运行限制，或重叠范围拒绝了地址批次 |
| 每个路由器一个设备而不是每个接口一个设备，或反之 | 同名 sysName 重复抑制设置 |
| 规则不匹配任何内容且日志警告某一列 | 规则过滤此设备的数据查询未返回的字段 |
| 规则从未创建图形模板 | 缺少必需的默认值、无效的数据源输出或创建失败 |
| 附加接口的意外图形 | 图形索引过滤器为空或比预期更宽泛 |
| 新的树规则未放置现有图形 | CLI 不会为现有图形回填图形叶规则 |
