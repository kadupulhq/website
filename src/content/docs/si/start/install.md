:::caution[භාවිතයට පෙර තහවුරු කරන්න]
මූලාශ්‍ර කේතය ලබාගත හැකි වුවද, සහාය දක්වන Kadupul නිකුතුවක් හෝ සංක්‍රමණ මාර්ගයක් නොමැත. මේවා මත විශ්වාසය තැබීමට පෙර උපස්ථ සහිත වෙන් කළ පිටපතක මෙම ක්‍රියාපටිපාටි පරීක්ෂා කරන්න. [ව්‍යාපෘති තත්ත්වය](/si/project/status/) බලන්න.
:::

පිළිවෙළින්, එක් වරක් මෙම පියවරයන් ඔස්සේ වැඩ කරන්න. සෑම පියවරක්ම පරීක්ෂණයකින් අවසන් වේ. ඉදිරියට යාමට පෙර එම පරීක්ෂණය සිදු කරන්න: මෙහි ලැයිස්තුගත කර ඇති සෑම අසාර්ථකත්වයක්ම දැන් සොයා ගැනීම පහසු වන අතර, දත්ත එකතු කරන්නා (poller) සතියක් ධාවනය වූ පසු සොයා ගැනීම මිල අධික වේ.

ධාරකයට විශේෂිත පූර්ව අවශ්‍යතා සඳහා [Windows ධාරකයක Linux](/si/guides/install-on-windows/) සහ [FreeBSD](/si/guides/install-on-freebsd/) බලන්න. මෙම ක්‍රියා පටිපාටි මුල සිට අග දක්වා පිළිගැනීමේ පරීක්ෂණයක් සම්පූර්ණ කළ බවට සාක්ෂි නොවේ.

## ඔබට මුලින්ම අවශ්‍ය දෑ

Kadupul යනු MySQL හෝ MariaDB තුළ වින්‍යාසයන් ගබඩා කරන සහ තැටියේ ඇති RRD ගොනුවල මිනුම් ගබඩා කරන PHP යෙදුමකි. මෙම පිටුව විස්තර කරන්නේ වත්මන් `main` මූලාශ්‍රයෙන් නව ප්‍රධාන සේවාදායක ස්ථාපනයක් සිදු කරන ආකාරය මිස, උත්ශ්‍රේණි කිරීමක් හෝ සංරක්ෂිත LTS පෙළ නොවේ. එය ධාවනය වීමට පෙර කරුණු හතරක් තිබිය යුතුය.

| සංරචකය | එය අවශ්‍ය වන්නේ ඇයි |
|---|---|
| ආරක්ෂක සහාය සහිත නිකුතුවක PHP 8.4 හෝ ඊට නව අනුවාදයක් | වෙබ් අතුරුමුහුණත සහ poller ධාවනය කරයි |
| MySQL හෝ MariaDB | උපාංග, ආකෘති, පරිශීලකයින්, සහ poller cache රඳවා තබා ගනී |
| RRDtool | round-robin archives සාදයි සහ යාවත්කාලීන කරයි, සහ ප්‍රස්තාර විදහා දක්වයි |
| net-snmp | උපාංග විමසීමට භාවිත කරන සේවාලාභී මෙවලම් සහ පුස්තකාල සපයයි |

[යෙදුම් ප්‍රකාශනය](https://github.com/kadupulhq/kadupul/blob/main/composer.json) මඟින් අවශ්‍ය වන `pdo_mysql`, `gd`, `sockets`, `gmp`, `intl`, `ldap`, `mbstring`, `pcntl`, `posix`, සහ `sqlite3` ඇතුළු දිගු ද PHP සඳහා අවශ්‍ය වේ. විධාන රේඛාව (CLI) සහ වෙබ් ධාවන පරිසර දෙක සඳහාම ඒවා ස්ථාපනය කරන්න. [අවශ්‍යතා](/si/reference/requirements/) මඟින් Composer අවශ්‍යතා ස්ථාපකයේ වෙනම පරීක්ෂණවලින් වෙන් කර හඳුනා ගනී.

## පියවර 1: ධාවන පරිසරය ස්ථාපනය කරන්න

ඔබේ බෙදාහැරීමේ පැකේජවලින් PHP සහ එහි දිගු, ඔබගේ දත්ත සමුදා සේවාදායකය, RRDtool, සහ net-snmp ස්ථාපනය කරන්න.

**එය පරීක්ෂා කරන්න.**

```bash
php -v
php -m | sort
rrdtool --version
snmpget --version
```

`php -m` මඟින් අවශ්‍ය දිගු ලැයිස්තුගත කළ යුතුය. net-snmp විධාන රේඛා මෙවලම් පවතින විට PHP `snmp` දිගුව විකල්ප වේ. Composer පරායත්තතා ස්ථාපනය කිරීමේදී තමන්ට අවශ්‍ය දිගු පරීක්ෂා කරයි; වෙබ් ස්ථාපකයට වෙනම දිගු පරීක්ෂාවක් ඇත. ධාවන පරිසර විකල්පයකින් Composer අවශ්‍යතාවයක් ඉවත් නොවේ.

විධාන රේඛා සහ වෙබ් සේවාදායක PHP වින්‍යාසයන් එකිනෙකට වෙනස් විය හැක. දෙකම පරීක්ෂා කරන්න. ස්ථාපකය අවම වශයෙන් 400M ක `memory_limit` සහ අවම වශයෙන් තත්පර 60 ක `max_execution_time` නිර්දේශ කරයි; එය ඒවායේ සීමාරහිත අගයන් (පිළිවෙළින් `-1` සහ `0`) ද පිළිගනී. එම නිර්දේශයන්ට වඩා අඩු අගයන් අනතුරු ඇඟවීම් ජනනය කරන අතර, නොමැති `date.timezone` යනු දෝෂයකි. `UTC` වැනි පැහැදිලි වේලා කලාපයක් සකසන්න, සහ විධාන රේඛා වින්‍යාසය හඳුනා ගැනීමට `php --ini` භාවිත කරන්න.

## පියවර 2: දත්ත සමුදාය සහ එහි පරිශීලකයා සාදන්න

හිස් දත්ත සමුදායක් සහ එම දත්ත සමුදාය සඳහා හිමිකම් ඇති එක් පරිශීලකයෙකු සාදන්න. දේශීය දත්ත සමුදායක් සඳහා, භාවිතයට පෙර උදාහරණ මුරපදය ප්‍රතිස්ථාපනය කරමින්, දත්ත සමුදා පරිපාලකයෙකු ලෙස මෙම SQL ධාවනය කරන්න:

```sql
CREATE DATABASE kadupul CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'kadupul'@'localhost' IDENTIFIED BY 'replace-with-a-unique-password';
GRANT ALL PRIVILEGES ON kadupul.* TO 'kadupul'@'localhost';
```

PHP වෙනත් පරිගණකයක සිට සම්බන්ධ වන්නේ නම් ඊට ගැළපෙන දත්ත සමුදා ගිණුම් ධාරකය (host) භාවිත කරන්න.

දත්ත සමුදා සේවාදායකයට එහි වේලා කලාප වගු දත්ත පිරවීමද අවශ්‍ය වන අතර, Kadupul පරිශීලකයාට `mysql` දත්ත සමුදාය තුළ ඒවා සඳහා කියවීමේ ප්‍රවේශය අවශ්‍ය වේ. එහිම ක්‍රමානුරූපයෙන් පිටත ඇති එකම අවසර ප්‍රදානය එයයි. නිරීක්ෂණ පද්ධතියක් ගැන කිසිවක් මෙය යෝජනා නොකරන අතර, එය විකල්ප නොවේ; පහත පරීක්ෂණය එය නොමැතිව අසමත් වේ.

```bash
# Populate the tables, then grant the one extra read the installer needs.
mysql_tzinfo_to_sql /usr/share/zoneinfo | mysql -u root -p mysql
mysql -u root -p -e "GRANT SELECT ON mysql.time_zone_name TO 'kadupul'@'localhost';"
```

**එය පරීක්ෂා කරන්න.** Kadupul දත්ත සමුදා පරිශීලකයා ලෙස ලොග් වී ධාවනය කරන්න:

```sql
SELECT COUNT(*) FROM mysql.time_zone_name;
```

අවසර දෝෂයකින් තොරව බිංදුව නොවන ගණනක් ලැබීම ඔබට අවශ්‍ය දේ වේ. බිංදුව යනු වගු කිසි විටෙකත් පටවා නොමැති බවයි; දෝෂයක් යනු පරිශීලකයාට ඒවා කියවිය නොහැකි බවයි. මේ දෙකම ස්ථාපකය නවත්වයි.

සේවාදායකයේම සැකසුම් හතරක් දැන්ම නිවැරදි කිරීමට තරම් වැදගත් වේ.

| සැකසුම | අවශ්‍ය දේ | හේතුව |
|---|---|---|
| `max_allowed_packet` | 16M හෝ ඊට වැඩි | ප්‍රධාන සේවාදායකය සහ දුරස්ථ එකතු කරන්නන් අතර විශාල සමමුහුර්ත කිරීම් |
| `character_set_server`, `collation_server` | `utf8mb4`, `utf8mb4_unicode_ci` | උපාංග විස්තර බහු-බයිට් අක්ෂර අඩංගු වේ |
| `innodb_file_per_table` | On | වගු ඉඩ වෙන වෙනම සහ කළමනාකරණය කළ හැකි පරිදි තබයි |
| `innodb_buffer_pool_size` | පද්ධති මතකයෙන් හතරෙන් එකක් පමණ | ක්‍රියාකාරී කට්ටලය මතකයේ රඳවා තබයි |

ස්ථාපකය මේවා පිළිබඳ තමන්ගේම කියවීම වාර්තා කරන අතර අවශ්‍ය ප්‍රමාණයට වඩා අඩු දේ සලකුණු කරයි, එබැවින් ඔබට මෙම වගුව විශ්වාසය මත පමණක් ගැනීමට අවශ්‍ය නොවේ. ඔබට බරක් (load) ඇති වූ පසු [දත්ත සමුදා සැකසුම්](/si/guides/tune-database-performance/) තවදුරටත් උපකාරී වේ.

## පියවර 3: එය දිගහරින්න, හිමිකාරිත්වය සකසන්න, සහ සේවය සලසන්න

ඔබේ වෙබ් සේවාදායකයට සේවය කළ හැකි ස්ථානයක යෙදුම තබන්න, ඉන්පසු එය අයිති වන්නේ කුමන පද්ධති පරිශීලකයාටද යන්න තීරණය කරන්න. එම තීරණය පිහිටීමට වඩා වැදගත් වේ. ක්‍රියාවලි දෙකක් මෙහි ලියයි: වෙබ් සේවාදායකය, සහ poller කාලසටහන්ගත කරන ඕනෑම දෙයක්. දෙකම එකම පරිශීලකයා ලෙස ධාවනය කරන්න. poller වරප්‍රසාද රහිතව ධාවනය කර ක්‍රියාවලි දෙකටම අවශ්‍ය ප්‍රවේශය ලබා දෙන්න. වැරදි හිමිකාරිත්වය හෝ මාතයන් මඟින් ප්‍රස්තාර විදහා දැක්වුවද පසුකාලීන යාවත්කාලීන කිරීම් වැළැක්විය හැක.

### ඔබ නිකුතුවක් දිගහැරීමට වඩා ගබඩාව clone කළේ නම්

Git පිටපතකට PHP පරායත්තතා සහ ජනනය කළ බ්‍රවුසර වත්කම් (assets) යන දෙකම අවශ්‍ය වේ. ගබඩාවේ `mise.toml` ධාවන පරිසරයන් ස්ථාපනය කර තිබියදී, ගබඩා මූලයේ සිට ධාවනය කරන්න:

```bash
mise exec -- php "$(command -v composer)" install --no-dev --optimize-autoloader
mise exec -- npm ci --ignore-scripts
mise exec -- npm run build
mise exec -- php bin/console asset-map:compile
mise exec -- php bin/console about
```

Composer මඟින් `include/vendor/` පුරවන අතර අගුළු දැමූ ගැළපුම් ගොනු ප්‍රතිස්ථාපනය කරයි. npm ගොඩනැගීම මඟින් `include/js/`, `include/fa/`, සහ `include/vendor/flag-icons/` යටතේ වත්කම් සාදයි. මූලාශ්‍ර ස්ථාපනයක් සඳහා Composer පමණක් ප්‍රමාණවත් නොවේ.

පරායත්තතා-සම්පූර්ණ නොබැඳි බණ්ඩලයක් (offline bundle) යනු වෙනම ගොඩනැගීමේ කෞතුක වස්තුවකි (build artifact). සාමාන්‍ය GitHub මූලාශ්‍ර සංරක්ෂිතයක් එම බණ්ඩලය නොවේ. ඉලක්කගත ධාරකයට අන්තර්ජාල ප්‍රවේශයක් නොමැති විට [නොබැඳි ගොඩනැගීමේ සහ තහවුරු කිරීමේ ක්‍රියාපටිපාටිය](https://github.com/kadupulhq/kadupul/blob/main/docs/symfony-migration.md#offline-installation) අනුගමනය කරන්න.

පරායත්තතා ස්ථාපනය කිරීමෙන් පසු ලිවිය හැකි මාර්ග සූදානම් කරන්න:

| කණ්ඩායම | නාමාවලි | ලිවිය හැකි අවස්ථාව |
|---|---|---|
| ස්ථාපනය අතරතුර | `resource/snmp_queries`, `resource/script_server`, `resource/script_queries`, `scripts` | ස්ථාපනය හෝ උත්ශ්‍රේණි කිරීම අතරතුර පමණි |
| ස්ථාපනය අතරතුර | `include/vendor/csrf/`, හෝ වින්‍යාස කළ `path_csrf_secret` පිහිටීම | ස්ථාපකය ස්ථාපනයට විශේෂිත වූ රහස සෑදිය යුතුය; ඉන්පසු එය ආරක්ෂා කර තබන්න |
| සැමවිටම | `log`, `cache/boost`, `cache/mibcache`, `cache/purifier`, `cache/realtime`, `cache/spikekill`, පද්ධති තාවකාලික නාමාවලිය | ස්ථාපනයේ ආයු කාලය පුරාම |
| Symfony ධාවන කාලය | `var/cache`, සහ ගොනු ලොග් කිරීම වින්‍යාස කර ඇත්නම් `var/log` | PHP ධාවන කාලය සහ cache-warming පරිශීලකයා සඳහා |

ස්ථාපනයේ ආයු කාලය පුරාම RRD නාමාවලියද ලිවිය හැකි විය යුතුය. එය ඔබගේ ඉතිහාසය රඳවා තබා ගනී, එබැවින් ඔබ දත්ත සමුදා නාමාවලියකට ලබා දෙන සැලකිල්ල ඊටත් ලබා දෙන්න.

වත්මන් සංක්‍රමණයට තවමත් පැරණි පිවිසුම්, ස්ථාපක, සහ ප්ලගින මාර්ග අවශ්‍ය වේ. මෙම ඒකාබද්ධ ස්ථාපනය සඳහා, පුද්ගලික නාමාවලි, වින්‍යාසය, පරායත්තතා සහ ධාවන කාල තත්ත්වය වෙත ප්‍රවේශය ප්‍රතික්ෂේප කරන පැහැදිලි නීති සමඟ ගබඩා මූලයට සේවය සලසන්න. සම්පූර්ණ ස්ථාපනය `public/` වෙත මාරු නොකරන්න: එය තවමත් භාවිතයේ පවතින පැරණි මාර්ග ඉවත් කරනු ඇත. Symfony හි වෙනම අන්ත ලක්ෂ්‍යයට වෙනස් රවුටින් ඇත; [සංක්‍රමණ උපදෙස්](https://github.com/kadupulhq/kadupul/blob/main/docs/symfony-migration.md) බලන්න.

Nginx සඳහා, මූලය සහ PHP-FPM upstream අනුවර්තනය කරමින්, ගබඩාවේ [Nginx ස්ථාන නීති](https://github.com/kadupulhq/kadupul/blob/main/tests/e2e/nginx.conf) වෙතින් ආරම්භ කරන්න. සාමාන්‍ය PHP හැසිරවීමට පෙර ප්‍රතික්ෂේප කිරීමේ නීති තබා ගන්න සහ `/app.php/...` සඳහා PATH_INFO ආරක්ෂා කරගන්න. Nginx විසින් `.htaccess` කියවන්නේ නැත. RRD ගොනු, ලොග් සහ රහස් HTTP හරහා ප්‍රවේශ විය නොහැකි ලෙස තබන්න; ගොනු අවසරයන් සේවය සැපයීම වළක්වයි කියා උපකල්පනය කරනවා වෙනුවට සැබෑ සේවාදායක වින්‍යාසය තහවුරු කරන්න.

**එය පරීක්ෂා කරන්න.** poller පරිශීලකයා බවට පත් වී, සෑම සැමවිටම-කණ්ඩායම් නාමාවලියකටම ගොනුවක් ලියන්න, ඉන්පසු එය මකන්න. `ls -l` හි නිවැරදි ලෙස පෙනෙන අවසරයක් SELinux හෝ AppArmor මඟින් තවමත් ප්‍රතික්ෂේප විය හැකි අතර, ගොනුව ලිවීම එය ආවරණය වන එකම පරීක්ෂාවයි. ඉන්පසු HTTP හරහා ලොග් නාමාවලිය යටතේ ඇති ගොනුවක් ඉල්ලා සිටින්න. ඔබට අවශ්‍ය වන්නේ ප්‍රතික්ෂේප කිරීමකි.

## පියවර 4: වින්‍යාස ගොනුව ලියන්න

නව ස්ථාපනයක් සඳහා, බෙදාහැර ඇති වින්‍යාස ගොනුව පිටපත් කරන්න:

```bash
cp include/config.php.dist include/config.php
```

පවතින ස්ථාපනයක වින්‍යාසය උඩින් නොලියන්න. පියවර 2 වෙතින් දත්ත සමුදා ධාරකය, නම, පරිශීලකයා, සහ මුරපදය සකසන්න. පළමු ස්ථාපනයකදී තවත් අගයන් දෙකක් වැදගත් වේ: `url_path`, එනම් මුලට සහ අගට slashes සහිතව යෙදුම සපයනු ලබන මාර්ගය, සහ `poller_id`, එනම් ප්‍රධාන සේවාදායකයක `1` වන අතර දුරස්ථ එකතු කරන්නෙකු මත පමණක් වෙනත් අගයක් වේ.

දුරස්ථ එකතු කරන්නාගේ කොටස comment කර තබන්න. ඔබ තවම එකක් සාදන්නේ නැත; ඔබ එය සාදන විට [දුරස්ථ දත්ත එකතු කිරීම](/si/concepts/remote-data-collection/) එය ආවරණය කරයි. අනෙකුත් සෑම සැකසුමකටම ක්‍රියාකාරී පෙරනිමියක් ඇත, එබැවින් ඒවායින් කිසිවක් වෙනස් කිරීමට පෙර [වින්‍යාසය](/si/reference/configuration/) කියවන්න.

එය භාවිත කරන Symfony විශේෂාංග සඳහා PHP ක්‍රියාවලි පරිසරය තුළ යෙදවීමට-විශේෂිත වූ `APP_SECRET` එකක් වින්‍යාස කරන්න. bootstrap එක පෙරනිමියෙන් `APP_ENV=prod` සහ `APP_DEBUG=0` වෙත සකසන අතර `.env` ගොනු පටවන්නේ නැත. මෙය පැරණි ස්ථාපකයේ CSRF රහසින් වෙන් වූවකි.

**එය පරීක්ෂා කරන්න.** අක්තපත්‍ර නොපෙන්වා වාක්‍ය ඛණ්ඩය (syntax) පරීක්ෂා කරන්න:

```bash
php -l include/config.php
```

බ්‍රවුසරයක ස්ථාපකය විවෘත කිරීමට පෙර ඊළඟ පියවරේදී ක්‍රමානුරූපය ආයාත කරන්න.

## පියවර 5: ක්‍රමානුරූපය ආයාත කරන්න

ස්ථාපකය අපේක්ෂා කරන්නේ වගු දැනටමත් පවතිනු ඇති බවයි. ඔබ විසින් සාදන ලද දත්ත සමුදාය තුළට සපයා ඇති ක්‍රමානුරූපය පටවන්න:

```bash
mysql -u kadupul -p kadupul < cacti.sql
```

හිස් දත්ත සමුදායකට එරෙහිව මෙය එක් වරක් කරන්න. මෙය උත්ශ්‍රේණි කිරීමේ ස්ක්‍රිප්ටයක් නොවේ; දත්ත පවතින දත්ත සමුදායකට එය ආයාත කිරීම අසමත් විය හැක හෝ පරස්පර සහ අසම්පූර්ණ දත්ත ඉතිරි විය හැක.

## පියවර 6: ස්ථාපකය ධාවනය කරන්න

බ්‍රවුසරයක අඩවිය විවෘත කර එය ඔස්සේ ඉදිරියට යන්න. ස්ථාපකය ස්ථාවර අනුපිළිවෙළක් ඔස්සේ ගමන් කරන අතර, එක් එක් පියවර ඊළඟ පියවර විවෘත කරයි:

1. පිළිගැනීම සහ බලපත්‍රය.
2. පරායත්තතා පරීක්ෂාව: PHP අනුවාදය සහ දිගු, විධාන රේඛාව සහ වෙබ් සේවාදායකය යන දෙකම සඳහා පියවර 1 හි PHP සැකසුම්, වේලා කලාප වගු, සහ පියවර 2 හි දත්ත සමුදා සැකසුම්. දෝෂ ඊළඟ බොත්තම අවහිර කරයි. අනතුරු ඇඟවීම් එසේ නොකරයි, නමුත් ඒවා කියවන්න.
3. ස්ථාපන වර්ගය: නව ප්‍රධාන සේවාදායකයක්, හෝ දුරස්ථ එකතු කරන්නෙකු.
4. අවසර පරීක්ෂාව: පියවර 3 හි නාමාවලි, ඒවාට ලිවීමෙන් පරීක්ෂා කරනු ලැබේ.
5. බයිනරි පිහිටීම්: PHP, RRDtool, සහ net-snmp මෙවලම් වෙත මාර්ග.
6. දත්ත ප්‍රභව පැතිකඩ සහ ආරම්භක පරතරය.
7. ආකෘති තේරීම: පූරණය කළ යුතු උපාංග ආකෘති මොනවාද යන්න.
8. වගු පරිවර්තනය, තහවුරු කිරීම, සහ ස්ථාපනයම.

එම ලැයිස්තුවේ අයිතම 6 යනු ආපසු හැරවීමට අපහසු එකයි. ඔබ තෝරා ගන්නා පැතිකඩ පසුව නිර්මාණය කරන සෑම RRD ගොනුවකටම ලියන පියවර සහ සංරක්ෂිත කට්ටලය තීරණය කරන අතර, පැතිකඩ සංස්කරණය කිරීමෙන් පවතින ගොනු සංක්‍රමණය නොවේ. රඳවා ගැනීමේ වෙනස්කම් සඳහා වෙනම, පරීක්ෂා කළ සංක්‍රමණයක් අවශ්‍ය වේ; ඒවාට සෑම විටම ඉතිහාසය ඉවත දැමීම අවශ්‍ය නොවේ. උපරිමයන් වැදගත් නම්, පැතිකඩ සාමාන්‍යයන් පමණක් නොව උපරිමයන් ද තබා ගන්නා බවට සහතික වන්න: එය පසුකර ක්ලික් කිරීමට පෙර [දත්ත ප්‍රභව සහ round-robin archives](/si/concepts/data-sources-and-rras/) කියවන්න. එහි පිරිනමන ආරම්භක පරතරය මිනිත්තුවක් හෝ මිනිත්තු පහකි. දත්ත ප්‍රභව පැතිකඩ මඟින් දත්ත එකතු කිරීමේ පරතරය සකසයි; ආරම්භකය සහ පැතිකඩ ස්ථාවරව වින්‍යාස කළ යුතුය.

## පියවර 7: පෙරනිමි අක්තපත්‍ර වෙනස් කරන්න

නැව්ගත කරන ලද ක්‍රමානුරූපය මඟින් `admin` මුරපදය සහිත `admin` නමින් පරිපාලක ගිණුමක් සකසන අතර, පළමු පිවිසුම වෙනසක් බල කරන ලෙස සලකුණු කර ඇත. එය අක්‍රිය කළ අමුත්තන්ගේ ගිණුමක් ද සකසයි. වෙනත් ඕනෑම කෙනෙකුට අවස්ථාව වෙත ළඟා වීමට පෙර මුරපදය වෙනස් කරන්න, එනම් ඔබ අන් අයට ගමන් කළ හැකි ජාලයකට එය සම්බන්ධ කිරීමට පෙරය.

## පියවර 8: poller කාලසටහන්ගත කරන්න

poller පිටතින් ආරම්භ කළ යුතුය. එහි දත්ත එකතු කිරීමේ පරතරය සහ ආරම්භක පරතරය ස්ථාවරව වින්‍යාස කරන්න; poller මිනිත්තුවක හෝ මිනිත්තු පහක ආරම්භක පරතරයන්ට සහාය දක්වන අතර සාමාන්‍ය ධාවන නියමිත වේලාවට පෙර පැමිණීමට එරෙහිව ආරක්ෂාවක් ඇත. මිනිත්තුවක ආරම්භකයක් සඳහා, `php` සහ යෙදුම් මාර්ගය ඒවායේ නිරපේක්ෂ මාර්ග සමඟ ප්‍රතිස්ථාපනය කරමින්, වරප්‍රසාද රහිත poller පරිශීලකයාගේ crontab තුළ මෙම ප්‍රවේශය ස්ථාපනය කරන්න:

```
* * * * * php -q /path/to/kadupul/poller.php > /dev/null 2>&1
```

හෝ ඔබගේ ස්ථාපන මාර්ගය සහ වරප්‍රසාද රහිත පරිශීලකයා සඳහා සකස් කරන ලද `service/cactid.service` භාවිතයෙන් නැව්ගත කරන ලද `cactid.php` daemon ධාවනය කරන්න. එක් ආරම්භකයක් භාවිත කරන්න: daemon භාවිත කරන විට cron job හෝ timer අක්‍රිය කරන්න.

වින්‍යාස කළ ආරම්භක පරතරයට සැබෑ කාලසටහන ගළපන්න. මිනිත්තුවට අඩු දත්ත එකතු කිරීමේ පැතිකඩ සඳහා, ආරම්භ කරන ලද poller එම පරතරය තුළ එකතු කිරීමේ චක්‍ර ධාවනය කරයි; මෙම cron ප්‍රවේශය සමඟ මිනිත්තුවට අඩු රිද්මයක් ප්‍රකාශ කිරීමට උත්සාහ නොකරන්න.

**එය පරීක්ෂා කරන්න.** poller පරිශීලකයා ලෙස අතින් එක් චක්‍රයක් ධාවනය කරන්න:

```bash
php -q /path/to/kadupul/poller.php --force --debug
```

`--force` කලින් ධාවනය වීමේ කාල ආරක්ෂණය මඟ හරියි. කාලසටහන්ගත ධාවනයක් සමඟ අතිච්ඡාදනය නොවන පරිදි scheduler නවතා මෙම අතින් පරීක්ෂාව භාවිත කරන්න. එය වෙනත් නඩත්තු හෝ ආරක්ෂක පරීක්ෂාවන් මඟ හරින්නේ නැත. ඔබට සාරාංශ පේළියක් සහිත පිරිසිදු නිමාවක් අවශ්‍ය වේ. ඉන්පසු scheduler සක්‍රීය කර පරතරයන් දෙකක් සඳහා එය තනිව තබන්න; ඔබ නොමැතිව තවත් ධාවනයක් සිදුවූ බව තහවුරු කරන්න.

## ඔබ එය නිරාවරණය කිරීමට පෙර

poller පද්ධති පරිශීලකයෙකු ලෙස ධාවනය වන අතර RRDtool සහ ඔබගේ එකතු කිරීමේ ස්ක්‍රිප්ට් ක්‍රියාත්මක කරයි. ස්ථාපනය විධානයන් ධාවනය කරන දෙයක් ලෙස සලකන්න, මන්ද එය සැබවින්ම එසේ කරන බැවිනි.

- TLS හරහා එය සේවය කරන්න.
- කෙටි වේලාවකට හෝ පෙරනිමි පරිපාලක මුරපදය තබා නොයන්න.
- දත්ත සමුදා පරිශීලකයා එහිම දත්ත සමුදායට සීමා කරන්න.
- RRD සහ ලොග් නාමාවලි ලේඛන මූලයෙන් පිටත තබන්න.
- ඔබ වෙනත් ආකාරයකින් තීරණය කරන්නේ නම් මිස අමුත්තන්ගේ ගිණුම අක්‍රිය කර තබන්න.
