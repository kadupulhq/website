net-snmp ධාවනය වන Linux ධාරකයක් කිසිදු අමතර කේතයක් නොමැතිව ඔබට බොහෝ මෙට්‍රික්ස් ලබා දෙයි. කාර්යය වන්නේ `snmpd` මඟින් නිවැරදි උප-වෘක්ෂයන් (subtrees) නිරාවරණය කර ගැනීම සහ ඔබ නිරීක්ෂණය කරන්නේ අතිච්ඡාදනය වන තැටි MIB දෙකෙන් කුමක්දැයි දැන ගැනීමයි.

## snmpd විසින් නිරාවරණය කළ යුතු දේ

Kadupul ප්‍රදේශ හතරක් පරීක්ෂා (poll) කරයි. තෝරාගත් ප්‍රස්ථාර සඳහා අවශ්‍ය උප-වෘක්ෂ නිරීක්ෂණ අනන්‍යතාවයට ලබා දෙන්න; සෑම ස්ථාපනයකටම සෑම උප-වෘක්ෂයක්ම අවශ්‍ය නොවේ.

| ප්‍රදේශය | උප-වෘක්ෂය | සපයන දේ |
|---|---|---|
| පද්ධතිය | `.1.3.6.1.2.1.1` | විස්තරය, ක්‍රියාකාරී කාලය (uptime), සම්බන්ධතාවය, නම, ස්ථානය |
| අතුරුමුහුණත් | `.1.3.6.1.2.1.2` සහ `.1.3.6.1.2.1.31` | ගමනාගමනය, දෝෂ, තත්ත්වය |
| ධාරක සම්පත් | `.1.3.6.1.2.1.25` | ක්‍රියාවලි, ප්‍රවිෂ්ට වූ පරිශීලකයින්, ආචයනය, ප්‍රොසෙසර |
| UCD / net-snmp | `.1.3.6.1.4.1.2021` | භාර සාමාන්‍යයන්, මතකය, CPU කාලය, තැටි I/O, ප්‍රකාශිත කොටස් |

බොහෝ බෙදාහැරීම් පද්ධති උප-වෘක්ෂය පමණක් ආවරණය වන පරිදි පෙරනිමි `snmpd.conf` ලබා දෙයි. එවිට උපාංගය ප්‍රතිචාර දක්වනු ඇත, පද්ධති විස්තරයක් වාර්තා කරනු ඇත, නමුත් කිසිවක් රැස් නොකරනු ඇත. මෙම සංයෝජනය Linux ධාරකයක වඩාත් පොදු ආරම්භක අසාර්ථකත්වය වන අතර එය සැකිලි ගැටළුවක් ලෙසම පෙනේ.

උපාංගයේ වින්‍යාස කර ඇති එකම SNMP අනන්‍යතාවය භාවිතා කරමින් poller ධාරකයේ සිට අවශ්‍ය ප්‍රදේශ පරීක්ෂා කරන්න. මෙම උදාහරණ නිදර්ශන ප්‍රජාවක් භාවිතා කරයි; එය ඔබගේ වින්‍යාසගත අගයෙන් ප්‍රතිස්ථාපනය කරන්න. සංඛ්‍යාත්මක OID දේශීය සංකේතාත්මක MIB අර්ථ දැක්වීම්වල අවශ්‍යතාවය මඟහරවයි.

```bash
snmpget  -v2c -c public server.example.net .1.3.6.1.2.1.1.1.0
snmpwalk -v2c -c public server.example.net .1.3.6.1.4.1.2021.10.1.3
snmpwalk -v2c -c public server.example.net .1.3.6.1.2.1.25.2.3.1.3
```

පළමු විධානය පමණක් ක්‍රියාත්මක වන්නේ නම්, නිශ්චිත ප්‍රතිචාරය විමර්ශනය කරන්න: සීමිත දසුනක්, ලබා ගත නොහැකි නියෝජිත මොඩියුලයක්, වෙනස් SNMP සන්දර්භයක් හෝ හිස් වගුවක් ප්‍රතිඵලය පැහැදිලි කළ හැකිය. Kadupul සැකිල්ල වෙනස් කිරීමට පෙර නියෝජිත වින්‍යාසය සහ ප්‍රවේශය තහවුරු කරන්න.

## උපාංගය එකතු කිරීම

[සැකිලි ආයාත කිරීම](/si/guides/import-and-export-templates/) සහ [ඔබේ පළමු ප්‍රස්ථාරය](/si/start/first-graph/) බලන්න.

මතක වස්තු කිලෝබයිට් වලින් පවතී. ඇසුරුම් කළ මතක ප්‍රස්ථාරය අක්ෂය බයිට් වලින් පෙන්වීමට පරිවර්තනයක් යොදයි. ඔබ මෙම OID වලින් ඔබේම ප්‍රස්ථාරයක් ගොඩනඟන්නේ නම්, එම පරිවර්තනය ඔබේ වගකීමකි.

ලැයිස්තුගත කර ඇති CPU වස්තු යල් පැන ගිය ප්‍රතිශත මිස සමුච්චිත CPU කාල ගණක නොවේ. මෙම තුන පමණක් සෑම ප්‍රොසෙසර් තත්ත්වයක්ම ආවරණය කරන බව උපකල්පනය නොකරන්න. Net-SNMP විසින් නොකැපූ ගණක (raw counters) වෙනුවෙන් මේවා අත්හැර දමා ඇත; නොකැපූ ගණක සඳහා නිසි අනුපාත සහ ප්‍රතිශත ගණනය කිරීම් අවශ්‍ය වේ මිස ගේජ් සැකිල්ලකට සරලව ඇතුළත් කිරීම නොවේ. [UCD-SNMP-MIB](https://www.net-snmp.org/docs/mibs/ucdavis.html) බලන්න.

### භාවිතා කළ යුතු තැටි විමසුම කුමක්ද

මේවා එකම දත්තවල දසුන් දෙකක් නොවේ.

ධාරක සම්පත් විමසුම මඟින් නියෝජිතයා ආචයනය ලෙස වාර්තා කරන සෑම දෙයක්ම හරහා ගමන් කරයි. බොහෝ Linux ධාරකවල, මෙය භෞතික මතකය, swap, tmpfs මවුන්ට් සහ සැබෑ ගොනු පද්ධති තනි ලැයිස්තුවකට ඇතුළත් කරයි. ප්‍රමාණ වෙන්කිරීමේ ඒකක වලින් ආපසු ලබා දෙන අතර, ප්‍රස්ථාරයට ගුණ කළ හැකි වන පරිදි විමසුම මඟින් වෙන්කිරීමේ ඒකක ප්‍රමාණය වෙනම ක්ෂේත්‍රයක් ලෙස කියවනු ලැබේ. කිසිවක් වින්‍යාස නොකර ඔබට සියල්ල ලැබේ, නමුත් ඔබට අවශ්‍ය නොවන දිගු ඇතුළත් කිරීම් ලැයිස්තුවක් ද ලැබේ.

net-snmp විමසුම `disk` විධානයන් හෝ `includeAllDisks` මඟින් ජනනය කරන UCD තැටි වගුව කියවයි. පැහැදිලි කොටස් හෝ පුළුල් සොයා ගැනීමක් තෝරන්න; ඒවා වෙනස් ප්‍රතිපත්ති වේ.

```
disk /      10%
disk /var   10%
```

විකල්පයක් ලෙස, `includeAllDisks 10%` මඟින් නියෝජිතයා ආරම්භයේදී හමු වූ තැටි පුරවයි. 10% අගය නිදහස් ඉඩ සීමාවක් වින්‍යාස කරයි; එය තේරීම් පෙරහනක් නොවන අතර එය විසින්ම Kadupul ඇඟවීම් වින්‍යාස නොකරයි. නියෝජිතයා නැවත පූරණය කරන්න හෝ නැවත ආරම්භ කරන්න, ඉන්පසු දර්ශක සමාලෝචනය කරන්න. හිස් විමසුමක් ප්‍රවේශ ගැටළු හෝ මොඩියුල ලබා ගැනීමේ හැකියාව පිළිබිඹු කළ හැකිය. [snmpd වින්‍යාසය](https://www.net-snmp.org/docs/man/snmpd.conf.html) බලන්න.

ඔබ සම්පූර්ණත්වය අපේක්ෂා කරන විට සහ පෙරීමට සූදානම්ව සිටින විට ධාරක සම්පත් විමසුමට ප්‍රමුඛත්වය දෙන්න. ඔබට ඉලක්කගත ලැයිස්තුවක් අවශ්‍ය වූ විට පැහැදිලි `disk` ඇතුළත් කිරීම් සහිත net-snmp විමසුමට ප්‍රමුඛත්වය දෙන්න. `includeAllDisks` එම ලැයිස්තුව පුළුල් කරයි; නියෝජිත නැවත ආරම්භ කිරීමෙන් පසු දර්ශක නැවත පරීක්ෂා කරන්න.

### අතුරුමුහුණත්

සේවාදායකයක අතුරුමුහුණත් දත්ත විමසුම ස්විචයක ආකාරයටම ක්‍රියා කරයි, එක් සටහනක් සහිතව: Linux යටතේ `ifDescr` යනු කර්නල් අතුරුමුහුණත් නාමය වන අතර එය නැවත පණගැන්වීමෙන් හෝ ධාවක යාවත්කාලීන කිරීමෙන් පසුව වෙනස් විය හැකිය. දර්ශක තේරීමේ විස්තර සඳහා [ස්විචයක් නිරීක්ෂණය කිරීම](/si/guides/monitor-a-switch/) බලන්න.

## SNMP ප්‍රමාණවත් නොවන විට

සමහර මෙට්‍රික්ස් සඳහා භාවිතා කළ හැකි MIB නොමැත. පෝලිම් ගැඹුර, යෙදුම් ගණකයක් හෝ ගොනුවක ඇති අංකයක් සඳහා ස්ක්‍රිප්ට් ආදානයක් අවශ්‍ය වේ.

කරුණු දෙකක් ඔබ ස්ක්‍රිප්ට් ලියන ආකාරය තීරණය කරයි.

**ස්ක්‍රිප්ට් එක ක්‍රියාත්මක වන්නේ poller ධාවනය වන පරිගණකයේ මිස නිරීක්ෂණය කරන ලද ධාරකයේ නොවේ.** ඉලක්කය වෙත ළඟා වීම ඔබේ ස්ක්‍රිප්ට් එකේ කාර්යයයි: SSH, HTTP ඇමතුමක්, නියෝජිතයෙකු හෝ ඔබ දැනටමත් යොදවා ඇති ඕනෑම යාන්ත්‍රණයක්.

**Poller සම්මත ප්‍රතිදානය පමණක් කියවන අතර වෙන කිසිවක් නැත.** පිටවීමේ තත්ත්වය ඇගයීමට ලක් නොකෙරේ.

| `U` | මෙම චක්‍රයේ අගයක් නොමැත, නොදන්නා ලෙස සටහන් වේ |
| `in:1420 out:980` | බහුවිධ අගයන්, දත්ත ප්‍රභවයකට එකක් බැගින් |

බහු-අගය ආකාරය සඳහා, යුගල තනි හිස්තැන් වලින් වෙන් කරනු ලබන අතර නම කෝලනයකින් අගයෙන් වෙන් කරනු ලැබේ. විග්‍රහකය (parser) හිස්තැන්වලට එරෙහිව සීමාකාරක ගණන් කරයි, එබැවින් අමතර අභ්‍යන්තර හිස්තැන් වලංගුකරණය අසාර්ථක වීමට හේතු විය හැක. PHP poller අග හිස්තැන් කපා දමයි. තනි හිස්තැන් සහිත කැනොනිකල් ආකෘතිය ප්‍රතිදානය කර රෝග විනිශ්චය stdout වෙතින් ඈත් කරන්න.

සැකිලි සංස්කාරකය විසින් පිළිගන්නා ලද අභ්‍යන්තර RRD දත්ත ප්‍රභව නම් `[a-zA-Z0-9_]{1,19}` සමඟ ගැළපේ; එහි තනි ඉරි (hyphens) පිළිගනු නොලැබේ. ස්ක්‍රිප්ට් ප්‍රතිදාන ලේබල් දත්ත ආදාන ක්ෂේත්‍ර නම්වලට ගැළපිය යුතු අතර අපේක්ෂිත අභ්‍යන්තර අයිතම වෙත සිතියම්ගත කළ යුතුය. සම්පූර්ණ ප්‍රතිදාන පේළිය අක්ෂර 512 ක තීරුවක ගබඩා වේ. විගණනය කරන ලද PHP poller ගිවිසුම සඳහා [දත්ත එකතු කිරීමේ ස්ක්‍රිප්ට් ලිවීම](/si/guides/write-a-data-collection-script/) බලන්න.

ඔබට යමක් මැනිය නොහැකි වූ විට `0` වෙනුවට `U` ආපසු දෙන්න. ශුන්‍යය යනු මිනුමක් වන අතර එය එලෙස සැලසුම් කෙරේ. දෙක වෙන වෙනම තබා ඇත්තේ මන්දැයි දැන ගැනීමට [දත්ත ප්‍රභව සහ RRA](/si/concepts/data-sources-and-rras/) බලන්න.

### ස්ක්‍රිප්ට් සේවාදායකය

සරල ස්ක්‍රිප්ට් එකක් එක් කාල පරාසයකට දත්ත ප්‍රභවයකට එක් වරක් ක්‍රියාත්මක වේ. PHP වලින් ලියන ලද ස්ක්‍රිප්ට් සඳහා, ස්ක්‍රිප්ට් සේවාදායක ආකෘතිය වෙනම දිගුකාලීන PHP ක්‍රියාවලියක ශ්‍රිතයක් කැඳවයි, පරිවර්තක ආරම්භක පොදු කාර්යය අඩු කරයි.

### අවසර ලැයිස්තු උගුල (whitelist trap)

දත්ත ආදාන අවසර ලැයිස්තු ගොනුවක් භාවිතා කරන විට, poller විසින් එක් එක් දත්ත ආදානයේ විධාන තන්තුව වාර්තා කර ඇති තන්තුව සමඟ සංසන්දනය කරයි. අවසර ලැයිස්තුව නැවත ජනනය නොකර වෙනස් වූ විධාන තන්තුවක් poller හැඹිලි ඇතුළත් කිරීම් නිර්මාණය කිරීම නවත්වන අතර දත්ත ප්‍රභවය ප්‍රස්ථාරයේ දෝෂයකින් තොරව නිහඬ වේ. ලොගය මෙය වාර්තා කරයි, UI වාර්තා නොකරයි.

```bash
php cli/input_whitelist.php --audit
php cli/input_whitelist.php --update --id=42
```

`42` යන්න විගණනය කරන ලද දත්ත ආදාන ක්‍රමයේ හැඳුනුම්පතෙන් ප්‍රතිස්ථාපනය කරන්න, උපාංග හැඳුනුම්පතකින් නොවේ. `--id` නොමැතිව යාවත්කාලීන කිරීම සමස්ත ආදාන ඉන්වෙන්ටරිය හරහා වත්මන් විධාන තන්තු පිළිගනී. කලින් වෙනස්කම් විගණනය කරන්න. යාවත්කාලීන කිරීමෙන් පසු, මූලාශ්‍ර සක්‍රීය කිරීම සහ ඵලදායී poller හැඹිලි ඇතුළත් කිරීම් තහවුරු කරන්න.
