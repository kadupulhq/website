:::caution[使用前に検証してください]
ソースコードは公開されていますが、正式にサポートされた Kadupul のリリースや移行パスは
まだ存在しません。本番環境で運用する前に、バックアップを備えた隔離環境で手順を
検証してください。[プロジェクトステータス](/ja/project/status/)を参照してください。
:::

:::danger[この操作は履歴データを書き換えます。復旧にはバックアップが必須です]
スパイク除去処理は、アーカイブをダンプし、値を編集し、一時的な別名ファイルとしてリストアし、
検証後に元ファイルと置き換えます。自動取り消し機能はありません。必ず復旧用コピーを
保存・検証し、最初に `--dryrun` を実行して、変更をコミットする前に対象サンプルを確認してください。
:::

ここでのスパイクとは、周囲のすべての値と比較して極端に巨大な1〜2個のサンプル値を指し、
グラフの垂直軸がその値に合わせて引き伸ばされ、他の正常なデータがベースライン上に平坦化されて
しまう状態を意味します。その測定値は誤りであり、視覚的にも極めて目立ちます。

## スパイクの発生原因

カウンター型のデータソースで生じるスパイクの大部分は、物理的な実測値ではなく算術計算の不具合によるものです。
カウンター型データソースは、連続する2回の測定値の差分から計算されたレートを記録します。
2回目の読み取り値が1回目に対して時間間隔と不釣り合いに過大になると、誤ったレートが算出されます。
カウンターのリセット、オーバーフロー（ラップ）処理の不備、インターフェースの再インデックスに伴う
別データソースへの誤関連付け、タイムスタンプの異常などが原因となります。通常のカウンターラップ自体は
異常の証拠ではありません。データソースの型と入力値を慎重に確認してください。

レート算出の仕組みについては[データソースと RRA](/ja/concepts/data-sources-and-rras/)を参照してください。

可能な限り根本原因を修正してください。スパイクの除去は表面的な対処に過ぎず、
次のスパイクの発生を防ぐものではありません。

## 4つの除去方式

このツールはファイル全体に対して処理を行います。RRD ファイル内の全アーカイブをダンプし、
置換すべき値を決定した上で、結果をリストアします。

| 方式 | 選択対象 | 時間ウィンドウの指定 |
|---|---|---|
| `stddev` | 平均値から N 標準偏差を超えて乖離している値 | 不要 |
| `variance` | 外れ値を除外した後の平均値を N パーセント超えて上回る値 | 不要 |
| `float` | 指定された時間ウィンドウ内のすべての値 | 必須 |
| `fill` | 指定された時間ウィンドウ内の不明値 (unknown) およびゼロ値サンプル | 必須 |

`stddev` と `variance` は統計的に自動探索します。`float` と `fill` は指定された
範囲内で指示通りの処理を機械的に実行するため、開始時刻と終了時刻を指定しないとエラー終了します。

`fill` は欠損データのみに限定されず、正常に測定されたゼロ値を非ゼロ値に
置き換えてしまうことがあります。意図的な改変である場合を除き、正当なゼロ値やアイドリング測定値を含む
期間に対しては使用しないでください。

分散方式 (variance) は、比較対象となる平均値を計算する前に、外れ値設定数 N だけ上位と下位の
サンプルを除外します。これにより、スパイク自身の巨大な値によって検出閾値が不当に引き上げられるのを防ぎます。

選択された対象は置換されます。置換値には3つの選択肢があります。

| 置換値 | 結果 |
|---|---|
| `last` | 直前の正常値。デフォルト設定。 |
| `avg` | フィールドおよびアーカイブごとに算出された平均値。計算方式は選択した手法に依存。 |
| `nan` | 統計的手法における不明値 (unknown)。ウィンドウ方式の制限は後述。 |

不明値は有効な測定値が存在しないことを正確に記録します。`last` および `avg` は、
後からグラフを見る人にとって実測値に見えるような数値を代入します。
置換値は意図を持って慎重に選定し、実際に保存された結果を確認してください。

**NaN を伴うウィンドウ方式の挙動：** `--avgnan=nan` を指定すると、`float` はウィンドウ内の
すべての有効値を不明値に置き換え、`fill` はウィンドウ内のゼロ値または非数値を不明値に置き換えます。
時間枠を指定した統計的手法は検出された外れ値のみを置き換えるため、ウィンドウ全体を消去するのとは異なります。

## プレビューと適用

```sh
# preview this exact method and replacement
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --avgnan=nan --dryrun

# after reviewing that preview, repeat its exact selection without --dryrun
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --avgnan=nan --backup

# narrow it to a known incident
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --outlier-start='2026-03-14 02:00' --outlier-end='2026-03-14 03:00' \
    --avgnan=nan --dryrun

```

ドライランは実ファイルを書き換えることなく RRD をダンプして解析します。実行には
有効な作業ディレクトリと保守権限が必要です。プレビューは確定コミットまでファイルを保護・予約するわけではありません。
新しいサンプルの到着や設定オプションの変更によって結果が変化する可能性があります。上記ウィンドウ指定の例も
統計的抽出を行うものであり、指定時間内の全データを無差別に削除するわけではありません。

時間引数には Unix タイムスタンプまたは日付文字列を指定できます。解析できない
文字列は処理前に拒否されます。タイムゾーンの解釈に曖昧さが生じる可能性がある場合は、Unix タイムスタンプを使用してください。

## ファイルに対して実際に実行される処理

重要なデータに適用する前に知っておくべき内部手順：

1. ファイルがバックアップディレクトリに XML としてダンプされます。
2. コメントが除去され、統計情報を得るために各アーカイブが走査されます。
3. 抽出された値が XML 内部で置換されます。
4. 元の物理ファイルがバックアップディレクトリにコピーされます。
5. 編集済み XML が同階層の一時ファイルにリストアされ、検証された上で、所有者、グループ、
   パーミッションを維持したまま元ファイルに上書きリネームされます。

ステップ4は必須の安全機構であり、省略できません。コピーに失敗した場合、リストア処理は
実行されません。万一の際に復旧の拠り所となるのは、コマンドラインの指定ではなくこのバックアップコピーです。
そのファイル名は元ファイルに基づき、既存成果物の上書きを防ぐため固有の接尾辞が付与されることがあります。
`--backup` は永続的な復旧スナップショットを明示的に要求します。レポートされるパスを確認し、
信頼する前にコピーの実体を検証してください。

本操作には信頼できるローカル POSIX ディレクトリとメンテナンスロックが必要です。
書き込み権限ビットがあるだけでは不十分です。サポート外のストレージや rrdcached エンドポイントが
設定されている環境では実行を拒否します。Kadupul のロック機構に非準拠の外部書き込みプロセスを停止してください。
ストレージを所有する所定のサービスアカウントで実行してください。ストレージアクセスに関する詳細は
[インストール要件](/ja/reference/requirements/)を参照してください。

## デフォルト値を制御する設定

コマンドライン引数が最優先されます。省略された項目はシステム設定から
取得され、Web 画面から実行した場合はユーザー単位の設定がシステム設定を上書きします。

| 設定項目 | デフォルト | 動作内容 |
|---|---|---|
| Removal method | Variance with outliers removed | 使用する除去方式 |
| Replacement method | Last known good | 除去した値の置き換え方法 |
| Number of standard deviations | 10 | `stddev` 方式の閾値（標準偏差倍率） |
| Variance percentage | 1000 | `variance` 方式の閾値（パーセンテージ） |
| Variance number of outliers | 5 | 平均値計算前に除外される上下のサンプル数 |
| Max kills per RRA | 5 | 1つの RRA あたりの最大除去数（現行では厳密な強制力はありません） |
| RRDfile backup directory | `cache/spikekill/` under the install | ダンプおよびバックアップコピーの保存先 |
| Backup retention | 3 months | バックアップコピーの保持期間 |

バッチモードも用意されています。スケジュール（6、12、24、48時間ごと）、基準時刻、
および対象グラフテンプレート一覧を指定します。バッチモードはデフォルトで無効です。
有効化すると、処理結果を人間が確認することなくシステムがアーカイブを自動改変することになります。
利用する場合はテンプレート一覧を極めて限定的に絞り込んでください。

## 注意点と落とし穴

**デフォルトの閾値は意図的に非常に広く設定されています。** 10標準偏差や
1000パーセントの分散は広大な許容範囲です。実行してもスパイクが報告されない場合、処理が失敗したのではなく、
指定された許容帯域に値が収まっていることを示しています。安易に方式を変えるのではなく、閾値を調整してください。

**Max kills per RRA は統計的手法にのみ適用されます。** `stddev` と
`variance` では、1つのアーカイブ内の全データソースを通してカウントされ、次のアーカイブで
リセットされます。ウィンドウ方式の `float` と `fill` は、ウィンドウ内の一致する全データを置換します。
集計カウントには NaN への置換も含まれます。完全なプレビューを確認し、狭い時間枠を指定してください。

**統合後の値を元通りに復元することはできません。** 古いアーカイブには、既に平均化された
1バケットあたり1つの値しか残っていません。その値を置き換えても、当時の真の測定値が
戻るわけではなく、もっともらしい推測値が入るだけです。過去に遡るほど、その修正は推測の域を出なくなります。

**バックアップディレクトリは正しく設定され、信頼できる状態でなければなりません。** ダンプと
復旧用コピーはそこに配置されます。存在しない、危険な、または検証不可能なディレクトリは拒絶されます。
エラーを回避するためにディレクトリを誰でも書き込める状態 (world-writable) にしないでください。

**システムログとは別に、独自の変更作業記録を残してください。** 作業者、
実行コマンド、時間範囲、バックアップパス、前後の確認結果を記録してください。要約された件数だけでは
何がどう変わったのかの十分な証拠になりません。

**所定のサービスアカウントで実行してください。** 正常に置換が完了すると、ファイルの
所有権とパーミッションが維持されます。root での実行はディレクトリの信頼性チェックを回避する手段にはなりません。
通常のポーリングが引き続き結果ファイルを更新できることを確認してください。

**データソースの関連付けが間違っている場合、スパイクを除去してもグラフは直りません。** インターフェースの
再インデックスにより誤ったデータソースに値が流入している場合、スパイクは単なる症状に過ぎません。
アーカイブの編集に着手する前に、[欠損データのトラブルシューティング](/ja/guides/troubleshoot-missing-data/)を確認してください。
