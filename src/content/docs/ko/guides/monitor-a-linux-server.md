소스 코드는 공개되어 있지만, 지원되는 Kadupul 릴리스나 마이그레이션 경로는 없습니다. 이를 신뢰하기 전에 백업이 준비된 격리된 사본에서 이러한 절차를 테스트하십시오. [프로젝트 상태](/ko/project/status/)를 참조하십시오.

net-snmp를 실행하는 Linux 호스트는 추가 코드 없이 대부분의 메트릭을 제공합니다. 핵심 작업은 `snmpd`가 올바른 하위 트리를 노출하도록 유도하고, 겹치는 두 디스크 MIB 중 어느 것을 확인하고 있는지 파악하는 것입니다.

## snmpd가 노출해야 하는 항목

Kadupul은 네 개 영역을 폴링합니다. 선택한 그래프에 필요한 하위 트리를 모니터링 ID에 부여하십시오. 모든 배포에 모든 하위 트리가 필요한 것은 아닙니다.

| 영역 | 하위 트리 | 제공 내용 |
|---|---|---|
| 시스템 | `.1.3.6.1.2.1.1` | 설명, 가동 시간(uptime), 담당자, 이름, 위치 |
| 인터페이스 | `.1.3.6.1.2.1.2` 및 `.1.3.6.1.2.1.31` | 트래픽, 오류, 상태 |
| 호스트 리소스 | `.1.3.6.1.2.1.25` | 프로세스, 로그인한 사용자, 스토리지, 프로세서 |
| UCD / net-snmp | `.1.3.6.1.4.1.2021` | 로드 애버리지, 메모리, CPU 시간, 디스크 I/O, 선언된 파티션 |

여러 배포판은 시스템 하위 트리만 포함하는 뷰를 부여하는 기본 `snmpd.conf`를 제공합니다. 이 경우 장치는 응답하고 시스템 설명을 보고하지만 아무것도 수집하지 않습니다. 이 조합은 Linux 호스트에서 가장 흔히 발생하는 초기 실패이며, 템플릿 문제와 똑같이 보입니다.

장치에 구성된 동일한 SNMP ID를 사용하여 폴러 호스트에서 필요한 영역을 확인하십시오. 이 예제에서는 예시 커뮤니티(community)를 사용합니다. 구성된 값으로 대체하십시오. 숫자 OID를 사용하면 로컬 기호 MIB 정의가 필요하지 않습니다.

```bash
snmpget  -v2c -c public server.example.net .1.3.6.1.2.1.1.1.0
snmpwalk -v2c -c public server.example.net .1.3.6.1.4.1.2021.10.1.3
snmpwalk -v2c -c public server.example.net .1.3.6.1.2.1.25.2.3.1.3
```

첫 번째 명령만 작동하는 경우 정확한 응답을 조사하십시오. 제한된 뷰, 사용할 수 없는 에이전트 모듈, 다른 SNMP 컨텍스트 또는 빈 테이블이 결과를 설명할 수 있습니다. Kadupul 템플릿을 변경하기 전에 에이전트 구성 및 접근 권한을 확인하십시오.

## 장치 추가

제공된 패키지 `install/templates/NetSNMP_Device.xml.gz`에는 Net-SNMP 장치 템플릿과 해당 종속성이 포함되어 있습니다. 템플릿이 없으면 가져온 다음 장치를 추가할 때 선택하십시오. 쿼리 인덱스를 확인하고 원하는 그래프를 명시적으로 생성하십시오. 장치 템플릿을 선택했다고 해서 수집이 작동한다는 증거는 아닙니다. [템플릿 가져오기](/ko/guides/import-and-export-templates/) 및 [첫 번째 그래프](/ko/start/first-graph/)를 참조하십시오.

## 데이터 쿼리 없이 얻을 수 있는 항목

이러한 고정 OID 데이터 템플릿은 패키지에 포함되어 있습니다. 하나의 그래프에 여러 개를 결합할 수 있으며 가용성은 대상 에이전트에 따라 다릅니다. 인덱스 검색이 필요하지 않습니다.

| 그래프 | OID | 저장 형식 |
|---|---|---|
| 1분 로드 애버리지 | `.1.3.6.1.4.1.2021.10.1.3.1` | `GAUGE` |
| 5분 로드 애버리지 | `.1.3.6.1.4.1.2021.10.1.3.2` | `GAUGE` |
| 15분 로드 애버리지 | `.1.3.6.1.4.1.2021.10.1.3.3` | `GAUGE` |
| 총 메모리 | `.1.3.6.1.4.1.2021.4.5.0` | `GAUGE` |
| 여유 메모리 | `.1.3.6.1.4.1.2021.4.6.0` | `GAUGE` |
| 버퍼 메모리 | `.1.3.6.1.4.1.2021.4.14.0` | `GAUGE` |
| 캐시 메모리 | `.1.3.6.1.4.1.2021.4.15.0` | `GAUGE` |
| 사용자 CPU | `.1.3.6.1.4.1.2021.11.9.0` | `GAUGE` |
| 시스템 CPU | `.1.3.6.1.4.1.2021.11.10.0` | `GAUGE` |
| 유휴 CPU | `.1.3.6.1.4.1.2021.11.11.0` | `GAUGE` |
| 인터럽트 | `.1.3.6.1.4.1.2021.11.7.0` | `GAUGE` |
| 컨텍스트 스위치 | `.1.3.6.1.4.1.2021.11.8.0` | `GAUGE` |
| 프로세스 수 | `.1.3.6.1.2.1.25.1.6.0` | `GAUGE` |
| 로그인한 사용자 수 | `.1.3.6.1.2.1.25.1.5.0` | `GAUGE` |

메모리 개체는 킬로바이트 단위입니다. 패키지된 메모리 그래프는 축이 바이트 단위로 표시되도록 변환을 적용합니다. 이러한 OID를 기반으로 자체 그래프를 작성하는 경우 해당 변환은 사용자가 직접 처리해야 합니다.

나열된 CPU 개체는 누적 CPU 시간 카운터가 아닌 더 이상 사용되지 않는 백분율입니다. 이 세 가지만으로 모든 프로세서 상태를 다룬다고 가정하지 마십시오. Net-SNMP는 원시 카운터를 선호하여 이를 더 이상 사용하지 않도록 권장합니다. 원시 카운터는 게이지 템플릿에 단순히 삽입하는 것이 아니라 적절한 비율 및 백분율 계산이 필요합니다. [UCD-SNMP-MIB](https://www.net-snmp.org/docs/mibs/ucdavis.html)를 참조하십시오.

## 데이터 쿼리가 필요한 항목

| 쿼리 | 검색 대상 | 기반 |
|---|---|---|
| SNMP - 마운트 지점 가져오기 | 에이전트가 스토리지라고 부르는 모든 항목 | `hrStorageTable`, `.1.3.6.1.2.1.25.2.3.1` |
| Net-SNMP - 모니터링 파티션 가져오기 | `snmpd.conf`에 선언된 파티션만 | `dskTable`, `.1.3.6.1.4.1.2021.9.1` |
| SNMP - 프로세서 정보 가져오기 | CPU당 하나의 항목 | 호스트 리소스 프로세서 부하 |
| Net-SNMP - 장치 I/O 가져오기 | 블록 장치 | `diskIOTable`, `.1.3.6.1.4.1.2021.13.15.1.1` |
| SNMP - 인터페이스 통계 | 네트워크 인터페이스 | `IF-MIB` |

### 사용할 디스크 쿼리 선택

이 둘은 동일한 데이터에 대한 서로 다른 두 가지 보기가 아닙니다.

호스트 리소스 쿼리는 에이전트가 스토리지로 보고하는 모든 항목을 순회합니다. 대부분의 Linux 호스트에서는 물리적 메모리, 스왑, tmpfs 마운트 및 실제 파일 시스템이 단일 목록에 포함됩니다. 크기는 할당 단위로 반환되며, 쿼리는 그래프가 곱할 수 있도록 할당 단위 크기를 별도 필드로 읽습니다. 아무것도 구성하지 않고도 모든 것을 얻을 수 있지만 원하지 않는 긴 항목 목록도 생성됩니다.

net-snmp 쿼리는 `disk` 지시문 또는 `includeAllDisks`로 채워진 UCD 디스크 테이블을 읽습니다. 명시적 파티션 또는 광범위한 검색을 선택하십시오. 이는 서로 다른 정책입니다.

```
disk /      10%
disk /var   10%
```

또는 `includeAllDisks 10%`를 사용하면 에이전트 시작 시 발견된 디스크가 채워집니다. 10% 값은 여유 공간 임계값을 구성합니다. 이는 선택 필터가 아니며 그 자체로 Kadupul 경고를 구성하지 않습니다. 에이전트를 다시 로드하거나 다시 시작한 다음 인덱스를 검토하십시오. 빈 쿼리는 액세스 문제 또는 모듈 가용성을 반영할 수도 있습니다. [snmpd 구성](https://www.net-snmp.org/docs/man/snmpd.conf.html)을 참조하십시오.

완전성을 원하고 선별할 준비가 되어 있는 경우 호스트 리소스 쿼리를 선호하십시오. 대상이 명확한 목록을 원하는 경우 명시적인 `disk` 항목이 있는 net-snmp 쿼리를 선호하십시오. `includeAllDisks`는 해당 목록을 확장합니다. 에이전트 재시작 후 인덱스를 다시 확인하십시오.

### 인터페이스

서버의 인터페이스 데이터 쿼리는 스위치와 똑같이 작동하지만 한 가지 주의할 점이 있습니다. Linux의 `ifDescr`은 커널 인터페이스 이름이며 재부팅이나 드라이버 업데이트 후 변경될 수 있습니다. 인덱스 선택 세부 정보는 [스위치 모니터링](/ko/guides/monitor-a-switch/)을 참조하십시오.

## SNMP로 충분하지 않을 때

일부 메트릭에는 사용 가능한 MIB가 없습니다. 대기열 깊이, 애플리케이션 카운터 또는 파일의 숫자에는 스크립트 입력이 필요합니다.

두 가지 사실이 스크립트 작성 방법을 결정합니다.

**스크립트는 모니터링 대상 호스트가 아니라 폴러가 실행 중인 시스템에서 실행됩니다.** 대상에 도달하는 것은 스크립트의 역할입니다. SSH, HTTP 호출, 에이전트 또는 이미 배포된 메커니즘을 사용할 수 있습니다.

**폴러는 표준 출력만 읽고 다른 것은 읽지 않습니다.** 종료 상태는 평가되지 않습니다.

출력 규칙 계약:

| 출력 | 의미 |
|---|---|
| `42` 또는 `3.7` | 단일 데이터 소스에 대한 단일 값 |
| `U` | 이 주기에 값이 없음, unknown으로 기록 |
| `in:1420 out:980` | 여러 값, 데이터 소스당 하나 |

다중 값 형식의 경우 쌍은 단일 공백으로 구분되고 이름은 콜론으로 값과 구분됩니다. 파서는 공백에 대해 구분 기호를 계산하므로 추가 내부 공백이 있으면 유효성 검사에 실패할 수 있습니다. PHP 폴러는 후행 공백을 자릅니다. 단일 공백이 있는 표준 형식을 출력하고 진단 메시지는 stdout 외부로 리디렉션하십시오.

템플릿 편집기에서 허용하는 내부 RRD 데이터 소스 이름은 `[a-zA-Z0-9_]{1,19}`와 일치합니다. 하이픈은 허용되지 않습니다. 스크립트 출력 레이블은 데이터 입력 필드 이름과 일치해야 하며 의도한 내부 항목에 매핑되어야 합니다. 전체 출력 라인은 512자 열에 저장됩니다. 감사된 PHP 폴러 계약에 대해서는 [데이터 수집 스크립트 작성](/ko/guides/write-a-data-collection-script/)을 참조하십시오.

측정할 수 없는 경우 `0` 대신 `U`를 반환하십시오. 영(0)은 유효한 측정값이며 그렇게 표시됩니다. 두 상태를 분리하여 유지하는 이유에 대해서는 [데이터 소스 및 RRA](/ko/concepts/data-sources-and-rras/)를 참조하십시오.

### 스크립트 서버

간단한 스크립트는 간격당 데이터 소스당 한 번 실행됩니다. PHP로 작성된 스크립트의 경우 스크립트 서버 형식은 별도의 오래 실행되는 PHP 프로세스에서 함수를 호출하여 인터프리터 시작 오버헤드를 줄입니다.

### 화이트리스트 함정

데이터 입력 화이트리스트 파일이 사용되는 경우 폴러는 각 데이터 입력의 명령 문자열을 기록된 명령 문자열과 비교합니다. 화이트리스트를 다시 생성하지 않고 변경된 명령 문자열은 폴러 캐시 항목 생성을 중지하고 데이터 소스는 그래프에 오류 없이 침묵합니다. 로그에는 보고되지만 UI에는 보고되지 않습니다.

```bash
php cli/input_whitelist.php --audit
php cli/input_whitelist.php --update --id=42
```

`42`를 장치 ID가 아니라 감사된 데이터 입력 방법의 ID로 대체하십시오. `--id`가 없는 업데이트는 입력 인벤토리 전체에서 현재 명령 문자열을 수락합니다. 사전에 변경 사항을 감사하십시오. 업데이트 후 소스 활성화 및 유효한 폴러 캐시 항목을 확인하십시오.

## 실패 모드

| 증상 | 흔한 원인 |
|---|---|
| 시스템 설명은 읽히지만 다른 것은 수집되지 않음 | `snmpd` 뷰가 시스템 하위 트리로 제한됨 |
| Net-SNMP 파티션 쿼리에서 인덱스를 찾지 못함 | `snmpd.conf`에 `disk` 또는 `includeAllDisks` 라인이 없음 |
| 호스트 리소스 파티션에 RAM 및 tmpfs가 포함됨 | 정상 동작. 에이전트가 이를 스토리지로 보고함 |
| 메모리 그래프가 1024배 차이 남 | 변환 없이 원시 OID를 기반으로 빌드됨 |
| 스크립트가 명령줄에서 값을 반환하지만 폴러가 unknown 기록 | 출력/매핑 불일치, 내부 구분 기호 오류 또는 잘못된 내부 이름 |
| 스크립트가 수동으로 작동하지만 폴러를 통해 실패함 | 폴러 사용자의 환경 및 권한으로 실행됨 |
