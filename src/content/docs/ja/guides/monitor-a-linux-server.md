net-snmp を実行している Linux ホストは、追加のコードを一切記述することなく、ほとんどのメトリクスを提供します。重要な作業は、`snmpd` に適切なサブツリーを公開させ、重複する 2 つのディスク MIB のどちらを確認しているかを把握することです。

## snmpd が公開すべき内容

Kadupul は 4 つの領域をポーリングします。選択したグラフに必要なサブツリーへのアクセス権を監視 ID に付与します。すべての展開で各サブツリーが必要になるわけではありません。

| 領域 | サブツリー | 提供内容 |
|---|---|---|
| システム | `.1.3.6.1.2.1.1` | 説明、稼働時間、連絡先、名前、場所 |
| インターフェース | `.1.3.6.1.2.1.2` および `.1.3.6.1.2.1.31` | トラフィック、エラー、状態 |
| ホストリソース | `.1.3.6.1.2.1.25` | プロセス、ログインユーザー、ストレージ、プロセッサ |
| UCD / net-snmp | `.1.3.6.1.4.1.2021` | ロードアベレージ、メモリ、CPU 時間、ディスク I/O、宣言されたパーティション |

一部のディストリビューションでは、システムサブツリーのみをカバーするビューを許可するデフォルトの `snmpd.conf` が提供されています。その場合、デバイスは応答してシステム説明を報告しますが、何も収集しません。この組み合わせは Linux ホストで最も一般的な初期の障害であり、テンプレートの問題とまったく同じように見えます。

デバイスに設定されているものと同じ SNMP ID を使用して、ポーラーホストから必要な領域を確認します。これらの例では説明用のコミュニティ名を使用しています。設定した値に置き換えてください。数値 OID を使用することで、ローカルのシンボリック MIB 定義に依存する必要がなくなります。

```bash
snmpget  -v2c -c public server.example.net .1.3.6.1.2.1.1.1.0
snmpwalk -v2c -c public server.example.net .1.3.6.1.4.1.2021.10.1.3
snmpwalk -v2c -c public server.example.net .1.3.6.1.2.1.25.2.3.1.3
```

最初のコマンドのみが機能する場合は、正確な応答を調査してください。制限されたビュー、利用できないエージェントモジュール、異なる SNMP コンテキスト、または空のテーブルが原因である可能性があります。Kadupul テンプレートを変更する前に、エージェントの設定とアクセスを確認してください。

## デバイスの追加

同梱のパッケージ `install/templates/NetSNMP_Device.xml.gz` には、Net-SNMP デバイステンプレートとその依存関係が含まれています。テンプレートがない場合はインポートし、デバイスを追加するときに選択します。クエリインデックスを確認し、目的のグラフを明示的に作成します。デバイステンプレートを選択しただけでは、収集が機能していることの証明にはなりません。[テンプレートのインポート](/ja/guides/import-and-export-templates/)および[最初のグラフ](/ja/start/first-graph/)を参照してください。

## データクエリなしで取得できるもの

これらの固定 OID データテンプレートはパッケージに含まれています。1 つのグラフでこれらを複数組み合わせることができます。利用可能かどうかはターゲットエージェントに依存します。これらはインデックス検出を必要としません。

| グラフ | OID | 保存形式 |
|---|---|---|
| 1分間ロードアベレージ | `.1.3.6.1.4.1.2021.10.1.3.1` | `GAUGE` |
| 5分間ロードアベレージ | `.1.3.6.1.4.1.2021.10.1.3.2` | `GAUGE` |
| 15分間ロードアベレージ | `.1.3.6.1.4.1.2021.10.1.3.3` | `GAUGE` |
| 合計メモリ | `.1.3.6.1.4.1.2021.4.5.0` | `GAUGE` |
| 空きメモリ | `.1.3.6.1.4.1.2021.4.6.0` | `GAUGE` |
| バッファメモリ | `.1.3.6.1.4.1.2021.4.14.0` | `GAUGE` |
| キャッシュメモリ | `.1.3.6.1.4.1.2021.4.15.0` | `GAUGE` |
| ユーザー CPU | `.1.3.6.1.4.1.2021.11.9.0` | `GAUGE` |
| システム CPU | `.1.3.6.1.4.1.2021.11.10.0` | `GAUGE` |
| アイドル CPU | `.1.3.6.1.4.1.2021.11.11.0` | `GAUGE` |
| 割り込み | `.1.3.6.1.4.1.2021.11.7.0` | `GAUGE` |
| コンテキストスイッチ | `.1.3.6.1.4.1.2021.11.8.0` | `GAUGE` |
| プロセス数 | `.1.3.6.1.2.1.25.1.6.0` | `GAUGE` |
| ログインユーザー数 | `.1.3.6.1.2.1.25.1.5.0` | `GAUGE` |

メモリオブジェクトはキロバイト単位です。パッケージ化されたメモリグラフは、軸にバイト単位で表示されるように変換を適用します。これらの OID から独自のグラフを作成する場合、その変換は各自の責任で行う必要があります。

リストされている CPU オブジェクトは非推奨のパーセンテージであり、累積 CPU 時間カウンターではありません。これら 3 つだけでプロセッサのすべての状態を網羅しているとは見なさないでください。Net-SNMP は、未加工カウンター（raw counters）を支持してこれらを非推奨としています。未加工カウンターは適切なレートとパーセンテージの計算が必要であり、単に gauge テンプレートに挿入するだけでは機能しません。[UCD-SNMP-MIB](https://www.net-snmp.org/docs/mibs/ucdavis.html) を参照してください。

## データクエリが必要なもの

| クエリ | 検出対象 | 支援元 |
|---|---|---|
| SNMP - マウントポイントの取得 | エージェントがストレージと呼ぶすべてのもの | `hrStorageTable`, `.1.3.6.1.2.1.25.2.3.1` |
| Net-SNMP - 監視対象パーティションの取得 | `snmpd.conf` で宣言されたパーティションのみ | `dskTable`, `.1.3.6.1.4.1.2021.9.1` |
| SNMP - プロセッサ情報の取得 | CPU ごとに 1 エントリ | ホストリソースプロセッサ負荷 |
| Net-SNMP - デバイス I/O の取得 | ブロックデバイス | `diskIOTable`, `.1.3.6.1.4.1.2021.13.15.1.1` |
| SNMP - インターフェース統計 | ネットワークインターフェース | `IF-MIB` |

### どちらのディスククエリを使用すべきか

これらは同じデータの 2 つのビューではありません。

ホストリソースクエリは、エージェントがストレージとして報告するすべてのものを走査します。ほとんどの Linux ホストでは、物理メモリ、スワップ、tmpfs マウント、および実際のファイルシステムが 1 つのリストにまとめられます。サイズはアロケーションユニット単位で返され、クエリはグラフが乗算できるようにアロケーションユニットサイズを個別のフィールドとして読み取ります。何も設定せずにすべてを取得できますが、不要なエントリの長いリストも取得されます。

net-snmp クエリは、`disk` ディレクティブまたは `includeAllDisks` によって入力される UCD ディスクテーブルを読み取ります。明示的なパーティションまたは広範な検出を選択します。これらは異なるポリシーです。

```
disk /      10%
disk /var   10%
```

あるいは、`includeAllDisks 10%` はエージェントの起動時に見つかったディスクを入力します。10% の値は空き領域のしきい値を構成します。これは選択フィルターではなく、Kadupul アラート自体を構成するものでもありません。エージェントをリロードまたは再起動してから、インデックスを確認してください。空のクエリは、アクセスの問題やモジュールの可用性を反映している可能性もあります。[snmpd 設定](https://www.net-snmp.org/docs/man/snmpd.conf.html)を参照してください。

完全性を求め、クリーンアップする準備ができている場合は、ホストリソースクエリを優先してください。対象を絞ったリストが必要な場合は、明示的な `disk` エントリを持つ net-snmp クエリを優先してください。`includeAllDisks` はそのリストを拡張します。エージェントの再起動後にインデックスを再確認してください。

### インターフェース

サーバー上のインターフェースデータクエリは、スイッチ上とまったく同じように動作しますが、1 つ注意点があります。Linux での `ifDescr` はカーネルインターフェース名であり、再起動やドライバーの更新後に変更される可能性があります。インデックス選択の詳細については、[スイッチの監視](/ja/guides/monitor-a-switch/)を参照してください。

## SNMP では不十分な場合

一部のメトリクスには使用可能な MIB がありません。キューの深さ、アプリケーションカウンター、またはファイル内の数値には、スクリプト入力が必要です。

2 つの事実がスクリプトの作成方法を決定します。

**スクリプトは、監視対象ホストではなく、ポーラーが実行されているマシン上で実行されます。** ターゲットへの到達は、SSH、HTTP 呼び出し、エージェント、またはすでに導入されているメカニズムなど、スクリプトの役割です。

**ポーラーは標準出力を読み取り、それ以外は読み取りません。** 終了ステータスは評価されません。

出力規約：

| 出力 | 意味 |
|---|---|
| `42` または `3.7` | 単一データソースの単一値 |
| `U` | このサイクルの値なし、unknown として記録 |
| `in:1420 out:980` | 複数の値、データソースごとに 1 つ |

複数値形式の場合、ペアは単一のスペースで区切られ、名前はコロンで値と区切られます。パーサーは空白に対して区切り文字をカウントするため、余分な内部スペースがあると検証に失敗する可能性があります。PHP ポーラーは末尾の空白をトリミングします。単一スペースの正規形式を出力し、診断メッセージは stdout からリダイレクトしてください。

テンプレートエディターで受け入れられる内部 RRD データソース名は `[a-zA-Z0-9_]{1,19}` と一致します。ハイフンは受け入れられません。スクリプト出力ラベルはデータ入力フィールド名と一致し、対象の内部項目にマップされている必要があります。出力行全体は 512 文字の列に保存されます。監査済みの PHP ポーラー規約については、[データ収集スクリプトの作成](/ja/guides/write-a-data-collection-script/)を参照してください。

測定できない場合は、`0` ではなく `U` を返してください。ゼロは測定値であり、そのようにプロットされます。両者を分けて保持する理由については、[データソースと RRA](/ja/concepts/data-sources-and-rras/) を参照してください。

### スクリプトサーバー

単純なスクリプトは、インターバルごとにデータソースごとに 1 回実行されます。PHP で書かれたスクリプトの場合、スクリプトサーバー形式は、個別の存続期間の長い PHP プロセス内の関数を呼び出し、インタープリターの起動オーバーヘッドを削減します。

### ホワイトリストの落とし穴

データ入力ホワイトリストファイルが使用されている場合、ポーラーは各データ入力のコマンド文字列を記録されたものと比較します。ホワイトリストを再生成せずに変更されたコマンド文字列はポーラーキャッシュエントリの作成を停止し、データソースはグラフ上でエラーを出さずに停止します。ログにはこれが報告されますが、UI には報告されません。

```bash
php cli/input_whitelist.php --audit
php cli/input_whitelist.php --update --id=42
```

`42` はデバイス ID ではなく、監査対象のデータ入力メソッドの ID に置き換えてください。`--id` を指定しない更新は、入力インベントリ全体の現在のコマンド文字列を受け入れます。事前に変更を監査してください。更新後、ソースの有効化と有効なポーラーキャッシュエントリを確認してください。

## 障害モード

| 症状 | 一般的な原因 |
|---|---|
| システム説明は読み取られるが、他には何も収集されない | `snmpd` ビューがシステムサブツリーに制限されている |
| Net-SNMP パーティションクエリでインデックスが見つからない | `snmpd.conf` に `disk` または `includeAllDisks` 行がない |
| ホストリソースパーティションに RAM と tmpfs が含まれている | 想定通り。エージェントはこれらをストレージとして報告する |
| メモリグラフが 1024 倍ずれている | 変換なしで未加工の OID 上に構築されている |
| スクリプトはコマンドラインで値を返すが、ポーラーは unknown を記録する | 出力/マッピングの不一致、内部区切りエラー、または無効な内部名 |
| スクリプトは手動で動作するが、ポーラー経由では失敗する | ポーラーユーザーとしてその環境と権限で実行されている |
