:::caution[사용 전 검증]
소스는 제공되지만 지원되는 Kadupul 릴리스나 마이그레이션 경로는 없습니다. 이러한 절차에 의존하기 전에 백업이 있는 격리된 사본에서 테스트하십시오. [프로젝트 상태](/ko/project/status/)를 참조하십시오.
:::

온도, 습도 및 순간 전력은 측정값이며 일반적으로 `GAUGE`로 저장됩니다. 누적 에너지 또는 이벤트 총계에는 카운터 유형이 대신 필요할 수 있습니다. 템플릿을 선택하기 전에 각 개체의 단위, 식별자 및 의미 체계를 확인하십시오.

무언가를 작성하기 전에 이미 제공된 항목을 확인하십시오.

## 기본 제공 항목

트리 자체의 쿼리 디렉터리에는 4개의 데이터 쿼리 정의만 존재하며 환경 관련 정의는 없습니다.

| 제공되는 SNMP 쿼리 | 대상 |
|---|---|
| `interface.xml` | 네트워크 인터페이스 |
| `host_disk.xml` | Host Resources 스토리지 |
| `net-snmp_disk.xml` | UCD 선언 파티션 |
| `net-snmp_devio.xml` | UCD 블록 장치 I/O |

센서 지원은 다른 두 가지 방식으로 제공됩니다.

**Net-SNMP 장치 패키지에 번들된 스크립트 서버 쿼리.** `resource/script_server/` 아래에 3개의 lmSensors 쿼리 XML 파일을 배포하려면 `install/templates/NetSNMP_Device.xml.gz`를 가져옵니다. 헬퍼 스크립트 `scripts/ss_netsnmp_lmsensors.php`도 소스 체크아웃에 존재합니다.

| 쿼리 | 테이블 |
|---|---|
| Net-SNMP - Sensors - Get Thermal Sensors | `.1.3.6.1.4.1.2021.13.16.2.1` |
| Net-SNMP - Sensors - Get Fan Sensors | `.1.3.6.1.4.1.2021.13.16.3.1` |
| Net-SNMP - Sensors - Get Voltage Sensors | `.1.3.6.1.4.1.2021.13.16.4.1` |

헬퍼는 인덱스, 이름 및 읽기 값 열을 사용합니다. 쿼리는 숫자 `sensorDevice`에 인덱스를 생성합니다. `sensorName`은 헬퍼가 18자로 자르는 표시 이름을 제공합니다. 이름이 고유한 센서 식별자임이 보장되지는 않습니다.

일반적인 `get sensorReading` 경로는 원시 값을 반환합니다. 레거시 온도 개체의 경우 밀리도, 전압의 경우 밀리볼트, 팬의 경우 RPM입니다. 온도 그래프는 `Divide by 1000` CDEF를 적용합니다. 전압 그래프에는 Volts 라벨에도 불구하고 CDEF가 없으며, 이는 [확인된 스케일링 버그](https://github.com/kadupulhq/kadupul/issues/247)입니다.

별도의 `query sensorReading` 경로는 온도와 전압의 크기를 조정하고 잘못된 상수 4294967294를 사용하여 부호 있는 전압 변환을 시도합니다. 또한 [사용할 수 없는 읽기 값에 대해 예외를 발생](https://github.com/kadupulhq/kadupul/issues/248)시킬 수도 있습니다. 이 검색 출력에서 저장된 단위를 유추하지 마십시오.

헬퍼는 여전히 레거시 온도 열 `.2.1.3`을 사용합니다. 현재 업스트림 [LM-SENSORS-MIB](https://raw.githubusercontent.com/net-snmp/net-snmp/master/mibs/LM-SENSORS-MIB.txt)는 부호 있는 열 `.2.1.4`를 선호하여 해당 부호 없는 개체를 더 이상 사용하지 않습니다. 템플릿을 조정하기 전에 실제 에이전트에서 지원 및 음수 온도 동작을 확인하십시오.

**가져올 수 있는 아카이브로 제공되는 장치 패키지.** 몇몇 패키지는 자체 쿼리 XML을 포함하고 있으며 가져오기 시 이를 쿼리 디렉터리에 씁니다. 여기에서 중요한 패키지는 다음과 같습니다.

| 패키지 | 제공 기능 |
|---|---|
| SNMP UPS | UPS-MIB 입력 및 출력 라인 쿼리와 배터리, 런타임, 온도 및 알람을 위한 고정 OID 템플릿 |
| AKCP Device | 온도, 습도, 공기 흐름 및 4-20 mA 센서를 위한 스크립트 쿼리 |
| APC InfraStruXure PDU | 차단기 및 위상 통계를 위한 쿼리 |
| APC InfraStruXure InRow CRAC | 온도, 습도, 공기 흐름 및 팬 속도를 포함한 장치 및 그룹 통계를 위한 쿼리 |
| BayTech PDU | 전류, 전압, 전력 및 온도가 포함된 콘센트 쿼리 및 3상 회로 쿼리 |

직접 쿼리를 작성하기 전에 일치하는 패키지를 검사하십시오. [템플릿 가져오기 및 내보내기](/ko/guides/import-and-export-templates/)를 따르고 파일 배치 및 검색을 확인한 다음 원하는 그래프를 명시적으로 생성하십시오. 패키지가 존재한다고 해서 장치 호환성이나 올바른 스케일링이 입증되는 것은 아닙니다. 아래의 UPS 및 lmSensors 결함에 주의해야 합니다.

## 센서가 취하는 두 가지 형태

SNMP 수집의 경우 스칼라 개체와 인덱스된 테이블 인스턴스를 구분하십시오.

**고정 OID.** 한 주소의 단일 스칼라 값으로, 해당 유형의 모든 장치에서 동일한 주소입니다. 배터리 온도. 총 출력 전력. 리터럴 OID에 대한 SNMP get과 읽기 값당 하나의 데이터 소스를 사용하는 고정 OID 데이터 소스를 사용하십시오.

**테이블.** 장치당 발견되는 알 수 없는 수의 읽기 값입니다. 랙 프로브, 멀티탭 콘센트, 위상별 측정값. 테이블을 탐색하고 인덱스를 학습하며 그래프가 될 행을 선택할 수 있는 데이터 쿼리를 사용하십시오.

제공되는 UPS 패키지는 둘 다 사용합니다. MIB의 개체 구조를 따르십시오. 전류 프로브가 하나만 있는 장치라도 인덱스된 테이블 행으로 노출될 수 있습니다.

| UPS 읽기 항목 | 형태 | OID |
|---|---|---|
| 배터리 온도 | 고정 | `.1.3.6.1.2.1.33.1.2.7.0` |
| 예상 남은 런타임 | 고정 | `.1.3.6.1.2.1.33.1.2.3.0` |
| 배터리 가동 시간 | 고정 | `.1.3.6.1.2.1.33.1.2.2.0` |
| 배터리 전압 | 고정 | `.1.3.6.1.2.1.33.1.2.5.0` |
| 존재하는 알람 | 고정 | `.1.3.6.1.2.1.33.1.6.1.0` |
| 입력 전압, 전류, 전력, 주파수 | 쿼리 | `.1.3.6.1.2.1.33.1.3.3.1` |
| 출력 전압, 전류, 전력, 부하 | 쿼리 | `.1.3.6.1.2.1.33.1.4.4.1` |

이러한 모든 데이터 소스는 `GAUGE`입니다. 카운터는 없습니다. 제공되는 템플릿 아카이브는 60초 단계와 600초 하트비트, 최솟값 0, 최댓값 없음을 선언하지만 온도는 최솟값이 없습니다. 가져온 프로필과 실제 RRD 구성을 확인하십시오. 이러한 선언이 실행 중인 폴링 주기를 설정하지는 않습니다. 유효한 음수 읽기 값에는 이를 표시하는 그래프 축도 필요합니다.

## OID 찾기

무언가를 작성하기 전에 장치를 탐색하십시오. 읽기 값 테이블, 레이블의 병렬 테이블, 공급업체가 선택한 승수, 그리고 사용 가능한 경우 유효성/상태 개체의 세 가지를 찾습니다.

```bash
snmpwalk -v2c -c public probe.example.net .1.3.6.1.2.1.33
# Replace this example enterprise number with the vendor's actual number.
vendor_oid='.1.3.6.1.4.1.318'
snmpwalk -v2c -c public probe.example.net "$vendor_oid"
```

예제 호스트와 커뮤니티를 구성된 값으로 바꾸고 폴러에서 프로브를 실행하십시오. 이름, 단위 및 의미 체계를 확인하기 위해 일치하는 MIB와 종속 항목을 로드합니다. 공급업체 개체 문서에서도 숫자 OID를 설명할 수 있습니다. 인접한 임계값이나 상태 코드는 측정값과 호환되지 않습니다.

```bash
snmptranslate -m +UPS-MIB -Td -OS .1.3.6.1.2.1.33.1.2.7
```

MIB 정의는 스케일링이 문서화된 곳입니다. 10분의 1도를 보고하는 공급업체는 개체의 설명이나 단위 절 및 관련 공급업체 문서에 이를 명시합니다. 한 번의 읽기 값에서 추측하면 23.5도가 235도의 그래프로 바뀔 수 있습니다.

표준 MIB는 사람들이 예상하는 것보다 더 많은 것을 다룹니다. `.1.3.6.1.2.1.33`의 UPS-MIB는 공급업체 전반에 걸쳐 공통적입니다. ENTITY-SENSOR-MIB는 센서 값과 함께 자체 스케일 및 정밀도 필드를 제공합니다. 엔터프라이즈 하위 트리를 찾기 전에 이를 확인하십시오.

테스트 설치 환경에서 대표적인 재부팅 및 프로브 변경 전반에 걸쳐 검색 결과를 비교하십시오. 변경되지 않은 두 번의 탐색만으로는 인덱스 안정성을 입증하지 못합니다. 장기적인 그래프를 생성하기 전에 사용 가능한 경우 안정적인 센서 식별자를 기록하십시오.

## 고정 OID 데이터 소스 구축

고정 OID 센서에는 SNMP get 데이터 입력을 사용하고 OID를 리터럴 값으로 사용하며 내부에 하나의 데이터 소스 항목이 있는 데이터 템플릿이 필요합니다. 유형을 `GAUGE`로 설정하고 센서가 실제로 그 이하로 내려갈 수 없는 경우에만 최솟값에 실제 값을 지정하며 공급업체가 상한을 문서화하지 않는 한 최댓값은 정의되지 않은 상태로 둡니다.

RRD 데이터 소스 경계를 벗어난 값은 알 수 없음이 됩니다. 그래프의 변환된 단위가 아닌 저장된 원시 단위로 이러한 경계를 설정하십시오. 그렇지 않으면 디스플레이 CDEF가 적용되기 전에 유효한 읽기 값이 손실될 수 있습니다.

## 데이터 쿼리 구축

쿼리에는 인덱스 OID, 탐색된 각 OID를 인덱스로 변환하는 방법, 원하는 열당 하나의 필드가 필요합니다.

UPS 출력 쿼리는 간단한 작동 예시입니다. 라인 테이블에 인덱스를 생성하고 정규식을 사용하여 반환된 각 OID의 끝에서 인덱스를 구문 분석하며 인덱스에 대한 하나의 입력 필드와 전압, 전류, 전력 및 부하에 대한 네 개의 출력 필드를 선언합니다. 출력 정의에는 메서드, 소스, 방향 및 열 OID가 포함됩니다. 열 OID는 유효한 인덱스 탐색 루트가 될 수 있습니다. 중요한 것은 쿼리의 파서와 실제로 반환된 OID를 일치시키는 것입니다. 인덱스가 선택되고 저장되는 방식에 대해서는 [데이터 쿼리 및 인덱스](/ko/concepts/data-queries-and-indexes/)를 참조하십시오.

재인덱스 방식을 신중하게 선택하십시오. 선택 항목은 없음, 가동 시간 역행 시, 인덱스 수 변경 시, 모든 필드 확인입니다. 센서 테이블은 약한 방식이 실패하는 대표적인 사례입니다. 랙 장치에서 프로브 하나를 뽑고 다른 프로브를 꽂으면 개수는 변경되지 않을 수 있지만 인덱스 뒤의 모든 읽기 값은 이제 다른 센서에 속하게 됩니다. 전체 확인에는 각 주기마다 SNMP 작업 비용이 듭니다. 쿼리가 확인할 수 있는 식별 필드를 확인하십시오. 변경되지 않은 숫자 인덱스나 중복/잘린 레이블은 물리적 프로브가 동일한 것임을 증명할 수 없습니다. 교체 후 검색을 새로 고치고 그래프 연결을 검토하십시오.

## 값 스케일링

변환이 발생하는 위치를 결정하고 한 곳에만 배치하십시오.

| 위치 | 사용 시기 |
|---|---|
| 수집 스크립트 내부 | 문서화된 수집기 계약을 사용할 때. lmSensors get은 현재 원시 단위를 반환함 |
| 그래프 항목의 CDEF 내부 | 원시 값을 저장할 가치가 있고 표시 단위가 표현상의 선택일 때 |

CDEF는 공급업체 승수에 대한 일반적인 해결책입니다. 제공되는 패키지에는 현재 데이터 소스, `10` 및 나눗셈으로 구성된 `Divide By 10`과 같은 정의가 포함되어 있습니다. 해당 원시 단위를 가진 개체에만 적용하십시오.

UPS 패키지에는 [잘못된 전력 및 시간 CDEF](https://github.com/kadupulhq/kadupul/issues/249)가 있습니다. On Battery 계열은 초를 60이 아닌 6000으로 나누고, 입력/출력 Watts 계열은 와트를 10으로 나눕니다. 준수하는 에이전트의 경우 600초는 10분으로 표시되어야 하고 1000와트는 1000와트로 표시되어야 합니다. 배터리 전압과 라인 전류는 10으로 나누어야 합니다. 예상 남은 런타임은 이미 분 단위입니다. [RFC 1628의 UPS 개체 단위](https://www.rfc-editor.org/rfc/rfc1628.html)를 참조하십시오.

원시 읽기 값을 저장하고 그래프에서 나누면 샘플이 데이터 소스 경계와 보존 기간을 유지하는 한 RRD 파일을 정확하게 유지하고 원시 기록을 다시 작성하지 않고도 디스플레이 승수를 수정할 수 있습니다. 수집기 측 변환은 저장 단위를 변경하고 정밀도를 버릴 수 있습니다. 이를 문서화하십시오. 설명되지 않은 원시 읽기 값을 검증된 엔지니어링 단위로 표시해서는 안 됩니다.

변환을 두 번 적용하지 마십시오. 스크립트가 이미 값의 크기를 조정한 그래프의 CDEF는 그럴듯하지만 잘못된 읽기 값을 생성할 수 있습니다.

## 측정값에 맞는 그래프 설정 지정

트래픽 기본값을 맹목적으로 복사하는 대신 측정값에 맞는 설정을 선택하십시오.

| 설정 | 트래픽 | 센서 |
|---|---|---|
| 데이터 소스 유형 | `COUNTER` | `GAUGE` |
| 기본값 | 1000, 축이 k 및 M으로 표시됨 | 여전히 1000이지만 도(degree) 단위에서 접두사는 의미 없음 |
| 자동 배율 조정 | 범위를 알 수 없으므로 필요함 | 범위를 알고 있으므로 일반적으로 필요하지 않음 |
| 상한 및 하한 | 자동 배율 조정 모드에 따라 다름 | 유용한 표시 범위 선택 |

명시적인 상한 및 하한과 실제 단위를 나타내는 수직 레이블을 설정하십시오. 제공되는 UPS 온도 그래프는 하한 0, 상한 100, 수직 레이블 `C`로 이를 수행합니다.

자동 배율 조정 옵션은 스위치가 아니라 일련의 선택 사항입니다. 제공되는 온도 그래프에서 사용하는 옵션은 `--alt-autoscale-max`와 함께 하한을 전달하며 저장된 상한 100은 전달하지 않습니다. 엄격한 경계가 없으면 범위를 벗어난 읽기 값으로 인해 전달된 제한이 확장될 수 있습니다. 구성된 제한이 자동으로 고정되는 것은 아닙니다. 관심 있는 경계를 유지하는 변형을 선택하십시오.

| 옵션 | 효과 |
|---|---|
| 제한을 무시하는 자동 배율 조정 | 양 끝이 유동적임. 범위를 전혀 모를 때 사용 |
| 하한을 허용하는 자동 배율 조정 | 하한을 전달함. 최댓값은 데이터를 따름 |
| 상한을 허용하는 자동 배율 조정 | 상한을 전달함. 최솟값은 데이터를 따름 |
| 두 제한을 모두 허용하는 자동 배율 조정 | 두 제한을 모두 전달함. 확장은 여전히 엄격 모드에 따름 |

값이 설정한 제한을 벗어날 때 축이 확장되는 것을 중지하는 엄격한 경계 옵션도 있습니다. 이탈을 확인하는 것보다 고정 축이 더 중요할 때는 켜고 그렇지 않을 때는 꺼두십시오. 엄격한 그래프는 표시된 범위 밖의 이탈을 잘라낼 수 있기 때문입니다. 그렇다고 해서 저장된 샘플이 삭제되는 것은 아닙니다. [RRDtool 그래프 제한 참조](https://rrdtool.org/rrdtool/doc/rrdgraph.en.html)를 참조하십시오.

SI 접두사가 판독자를 혼란스럽게 할 수 있는 도(degree)나 백분율의 경우 단위 지수를 0으로 설정하는 것을 고려하십시오. 기본값 1000은 접두사 단계를 제어하며 접두사를 비활성화하거나 측정 단위를 변환하지는 않습니다.

### 여기서는 트래픽보다 통합이 더 중요합니다

1시간 동안 평균을 낸 인터페이스 카운터는 무슨 일이 일어났는지 대략적으로 알려줍니다. 1시간 동안 평균을 낸 온도는 중요했던 10분간의 급격한 이탈을 숨깁니다. 이러한 데이터 소스 뒤의 스토리지 프로필이 `MAX` 아카이브를 유지하는지 확인하고, 적절한 `MAX` 통합을 읽도록 플롯된 시리즈를 구성하십시오. `AVERAGE` 시리즈에 대한 범례 최댓값은 원래 피크를 복구하지 못합니다.

MAX 아카이브조차 수집된 샘플에 표현된 피크만 보존합니다. 폴링 사이의 급격한 변화나 저장 전에 거부된 값은 복구할 수 없습니다. [데이터 보존 관리](/ko/guides/manage-data-retention/) 및 [데이터 소스 및 아카이브](/ko/concepts/data-sources-and-rras/)를 참조하십시오.

## 사용할 만한 MIB가 없는 경우

많은 환경 장비가 Modbus, 직렬 프로토콜 또는 HTTP API를 사용하며 해당 SNMP 에이전트는 유용한 것을 노출하지 않습니다. 이러한 장비에는 스크립트 데이터 입력이 필요합니다. 스크립트는 장치가 아닌 폴러 호스트에서 실행되며 장치에 도달하는 것은 스크립트의 문제입니다. 출력 계약에 대해서는 [데이터 수집 스크립트 작성](/ko/guides/write-a-data-collection-script/)을 참조하십시오.

센서에 도달할 수 없는 경우 `0` 대신 `U`를 반환하십시오. 오프라인이 된 프로브는 0도를 읽는 프로브가 아닙니다.

## 오류 모드

| 증상 | 일반적인 원인 |
|---|---|
| 온도가 10배 또는 100배 큰 숫자로 그래프에 표시됨 | 공급업체 승수가 나누어지지 않음 |
| 온도가 10배 작게 그래프에 표시됨 | 스크립트에서 한 번, CDEF에서 한 번 두 번 나누어짐 |
| 전압 레일이 수십억으로 표시됨 | 음수 값을 보유한 수정되지 않은 부호 없는 SNMP 정수 |
| 프로브를 교체한 후 센서 그래프가 평평해짐 | 테이블이 다시 인덱스되어 데이터 소스가 이제 다른 센서를 가리킴 |
| 임계값 위의 읽기 값이 공백으로 표시됨 | 데이터 소스에 최댓값이 설정되었으며 실제 값이 이를 초과함 |
| 도(degree) 읽기 값에서 축에 k 또는 M 라벨이 붙음 | 트래픽 템플릿에서 상속된 기본값 및 단위 설정 |
| 주간 보기에서 급격한 이탈이 보이지 않음 | 선택한 통합, 유지된 해상도, 폴링 간격 및 거부된 샘플 확인 |
| 쿼리가 인덱스를 반환하지 않음 | 반환된 OID, 파서 일치, 액세스 제한 및 개체 지원 확인. 열 루트가 유효할 수 있음 |
| Linux 호스트에서 lmSensors 쿼리가 아무것도 찾지 못함 | 에이전트 지원, 액세스, 노출된 센서 행 및 정확한 SNMP 오류 확인 |
