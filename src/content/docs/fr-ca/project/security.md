Signalez les vulnérabilités en privé, y compris celles du code non publié. N’ouvrez pas de ticket public et ne publiez pas de correctif avant une évaluation privée.

Cette page est une introduction résumée. Consultez la page complète en anglais pour davantage de détails. [English](/project/security/)

[Politique de sécurité du dépôt](https://github.com/kadupulhq/kadupul/blob/main/SECURITY.md)

## Signaler une vulnérabilité en privé

Indiquez la version ou le commit, les étapes de reproduction, la configuration nécessaire et si une authentification est requise. Les responsables visent un accusé de réception sous trois jours ouvrables ; ce n’est pas une date de correction garantie.

[Signaler une vulnérabilité en privé](https://github.com/kadupulhq/kadupul/security/advisories/new)

Les vulnérabilités du code partagé nécessitent une divulgation coordonnée avec les autres projets concernés avant toute publication. Convenez de l’attribution et du calendrier pendant l’évaluation privée.

La politique couvre l’application, le collecteur, l’installateur et le création de paquets logiciels. Elle exclut les modules complémentaires tiers, RRDtool, Net-SNMP, le serveur web, la base de données et les cas exigeant qu’un administrateur agisse contre sa propre installation.
