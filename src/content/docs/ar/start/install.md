:::caution[تحقّق قبل الاستخدام]
الشيفرة المصدرية متاحة، لكن لا يوجد إصدار معتمد أو مسار ترقية مدعوم لـ Kadupul. اختبر هذه الإجراءات على نسخة معزولة مع وجود نسخ احتياطية قبل الاعتماد عليها. انظر [حالة المشروع](/ar/project/status/).
:::

اتّبع هذه الخطوات بالترتيب، مرة واحدة. تنتهي كل خطوة بعملية فحص. نفّذ الفحص قبل الانتقال إلى ما بعده: فاكتشاف أي مشكلة مدرجة هنا الآن أمر يسير وغير مكلّف، بينما يصعب اكتشافها وتصحيحها بعد تشغيل أداة الاستقصاء لمدة أسبوع.

للمتطلبات الخاصة بالمضيف، راجع [Linux على مضيف Windows](/ar/guides/install-on-windows/) و[FreeBSD](/ar/guides/install-on-freebsd/). هذه الإجراءات لا تُعد دليلاً على اجتياز اختبار قبول شامل.

## ما تحتاجه أولاً

تطبيق Kadupul هو تطبيق PHP يخزن إعداداته في MySQL أو MariaDB ويخزن القياسات في ملفات RRD على القرص. تصف هذه الصفحة تثبيتًا جديدًا على خادم رئيسي انطلاقًا من شيفرة `main` المصدرية الحالية، وليس ترقية أو تثبيتًا لخط LTS المؤرشف. هناك أربعة متطلبات أساسية يجب توافرها قبل تشغيل التطبيق.

| المكون | سبب الحاجة إليه |
|---|---|
| PHP 8.4 أو أحدث، في إصدار يحظى بدعم أمني | يشغّل واجهة الويب وأداة الاستقصاء |
| MySQL أو MariaDB | يحتوي على الأجهزة، والقوالب، والمستخدمين، وذاكرة التخزين المؤقت لأداة الاستقصاء |
| RRDtool | ينشئ محفوظات round-robin ويحدّثها، ويرسم المخططات البيانية |
| net-snmp | يوفر أدوات سطر الأوامر ومكتبات العميل المستخدمة للاستعلام عن الأجهزة |

يحتاج PHP أيضًا إلى الامتدادات التي يتطلبها [ملف تعريف التطبيق](https://github.com/kadupulhq/kadupul/blob/main/composer.json)، بما في ذلك `pdo_mysql`، و`gd`، و`sockets`، و`gmp`، و`intl`، و`ldap`، و`mbstring`، و`pcntl`، و`posix`، و`sqlite3`. ثبّتها لكلٍّ من بيئتي تشغيل سطر الأوامر وخادم الويب. توضّح صفحة [المتطلبات](/ar/reference/requirements/) الفرق بين متطلبات Composer والفحوصات المنفصلة التي يجريها برنامج التثبيت.

## الخطوة 1: تثبيت بيئة التشغيل

ثبّت PHP مع امتداداته، وخادم قاعدة البيانات، وRRDtool، وnet-snmp من حزم التوزيعة الخاصة بك.

**تحقّق من ذلك.**

```bash
php -v
php -m | sort
rrdtool --version
snmpget --version
```

يجب أن يسرد أمر `php -m` الامتدادات المطلوبة. يعد امتداد `snmp` الخاص بـ PHP اختياريًا عند توفر أدوات سطر الأوامر الخاصة بـ net-snmp. يتحقق Composer من امتداداته المطلوبة أثناء تثبيت الاعتماديات؛ بينما يحتوي برنامج التثبيت عبر الويب على فحص مستقل للامتدادات. إن وجود بديل في بيئة التشغيل لا يسقط متطلبات Composer.

قد تختلف إعدادات PHP لسطر الأوامر عن إعدادات خادم الويب، لذا تحقّق من كليهما. يوصي برنامج التثبيت بقيمة `memory_limit` لا تقل عن 400M وقيمة `max_execution_time` لا تقل عن 60 ثانية؛ كما يقبل أيضًا القيم غير المحدودة (`-1` و`0` على التوالي). القيم الأقل من هذه التوصيات تصدر تحذيرات، في حين يُعتبر غياب `date.timezone` خطأً مانعًا. اضبط منطقة زمنية صريحة، مثل `UTC`، واستخدم `php --ini` لمعرفة ملف الإعدادات المستخدم في سطر الأوامر.

## الخطوة 2: إنشاء قاعدة البيانات ومستخدمها

أنشئ قاعدة بيانات فارغة واحدة، ومستخدمًا واحدًا يملك الصلاحيات عليها. بالنسبة لقاعدة بيانات محلية، نفّذ أوامر SQL التالية بصفتك مسؤول قاعدة البيانات، مع استبدال كلمة المرور النموذجية قبل الاستخدام:

```sql
CREATE DATABASE kadupul CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'kadupul'@'localhost' IDENTIFIED BY 'replace-with-a-unique-password';
GRANT ALL PRIVILEGES ON kadupul.* TO 'kadupul'@'localhost';
```

استخدم اسم المضيف المطابق لحساب قاعدة البيانات إذا كان اتصال PHP يجري من جهاز آخر.

يحتاج خادم قاعدة البيانات أيضًا إلى ملء جداول المناطق الزمنية الخاصة به، ويحتاج مستخدم Kadupul إلى صلاحية قراءة هذه الجداول في قاعدة بيانات `mysql`. وهذا هو الامتياز الوحيد الممنوح له خارج مخططه الخاص. لا شيء في نظام المراقبة يشير بديهيًا إلى ذلك، إلا أنه إلزامي؛ إذ سيفشل الفحص أدناه بدونه.

```bash
# Populate the tables, then grant the one extra read the installer needs.
mysql_tzinfo_to_sql /usr/share/zoneinfo | mysql -u root -p mysql
mysql -u root -p -e "GRANT SELECT ON mysql.time_zone_name TO 'kadupul'@'localhost';"
```

**تحقّق من ذلك.** سجّل الدخول بصفتك مستخدم قاعدة بيانات Kadupul ونفّذ:

```sql
SELECT COUNT(*) FROM mysql.time_zone_name;
```

النتيجة المنشودة هي الحصول على عدد غير صفري دون أخطاء في الصلاحيات. يشير الصفر إلى أن الجداول لم تُحمَّل أبدًا؛ بينما يعني الخطأ أن المستخدم لا يملك صلاحية قراءتها. كلاهما يوقف برنامج التثبيت.

هناك أربعة إعدادات خاصة بالخادم ذات أهمية كافية لتصحيحها الآن.

| الإعداد | المطلوب | السبب |
|---|---|---|
| `max_allowed_packet` | 16M أو أكثر | عمليات المزامنة الكبيرة بين الخادم الرئيسي وجوامع البيانات البعيدة |
| `character_set_server`، و`collation_server` | `utf8mb4`، و`utf8mb4_unicode_ci` | تحتوي أوصاف الأجهزة على محارف متعددة البايتات |
| `innodb_file_per_table` | On | يبقي مساحات الجداول منفصلة وقابلة للإدارة |
| `innodb_buffer_pool_size` | نحو ربع ذاكرة النظام تقريبًا | يحافظ على مجموعة البيانات العاملة داخل الذاكرة |

يعرض برنامج التثبيت قراءته الخاصة لهذه الإعدادات ويميّز ما هو دون المطلوب، لذا لست مضطرًا للاعتماد على الجدول دون تحقق. يتناول دليل [ضبط أداء قاعدة البيانات](/ar/guides/tune-database-performance/) تفاصيل أوفى بمجرد وجود حمل عمل.

## الخطوة 3: فك الحزمة وضبط الملكية وتقديم الخدمة

ضع التطبيق في مسار يمكن لخادم الويب تقديم الخدمة منه، ثم حدد مستخدم النظام الذي سيمتلكه. هذا القرار أكثر أهمية من موقع الملفات نفسه. هناك عمليتان تقومان بالكتابة هنا: خادم الويب، والمسؤول عن جدولة أداة الاستقصاء. شغّل كلتيهما بنفس المستخدم. شغّل أداة الاستقصاء دون صلاحيات مميزة وامنح العمليتين حق الوصول الذي تحتاجانه. قد تؤدي الأذونات أو أوضاع الملكية غير الصحيحة إلى منع التحديثات اللاحقة حتى وإن كانت الرسوم البيانية تظهر بشكل طبيعي.

### إذا استنسخت المستودع بدلًا من فك حزمة إصدار

يحتاج مستودع Git إلى كلٍّ من اعتماديات PHP وأصول المتصفح المُولَّدة. مع تثبيت بيئات التشغيل المحددة في `mise.toml` الخاصة بالمستودع، نفّذ من جذر المستودع:

```bash
mise exec -- php "$(command -v composer)" install --no-dev --optimize-autoloader
mise exec -- npm ci --ignore-scripts
mise exec -- npm run build
mise exec -- php bin/console asset-map:compile
mise exec -- php bin/console about
```

يملأ Composer دليل `include/vendor/` ويستعيد ملفات التوافقية المثبتة. وينشئ بناء npm الأصول تحت أدلة `include/js/`، و`include/fa/`، و`include/vendor/flag-icons/`. لا يكفي Composer وحده للتثبيت انطلاقًا من المصدر.

تُعد الحزمة غير المتصلة بالإنترنت المكتملة الاعتماديات ناتج بناء منفصلًا. وأرشيف المصدر العام على GitHub ليس هذه الحزمة. اتّبع [إجراء البناء والتحقق في وضع عدم الاتصال](https://github.com/kadupulhq/kadupul/blob/main/docs/symfony-migration.md#offline-installation) عندما لا يتوفر للخادم المستهدف اتصال بالإنترنت.

جهّز المسارات القابلة للكتابة بعد تثبيت الاعتماديات:

| المجموعة | الأدلة | إمكانية الكتابة |
|---|---|---|
| أثناء التثبيت | `resource/snmp_queries`، و`resource/script_server`، و`resource/script_queries`، و`scripts` | أثناء التثبيت أو الترقية فقط |
| أثناء التثبيت | `include/vendor/csrf/`، أو موقع `path_csrf_secret` المضبوط | يجب على برنامج التثبيت إنشاء السر الخاص بالتثبيت؛ واحتفظ به بعد ذلك |
| دائمًا | `log`، و`cache/boost`، و`cache/mibcache`، و`cache/realtime`، و`cache/spikekill`، والدليل المؤقت للنظام | طوال فترة عمل التثبيت |
| بيئة تشغيل Symfony | `var/cache`، وكذلك `var/log` إذا تم ضبط تسجيل الملفات | لبيئة تشغيل PHP ومستخدم تجهيز ذاكرة التخزين المؤقت |

يجب أن يكون دليل RRD قابلاً للكتابة طوال عمر التثبيت أيضًا؛ فهو يحفظ سجل بياناتك التاريخي، لذا عامله بنفس العناية التي توليها لدليل قاعدة البيانات.

لا تزال عملية الانتقال الحالية بحاجة إلى مسارات تسجيل الدخول وبرنامج التثبيت والمكونات الإضافية القديمة. بالنسبة لهذا التثبيت المشترك، قدّم محتوى جذر المستودع مع وضع قواعد صريحة تمنع الوصول إلى الأدلة الخاصة والإعدادات والاعتماديات وحالة بيئة التشغيل. لا تقم بتحويل التثبيت بالكامل إلى `public/`؛ فهذا سيزيل المسارات القديمة التي لا تزال قيد الاستخدام. لنقطة نهاية Symfony المستقلة توجيه مختلف؛ راجع [تعليمات الانتقال](https://github.com/kadupulhq/kadupul/blob/main/docs/symfony-migration.md).

بالنسبة لـ Nginx، ابدأ من [قواعد مواقع Nginx](https://github.com/kadupulhq/kadupul/blob/main/tests/e2e/nginx.conf) الخاصة بالمستودع، مع مواءمة مسار الجذر والمخدم الوسيط لـ PHP-FPM. احتفظ بقواعد الرفض قبل المعالجة العامة لـ PHP وحافظ على PATH_INFO لـ `/app.php/...`. لا يقرأ Nginx ملفات `.htaccess`. حافظ على بقاء ملفات RRD والسجلات والأسرار غير قابلة للوصول عبر HTTP؛ وتحقّق من تكوين الخادم الفعلي بدلًا من افتراض أن أذونات الملفات تمنع تقديمها.

**تحقّق من ذلك.** تحوّل إلى مستخدم أداة الاستقصاء، واكتب ملفًا داخل كل دليل من أدلة المجموعة الدائمة، ثم احذفه. قد يتم رفض الإذن الذي يبدو سليمًا في `ls -l` بواسطة SELinux أو AppArmor، وكتابة الملف هي الفحص الوحيد الذي يغطي ذلك. ثم اطلب ملفًا يقع ضمن دليل السجلات عبر HTTP؛ والنتيجة المطلوبة هي رفض الطلب.

## الخطوة 4: كتابة ملف الإعدادات

بالنسبة لتثبيت جديد، انسخ ملف الإعدادات المرفق:

```bash
cp include/config.php.dist include/config.php
```

لا تستبدل إعدادات تثبيت قائم. اضبط مضيف قاعدة البيانات واسمها ومستخدمها وكلمة المرور من الخطوة 2. هناك قيمتان أخريان لهما أهمية في التثبيت الأول: `url_path`، وهو المسار الذي يُقدَّم التطبيق تحته مع وضع شرطات مائلة في البداية والنهاية، و`poller_id`، وهو `1` على الخادم الرئيسي وقيمة أخرى فقط على جامع البيانات البعيد.

اترك قسم جامع البيانات البعيد معطلاً كتعليق. فأنت لم تنشئ واحدًا بعد؛ يغطي دليل [جمع البيانات عن بُعد](/ar/concepts/remote-data-collection/) ذلك عندما تصبح مستعدًا. لكل إعداد آخر قيمة افتراضية صالحة للعمل، لذا اقرأ صفحة [الإعدادات](/ar/reference/configuration/) قبل تغيير أيٍّ منها.

اضبط متغير `APP_SECRET` خاصًا بالنشر في بيئة معالجة PHP لميزات Symfony التي تستخدمه. يضبط الإقلاع الأولي افتراضيًا `APP_ENV=prod` و`APP_DEBUG=0` ولا يقوم بتحميل ملفات `.env`. وهذا منفصل عن سر CSRF الخاص ببرنامج التثبيت القديم.

**تحقّق من ذلك.** افحص البنية النحوية دون عرض بيانات الاعتماد:

```bash
php -l include/config.php
```

استورد المخطط في الخطوة التالية قبل فتح برنامج التثبيت في المتصفح.

## الخطوة 5: استيراد المخطط

يتوقع برنامج التثبيت أن تكون الجداول موجودة بالفعل. حمّل المخطط المرفق إلى قاعدة البيانات التي أنشأتها:

```bash
mysql -u kadupul -p kadupul < cacti.sql
```

قم بهذا الإجراء مرة واحدة، على قاعدة بيانات فارغة. هذا ليس نص ترقية برمجياً؛ فاستيراده إلى قاعدة بيانات تحتوي على بيانات قد يفشل أو يترك بيانات متضاربة وغير مكتملة.

## الخطوة 6: تشغيل برنامج التثبيت

افتح الموقع في متصفح واتبع الخطوات. يمر برنامج التثبيت عبر تسلسل ثابت، وكل خطوة تفتح الطريق للخطوة التالية:

1. الترحيب والترخيص.
2. فحص الاعتماديات: إصدار PHP وامتداداته، وإعدادات PHP من الخطوة 1 لكل من سطر الأوامر وخادم الويب، وجداول المناطق الزمنية، وإعدادات قاعدة البيانات من الخطوة 2. تمنع الأخطاء زر المتابعة. أما التحذيرات فلا تمنعه، ولكن يجب قراءتها بعناية.
3. نوع التثبيت: خادم رئيسي جديد، أو جامع بيانات بعيد.
4. فحص الأذونات: الأدلة المحددة في الخطوة 3، ويتم اختبارها عن طريق الكتابة فيها.
5. مواقع الملفات التنفيذية: مسارات PHP وRRDtool وأدوات net-snmp.
6. ملف تعريف مصدر البيانات وفاصل المشغّل الزمني.
7. اختيار القوالب: تحديد قوالب الأجهزة المراد تحميلها.
8. تحويل الجداول، والتأكيد، وعملية التثبيت نفسها.

العنصر 6 في هذه القائمة هو العنصر الذي يصعب التراجع عنه لاحقًا. يحدد الملف التعريفي الذي تختاره الخطوة ومجموعة المحفوظات المكتوبة في كل ملف RRD يتم إنشاؤه بعد ذلك، ولا يؤدي تعديل الملف التعريفي إلى ترحيل الملفات الحالية. تتطلب تغييرات فترات الاحتفاظ بالبيانات ترحيلاً مستقلاً ومختبرًا؛ ولا تقتضي دائمًا التخلص من البيانات التاريخية. وإذا كانت قيم الذروة مهمة بالنسبة لك، فتأكد من أن الملف التعريفي يحتفظ بالقيم القصوى وليس المتوسطات فقط: اقرأ [مصادر البيانات ومحفوظات round-robin](/ar/concepts/data-sources-and-rras/) قبل تخطي هذه الخطوة. الفاصل الزمني للمشغّل المعروض هناك هو دقيقة واحدة أو خمس دقائق. يحدد ملف تعريف مصدر البيانات فاصل الجمع الزمني؛ ويجب ضبط المشغّل والملف التعريفي بشكل متسق.

## الخطوة 7: تغيير بيانات الاعتماد الافتراضية

يُنشئ المخطط المرفق حساب مسؤول باسم `admin` وكلمة مرور `admin`، مع تمييزه بحيث تفرض عملية تسجيل الدخول الأولى تغييرهما. كما يُنشئ حساب ضيف معطلاً. غيّر كلمة المرور قبل أن يصبح الخادم متاحًا لأي شخص آخر، أي قبل توصيله بشبكة يمكن للآخرين الوصول إليها.

## الخطوة 8: جدولة أداة الاستقصاء

يجب تشغيل أداة الاستقصاء من خارج التطبيق. اضبط فاصل الجمع الزمني وفاصل المشغّل الزمني بشكل متسق؛ تدعم أداة الاستقصاء فواصل تشغيل مدتها دقيقة واحدة أو خمس دقائق، وتحتوي على آلية حماية تمنع الدورات العادية من العمل قبل أوانها. لتشغيل كل دقيقة، أضف هذا الإدخال إلى crontab الخاص بمستخدم أداة الاستقصاء غير المميّز، مع استبدال `php` ومسار التطبيق بمساراتهما المطلقة:

```
* * * * * php -q /path/to/kadupul/poller.php > /dev/null 2>&1
```

أو شغّل الخادم الخفي المرفق `cactid.php` باستخدام `service/cactid.service`، بعد مواءمته مع مسار التثبيت والمستخدم غير المميّز. استخدم مشغلاً واحدًا فقط: عطّل مهمة cron أو المؤقت عند استخدام الخادم الخفي.

طابق الجدول الزمني الفعلي مع فاصل المشغّل المضبوط. بالنسبة لملفات تعريف الجمع التي تقل عن دقيقة، تشغّل أداة الاستقصاء دورات الجمع ضمن ذلك الفاصل؛ فلا تحاول التعبير عن وتيرة أقل من دقيقة باستخدام إدخال cron هذا.

**تحقّق من ذلك.** نفّذ دورة واحدة يدويًا بصفتك مستخدم أداة الاستقصاء:

```bash
php -q /path/to/kadupul/poller.php --force --debug
```

يتخطى خيار `--force` آلية الحماية من التشغيل المبكر. استخدم هذا الفحص اليدوي مع إيقاف المجدول لتجنب تداخله مع دورة مجدولة. هذا الخيار لا يتجاوز فحوصات الصيانة أو السلامة الأخرى. والمطلوب هو انتهاء الأمر بنجاح مع ظهور سطر ملخص. ثم فعّل المجدول واتركه لفترتين زمنيتين؛ وتأكد من تنفيذ دورة أخرى تلقائيًا دون تدخلك.

## ما قد يتعطل

هذه هي المشكلات وحالات الفشل التي تواجه التثبيت الأول في الواقع.

| العَرَض | السبب | أين تبحث |
|---|---|---|
| توقف برنامج التثبيت عند إعدادات PHP التي تبدو صحيحة | يقرأ خادم الويب وسطر الأوامر ملفات `php.ini` مختلفة | `php --ini`، والملف الذي يبلغ عنه SAPI للويب |
| توقف برنامج التثبيت عند المناطق الزمنية | لم يتم تحميل جداول المناطق الزمنية، أو لا يستطيع مستخدم Kadupul قراءتها | `SELECT COUNT(*) FROM mysql.time_zone_name` |
| فشل خطوة الأذونات على دليل يبدو قابلاً للكتابة | خطأ في المالك، أو بسبب SELinux وAppArmor | اكتب ملفًا بصفتك مستخدم أداة الاستقصاء |
| اكتمال التثبيت دون وصول أي بيانات على الإطلاق | لم تتم جدولة أداة الاستقصاء أبدًا | شغّل `poller.php --force --debug` يدويًا |
| وصول بيانات لبضع دورات ثم توقفها تمامًا | تعمل أداة الاستقصاء بالمستخدم الخاطئ، تاركة ملفات لا يستطيع مستخدم الويب تحديثها | مالك الملفات داخل دليل RRD |
| ظهور فجوات صغيرة كثيرة في المخططات البيانية | تعارض بين الفاصل الزمني المجدول والفاصل الزمني المضبوط | قارن crontab بالفاصل الزمني المضبوط |
| رفض Composer للتثبيت | إصدار PHP أقل من 8.4 أو هناك امتداد مطلوب في ملف التعريف مفقود | `php -v`، و`php -m`، ورسالة خطأ Composer |
| عدم قدرة أداة الاستقصاء على تشغيل أكثر من عملية واحدة | غياب امتداد `pcntl` أو `posix` | `php -m` |

تغطي صفحة [سجلات الأحداث](/ar/reference/logging/) أماكن تسجيل كل منها. وتغطي صفحة [استكشاف أخطاء البيانات المفقودة وإصلاحها](/ar/guides/troubleshoot-missing-data/) الحالة التي يكون فيها التثبيت سليمًا وتواجه مشكلة في جهاز واحد فقط.

## قبل إتاحة الخادم للوصول الخارجي

تعمل أداة الاستقصاء بصفتها مستخدم نظام وتقوم بتنفيذ RRDtool ونصوص الجمع البرمجية الخاصة بك. عامل التثبيت كشيء ينفذ أوامر النظام، لأنه يفعل ذلك بالفعل.

- قدّم الخدمة عبر اتصال آمن TLS.
- لا تترك كلمة مرور المسؤول الافتراضية كما هي، حتى لفترة وجيزة.
- قيد مستخدم قاعدة البيانات في حدود قاعدة البيانات الخاصة به فقط.
- أبقِ دليلي RRD والسجلات خارج جذر المستندات المعروضة على الويب.
- اترك حساب الضيف معطلاً ما لم تقرر خلاف ذلك صراحةً.

يغطي دليل [تأمين تثبيت متصل بالإنترنت](/ar/guides/secure-an-internet-facing-install/) بقية التفاصيل. الخطوة التالية: [إضافة أول جهاز](/ar/start/first-device/).
