:::caution[사용 전 검증]
소스는 제공되지만 지원되는 Kadupul 릴리스나 마이그레이션 경로는 없습니다. 이러한 절차에 의존하기 전에 백업이 있는 격리된 사본에서 테스트하십시오. [프로젝트 상태](/ko/project/status/)를 참조하십시오.
:::

제공되는 ESXi 패키지는 호스트 측정값과 게스트 인벤토리 수를 수집합니다. 게스트별 CPU, 메모리 또는 경합 측정값은 제공하지 않습니다. 그래프를 선택하기 전에 하이퍼바이저 버전에서 노출하는 개체를 확인하십시오.

## 기본 제공 항목

하나의 하이퍼바이저 장치 템플릿이 제공됩니다: **ESXi Device**. 이는 장치 패키지이므로 `install/templates/ESXi_Device.xml.gz`에 스크립트와 데이터 쿼리 파일이 포함되어 있습니다. [템플릿 가져오기 및 내보내기](/ko/guides/import-and-export-templates/)를 따르고 파일 배치를 포함하여 가져오기가 완료되었는지 확인하십시오. 장치 템플릿을 선택하고 검색을 검사한 후 원하는 그래프를 명시적으로 생성하십시오. 패키지를 가져오거나 장치 템플릿을 연결하는 것만으로는 그래프가 생성되지 않습니다.

| 제공 항목 | 용도 |
|---|---|
| `resource/snmp_queries/esxi_cpu.xml` | 프로세서를 검색하고 프로세서별 부하를 읽음 |
| `resource/snmp_queries/esxi_hw.xml` | 하드웨어 구성 요소를 검색하고 해당 상태를 읽음 |
| `resource/snmp_queries/interface.xml` | 표준 인터페이스 통계 쿼리 |
| `resource/script_server/host_disk.xml` | Host Resources 스토리지 테이블을 통한 마운트된 파티션 |
| `scripts/ss_esxi_vhosts.php` | `install/templates/ESXi_Device.xml.gz` 내에 번들됨. 게스트 수, 전원이 켜진 게스트 수 및 게스트 도구 상태를 계산 |
| `scripts/ss_multicpu_avg.php` | 프로세서별 부하를 하나의 숫자로 평균화 |
| `scripts/ss_hstats.php` | Kadupul이 해당 장치에 대해 이미 보유하고 있는 폴링 통계를 읽음 |
| `scripts/ss_host_disk.php` | 파티션 쿼리 지원 |

이 체크아웃에는 Hyper-V, KVM/libvirt, Xen 또는 Proxmox용 전용 장치 패키지가 제공되지 않습니다. 일반 Linux/Windows 템플릿은 해당 에이전트가 지원하는 호스트 지표를 처리할 수 있습니다. 하이퍼바이저별 수집에는 적절한 템플릿과 수집기가 필요합니다. [데이터 수집 스크립트 작성](/ko/guides/write-a-data-collection-script/)을 참조하십시오.

## 먼저 에이전트 켜기

기존 에이전트 구성을 검토하고 사용 중인 ESXi 버전에 맞는 지침을 따르십시오. 패키지 참고 사항에는 공장 초기화가 포함되어 있지만, 이는 일상적인 전제 조건이 아니며 기존 SNMP 구성을 지울 수 있습니다. 커뮤니티 기반 설정의 경우 다음 명령이 에이전트 값을 설정합니다. 커뮤니티 목록을 설정할 때 예제를 바꾸고 필요한 기존 커뮤니티를 보존하십시오.

```bash
esxcli system snmp get
esxcli system snmp set -c YOUR_STRING
esxcli system snmp set -p 161
esxcli system snmp set -L "City, State, Country"
esxcli system snmp set -C noc@example.com
esxcli system snmp set -e yes
```

첫 번째 명령은 구성을 표시하고 마지막 명령은 에이전트를 활성화합니다. 커뮤니티 옵션은 구성된 목록을 대체합니다. 폴러에서 필요한 방화벽 액세스를 확인하고 [ESXCLI SNMP 명령 참조](https://developer.broadcom.com/xapis/esxcli-command-reference/latest/namespace/esxcli_system.html)를 참조하십시오. 이러한 명령은 커뮤니티 기반 폴링을 구성하며 SNMPv3을 구성하지 않습니다. 장치를 추가하기 전에 폴러가 실행되는 머신에서 확인하십시오.

```bash
snmpget  -v2c -c YOUR_STRING esxi.example.net .1.3.6.1.2.1.1.1.0
snmpwalk -v2c -c YOUR_STRING esxi.example.net .1.3.6.1.2.1.25.3.3.1.2
snmpwalk -v2c -c YOUR_STRING esxi.example.net .1.3.6.1.4.1.6876.2.1.1.6
```

첫 번째 명령은 작동하고 세 번째 명령은 아무것도 반환하지 않는 경우 SNMP 오류, 액세스 정책 및 에이전트 지원을 검사하십시오. 빈 walk만으로는 원인을 파악할 수 없습니다. 번들로 제공되는 게스트 스크립트는 SNMPv1을 사용하므로 성공적인 v2c 프로브가 해당 수집 경로를 검증하지는 않습니다. 빈 게스트 walk는 그래프 간격이 아니라 0 개수를 생성합니다. [빈 결과 버그](https://github.com/kadupulhq/kadupul/issues/245)를 참조하십시오.

## 호스트가 노출하는 항목

| 영역 | 하위 트리 | 제공 내용 |
|---|---|---|
| 프로세서 | `.1.3.6.1.2.1.25.3.3.1` | 에이전트가 노출하는 각 프로세서의 부하 |
| 하드웨어 구성 요소 | `.1.3.6.1.2.1.25.3.2.1` | 구성 요소 인덱스, 설명 및 상태 |
| 스토리지 | `.1.3.6.1.2.1.25.2.3.1` | 에이전트가 보고하기로 선택한 데이터스토어 및 로컬 파일 시스템 |
| 인터페이스 | `.1.3.6.1.2.1.2` 및 `.1.3.6.1.2.1.31` | 트래픽, 오류, 상태 |
| 게스트 인벤토리 | `.1.3.6.1.4.1.6876` | 게스트별 전원 상태 및 게스트 도구 상태 |

처음 네 개는 Linux 호스트가 응답하는 것과 동일한 표준 Host Resources 및 인터페이스 테이블입니다. 이러한 테이블의 작동 방식과 선호할 디스크 테이블에 대해서는 [Linux 서버 모니터링](/ko/guides/monitor-a-linux-server/)을 참조하십시오.

다섯 번째는 제공되는 게스트 수 계산 스크립트에서 사용하는 공급업체 하위 트리입니다.

## 그래프 템플릿

| 그래프 | 소스 | 읽는 내용 |
|---|---|---|
| ESXi - CPU | 데이터 쿼리 | 검색된 하나의 프로세서에 대한 부하 |
| ESXi - MultiCPU Average | 스크립트 | 모든 프로세서 부하의 평균 |
| ESXi - Hardware | 데이터 쿼리 | 검색된 하나의 구성 요소 상태 |
| ESXi - VHosts | 스크립트 | 게스트 수 및 게스트 도구 상태 |
| Host MIB - Processes | 고정 OID | 호스트의 프로세스 수 |
| Host MIB - Logged in Users | 고정 OID | 호스트의 세션 수 |
| Device - Uptime | 스크립트 | Kadupul이 마지막으로 기록한 가동 시간 |
| Device - Polling Time | 스크립트 | Kadupul이 이 장치를 폴링하는 데 걸린 시간 |
| 인터페이스 그래프 | 데이터 쿼리 | 인터페이스별 트래픽, 오류, 패킷, 상태 |

프로세서 쿼리는 검색된 항목당 부하를 읽습니다. 행 수가 호스트의 하드웨어 스레드 수와 일치한다고 가정하지 마십시오. 패키지된 인덱스 패턴은 한 자리 또는 두 자리 인덱스만 허용하고 CPU가 적은 호스트에서도 100 이상을 거부합니다. 검색 결과를 원시 walk와 비교하십시오. [CPU 인덱스 버그](https://github.com/kadupulhq/kadupul/issues/246)를 참조하십시오. 평균 스크립트는 프로세서 부하를 독립적으로 탐색하고 반환된 행의 평균을 계산합니다.

Device - Uptime 및 Device - Polling Time은 Kadupul의 저장된 장치 레코드를 읽습니다. 가동 시간 헬퍼는 경과 시간을 추정하지 않고 저장된 SNMP 가동 시간을 반환합니다. 폴링 시간은 Kadupul의 수집 작업을 설명합니다. 오래된 저장 값은 현재 도달 가능성을 입증하지 않습니다. 수집이 중지되면 이러한 헬퍼는 새 샘플을 생성하지 않습니다.

## 수 계산의 문제점

이 부분은 가상화를 물리적 서버와 다르게 만드는 부분이며, 그 어떤 것도 그래프 템플릿으로 해결되지 않습니다.

**게스트는 이동합니다.** 다른 호스트로 마이그레이션된 게스트는 첫 번째 호스트의 인벤토리에서 사라지고 두 번째 호스트의 인벤토리에 나타납니다. 독립적으로 측정된 샘플은 해당 게스트를 일시적으로 이중 계산하거나 누락할 수 있습니다. 수치 변경만으로는 마이그레이션을 증명할 수 없습니다. 이를 설명하려면 하이퍼바이저 인벤토리 식별자와 이벤트를 사용하십시오.

**리소스가 공유되므로 게스트별 기여도는 추정치입니다.** 호스트는 물리적 프로세서 부하를 보고합니다. 어떤 게스트가 이를 유발했는지는 보고하지 않습니다. 호스트 CPU를 게스트 수로 나누면 산술적으로는 맞지만 아무도 묻지 않은 질문에 답하는 숫자가 생성됩니다.

**오버커밋으로 인해 할당량과 사용량은 서로 다른 수량이 됩니다.** 할당된 가상 CPU는 물리적 코어를 의도적으로 초과할 수 있으며, 할당된 메모리는 물리적 메모리를 의도적으로 초과할 수 있습니다. 할당된 리소스 그래프는 측정된 수요가 아닌 할당을 설명합니다. 이를 물리적 용량, 구성된 제한 및 실제 사용량과 비교하십시오.

**이러한 테이블에는 경합이 나타나지 않습니다.** 게스트가 리소스 부족 상태임을 알려주는 측정값, 즉 물리적 프로세서를 기다리는 데 보낸 시간과 호스트가 게스트로부터 회수한 메모리는 이 템플릿이 수집하는 항목에 없습니다. 심각하게 경합 중인 게스트가 있는 60% CPU의 호스트는 원활하게 실행되는 게스트가 있는 60% CPU의 호스트와 여기에서 동일하게 보입니다.

**게스트 및 호스트 측정값은 서로 다른 질문에 답합니다.** 게스트 사용률만으로는 호스트 일정 지연을 설명하지 못할 수 있습니다. 호스트 부하에서 기여도를 도출하기보다는 게스트/애플리케이션 측정값을 하이퍼바이저 경합 지표와 연관시키십시오.

### 대신 해야 할 일

| 질문 | 답이 있는 곳 |
|---|---|
| 호스트가 포화 상태인가 | 호스트에서 가져온 호스트 프로세서 부하 |
| 게스트가 포화 상태인가 | 게스트 내부 및 하이퍼바이저가 보유한 경합 지표 |
| 실행 중인 게스트 수 | 호스트 게스트 인벤토리 수 |
| 환경이 용량 초과 상태인가 | 이 그래프에서는 알 수 없음. 호스트가 노출하지 않는 배치 데이터 필요 |
| 게스트가 이동했는가 | 하이퍼바이저 인벤토리 식별자 및 마이그레이션 이벤트. 수치 단계만으로는 부족함 |

게스트에 관한 모든 사항은 게스트 자체 장치로 모니터링하고 호스트에 관한 모든 사항은 호스트를 모니터링하십시오. 호스트 수준 숫자에서 게스트별 그래프를 작성하지 마십시오. 이러한 그래프는 파생된 것이며 신뢰할 수 있어 보이지만 나중에 아무도 알아챌 수 없는 방식으로 잘못되어 있습니다.

## 제공되는 게스트 수 계산의 함정

게스트 인벤토리 스크립트의 출력에 의존하기 전에 이를 이해하는 것이 좋습니다.

**SNMP 버전 1과 커뮤니티 문자열로만 탐색합니다.** 버전은 스크립트에 고정되어 있으며 장치의 v3 자격 증명은 전달되지 않습니다. v3으로 구성된 장치는 다른 경로를 통해 수집할 수 있지만 게스트 수집은 실패합니다. 해당 에이전트가 v1을 통해 저장된 커뮤니티를 독립적으로 수락하는 경우 게스트 수집이 여전히 성공할 수 있습니다. 장치에서 v3을 선택하는 것 자체가 결과를 결정하지는 않습니다. 빈 게스트 walk는 0으로 반환됩니다. 헬퍼를 수용하기 위해 에이전트의 보안 정책을 다운그레이드하지 않고 이 프로토콜 불일치를 확인하십시오.

**계산은 전원 상태 테이블에서 가져옵니다.** 게스트 총계로 보고되는 숫자는 별도의 인벤토리 개체가 아닌 전원 상태 하위 트리의 walk에 의해 반환된 항목 수입니다. 호스트가 나열하지만 전원 상태 항목이 없는 게스트는 계산되지 않습니다.

**전원 켜짐은 상태 텍스트에서 일치합니다.** 트리밍 및 소문자 변환 후 `powered on` 및 `poweredon`만 실행 중인 수를 증가시킵니다. 다른 표현은 증가시키지 않습니다. 0을 해석하기 전에 원시 에이전트 응답을 비교하십시오.

**게스트 도구 분류에는 확인된 결함이 있습니다.** 리터럴 `not installed`는 일치가 오프셋 0에서 시작하기 때문에 실행 중인 것으로 계산됩니다. 인식할 수 없는 텍스트도 실행 중으로 처리됩니다. 해당 수를 도구가 정상이라는 증거로 취급하지 마십시오. [도구 상태 버그](https://github.com/kadupulhq/kadupul/issues/244)를 참조하십시오.

**호출당 세 번 탐색합니다.** 전원 상태 테이블을 두 번 읽은 다음 도구 테이블을 읽으므로 자체 수치조차 원자적 인벤토리 스냅샷이 아닙니다. 게스트가 많은 호스트에서는 해당 수집 비용을 측정하십시오. 폴러의 여유가 없다면 스레드를 늘리기 전에 간격을 늘리는 후보가 됩니다. [폴러 확장](/ko/guides/scale-the-poller/)을 참조하십시오.

이 스크립트는 일반적으로 빈 탐색에 대한 0을 포함하여 5개의 명명된 값을 모두 출력합니다. 따라서 실패한 탐색으로 인해 구문적으로는 완전하지만 잘못된 샘플이 생성될 수 있습니다. 불완전한 출력의 경우 PHP 출력 프로세서는 연결된 데이터 소스에 필요한 필드를 확인하고 불완전한 타임스탬프 그룹을 보류합니다. 반드시 즉시 폐기하는 것은 아닙니다. [폴러 캐시](/ko/concepts/the-poller-cache/)를 참조하십시오.

## 나머지 부분의 함정

**프로세서 평균은 불균형을 숨깁니다.** 고정된 코어가 1개이고 유휴 코어가 63개인 호스트는 평균이 낮게 측정됩니다. 이것이 중요한 곳에서는 검증된 프로세서별 그래프를 유지하십시오. 또한 평균 헬퍼는 빈 탐색에 대해 `load:0`을 반환하는데, 이는 측정된 유휴 CPU와 구별할 수 없습니다. 이를 수집 상태 및 알려진 빈 결과 버그와 연관시키십시오.

**프로세서 인덱스는 위치 기반입니다.** 프로세서 테이블을 탐색하여 검색됩니다. 에이전트 인덱스가 변경되면 연속성을 신뢰하기 전에 식별자 매핑을 확인하십시오. 패키지된 한 자리/두 자리 제한은 별도의 검색 결함입니다.

**스토리지 항목은 에이전트가 스토리지라고 부르는 모든 것입니다.** 곱셈이 필요한 할당 단위로 원치 않는 항목과 혼합된 데이터스토어를 예상하십시오. 이는 ESXi의 특이한 동작이 아니라 Host Resources 동작입니다. 바이트를 해석하기 전에 캐시된 할당 단위를 확인하십시오. 공유 스크립트에는 유효하지 않은 음수 샘플 또는 누락된 승수에 대한 [알려진 변환 결함](https://github.com/kadupulhq/kadupul/issues/243)이 있습니다.

**하이퍼바이저의 인터페이스 이름은 변경되기 전까지 안정적입니다.** 드라이버 업데이트나 재구성으로 인해 번호가 다시 매겨질 수 있습니다. 인덱스가 선택되는 방식과 이것이 왜 중요한지에 대해서는 [스위치 모니터링](/ko/guides/monitor-a-switch/)을 참조하십시오.

**스크립트는 폴러 호스트에서 실행됩니다.** 캐시된 명령에 의해 전달된 장치 ID를 사용하여 하이퍼바이저 자체에 도달합니다. 게스트 및 CPU 평균 헬퍼는 호출할 때마다 현재 장치 행을 가져옵니다. 커뮤니티 변경 시 해당 명령 인수를 다시 빌드할 필요가 없습니다. 다른 수집기는 작업 항목에 자격 증명을 포함할 수 있습니다. [폴러 캐시](/ko/concepts/the-poller-cache/)를 참조하십시오.

## 오류 모드

| 증상 | 일반적인 원인 |
|---|---|
| 게스트 수를 제외한 모든 항목이 수집됨 | 장치가 SNMP v3으로 구성되어 있고 게스트 스크립트가 v1을 사용함 |
| 게스트 수는 맞지만 전원이 켜진 수가 0임 | 정확한 전원 상태 텍스트와 두 번째 walk가 성공했는지 확인 |
| 게스트 수가 0으로 떨어졌다가 복구됨 | 실패/빈 탐색 확인. 헬퍼가 모두 0인 라인을 출력할 수 있음 |
| 하드웨어 변경 후 프로세서 그래프가 나타났다가 중지됨 | 변경된 인덱스와 패키지된 한 자리 또는 두 자리 제한 확인 |
| 게스트가 느린 동안 호스트 CPU가 낮고 평평함 | 경합뿐만 아니라 수집 실패 확인. 빈 평균 탐색은 0으로 보고됨 |
| 데이터스토어 그래프에 요청하지 않은 파티션이 포함됨 | 에이전트가 이를 스토리지로 보고함 |
| 폴러 중단 후 가동 시간 그래프가 비정상적으로 보임 | 실시간 읽기가 아닌 Kadupul의 마지막 기록 값을 보고함 |
| 유지 관리 중 호스트 간 총 게스트 수가 급증함 | 마이그레이션 중인 게스트가 일시적으로 두 번 계산되거나 전혀 계산되지 않음 |
