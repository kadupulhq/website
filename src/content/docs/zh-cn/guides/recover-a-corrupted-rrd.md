:::caution[使用前请充分验证]
源代码已公开，但目前没有官方支持的 Kadupul 发行版或迁移路径。在依赖这些流程之前，
请在带备份的隔离测试环境中进行验证。参见[项目状态](/zh-cn/project/status/)。
:::

物理层面的文件损坏极其罕见。大多数被报告为损坏的文件实际上结构完好，
只是与数据库记录存在分歧、轮询器没有写入权限，或者因为完全与文件无关的原因停止接收
新数据。在动手修改任何内容之前，请先明确具体是哪种情况，因为针对一种情况的修复手段往往会加剧另一种情况的故障。

:::danger[妥善保存原始文件]
**在执行本页介绍的任何修复操作前，请务必先复制文件备份。** 将数据恢复到独立的候选文件中，
并在替换正式文件前仔细检查。缩小或删除归档会导致保留的历史数据永久丢失。修改最大值只会影响后续的输入验证；
它不会追溯清除已存储的样本。RRD 文件不提供任何自动撤销功能。
:::

## 1. 明确故障类型

| 观察到的现象 | 通常代表的原由 | 跳转至 |
|---|---|---|
| 图形绘制出错误提示而不是图表 | 文件缺失、不可读或所在目录不可写 | 步骤 2 |
| 图形空白但没有错误提示 | 所选时间范围内没有可用数值，或图形定义存在问题 | [排查缺失数据故障](/zh-cn/guides/troubleshoot-missing-data/) |
| 图形在某一固定时刻停滞且不再更新 | 轮询器故障、权限问题或心跳超时 | 步骤 3 |
| 图形有数据，但在未修改配置的情况下形态发生突变 | 文件与数据库记录不一致 | 步骤 4 |
| 保留的数据全部为未知值 (unknown) | 需要检查数据采集、时间同步、阈值限制或数据源配置 | [排查缺失数据故障](/zh-cn/guides/troubleshoot-missing-data/) |
| `rrdtool` 拒绝读取文件 | 路径缺失、访问权限失败、格式不兼容或文件物理损坏 | 步骤 2 和 3，然后转至步骤 5 |

Kadupul 会将第一种情况转化为可读的错误文本而非破碎的图片，
能够区分不可写的目录与不可写的文件，并在文件不存在时提示可能是轮询器尚未开始运行。
该提示仅作为线索而非最终诊断：误删除、路径变更或不完整的恢复操作同样会导致文件缺失。

## 2. 检查文件

在数据源专属页面上提供了两种视图，均支持按会话开启。
调试视图打印 Kadupul 当前会为该数据源生成的 `rrdtool create` 命令。信息视图则是此处的核心：
它通过 `rrdtool info` 读取物理文件，从数据库中读取数据源定义，并对比输出
两者差异。当差异可以在不重建文件的情况下调和时，它会输出对应的
`rrdtool tune` 或 `rrdtool resize` 命令文本，供您手动执行，
而不是直接在后台擅自执行。

在终端中执行相同的首要步骤：

```bash
rrdtool info /path/to/rra/42/1337.rrd
```

文件头部给出了步长、最后更新时间、每个数据源名称及其类型、
心跳、最小值与最大值，以及每个归档的合并函数、行数
和分辨率。如果该命令报错，请保留错误信息并检查路径、
权限及 RRDtool 兼容性，不要立即草率断定文件损坏。命令 `info` 执行成功
仅代表元数据正常读取；还应检查 `fetch` 的输出并测试转储操作，以检验实际历史数据。

## 3. 先排查机械与系统级原因

| 检查项 | 为什么必须在修复前排查 |
|---|---|
| 文件所有权与访问权限 | 维护期间由 root 创建的文件，从那一刻起对于轮询器而言便永久不可写 |
| 目录所有权与访问权限 | 轮询器无法在其没有写入权限的目录中创建替换文件 |
| 剩余磁盘空间与 inode | 文件系统占满会导致写入截断，其表面现象与文件损坏完全一致 |
| 是否存在第二个写入进程 | 并发或无序的更新可能导致写入失败或使维护快照失效；请检查日志 |

请务必以拥有并更新 RRD 文件的系统账号运行维护操作，并保持其权限模式、
所有者与用户组不变。在复制或替换文件前，停止所有写入进程，包括
远程采集器、计划任务以及手动维护脚本。只有在数据生产者完全停止后，方可排空待处理的写入队列。
常规终端命令不会自动获取 Kadupul 的存储锁。
请参阅[存储要求](/zh-cn/reference/requirements/)以及[备份与恢复](/zh-cn/guides/back-up-and-restore/)中的停收静止流程。

## 4. 查看检查器已发现的内容

Kadupul 能够按计划检查启用的设备上与图形关联的数据源，
并记录检查结果；这并非对磁盘上所有文件的全面盘点。该功能默认
处于关闭状态。界面指明了开启路径：Configuration -> Settings -> Data。

| 设置项 | 默认值 | 效果 |
|---|---|---|
| Enable RRDfile Check | off | 启用后才会开始执行任何检查 |
| Check Frequency | 4 hours | 亦提供 1 hour、24 hours，或在每次 boost 周期后运行 |
| Number of RRDfile Check Processes | 1 process | 将文件列表分散到多个并发进程中执行 |
| RRDChecker Timeout | 1 hour | 运行超过此时长将被强制终止 |

检查结果会汇总在列表中，展示设备、数据源、内部数据源 ID、
报警消息和记录日期。您可以按时间筛选、搜索文本，并在采取处理措施后
清理已处理的条目。

检查器能够记录的消息类型及其具体含义：

| 报警消息 | 含义 |
|---|---|
| RRDfile does not exist | 文件从未被创建、已被移动或删除，或者配置的文件路径发生变更 |
| RRDfile is not writable | 轮询器运行用户没有该文件的写入权限 |
| RRDfile modify time older than hour | 至少已有一个小时没有任何数据写入该文件 |
| Last update value in RRDfile is older than 1 hour | 文件自身记录的最后更新时间戳已过时，这比文件修改时间具有更强的确诊效力 |
| The RRDfile step does not match the Data Source Profile step | 文件的创建步长与配置文件当前的步长不一致 |
| There are more, or less, Data Sources in the database than in the RRDfile | 模板在文件创建后增加或减少了字段 |
| The Data Source '...' exists in RRDfile, but not in database | 从文件角度指出存在的多余字段 |
| Data Source name '...' exists in the Database, but not in RRDfile | 指出轮询器试图写入但在文件中没有对应存储位置的字段 |
| The RRDfile Minimal Heart... is lower than polling interval | 检查器警示心跳值小于或等于轮询间隔；偶发延迟的采样可能会变成未知值 |
| The RRDfile minimal heartbeat... should be 'N' and is currently 'M' | 文件的实际心跳低于配置文件设定；此检查不会警示高于设定的情况 |
| Stale values for last 24 hours, or last hour | 在该时间窗口内读取的所有采样值均为未知 (unknown) |
| More than 50% (n/m) values are NaN in last 24 hours, or last hour | 存在部分采集故障 |
| No data returned, maybe corrupted Data Source | 对文件执行 fetch 命令没有返回任何数据 |

检查过程会自动修正数据库中记录的步长与心跳，使其与配置文件相匹配，
这能够消除配置文件与数据源记录之间的漂移，但不会对物理文件本身进行修改。
文件与数据库之间的字段数量不一致只会被报告而不会自动修复，因为任何一方都有可能是错误的一方。

## 5. 转储、编辑与恢复

RRDtool 可以将可读文件序列化为 XML 格式，并据此重建候选文件。
这有助于纠正已知的结构性偏差，但无法恢复已经丢失的采样数据，
也无法保证损坏严重的文件一定能够被正确解析。Kadupul 在进行结构调整时同样使用 dump/restore 辅助工具。
本地恢复工具会在同级生成临时兄弟文件，并在成功后重命名覆盖目标；但这并不等同于备份。

在停止所有写入进程后，以 RRD 文件属主身份运行以下操作。请将示例路径替换为
实际的数据源路径。私有工作目录创建在原文件同级目录下，
以确保候选文件位于相同的文件系统上：

```bash
set -eu
umask 077
rrd=/path/to/rra/42/1337.rrd
work=$(mktemp -d "$(dirname "$rrd")/rrd-recovery.XXXXXX")
cp -p "$rrd" "$work/original.rrd"
rrdtool dump "$work/original.rrd" > "$work/recovery.xml"
# Edit recovery.xml only when the required correction is understood.
rrdtool restore "$work/recovery.xml" "$work/candidate.rrd"
rrdtool info "$work/candidate.rrd"
rrdtool fetch "$work/candidate.rrd" AVERAGE --start end-1h --end now
```

请选择包含已知有效数据的 fetch 时间范围与合并函数；
上述命令中的最后 1 小时仅作为示例。仔细对比源文件与候选文件的数据源名称、
步长、归档、最后更新时间戳以及样本数值。未经编辑的原样 dump/restore
操作可能会改变二进制布局，因此应比对实际数值，而不是要求文件哈希完全一致。

请妥善保留原始副本。只有在全面验证无误后，方可在写入进程保持停止的状态下，恢复候选文件所需的权限模式、
属主和属组，并重命名覆盖生产路径。在恢复数据采集之前，确认
轮询器账户能够正常读取和更新该文件。本示例在安装替换之前停下，
以防止可读但数据不正确的候选文件被意外投入使用。

XML 与候选文件需要额外的磁盘空间。失败的转储操作可能会产生不完整的
XML；切勿尝试恢复此类残损文件。请检查访问权限、可用空间及报错信息。如果在这些排查后原文件
仍无法转储，请改用经过验证的有效备份进行恢复。RRDtool 的
[`restore -f`](https://oss.oetiker.ch/rrdtool/doc/rrdrestore.en.html) 参数允许强制覆盖
目标；而本分步示例中特意采用了全新的独立输出目标。

## 6. 哪些数据可以保留，哪些不能

| 损坏形态 | 历史数据是否可恢复 |
|---|---|
| 文件不可写，其余完整 | 保留的历史数据完好无损。错过的采集更新无法仅通过修复权限来找回 |
| 心跳、最小值或最大值错误 | 可以恢复。使用 `rrdtool tune` 调整头部信息，不会破坏已存数据 |
| 步长错误 | 需要经过验证的显式转换；仅修改数据库中的配置文件无法转换文件本身 |
| 文件中缺失数据源字段 | 现有字段保留其历史数据。新字段从空数据开始记录 |
| 归档被删除或从未创建 | 无法恢复。从未存储过的分辨率数据无法凭空重建 |
| 因缩小容量的 resize 操作导致归档行数减少 | 无法恢复。被丢弃的行在命令执行瞬间即已永久抹除 |
| 文件被截断，转储失败 | 无法恢复。必须从备份中恢复 |
| 头部完整，尾部被截断 | 绝不能假设头部可读就代表转储完整；若转储失败，必须使用经过验证的备份 |

修改轮询间隔或将数据源迁移至其他保留配置文件
不会自动改变现有文件的结构。RRDtool 还提供了结构性的
[`tune` 操作](https://oss.oetiker.ch/rrdtool/doc/rrdtune.en.html)，包括步长调整选项；
请针对您的安装版本和归档布局对转换行为进行严格验证，不要盲目假定可以无损修改间隔。请参阅
[数据源与归档](/zh-cn/concepts/data-sources-and-rras/)以及
[管理数据保留策略](/zh-cn/guides/manage-data-retention/)。使用 `tune` 调高最大值
是安全的操作；而调低最大值会导致此后所有高于新上限的值均被记录为未知 (unknown)。

## 7. 在保留可用数据的同时重建文件

Kadupul 附带了一个拼接 (splice) 工具，可从旧的可读文件中提取数据填充至新文件。
请将拼接结果视为评估候选：该工具可能会填充空白并替换合法的零值，
因此它并非对原始测量历史的完全无损复制。请在主数据采集器的应用程序根目录下运行该工具，
并在可信的可写目录中使用隔离副本。

在步骤 5 中的私有 `$work` 目录内创建具备预期结构的 `new.rrd`，
然后预览合并过程：

```bash
php cli/splice_rrd.php --oldrrd="$work/original.rrd" \
                       --newrrd="$work/new.rrd" \
                       --finrrd="$work/merged.rrd" --dryrun
```

两个输入文件必须均已存在且能够通过工具的可写性检查。
新文件提供基础骨架结构。若未指定 `--finrrd`，输出路径将为新文件路径
附加 `.new` 后缀；请指定一个明确的全新输出路径，以避免覆盖先前的候选文件。
`--dryrun` 会使用临时 XML 以及 SQLite 存储（若可用）进行解析合并，但会跳过最终的 RRD 恢复步骤。
这并不能证明最终的恢复必然成功。移除 `--dryrun` 即可生成独立的候选文件。
在预览阶段避免使用 `--owner`，并以所需的服务账号运行；在安装替换前检查输出文件的实际归属所有权。

:::caution[拼接操作会将零值视为数据空洞]
合并过程会遍历新文件，对于每个包含未知值**或零值**的数据槽位，寻找
旧文件中最接近的匹配值并写入该值。因此，新文件中合法的真实零值将被旧数据覆盖。
对于长期合法处于零值状态的指标（例如空闲端口、清空的队列、静止的计数器），在正式上线前
务必仔细审查结果。旧文件中的未知值也会使用前序数值填充，因此合并输出可能会在实际缺失的数据段上编造出虚假的连续性。
:::

拼接完成后，将文件放置在数据源期望的路径下，赋予轮询器所需的属主权限，
并确认图形能够正常绘制。

## 8. 填补空白数据及其风险权衡

| 工具脚本 | 写入的内容 |
|---|---|
| `cli/batchgapfix.php` | 在多台设备上并行填充指定日期范围的数据，填充值为最后已知值或平均值 |
| `cli/float_rrdfiles.php` | 通过相同的 dump 与 restore 链路在选定图形中对特定范围执行浮动调整 |

这两种工具都会人为捏造测量数据。在对应的时间戳上从未真正采集过任何数据，而在处理之后，
文件中没有任何标记可以将这些捏造的数值与真实测量值区分开来。只有在您确知该空白期
并非真正故障时才可使用：例如因停机维护而关闭轮询器、系统迁移窗口期等。
绝不可在用于容量规划或计费审计的关键数据上使用。同样的审慎原则也适用于[消除数据突刺](/zh-cn/guides/remove-spikes-from-data/)。

## 9. 自动化调试单个数据源

针对行为异常的单一数据源，Kadupul 可以在接下来的几个轮询周期内运行调试检查
并给出判定报告：文件是否存在、文件及其目录是否可写、文件属主与轮询器运行账号是否匹配、
数据源是否处于活动状态、文件是否符合数据源定义、轮询后最后更新时间戳是否发生推进，以及数值是否可用。
其自动修复动作非常保守克制。它仅会执行比对产生的 `rrdtool tune` 建议，
绝不进行额外操作；当建议列表为空或文件不可写时，它会终止操作并记录日志原因。
它不会重建文件、不会添加数据源，也不会修改归档结构。

## 10. 删除操作的独立风险

Kadupul 会跟踪数据源已不复存在的孤立归档文件，并提供删除选项。
它还可以配置为在删除数据源时自动执行联动操作，支持两种模式：
彻底删除，或移动至归档目录。

:::danger[删除操作不可逆]
彻底删除模式会直接从磁盘上抹除文件。系统没有回收站机制，数据
也并未保存在数据库中。如果您无法百分之百确信列表中的每个文件均为真正无用的孤儿文件，
请将模式设置为归档，这会将文件转移至您指定的目录中，以便您日后手动清理。
:::

有些文件可能表面上看起来像孤儿文件，但事实并非如此。数据源被迁移至新路径、
恢复流程仅部分完成，或者设备以全新 ID 重建，都会留下没有配置直接指向的文件。
在执行清理前，请务必先将文件列表与您自身的变更记录进行核对。

## 常见故障模式

| 故障现象 | 根本原因 |
|---|---|
| 修复成功执行，但图形仍然空白 | 请检查文件访问权限、选定的时间范围、数据采集状态以及图形定义 |
| `rrdtool dump` 对文件执行报错 | 在断定物理损坏前，先仔细排查路径、权限、存储状态及格式兼容性 |
| 执行了 Tune 调整，但未见任何改变 | 修改头部信息不会追溯填充历史未知样本；请同时核验物理文件与数据库定义 |
| 调整间隔后图表各处出现细密空白条纹 | 物理文件内部依然沿用旧的步长与心跳值 |
| 拼接后的文件在原本新文件记录为零的位置出现了旧数据 | 属于工具预期行为。拼接算法会将零值与未知值一视同仁地进行回填 |
| 检查器报警列表持续增长永不减少 | 检查结果在手动清除前会一直保留；仅排除故障根因不会自动抹除已有记录 |

请按照统一的备份计划，将归档目录与数据库作为一个整体同步备份，并定期进行
恢复演练。灾难恢复的上限严格受限于备份创建瞬间所保留的数据状态。请参阅
[备份与恢复](/zh-cn/guides/back-up-and-restore/)。
