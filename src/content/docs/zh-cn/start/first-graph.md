这里的图表并不是你原始数据的直接快照。它是对你数据某种汇总方式的呈现，而清楚了解当前展示的是哪种汇总至关重要。

## 你正在看的是什么

每张图表均基于循环归档（round-robin archive）绘制而成。该归档以完整分辨率保存最近的样本，并将较早的样本合并汇总到粒度更粗的数据桶（bucket）中。当你将视图缩放到一年的跨度时，你看到的并不是每一个五分钟的原始样本。你看到的是每个数据桶中的单个数值，该数值由汇总函数决定。

该函数通常是平均值（average）。它也可以是最大值（maximum）或最小值（minimum）。这一点比本页上的任何其他内容都更为重要。

对于常规的按需图表请求，Kadupul 会根据图表的配置拼装出一条 RRDtool 命令，并针对磁盘上的文件执行该命令。该命令由三类指令组成，了解它们各自的作用有助于理解图表生成过程。

| 组成部分 | 实际作用 |
|---|---|
| 定义项（definition） | 指定一个文件、该文件内部的数据源以及一个汇总函数 |
| 绘图项（drawing item） | 将一个数据序列转换为线条、填充区域或堆叠中的一条色带 |
| 图例项（legend item） | 输出单个数值，该数值是在你当前查看的时间窗口上计算得出的 |

完整的组织架构在[图表的绘制原理](/zh-cn/concepts/how-graphs-are-drawn/)中有详细说明。你今天不需要掌握所有细节。你只需要明白：图表定义与所请求的时间范围共同决定了最终生成的图像。缓存机制与实时图表链路的表现可能会有所不同。

## 从最近四小时开始

建议先从较短的近期时间窗口开始查看。所选择的具体归档取决于数据保留期、步长（step）和图表分辨率；四小时的时间跨度并不保证展示的就是原始或未汇总的数据。即使是最精细的归档也包含时间归一化后的数值。在对比具体数值之前，请使用图表的调试命令以及 `rrdtool info` 来检查所请求的函数和可用的归档步长。

新生成的图表通常具有两个正常特征，但这往往会让初学者产生误解。

**线条可能在当前时刻之前终止。** 当前所在的数据桶可能尚未完成采集。采集时机、写入缓冲和归一化处理也可能会推迟可见的终点位置。请核查更新时间戳是否在持续推进，而不是将固定的时间滞后直接视为系统正常的证据。

**最初的一段可能是空白的。** 一小时前创建的数据源只包含一小时的数据，而其余十一个月的内容为空。归档在创建时就会完整分配所需的磁盘空间，因此空白部分实际上是等待填入数据的真实存储空间。

## 扩大时间范围并观察峰值变化

将查看范围扩大到一周。当图表选取粒度更粗的平均值归档时，峰值可能会随之缩小。例如，如果利用率在五分钟内达到 100%，而在该小时剩余的 55 分钟内为零，则整小时的平均利用率约为 8.3%。在一个整体处于空闲的小时内出现持续四分钟的突发流量，其平均值仅约为 6.7%。较短的峰值可能已经在最初的采样间隔内部被平滑处理了。

汇总过程会舍弃细节。如果高精度的历史数据已经过期，无论如何放大视图，也无法从平均值归档中重新还原出这些细节。

这就是三大常见错误中的第一个，也是最容易引发无谓争论的一个。

**将平均值误读为峰值。** 如果你关注的是网络饱和状态，请查看基于最大值构建的图表，而不是基于平均值的图表。这只有在归档本身保留了最大值数据时才有效。如果只保留了粗粒度的平均值，原始峰值就无法被重构。MAX 归档保留的是其输入端时间归一化点之中的最大值，而不是两次轮询之间未被观测到的瞬时峰值。

这里存在一种隐蔽的异常情况值得了解：如果某个图表项请求了最大值，而数据文件中并未包含该项，Kadupul 的选择辅助逻辑可能会回退到首个可用函数，或者在无法判定可用函数时回退到 AVERAGE。生成的图表看起来很正常，但它解答的其实是另一个完全不同的问题。

**将间断误读为零值。** 图表上的间断代表绘制的是未知值（unknown）。其产生原因包括更新丢失、显式的未知输入、被拒绝的数据值以及图表表达式的计算结果。它并不能唯一证明设备处于不可用状态。

心跳（heartbeat）是两次更新之间允许的最大时间间隔，而不是追加到步长之上的额外时间。例如，步长为 300 秒且心跳为 600 秒的配置，允许两次更新之间的最大间隔为 600 秒，而不是 900 秒。归档的未知数据阈值也会对可见的间断产生影响。请参阅 [RRDtool’s data-source definitions](https://oss.oetiker.ch/rrdtool/doc/rrdcreate.en.html) 以及[时间与时间间隔](/zh-cn/concepts/time-and-intervals/)。

在此处需要警惕堆叠图表。某些模板在其图表表达式中会将未知值替换为零。在这些图表上，由于设计使然，服务中断与空闲时段在视觉上看起来完全一致。在得出某项服务已经停止运行的结论之前，请务必查看未堆叠的普通视图。

**对比两个垂直刻度不同的图表。** 并排放置的两张图表各自会根据自身的数据进行刻度缩放。一个小幅度波动和一个大幅度跳变看起来可能一模一样。在下结论之前，请仔细核对坐标轴刻度。

在查看坐标轴的同时，请一并检查其基数。图表可以使用千进制（1000）或以 1024 为底数进行标注。底层存储的数值是完全相同的，改变的只是坐标轴标签。两者的差异取决于前缀单位：在第一级次方上，1024 与 1000 相差 2.4%，而在更大的前缀单位下这一差异会继续扩大。此外还需检查位（bit）与字节（byte）的换算、图表表达式以及数据汇总方式；单凭百分比差异本身并不能定位根本原因。

## 解读图例

图例承载的数值往往比线条的轮廓形状更为关键。“当前值”（Current）通常是所选序列的 LAST 归纳值，它并不一定代表你在查看图表的当下瞬间所采集到的测量值。平均值和最大值都是基于你当前查看的时间窗口计算得出的，而不是涵盖所有历史时间，因此它们会随着视图缩放而动态变化。

系统预设的图例条目包括最小值、最大值、平均值以及显示为“当前值”的最新值。其中有两点常常令使用者感到意外。

**图例中的数值是对绘制内容的归纳，而不是对底层存储内容的直接归纳。** 在基于平均值读取的序列上打印出的最大值，是这些派生平均值在当前选定分辨率下的最大值。它并不代表曾经采集到的历史最大瞬时样本。在一条繁忙的链路上，这两个数值差异巨大，且各自解答着不同层面的问题。

**检查图例具体使用了哪个数据序列。** 普通的 GPRINT 条目可以继承前一个绘图项的序列；而专用的最小值、最大值、平均值和最新值项则拥有独立的内部处理逻辑。因此，在图表模板中调整项目的顺序可能会改变图例报告的内容，哪怕并没有人直接修改过图例本身的配置。如果在进行了一次不相关的模板编辑后数值发生了变动，请首先检查项目的排列顺序。

## 当图表看起来异常时

请按以下顺序检查数据采集链路；故障可能发生在不止一个阶段。

1. 设备此时此刻是否正在正常响应？
2. 轮询器是否正在运行，并且能在其设定的周期内执行完毕？
3. RRD 文件是否具有较新的更新时间？
4. 图表读取的数据源是否确实是你所认为的那一个？

具体排查步骤：

**步骤 1。** 从指定的采集器上运行在添加设备时执行过的同一个 `snmpget` 命令。如果该命令失败，在评判图表之前请先解决数据采集故障。

**步骤 2。** 查找轮询结束摘要。如果缺失，请检查计划任务调度、配置的日志目标位置以及轮询器过早退出的错误。执行耗时超过周期时间会导致更新滞后；请将由此产生的更新间断与心跳设置进行比对。

**步骤 3。** 直接向 RRDtool 查询：

```bash
rrdtool last /path/to/rra/the_file.rrd
rrdtool info /path/to/rra/the_file.rrd
```

`last` 会报告最后一次更新的时间戳，其中包括包含未知值的更新；缓冲写入可能会推迟该时间戳的刷新。请按照设备指南中的说明使用 `lastupdate` 和 `fetch` 检查具体数据值。`info` 会告诉你步长、心跳、数据源类型以及当前存在哪些归档。如果文件中不存在最大值归档，就可以明确解答上述关于峰值疑问的成因。

**步骤 4。** 开启图表调试模式，仔细查看图表生成的完整命令。该命令列出了涉及的文件、文件内部的数据源以及各自使用的汇总函数。在重新应用模板或重新建立接口索引后，图表指向了非预期数据源的情况十分常见。

## 常见症状及其典型含义

| 观察到的现象 | 常见原因 |
|---|---|
| 保持在零刻度的平直横线 | 可能是真实测量值为零，或者是表达式将未知值强制替换成了零 |
| 线条中断后又恢复绘制 | 未知值打断了绘制的序列；请检查数据采集状态和图表计算表达式 |
| 全程布满细小的间断 | 轮询器完成超时，或者心跳时间设置得过于接近步长时间 |
| 峰值在四小时视图中可见，在一周视图中消失 | 在断定数据丢失或采集故障前，请先核实归档分辨率与汇总规则 |
| 图例显示的最大值低于绘制出的曲线峰值 | 图例所归纳的数据序列与你所认为的序列不一致 |
| 整个图表为空且无任何报错 | 其背后没有关联数据源，或者尚未采集到任何数据 |
| 数值出现数量级偏差 | 数据源类型选择错误，或者 32 位计数器发生了数值回绕 |
| 同一条链路的两张图表存在细微差异 | 坐标轴基数不同，或者采用了不同的数据汇总方式 |

[排查数据缺失问题](/zh-cn/guides/troubleshoot-missing-data/)对这一诊断路径进行了更深入的探讨。在确认图表数据准确可靠之后，[调整图表外观](/zh-cn/guides/tune-graph-appearance/)介绍了如何进一步修改图表的视觉呈现方式。
