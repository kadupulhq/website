:::caution[사용 전 검증 필요]
소스 코드는 공개되어 있지만, 공식적으로 지원되는 Kadupul 릴리스나 마이그레이션 경로는
아직 없습니다. 본 운영 환경에 적용하기 전에 백업이 준비된 격리 환경에서 이 절차를
테스트하십시오. [프로젝트 상태](/ko/project/status/)를 참조하십시오.
:::

:::danger[이 작업은 과거 데이터를 수정합니다. 복구에는 백업이 필수입니다]
스파이크 제거는 아카이브를 덤프하고, 값을 수정한 뒤, 임시 형제 파일로 복원하고
검증을 거쳐 원본 파일을 대체합니다. 자동 실행 취소 기능은 없습니다. 복구 복사본을
반드시 보존 및 검증하고, 먼저 `--dryrun`을 실행한 후 대상 샘플을 확인하고 변경을 적용하십시오.
:::

여기서 스파이크란 주변의 모든 정상 값에 비해 너무나 거대하여 세로 축이 그 값에 맞춰 늘어나고
그래프의 나머지 정상 데이터가 바닥선에 평평하게 눌려버리는 1~2개의 샘플 값을 의미합니다.
이 측정값은 명백한 오류이며 시각적으로도 심각한 왜곡을 일으킵니다.

## 스파이크의 원인

카운터 기반 데이터 소스에서 발생하는 스파이크의 대부분은 물리적 측정 오류가 아니라 산술 계산상의 오류입니다.
카운터 데이터 소스는 연속된 두 측정값의 차이로부터 계산된 변화율을 저장합니다.
두 측정값 사이의 경과 시간에 비해 두 번째 측정값이 첫 번째 측정값보다 비정상적으로 크게 입력되면
잘못된 변화율이 계산됩니다. 카운터 리셋, 오버플로(wrap) 처리 실패, 인터페이스 재색인으로 인한
엉뚱한 데이터 소스로의 값 유입, 타임스탬프 오류 등이 주된 원인입니다. 정상적인 카운터 오버플로 자체가
불량 샘플의 증거는 아닙니다. 데이터 소스 타입과 입력된 원시 측정값을 검증하십시오.

변화율 계산 원리는 [데이터 소스 및 RRA](/ko/concepts/data-sources-and-rras/)를 참조하십시오.

가능한 경우 근본 원인을 해결하십시오. 스파이크 제거는 시각적인 교정에 불과하며,
다음에 발생할 스파이크를 방지하지는 못합니다.

## 네 가지 제거 방법

이 도구는 파일 전체를 대상으로 동작합니다. RRD 파일 내의 모든 아카이브를 덤프하고,
대체할 값을 결정한 뒤, 결과를 복원합니다.

| 방법 | 선택 대상 | 시간 윈도우 필요 여부 |
|---|---|---|
| `stddev` | 평균으로부터 N 표준편차 이상 벗어난 값 | 불필요 |
| `variance` | 이상치를 제외한 후 평균보다 N 퍼센트 초과하여 높은 값 | 불필요 |
| `float` | 지정된 시간 윈도우 내의 모든 값 | 필수 |
| `fill` | 지정된 시간 윈도우 내의 알 수 없는 값(unknown) 및 0 값 샘플 | 필수 |

`stddev`와 `variance`는 통계적 탐색을 수행합니다. `float`와 `fill`은 지정된 범위 내에서
지시받은 작업을 기계적으로 수행하므로, 시작 시간과 종료 시간을 지정하지 않으면 즉시 실패합니다.

`fill`은 누락된 데이터에만 국한되지 않습니다. 측정된 정상 0 값을 0이 아닌 값으로
대체할 수 있습니다. 정상적인 유휴 상태나 0 측정값이 포함된 시간 범위에는
이러한 수정이 의도된 것이 아닌 한 사용하지 마십시오.

분산 방식(variance)은 비교 기준이 되는 평균을 계산하기 전에 상위 및 하위 N개의 샘플을
미리 제외하며, 여기서 N은 이상치 설정값입니다. 이를 통해 스파이크 값 자체가
스파이크를 탐지해야 하는 임계값을 부풀리는 현상을 방지합니다.

선택된 값은 모두 대체되며, 세 가지 대체 옵션이 제공됩니다.

| 대체 값 | 결과 |
|---|---|
| `last` | 마지막으로 알려진 정상 값. 기본값. |
| `avg` | 필드/아카이브별로 계산된 평균값. 계산 방식은 선택한 알고리즘에 따라 달라짐. |
| `nan` | 통계적 방식에서의 알 수 없는 값. 윈도우 방식의 제한 사항은 아래 참조. |

알 수 없는 값은 유효한 측정값을 사용할 수 없음을 명확히 기록합니다. `last`와 `avg`는
나중에 그래프를 보는 사람에게 실제 측정값처럼 보일 수 있는 값을 삽입합니다.
대체 옵션을 신중히 선택하고 실제로 저장된 결과를 검증하십시오.

**NaN을 사용하는 윈도우 방식:** `--avgnan=nan` 옵션을 주면 `float`는 윈도우 내의 모든 유효한 값을
알 수 없음으로 대체하고, `fill`은 윈도우 내의 0 또는 숫자가 아닌 값을 알 수 없음으로 대체합니다.
선택적 시간 범위를 지정한 통계적 방식은 감지된 이상치만 대체하므로 전체 윈도우를 비우는 것과는 다릅니다.

## 미리보기 후 변경 적용

```sh
# preview this exact method and replacement
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --avgnan=nan --dryrun

# after reviewing that preview, repeat its exact selection without --dryrun
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --avgnan=nan --backup

# narrow it to a known incident
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --outlier-start='2026-03-14 02:00' --outlier-end='2026-03-14 03:00' \
    --avgnan=nan --dryrun

```

드라이런은 실제 운영 파일을 수정하지 않고 RRD를 덤프하여 분석합니다. 실행을 위해서는
여전히 정상적인 작업 디렉터리와 유지보수 권한이 필요합니다. 미리보기가 실제 적용 시점까지 파일을 잠그는 것은 아닙니다.
새로운 샘플이 추가되거나 옵션이 변경되면 결과가 달라질 수 있습니다. 위의 윈도우 예제 또한 통계적 필터링을
사용하므로 해당 윈도우 내의 모든 값을 무조건 삭제하지는 않습니다.

시간 인수에는 Unix 타임스탬프 또는 날짜 문자열을 지정할 수 있습니다. 파싱할 수 없는
문자열은 파일 수정 전에 거부됩니다. 표준시간대 해석에 혼선이 생길 수 있는 경우 Unix 타임스탬프를 사용하십시오.

## 파일에서 실제로 수행되는 작업

중요한 운영 데이터에 적용하기 전에 알아두어야 할 내부 처리 과정:

1. 파일이 백업 디렉터리에 XML 형식으로 덤프됩니다.
2. 주석이 제거되고 통계 산출을 위해 각 아카이브가 스캔됩니다.
3. XML 내에서 선택된 값들이 대체됩니다.
4. 원본 파일이 백업 디렉터리에 그대로 복사됩니다.
5. 수정된 XML이 개인 형제 파일로 복원되고, 유효성 검증을 거친 후, 소유자, 그룹, 권한 모드를
   유지한 채 원본 파일 위에 덮어쓰기 방식으로 이름이 변경됩니다.

4단계는 필수적인 안전장치이며 건너뛸 수 없습니다. 복사에 실패하면 복원 프로세스가
실행되지 않습니다. 문제 발생 시 복구할 수 있는 근거는 커맨드라인 옵션이 아닌 바로 이 백업 복사본입니다.
복사본 파일명은 원본에 기반하며 기존 백업의 덮어쓰기를 방지하기 위해 고유 접미사가 붙을 수 있습니다.
`--backup`은 영구적인 복구 스냅샷을 명시적으로 요청합니다. 보고된 경로를 확인하고
신뢰하기 전에 복사본이 제대로 생성되었는지 검증하십시오.

이 작업에는 신뢰할 수 있는 로컬 POSIX 디렉터리와 유지보수 락이 필요합니다.
단순한 쓰기 권한 비트만으로는 부족합니다. 지원되지 않는 스토리지나 rrdcached 엔드포인트가
구성된 환경에서는 실행이 거부됩니다. Kadupul의 락 프로토콜에 참여하지 않는 외부 쓰기 프로세스를 중지하십시오.
스토리지 소유 권한을 가진 전용 서비스 계정으로 실행하십시오. 스토리지 접근 요건은
[설치 요구사항](/ko/reference/requirements/)을 참조하십시오.

## 기본값을 제어하는 설정

커맨드라인 인수가 항상 우선합니다. 생략된 인수는 시스템 설정에서
가져오며, 웹 인터페이스에서 도구를 실행할 때는 사용자별 설정이 시스템 설정을 덮어씁니다.

| 설정 항목 | 기본값 | 동작 내용 |
|---|---|---|
| Removal method | Variance with outliers removed | 사용할 스파이크 제거 알고리즘 |
| Replacement method | Last known good | 제거된 값을 대체할 방식 |
| Number of standard deviations | 10 | `stddev` 방식의 표준편차 임계값 배수 |
| Variance percentage | 1000 | `variance` 방식의 퍼센트 임계값 |
| Variance number of outliers | 5 | 평균 계산 전 제외할 상하위 샘플 개수 |
| Max kills per RRA | 5 | RRA당 최대 제거 한도 (현재 엄격하게 강제되지는 않음) |
| RRDfile backup directory | `cache/spikekill/` under the install | 덤프 및 백업 복사본이 저장되는 경로 |
| Backup retention | 3 months | 복사본 보존 기간 |

배치 모드도 제공됩니다. 실행 주기(6, 12, 24, 48시간마다), 기준 시각,
작업을 적용할 그래프 템플릿 목록을 지정합니다. 배치 모드는 기본적으로 꺼져 있습니다.
이를 켜면 관리자가 결과를 직접 확인하지 않고 시스템이 자동으로 아카이브를 수정하게 됩니다.
활성화할 경우 템플릿 목록을 매우 엄격하게 제한하십시오.

## 함정

**기본 임계값은 의도적으로 매우 넓게 설정되어 있습니다.** 10 표준편차와
1000% 분산은 대단히 넓은 허용 범위입니다. 도구를 실행했을 때 아무런 스파이크가 감지되지 않았다고 해서
작업이 실패한 것이 아닙니다. 단지 수집된 값들이 지정한 허용 범위 내에 있음을 알려준 것뿐입니다.
임의로 제거 방식을 바꾸기보다는 임계값을 좁혀보십시오.

**Max kills per RRA는 통계적 방식에만 적용됩니다.** `stddev`와
`variance`의 경우 이 카운트는 하나의 아카이브 내 모든 데이터 소스에 걸쳐 계산되며 다음 아카이브로
넘어갈 때 초기화됩니다. 윈도우 방식인 `float`와 `fill`은 윈도우 내의 일치하는 모든 값을 무조건 대체합니다.
요약 건수에는 NaN으로의 대체도 포함됩니다. 전체 미리보기를 면밀히 검토하고 좁은 시간 윈도우를 사용하십시오.

**통합된 과거 값은 원본대로 복원할 수 없습니다.** 오래된 아카이브는 이미 평균화된
버킷당 하나의 값만 보존합니다. 그 값을 교체한다고 해서 당시의 실제 측정값이
복구되는 것은 아니며 그럴듯한 추정값이 들어갈 뿐입니다. 더 먼 과거로 갈수록 이러한 보정은 단순한 추측에 가까워집니다.

**백업 디렉터리는 반드시 구성되어 있어야 하고 신뢰할 수 있어야 합니다.** 덤프 파일과
복구 사본이 그곳에 저장됩니다. 누락되었거나, 안전하지 않거나, 검증할 수 없는 디렉터리는 거부됩니다.
오류를 피하겠다고 디렉터리에 전체 쓰기 권한(world-writable)을 부여하지 마십시오.

**애플리케이션 로그 외에 별도의 관리자 변경 작업 기록을 남기십시오.** 작업자,
실행 명령어, 시간 범위, 백업 경로, 작업 전후 검증 결과를 기록하십시오. 단순한 요약 건수 수치만으로는
무엇이 어떻게 변경되었는지 입증할 수 없습니다.

**지정된 서비스 계정으로 실행하십시오.** 파일 교체가 성공하면 파일의
소유권과 권한 모드가 보존됩니다. root 계정으로 실행한다고 해서 디렉터리 신뢰성 검사를 건너뛸 수 있는 것은 아닙니다.
정상적인 폴링 프로세스가 교체된 결과 파일을 계속 갱신할 수 있는지 확인하십시오.

**데이터 소스 자체가 잘못 매핑된 경우 스파이크를 제거해도 그래프가 고쳐지지 않습니다.** 인터페이스
재색인으로 인해 값이 엉뚱한 데이터 소스로 흘러 들어간 경우 스파이크는 하나의 증상에 불과합니다.
아카이브를 편집하기 전에 [누락된 데이터 문제 해결](/ko/guides/troubleshoot-missing-data/)을 먼저 확인하십시오.
