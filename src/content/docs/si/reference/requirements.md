## ධාවන පරිසරය

`main` සඳහා PHP 8.4 හෝ ඊට නව අනුවාදයක් අවශ්‍ය වන අතර Symfony 7.4 පැරණි පිවිසුම් ස්ථාන සමඟ එක්ව භාවිත කරයි. `lts/1.2` ශාඛාවට වෙනම අවශ්‍යතා ඇත. MySQL හෝ MariaDB, RRDtool, සහ PHP දත්ත එකතු කරන්නෙකු හෝ ගැළපෙන Spine ගොඩනැගීමක් ස්ථාපනය කරන්න. මූලාශ්‍රයෙන් ගොඩනැගීමේදී `mise exec` හරහා `mise.toml` හි අනුවාද භාවිත කරන්න; පරායත්තතා යාවත්කාලීන නොකර අගුළු දැමූ අනුවාද ස්ථාපනය කරන්න.

## PHP

ප්‍රකාශන ගොනුව PHP වලට අමතරව පහත දිගු ඉල්ලා සිටී:

`PDO`, `Phar`, `dom`, `gd`, `gmp`, `intl`, `json`, `ldap`, `mbstring`, `mysqlnd`, `openssl`, `pcntl`, `pdo_mysql`, `posix`, `sockets`, `sqlite3`, `xml`.

ස්ථාපකය වෙනමම `ctype`, `date`, `filter`, `hash`, `pcre`, `session`, `simplexml`, `spl`, `standard` සහ `zlib` ඇතුළු වෙනත් දිගු පරීක්ෂා කරයි. Unix හි `posix` සහ CLI සඳහා `pcntl` ද, Windows හි `com_dotnet` ද පරීක්ෂා කරයි. ස්ථාපක පරීක්ෂණය සමත් වීම Composer අවශ්‍යතා සපුරා ඇති බවට සාක්ෂියක් නොවේ. CLI සහ වෙබ් PHP වෙන වෙනම පරීක්ෂා කරන්න. `date.timezone` සකසන්න; ස්ථාපකය `memory_limit=400M` සහ `max_execution_time=60`, හෝ සීමා රහිත අගයන් නිර්දේශ කරයි. විකල්ප `snmp` දිගුව ක්‍රියාවලිය තුළ විමසුම් සක්‍රිය කරයි; `gettext` පරිවර්තන නාමාවලි සක්‍රිය කරයි.

## දත්ත සමුදාය

සැපයුම්කරු විසින් නඩත්තු කරන MySQL හෝ MariaDB නිකුතුවක් භාවිත කර ඉලක්ක කේත සංශෝධනය සමඟ තහවුරු කරන්න. ස්ථාපකයේ පැරණි MySQL 5.6 සහ MariaDB 10.0 සීමා 2026–2027 සඳහා සහාය තහවුරු නොකරයි. වත්මන් `main` හි `poller_output`, `poller_output_boost` සහ `poller_output_realtime` සඳහා InnoDB භාවිත කරයි; සමහර සම්බන්ධීකරණ වගු තවම MEMORY භාවිත කරයි. සියලු වගු එකම එන්ජිමකට පරිවර්තනය නොකරන්න. `mysql.time_zone_name` වෙත දත්ත පුරවා යෙදුම් ගිණුමට එය සඳහා SELECT අවසරය දෙන්න.

## RRDtool

ක්‍රියාත්මක කළ හැකි ගොනුවේ නිරපේක්ෂ මාර්ගය සකසා වින්‍යාස කළ අනුවාදය ස්ථාපිත බයිනරි අනුවාදයට ගළපන්න. `DCOUNTER` සහ `DDERIVE` සඳහා RRDtool 1.5 හෝ නව අනුවාදයක් අවශ්‍යයි. Unix දේශීය ගබඩාව සඳහා POSIX අනන්‍යතා පරීක්ෂණ සහ නිසි ලෙස ක්‍රියා කරන නාමාවලි `flock` අවශ්‍යයි. තනි ප්‍රවේශයක් අවශ්‍ය නඩත්තුවට පෙර බාහිර ලිවීමේ ක්‍රියාවලි සහ cache සේවා නවත්වන්න. පැරණි proxy මාර්ගය පවතින නමුත් එය තහවුරු කළ යෙදවීමක සහතිකයක් නොවේ.

## net-snmp

PHP `snmp` නොමැති හෝ අක්‍රිය කර ඇති විට Net-SNMP මෙවලම් ස්ථාපනය කරන්න. `path_snmpget`, `path_snmpgetnext`, `path_snmpwalk`, `path_snmpbulkwalk` සහ `path_snmptrap` සඳහා අදාළ ක්‍රියාත්මක කළ හැකි ගොනු මාර්ග සකසන්න. උපාංගයේ SNMP අනුවාදය සමඟ තෝරාගත් මාර්ගය පරීක්ෂා කරන්න; අදාළ නම් IPv6 හරහා SNMPv3 ද ඇතුළත් කරන්න. එම සංයෝජනය සඳහා PHP `snmp` භාවිතයට එරෙහිව පැරණි ස්ථාපකය අවවාද කරයි.

## වෙබ් සේවාදායකය

සකසා ඇති වෙබ් ධාවන පරිසරය හරහා PHP ක්‍රියාත්මක කර TLS භාවිත කරන්න. `/app.php/...` සමඟ පැරණි මාර්ග රැකගන්න; පැරණි පිටු පවතින තුරු සම්පූර්ණ ලේඛන මූලය `public/` වෙත මාරු නොකරන්න. ගැළපුම් පිවිසුම සඳහා PATH_INFO සකසන්න. Nginx විසින් `.htaccess` නොසලකා හරියි; PHP සැකසීමට පෙර මූලාශ්‍රය, වින්‍යාසය, පරායත්තතා, මෙවලම්, පරීක්ෂණ, රහස් සහ ධාවන තත්ත්වය සඳහා පැහැදිලි ප්‍රවේශ තහනම් නීති යොදන්න. URL උපසර්ගය `$url_path` සමඟ ගළපන්න.

## කාලසටහන

එක් ආරම්භක ක්‍රමයක් පමණක් භාවිත කරන්න: cron, Task Scheduler හෝ සපයා ඇති දත්ත එකතු කිරීමේ daemon සේවාව. එහි වාර ගණන වින්‍යාස කළ ආරම්භක පරතරයට ගළපන්න. විනාඩියකට අඩු පරතරයකින් දත්ත එකතු කිරීම එම පරතරය ඇතුළත සිදු වේ; cron පමණක් එවැනි කාලසටහනක් ලබා නොදෙයි. ක්‍රියාවලි එකිනෙක මත නොවැටීමට සාමාන්‍ය ආරම්භක ක්‍රමය නවත්වා poller ගිණුමෙන් පරීක්ෂණ ක්‍රියාත්මක කරන්න.

## ගොනු පද්ධතිය

සැබෑ RRD මාර්ග, ලොග්, cache සහ Symfony ධාවන නාමාවලි වෙත අවශ්‍ය ගිණුම්වලට පමණක් ප්‍රවේශය දෙන්න. පෙරනිමි RRD නාමාවලිය `rra/` වේ. වෙනම Unix වෙබ් සහ poller ගිණුම් සඳහා `include/config.php` තුළ `rrd_maintenance_trusted_uids` වෙත පැහැදිලි සංඛ්‍යාත්මක හැඳුනුම් ද, ලිවීමට අවසර ඇති කණ්ඩායම් සඳහා `rrd_maintenance_trusted_gids` ද අවශ්‍යයි. ලැයිස්තුගත කණ්ඩායම්වල සෑම සාමාජිකයෙකුම විශ්වාස කළ හැකි අයෙකු විය යුතුය. සාමාන්‍ය අවසර ද තවදුරටත් අදාළ වේ; සියලු දෙනාට ලිවිය හැකි ගබඩාව ප්‍රතික්ෂේප කෙරේ. සියලු ලිවීමේ ක්‍රියාවලිවල එකම විශ්වාස සැකසුම් භාවිත කර උත්ශ්‍රේණියට පෙර ගිණුම් දෙකම පරීක්ෂා කරන්න.

## වරප්‍රසාද

වෙබ් ක්‍රියාවලිය සහ poller කැපවූ වරප්‍රසාද රහිත ගිණුම්වලින් ක්‍රියාත්මක කරන්න. raw ICMP සඳහා අමතර මෙහෙයුම් පද්ධති වරප්‍රසාද අවශ්‍යයි; ඒවා නොමැති නම් TCP, UDP හෝ SNMP පරීක්ෂණ භාවිත කරන්න. ping සක්‍රිය කිරීමට සම්පූර්ණ යෙදුම root ලෙස ක්‍රියාත්මක නොකරන්න. දේශීය RRD සඳහා විනාශකාරී නඩත්තුවට අවශ්‍ය ACL තහවුරු කිරීම Windows හි නොමැත; සාමාන්‍ය යාවත්කාලීන සඳහා RRDtool හි සමමුහුර්ත පිළිගැනීම් භාවිත කරයි. Unix දත්ත සැකසුම් වේගය පිළිබඳ සාක්ෂි Windows ධාරිතාව තහවුරු නොකරයි.

## PHP අනුවාදය පිළිබඳව

2026–2027 සැලසුම් සඳහා PHP 8.4 වෙත 2026 දෙසැම්බර් 31 දක්වා සක්‍රිය සහායත් 2028 දෙසැම්බර් 31 දක්වා ආරක්ෂක නිවැරදි කිරීම්ත් ලැබේ. PHP 8.5 වෙත 2027 දෙසැම්බර් 31 දක්වා සක්‍රිය සහායත් 2029 දෙසැම්බර් 31 දක්වා ආරක්ෂක නිවැරදි කිරීම්ත් ලැබේ. මේවා PHP ව්‍යාපෘතියේ දිනයන් වන අතර Kadupul ගැළපුම් වගුවක් නොවේ. නව ධාවන පරිසරයන් භාවිතයට ගැනීමට පෙර අගුළු දැමූ පරායත්තතා සමඟ පරීක්ෂා කරන්න. Symfony හි අඩු PHP අවම අවශ්‍යතාව Kadupul හි අවම 8.4 සීමාව අඩු නොකරයි. යෙදවීමට පෙර නිල කාලසටහන් සහ ඉලක්ක කේත සංශෝධනය නැවත පරීක්ෂා කරන්න.
