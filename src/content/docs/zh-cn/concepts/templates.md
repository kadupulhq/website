模板的存在是为了让添加第一百台交换机的工作量与添加第二台时相同。系统中有四种模板，它们呈层级堆叠关系。

具体的操作流程请参考[使用并验证模板](/zh-cn/guides/template-workflow/)。

**数据模板**定义要采集的内容及存储方式：字段、类型、数值上下限、存储配置文件以及用于提取数值的输入方法。每个对象的自定义字段和现有的 RRD 文件可能与当前模板不同；模板本身并不是物理文件布局的绝对保证。

**图表模板**定义绘图方式：包含哪些项、排列顺序、颜色方案、图例行以及坐标轴说明。

**设备模板**将适用于特定硬件类别的各种数据查询与图表模板打包在一起，因此在添加设备时选择正确的模板就能完成绝大部分配置工作。

**数据查询**用于处理事先无法确定项目数量的情形。交换机具有若干端口，通过遍历设备即可发现这些端口，数据查询会记录带索引的结果以供创建图表。单纯的发现操作不会生成固定数量的图表或数据源。

## 层级如何叠加

这四种类型并不是同一对象的四个层次，而是每一层都向下指向下一层。

| 类型 | 指向对象 | 生成结果 |
|---|---|---|
| 设备模板 | 图表模板与数据查询 | 不直接生成内容。它是设备可用功能的清单 |
| 数据查询 | 索引结果的图表定义与映射 | 发现的行；选定的图表创建操作可创建或复用数据源 |
| 图表模板 | 各项需要数据时对应的数据模板字段 | 可引用多个数据源的图表 |
| 数据模板 | 输入方法与存储配置文件 | 数据源元数据；在写入路径需要时创建 RRD |

承载数据的模板项指向模板字段；实例化后的项则映射到本地字段。文本与常量项不需要数据源引用。图表创建过程会解析这些映射关系，后续的重新应用模板或更改项配置也能改变它们。图表创建可以复用兼容的数据源，无需为每个图表创建新文件。

## 模板化还是按对象独立

图表和数据源级别的许多字段在模板行中都有配套的标志位。对于这些字段，该标志控制向关联子对象的常规推送。其他字段、图表项和输入映射则遵循独立的传播规则。

| 标志 | 含义 | 保存时的行为 |
|---|---|---|
| 清除 | 字段受模板管控 | 写入每个子对象，覆盖原有的所有设置 |
| 勾选 | 字段按对象独立 | 在每个子对象上保持原有设置不变 |

标志位针对各个字段独立设置。图表模板可以将其坐标轴标签推送到关联的图表中，同时将标题和垂直刻度上限保留给图表创建者自定义。这种混合配置是常态，而非特例。

该设计的两项特性常让使用者措手不及。

标志位保存在模板上，它仅决定下一次保存时的动作。在推送操作已经覆盖字段之后，再将其标记为按对象独立，并不能恢复任何旧值。原有的独立配置已经丢失；标志位保护的只是未来的修改。

反向操作更加危险。如果一个字段按对象独立保留了数年，一旦清除其标志位，只需一次保存就会将模板上的值同时覆盖到所有子对象中，而模板上的值往往是未曾核对过的占位符。

### 并非所有字段都带有标志位

只有存在对应标志位时，字段才会参与这种受控推送。在数据源级别，有四个字段具备标志位，而有两个字段刻意不设标志位。

| 字段 | 标志位 | 行为 |
|---|---|---|
| 名称 | 有 | 受模板管控或按对象独立 |
| 激活状态 | 有 | 受模板管控或按对象独立 |
| 步长 | 有 | 受模板管控或按对象独立 |
| 存储配置文件 | 有 | 受模板管控或按对象独立 |
| 输入方法 | 无，且始终标记为受模板管控 | 模板保存处理程序会明确更新关联的数据源行 |
| RRD 文件路径 | 无，且始终标记为不受模板管控 | 常规模板推送会排除该项；重新应用模板会保留现有路径 |

保留路径可在常规模板变更期间保护与历史数据的既有绑定。这并不意味着路径不能通过其他管理操作进行编辑或迁移。在更改之前请仔细核对文件标识。

数据源项上的字段全部带有标志位：字段名称、类型、心跳、最小值、最大值以及为其提供数据的输入字段。

## 图表输入的作用方向相反

图表模板可以声明一个命名输入，将多个图表项绑定到同一个可编辑字段，这样在图表上修改一个值就会同步更新共享该输入的所有项。这就是单个颜色或图例配置能够控制一组相关项的底层机制。

它推送的值并不来自模板。它会读取属于该输入的其他项上的当前值并进行同步。因此，图表输入是在图表自身的各个项之间横向扩散，而不是从模板向下传递，这就是为什么修改一项输入可能会更改模板并未直接触及的图表。

## 传播的内容与时机

| 变更项 | 是否作用于已有对象 | 方式 |
|---|---|---|
| 图表模板字段（受模板管控） | 是，保存时生效 | 写入由该模板衍生的每个图表 |
| 图表模板字段（按对象独立） | 否 | 子对象保留自身原值 |
| 图表项外观样式 | 是，保存时生效 | 颜色、透明度、项类型、线宽、虚线样式、CDEF、VDEF、位移、整合函数、对齐、文本及图例格式 |
| 图表项的新增、删除或重定向字段 | 视操作而定 | 匹配、添加、删除与重新映射采用不同路径；请核对生成的本地项映射 |
| 数据模板字段（受模板管控） | 是，保存时生效 | 写入由该模板衍生的每个数据源 |
| 数据模板输入字段值 | 若受模板管控 | 模板与子对象标志、查询索引字段及主机字段规则会约束传播范围 |
| 数据模板存储配置文件、步长、归档 | 仅数据库生效 | 已存在的文件保持其创建时的结构 |
| 新增到数据模板的字段 | 仅数据库生效 | 现有物理文件中没有多余空间存放它们 |
| 设备模板内容 | 需单独同步 | 仅修改关联关系并不会自动同步每台现有设备 |

数据库层面的传播取决于保存路径与覆盖规则。更新模板元数据本身不会迁移现有的 RRD 文件；文件维护属于独立操作。在正在使用的数据模板编辑器中，某些结构性控件为只读状态。参见[创建自定义模板](/zh-cn/guides/create-custom-templates/)。

## 设备模板具有明确的同步路径

编辑设备模板的关联设置会更改提供给新设备的内容。现有设备则需要执行单独的重新应用或同步操作。批量处理工具默认选择处于 Up 或 Recovering 状态的设备，除非调用者明确包含宕机设备；在假设所有设备均已更新前请核验选取范围。

同步操作会补齐缺失的图表模板关联，刷新选定的数据查询，并清除不再需要的废弃图表模板关联。它不会仅因为模板从设备模板中移除就直接删除现有的图表。它还会触发自动化和插件钩子，可能导致配置好的图表自动化规则开始运行。

同步完成后请检查生成的设备关联和图表。它们并不一定是历史上应用过的所有模板版本的永久并集。

## 索引以及端口移动的原因

数据查询必须判定发现的哪个实体对应于哪个现有的数据源。这就是索引。在硬件调整或配置变更后，数字索引可能会改变。选用合适且稳定的字段有助于保持身份一致性，但接口名称也可能被重命名或复用。请在真实设备上验证唯一性、持久性及重新索引机制；没有任何单个字段名称本身能绝对保障连续性。

这项决策在做出时看似微不足道，一旦选错则代价高昂。它是针对每台设备每次运行分别进行的，而不是针对查询只做一次，因此两台完全相同的交换机最终可能基于不同的字段建立索引。关于字段的选择、索引丢失时的后果以及检测重新编号的成本，请参见[数据查询与索引](/zh-cn/concepts/data-queries-and-indexes/)。

## 后续修改模板

图表修改在相关保存和传播完成后会影响后续的渲染。参数替换与图像缓存可能会影响查看者所见的内容，因此不要假定所有图表都会立即改变。请检查有代表性的子图表及其项映射；参见[微调图表外观](/zh-cn/guides/tune-graph-appearance/)。

保存数据模板不会自动调整现有 RRD 文件的物理结构。文件实际的数据源定义和归档可能与数据库配置文件不一致。在维护前请同时检查两者；重新创建文件只是其中一种选择。

根据变更内容的不同，借助 RRDtool 支持的微调操作、归档容量调整或受控的转储/恢复流程，可以保留部分或全部既有历史记录。这些操作有其局限性，需要备份与验证；它们无法凭空重建从未存储过的数据。删除并重新创建文件会彻底丢失历史。参见[管理数据保留期](/zh-cn/guides/manage-data-retention/)与[数据源与轮询归档](/zh-cn/concepts/data-sources-and-rras/)。

## 其他也称为模板的术语

还有四种对象使用了该词汇，但其行为与上述四种并不相同。颜色模板是应用于图表项的具名调色板。聚合模板描述如何将多个图表合并为一个。自动化模板将发现的设备匹配到设备模板。图表预设定义提供可复用的图例格式。

它们均不在本文所述的层级结构之中。了解它们主要是为了在检索结果中出现模板一词时能够准确辨识其具体类型。
