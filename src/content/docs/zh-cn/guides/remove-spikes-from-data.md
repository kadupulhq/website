:::caution[使用前请充分验证]
源代码已公开，但目前没有官方支持的 Kadupul 发行版或迁移路径。在依赖这些流程之前，
请在带备份的隔离测试环境中进行验证。参见[项目状态](/zh-cn/project/status/)。
:::

:::danger[此操作将篡改历史数据；恢复必须依赖有效备份]
消除突刺的操作会转储归档、修改异常数值、恢复至同级临时文件，并在验证通过后
替换原文件。该过程不提供任何自动撤销机制。请务必保留并验证恢复副本，
先使用 `--dryrun` 预览效果，并在确认目标样本无误后再提交更改。
:::

此处的“突刺”是指一两个远大于周边所有正常数值的极端采样值，
其数值之大会迫使图表纵坐标轴被急剧拉伸，从而使图表其余正常数据全部被压缩贴平在
基准线上。这种测量值不仅是错误的，而且具有极其强烈的视觉干扰。

## 突刺产生的原因

基于计数器 (counter) 的数据源中出现的突刺绝大多数是算术异常，而非真实的物理测量值。
计数器类型的数据源通过计算两次读数之间的差值来得出速率。任何使得第二次读数
在相对极短时间内远大于第一次读数的因素，都会产生虚假的高额速率。计数器被复位、
溢出翻转 (wrap) 处理逻辑不当、接口重新索引导致读数被关联到错误的数据源，
或者时间戳错乱，都是常见的触发诱因。正常的计数器翻转本身并不必然意味着错误采样；
在处理前请仔细核验数据源类型和原始输入读数。

关于速率的具体计算方式，请参阅[数据源与 RRA](/zh-cn/concepts/data-sources-and-rras/)。

请尽可能从源头修复根本原因。消除突刺只是一种事后视觉修饰手段；它无法阻止
下一次突刺的再次产生。

## 四种处理方法

该工具作用于整个文件：它会转储 RRD 文件中的每个归档，判定
需要替换哪些数值，并恢复生成处理后的结果。

| 方法 | 筛选的目标数据 | 是否需要指定时间窗口 |
|---|---|---|
| `stddev` | 偏离平均值超过 N 倍标准差的数值 | 否 |
| `variance` | 在剔除离群值后，高出平均值超过 N% 的数值 | 否 |
| `float` | 指定时间窗口内的所有数值 | 是 |
| `fill` | 指定时间窗口内的未知值 (unknown) 以及零值样本 | 是 |

`stddev` 和 `variance` 采用统计搜索。`float` 和 `fill` 则严格按照指令处理您指定的
时间范围，如果您未同时提供起始和结束时间，这两种方法会立即报错退出。

`fill` 方法并不仅限于填充缺失数据：它还会将测量得到的真实零值替换为
非零值。除非这种篡改完全符合您的明确意图，否则请切勿在包含合法空闲或零值读数的时间段内使用它。

方差分析法 (variance) 会在计算比较基准均值之前先剔除最高和最低的 N 个采样值，
其中 N 即为离群值数量设置。这种机制可以防止突刺自身的极值人为拉高本用于捕捉它的检测阈值。

所有被筛选出的目标值都会被替换，系统提供了三种替换选项：

| 替换值类型 | 结果 |
|---|---|
| `last` | 最后已知有效值。此为默认选项。 |
| `avg` | 针对该字段/归档计算得出的平均值；具体计算方式取决于所选方法。 |
| `nan` | 统计方法下的未知值 (unknown)；详见下文窗口方法的局限说明。 |

未知值表示此处缺乏可用测量数据。`last` 和 `avg` 替换的值可能会在日后
让查看图表的人误以为是真实测量值。请慎重选择替换策略并检查最终写入的实际数据。

**带 NaN 的窗口方法：** 在指定 `--avgnan=nan` 时，`float` 会将窗口内的所有已知有效值
替换为未知，而 `fill` 会将窗口内的零值或非数字值替换为未知。
带可选时间边界的统计方法仅会替换检测出的离群值，并不等同于清空整个时间窗口。

## 先预览，后提交

```sh
# preview this exact method and replacement
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --avgnan=nan --dryrun

# after reviewing that preview, repeat its exact selection without --dryrun
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --avgnan=nan --backup

# narrow it to a known incident
php cli/removespikes.php --rrdfile=/path/to/file.rrd \
    --method=stddev --outlier-start='2026-03-14 02:00' --outlier-end='2026-03-14 03:00' \
    --avgnan=nan --dryrun

```

模拟运行 (dry run) 会转储并分析 RRD，而不会重写生产中的实时文件。它依然
需要可用的工作目录和维护权限。预览操作不会锁定文件直到后续提交：新的采样写入或修改命令选项都可能
改变最终的处理结果。上述限定时间窗口的示例采用的依然是统计筛选；它不会盲目抹除
该窗口内的所有数据。

时间参数支持 Unix 时间戳或标准日期字符串。任何无法被正确解析的字符串都会在
重写文件前被直接拒绝。在时区判定可能存在歧义时，推荐使用 Unix 时间戳。

## 文件的实际处理流程

在对关键业务数据执行操作前，有必要深入了解其内部处理链路：

1. 文件被转储为 XML 格式保存在备份目录中。
2. 剥离注释并扫描每个归档以计算统计数据。
3. 在 XML 内部完成选定数值的替换。
4. 将原始物理文件完整复制到备份目录中。
5. 将编辑后的 XML 恢复至私有同级文件中，校验通过后重命名覆盖原文件，
   同时保持其原有的属主、属组和权限模式。

步骤 4 是系统的安全保护底线，具有不可逾越的强制性：如果复制备份失败，后续的恢复流程
将被直接中止。如果您需要回滚，所依据的是该备份副本，而非任何命令行参数。其命名基于原始文件名，
并可能追加唯一后缀以避免覆盖已存在的历史制品。`--backup` 参数会额外请求创建持久化的
恢复快照。在依赖它们之前，请仔细核验输出报告的路径并检查文件完整性。

该操作需要受信任的本地 POSIX 目录及维护锁机制支持；
单纯具备可写权限位是不足够的。该工具拒绝不受支持的存储介质以及配置了
rrdcached 端点的情况。请停止外部写入进程，因为它们并不参与 Kadupul 的锁协议。
请以拥有存储权限的目标服务账号运行此操作。存储访问细节请参阅[安装要求](/zh-cn/reference/requirements/)。

## 控制默认行为的配置项

命令行参数享有最高优先级。任何未在命令行指定的选项均取自
系统设置；当通过 Web 界面运行该工具时，用户级配置会覆盖全局系统配置。

| 配置项 | 默认值 | 作用说明 |
|---|---|---|
| Removal method | Variance with outliers removed | 指定使用的消除算法 |
| Replacement method | Last known good | 指定用什么数值填补被移除的位置 |
| Number of standard deviations | 10 | `stddev` 方法的偏差倍数阈值 |
| Variance percentage | 1000 | `variance` 方法的百分比阈值 |
| Variance number of outliers | 5 | 计算均值前剔除的高低极值样本数 |
| Max kills per RRA | 5 | 预期的消除上限；目前尚未做到绝对可靠的硬性拦截 |
| RRDfile backup directory | `cache/spikekill/` under the install | 转储文件和原始备份的存放路径 |
| Backup retention | 3 months | 备份文件的保留时间 |

系统还提供批处理模式：指定执行周期（每 6、12、24 或 48 小时）、基准时间
以及需要执行操作的图形模板列表。批处理模式默认关闭。
开启该模式意味着系统将在无人直接核验结果的情况下自主篡改归档数据。
如果您确需开启，请务必极其严格地限制模板范围。

## 陷阱

**默认阈值设置得非常宽松。** 十倍标准差以及
1000% 的方差是非常宽泛的范围。一次运行如果没有报告任何突刺，很大概率并不意味着
命令执行失败；它只是如实报告现有数值全部落在您要求的容差范围之内。此时应收紧
阈值，而不是胡乱切换处理方法。

**Max kills per RRA 仅对统计方法有效。** 对于 `stddev` 和
`variance`，该计数涵盖单个归档内的所有数据源，并在进入下一个归档时重置清零。
而 `float` 和 `fill` 这两种窗口方法会无差别替换窗口内的每一个匹配值。
摘要计数中包含了 NaN 替换。请仔细审查完整预览并尽量指定狭窄的时间窗口。

**合并后的聚合数值无法还原。** 较老的归档针对每个时间槽仅保留一个
已经过平均计算的数值。替换该数值并不能恢复该时间段内的真实测量数据；
它只是填补了一个合乎情理的推算值。时间追溯得越久远，这种修正就越接近于纯粹的猜测。

**备份目录必须完成配置且具备完全信任。** 转储文件和恢复快照均保存在该目录下。
缺失、不安全或无法验证的目录将被直接拒绝；切勿为了绕过错误而将目录赋予全员可写 (world-writable) 权限。

**在应用程序日志之外，建立您自有的变更记录审计。** 记录操作人员、
执行命令、时间范围、备份路径以及操作前后的比对检查。单纯的汇总统计数字
不足以证明到底发生了哪些具体的改动。

**以规划的服务账号执行命令。** 成功的文件替换会完整保留原文件的
属主和权限。Root 账户并不能规避目录信任检查；操作完成后，请确认日常轮询器依然
具备更新该文件的权限。

**如果数据源本身关联错误，消除突刺并不能解决图表异常。** 如果
接口重新索引导致读数被错误地记录到另一个数据源中，突刺仅仅是一种表象。
在着手修改归档之前，请先阅读[排查缺失数据故障](/zh-cn/guides/troubleshoot-missing-data/)。
