通常の画像リクエストでは、グラフ設定からRRDtoolコマンドを組み立て、参照されているRRDファイルを読み取ることができます。有効なキャッシュ画像でもリクエストを処理でき、オンデマンドのBoost処理によってレンダリング前にファイルを更新することもできます。データの鮮度制限については、[大量書き込み](/ja/concepts/high-volume-writes/)を参照してください。

## 処理の順序

コマンド生成に進むリクエストの場合：

1. 要求された時間枠とグラフ設定を解決します。
2. データベースプロファイルから解像度を見積もり、統合関数を選択します。
3. 必要なフィールドと関数の重複を排除した `DEF` 参照を出力します。
4. 参照されている `CDEF` および `VDEF` 式を出力します。
5. 適用可能なオプションやプラグインによる変更を伴い、設定された順序で描画および印刷アイテムを出力します。
6. RRDtoolに実際のファイルを読み取らせ、結果をレンダリングさせます。

## アーカイブの選択

Kadupulは、アーカイブ期間やグラフオプションを計算する際にデータベースのプロファイル行を参照します。自動見積もりでは、ステップ時間×ステップ数×行数、要求されたカバー範囲、アーカイブのステップ数を考慮します。明示的なアーカイブ選択は別のパスをたどります。これらのプロファイル計算は、各ファイル内のすべての実際の物理アーカイブを検査するわけではないため、プロファイル変更後に既存のファイルと不一致が生じる可能性があります。

生成された `DEF` は、ファイル、データソース名、統合関数を指定します。RRDtoolは適切な解像度で利用可能なアーカイブを選択し、グラフの幅と時間枠に合わせてデータをさらに統合する場合があります。アプリケーションの見積もりは、特定の物理アーカイブが読み取られることを保証するものではありません。上流の[RRDtoolデータ定義ドキュメント](https://oss.oetiker.ch/rrdtool/doc/rrdgraph_data.en.html)を参照してください。

時間枠を広げたり画像の幅を変更したりすると、表示される解像度が変化する可能性があります。より細かいアーカイブに依然として短いスパイクが含まれていても、平均に基づく粗い系列ではそれが隠れてしまうことがあります。プロファイルだけでなく、実際のファイル構成とコマンドを比較してください。[データソースとラウンドロビンアーカイブ](/ja/concepts/data-sources-and-rras/)を参照してください。

呼び出し元が終了時刻を指定しない場合、通常のレンダラーは最初に現在時刻からのメインポーラーの前回実行オフセットを使用し、その値が利用できないか未来の日時である場合はポーリング間隔にフォールバックします。後続のコードには統合間隔へのフォールバックもありますが、普遍的なデフォルトではありません。明示的な終了時刻はこの初期化を上書きします。グラフが現在時刻より前で終了していること自体は、選択されたアーカイブを証明するものでも、最新のサンプルが書き込まれたことを証明するものでもありません。

## グラフアイテム

グラフはアイテムの順序付きリストです。コマンド生成では、アイテムの省略、定義の再利用、または1つのアイテムを複数の命令に展開することができます。描画順序は単なる視覚的レイアウト以上の意味を持ちます。

| アイテム | 描画内容 | 備考 |
|---|---|---|
| `AREA` | 軸から値までの塗りつぶし領域 | 後の領域が前の領域の上に描画 |
| `STACK` | 前のアイテムの上部から始まる塗りつぶし領域 | スタックフラグ付きの領域として出力 |
| `LINE1`、`LINE2`、`LINE3` | 幅が1、2、または3ピクセルの線 | 破線に設定可能 |
| `LINE:STACK` | 現在のスタック累計合計の上に引かれる線 | |
| `TICK` | プロットの端に沿った目盛りマーク | 大きさではなく状態の把握に有用 |
| `GPRINT` | 描画なし。凡例に数値を1つ出力 | |
| `COMMENT` | 描画なし。凡例にリテラルテキストを出力 | 長いコメントは折り返し |
| `HRULE` | 固定値の水平線 | |
| `VRULE` | 固定時刻の垂直線 | |
| `TEXTALIGN` | 描画なし。後続の凡例テキストの配置を設定 | |

どの設定列がどのタイプに適用されるかを含む完全なリストは、[グラフアイテム](/ja/reference/graph-items/)に記載されています。

`AREA` と `STACK` は最も誤解されやすい組み合わせです。エリアはゼロから始まるため、2つのエリアは重なり合い、高いエリアが低いエリアを隠してしまいます。スタックは前のアイテムが終了した位置から始まるため、2番目の帯の視認できる高さはその帯自体の値を表しますが、その上端は全体の合計を示します。スタックされたグラフはY軸の位置ではなく帯の高さとして読み取る必要があります。そうしないと一番下の系列を除くすべての系列を誤読することになります。

`HRULE` はテンプレート置換を含めることができる値を受け取ります。結果から非数値文字が削除され、数値が何も残らない場合は、レンダリングを失敗させるのではなくゼロの位置にルールが描画されます。ゼロにあるルールは、意図的なものである場合と置換失敗による場合があります。判断を下す前に解決されたコマンドを検査してください。数値フィルターは、単位や非対応の数値表記を含む文字列を変更することもあります。

`VRULE` はUnixタイムスタンプまたは `hours:minutes` のペアを受け取ります。負の時間の値は時計の時刻ではなく現在からの逆方向のオフセットとして解釈されます。

## 2つの役割、1つの言葉

統合関数という言葉は2つの異なる目的に使用され、同じ4つの名前（`AVERAGE`、`MIN`、`MAX`、`LAST`）が両方の場所に現れます。

最初の役割はアーカイブの選択です。`DEF` はファイル、その内部のデータソース、および統合関数を指定します。その関数は要求されるアーカイブファミリーを絞り込みます。`MAX` を要求すると、後述のアプリケーションフォールバックおよび解像度の選択に従って、RRDtoolは一致する保存済み統合データを必要とします。

2番目の役割は凡例の計算です。`GPRINT` は描画された時間枠全体を1つの印刷された数値に縮約し、その関数が計算方法を決定します。その縮約はすでに読み取られた系列に対して行われます。これは表示上の集約であり、物理的なストレージではありません。

したがって、`AVERAGE` で読み取られた `DEF` に対して `MAX` を示す `GPRINT` は、レンダリングされた時間枠におけるその平均値ベースの系列の最大値を出力するのであり、必ずしも生の最大サンプルを出力するわけではありません。5分というのは一例に過ぎず、実効解像度は変動します。これらは異なる数値であり、混雑した回線では非常に大きな差が生じます。どちらの読み取り値も正当です。ただし、通常意図しているのは一方だけです。

## 暗黙のフォールバック

最適関数ヘルパーを使用するアイテムタイプの場合、Kadupulはファイルの統合関数を読み取り、要求されたものが存在すればそれを使用し、存在しなければ最初に報告されたものを使用します。有効なローカルデータソースに対して関数が1つも取得できない場合、ヘルパーはAVERAGEにフォールバックします。固定のGPRINTバリアントは別のパスをたどり、このヘルパーを使用しないため、不足しているすべての関数が修復されるという普遍的な保証はありません。

したがって、`MAX` を要求する描画アイテムは、ファイルにAVERAGEアーカイブしか含まれていない場合、最終的に平均値を読み取ることになる可能性があります。生成された `DEF` と `rrdtool info` の出力を検査してください。アーカイブのメンテナンスによって既存のレイアウトを変更することはできますが、アーカイブを追加しても過去の平均化によって破棄されたピーク値を再構築することはできません。[データ保持の管理](/ja/guides/manage-data-retention/)を参照してください。

## GPRINTは隣のアーカイブを借用する

通常の `GPRINT` は独自のアーカイブを持ちません。データソース名とローカルテンプレートフィールドIDをキーとして、直前にある一致する `AREA`、`STACK`、ライン、または `TICK` アイテムの統合関数を再利用します。先行する一致アイテムがない場合は、自身の設定された関数で最適関数ヘルパーを使用します。固定バリアントは自身の設定された関数を直接使用します。

これは、グラフテンプレート内のアイテムを並べ替えると、誰も凡例に触れていなくても凡例の報告内容が変わる可能性があることを意味します。`GPRINT` ブロックの上に `MAX` を読み取る `LINE` を配置すると、一致する凡例は最大値を要約できます。それを下に移動すると、先行する一致アイテムまたはフォールバックが入力系列を決定します。無関係なテンプレートの編集後に凡例の数値が変わった場合は、まずアイテムの順序を確認してください。

## CDEFとVDEF

どちらもデータを描画する前に変換します。これらには互換性はありません。

| | CDEF | VDEF |
|---|---|---|
| 生成物 | 系列（タイムスロットごとに1つの値） | スカラー値（一部の関数では関連する時刻も含む） |
| 線または面として描画可能か | はい | スカラーにより一定レベルを提供可能 |
| 構成要素 | 関数、算術演算子、他のCDEF、特殊データソース、リテラル | 1つの参照に適用される1つの関数 |
| ネスト | CDEFは別のCDEFを参照可能 | VDEFには算術演算を含めることは不可 |

CDEFは逆ポーランド記法で評価されるスタック式です。使用できる語彙は非常に豊富で、[グラフアイテム](/ja/reference/graph-items/)に全リストが記載されています。算術演算、比較演算子、条件演算子、三角関数、データソース間の集約、スタック操作、X軸上の位置を定義に知らせる時間関数などがあります。`UN` と `UNKN` は早い段階で習得する価値があります。未知の値をゼロに置き換えると視覚的な途切れを防ぐことができますが、測定値の欠落を隠すことにもなります。その表示上の選択は明示的に行ってください。

CDEFは固定のデータソース名ではなく特殊な参照も読み取ります。1つは現在のアイテムのデータソースに解決され、これにより単一のCDEFをテンプレート内のすべてのアイテムで再利用できるようになります。他の参照はグラフ上のすべてのデータソース、または重複の有無を問わず類似するすべてのデータソースに解決され、入力を個別に指定することなく合計ラインを作成できます。

VDEFは系列をスカラー値に縮約します。最大値、最小値、平均値、標準偏差、最初の値、最後の値、合計、パーセンタイル、または最小二乗近似の傾き、切片、相関などです。RRDtoolはVDEF内での算術演算をサポートしていないため、VDEFが計算された入力を必要とする場合、Kadupulは生データソースではなくアイテムのCDEF上にそれを構築します。これが計算の推奨ルートです。CDEFで計算を行い、VDEFでそれを縮約します。

VDEFに基づく `GPRINT` は統合関数の引数を必要としません。VDEFがすでに縮約を提供しているためです。VDEFは描画用のスカラー値を提供することもできます。RRDtoolはVDEFベースの線をサポートしています。上流の[グラフ要素ドキュメント](https://oss.oetiker.ch/rrdtool/doc/rrdgraph_graph.en.html)を参照してください。

CSVエクスポートはサポートされている描画タイプを系列列として選択します。凡例項目は同等の列としてエクスポートされません。VDEFに基づく描画項目はグラフ画像には描画されますが、VDEFは時系列ではなく単一値であるため、エクスポートからは除外されます。

## 同じデータが異なって見える理由

以下に示す項目はいずれも、保存された単一のサンプルを変更することなく画像の見た目を変化させます。

| 選択項目 | 影響 |
|---|---|
| 時間枠の長さと画像の幅 | アーカイブの選択と追加の統合が変化する可能性 |
| `DEF` の統合関数 | ピーク、ボトム、平均、最新値のどれを読み取るかを決定 |
| 不足している統合関数 | 一部のアイテムパスは別の関数で代替。その他は失敗する場合あり |
| `AREA` と `STACK` | 絶対的な高さと累積的な高さの違い |
| アイテムの順序 | 上書き描画、スタック順序、`GPRINT` が借用するアーカイブ |
| 基数 1000 または 1024 | 軸の目盛り表記を変更。数値自体は同一 |
| オートスケールモード、固定限界、対数スケール | Y軸を変更し、変化の大きさの視覚的印象を変化 |

グラフ間で表示が一致しない場合は、レンダリングされたコマンド、実際の物理ファイル構成、キャッシュ状態、サンプルの鮮度を比較してください。これらの表示設定の確認は有用ですが、収集、保存、マッピングのエラーを排除するものではありません。具体的な調査手順については、[不足データのトラブルシューティング](/ja/guides/troubleshoot-missing-data/)を参照してください。
