템플릿은 100번째 스위치를 추가하는 작업 부담을 2번째 스위치를 추가할 때와 동일하게 유지하기 위해 존재합니다. 네 가지 유형이 있으며 서로 계층 구조로 쌓입니다.

실질적인 작업 절차는 [템플릿 사용 및 검증](/ko/guides/template-workflow/)을 따르세요.

**데이터 템플릿**은 수집 대상과 저장 방식을 정의합니다. 필드, 해당 유형, 경계값, 스토리지 프로필 및 수치를 가져오는 입력 방법이 포함됩니다. 객체별 필드와 기존 RRD 파일은 현재 템플릿과 다를 수 있으며, 템플릿 자체가 물리적 파일 레이아웃을 보장하지는 않습니다.

**그래프 템플릿**은 그리는 방식을 정의합니다. 포함할 항목, 순서, 색상, 범례 줄 및 축 표시 내용이 여기에 해당합니다.

**디바이스 템플릿**은 하드웨어 클래스에 적합한 데이터 쿼리와 그래프 템플릿을 번들로 묶어 제공하므로 디바이스 추가 시 적절한 템플릿을 선택하는 것만으로 대부분의 작업이 완료됩니다.

**데이터 쿼리**는 항목의 수를 사전에 알 수 없는 경우를 처리합니다. 스위치에는 디바이스 조사를 통해 검색되는 여러 포트가 있으며, 데이터 쿼리는 그래프 생성을 위해 인덱싱된 결과를 기록합니다. 검색 작업 자체만으로 고정된 수의 그래프나 데이터 소스가 생성되지는 않습니다.

## 계층이 쌓이는 방식

네 가지 유형은 동일한 대상의 네 개 층위가 아닙니다. 각 항목은 계층에서 다음 항목을 가리킵니다.

| 유형 | 가리키는 대상 | 생성 결과 |
|---|---|---|
| 디바이스 템플릿 | 그래프 템플릿 및 데이터 쿼리 | 직접적인 생성물 없음. 디바이스에 제공할 항목 목록 |
| 데이터 쿼리 | 인덱싱된 결과의 그래프 정의 및 매핑 | 검색된 행. 선택된 그래프 생성 작업을 통해 데이터 소스를 생성하거나 재사용 |
| 그래프 템플릿 | 항목에 데이터가 필요한 데이터 템플릿 필드 | 여러 데이터 소스를 참조할 수 있는 그래프 |
| 데이터 템플릿 | 입력 방법 및 스토리지 프로필 | 데이터 소스 메타데이터. 쓰기 경로에서 필요로 할 때 RRD 생성 |

데이터를 포함하는 템플릿 항목은 템플릿 필드를 참조하며, 인스턴스화된 항목은 로컬 필드에 매핑됩니다. 텍스트 및 상수 항목은 데이터 소스 참조가 필요하지 않습니다. 그래프 생성 시 이러한 매핑이 확인되며, 이후 템플릿 재적용이나 항목 변경 시에도 매핑이 변경될 수 있습니다. 그래프 생성은 매번 새 파일을 만드는 대신 호환 가능한 데이터 소스를 재사용할 수 있습니다.

## 템플릿 기반 또는 객체별 독립

그래프 및 데이터 소스 수준의 많은 필드에는 템플릿 행에 대응하는 플래그가 있습니다. 해당 필드의 경우 플래그가 연결된 하위 요소로의 일반적인 전파를 제어합니다. 기타 필드, 그래프 항목 및 입력 매핑에는 별도의 전파 규칙이 적용됩니다.

| 플래그 | 의미 | 저장 시 동작 |
|---|---|---|
| 해제 | 필드가 템플릿을 따름 | 모든 하위 요소에 기록되어 기존 설정을 덮어씀 |
| 설정 | 필드가 객체별로 독립됨 | 모든 하위 요소에서 변경되지 않고 유지됨 |

플래그는 필드별로 설정됩니다. 그래프 템플릿은 축 레이블을 연결된 그래프에 전파하면서도 제목과 수직 한계값은 그래프 생성자의 설정에 남겨둘 수 있습니다. 이러한 혼합 구성은 예외가 아니라 일반적인 경우입니다.

이 설계의 두 가지 특성은 혼란을 유발하기 쉽습니다.

플래그는 템플릿에 존재하며 다음 저장 작업에서 수행할 동작만 결정합니다. 전파 작업이 이미 설정을 덮어쓴 후에 필드를 객체별 독립으로 변경해도 이전 값은 복원되지 않습니다. 기존의 개별 값은 사라졌으며 플래그는 향후의 변경만을 보호합니다.

그 반대는 더 위험합니다. 수년간 객체별로 유지되었던 필드의 플래그를 해제하면 단 한 번의 저장으로 모든 하위 요소의 해당 필드가 템플릿의 값으로 일괄 덮어써집니다. 그 값은 대개 한 번도 확인하지 않은 기본 플레이스홀더인 경우가 많습니다.

### 모든 필드에 플래그가 있는 것은 아님

필드는 해당 플래그가 존재하는 경우에만 이 메커니즘에 참여합니다. 데이터 소스 수준에서는 4개 필드에 플래그가 있으며 2개 필드에는 의도적으로 플래그가 없습니다.

| 필드 | 플래그 | 동작 |
|---|---|---|
| 이름 | 있음 | 템플릿 기반 또는 객체별 독립 |
| 활성 상태 | 있음 | 템플릿 기반 또는 객체별 독립 |
| 스텝 | 있음 | 템플릿 기반 또는 객체별 독립 |
| 스토리지 프로필 | 있음 | 템플릿 기반 또는 객체별 독립 |
| 입력 방법 | 없음 (항상 템플릿 기반으로 표시됨) | 템플릿 저장 핸들러가 연결된 데이터 소스 행을 명시적으로 업데이트 |
| RRD 파일 경로 | 없음 (절대 템플릿 기반이 아님으로 표시됨) | 일반 템플릿 전파에서 제외됨. 템플릿 재적용 시에도 기존 경로 유지 |

경로 유지는 일반적인 템플릿 변경 중에 기록 데이터와의 기존 연결을 보호합니다. 그렇다고 해서 다른 관리 작업을 통해 경로를 수정하거나 이동할 수 없다는 의미는 아닙니다. 변경하기 전에 파일 식별성을 확인하세요.

데이터 소스 항목의 필드에는 모두 플래그가 있습니다. 필드 이름, 유형, 하트비트, 최소값, 최대값 및 데이터를 제공하는 입력 필드가 포함됩니다.

## 그래프 입력은 반대 방향으로 작용

그래프 템플릿은 여러 그래프 항목을 하나의 편집 가능한 필드에 연결하는 명명된 입력을 선언할 수 있으므로 그래프에서 하나의 값을 편집하면 이를 공유하는 모든 항목이 업데이트됩니다. 이것이 단일 색상이나 범례 설정으로 연관된 항목 그룹을 제어하는 방식입니다.

전파되는 값은 템플릿의 값이 아닙니다. 입력에 속한 다른 항목의 현재 값을 읽어서 전달합니다. 따라서 그래프 입력은 템플릿에서 아래로 내려오는 대신 그래프 자체의 항목 간에 수평으로 전파되므로, 입력을 편집하면 템플릿이 직접 건드리지 않은 그래프가 변경될 수 있습니다.

## 전파 대상 및 시점

| 변경 항목 | 기존 객체에 반영 여부 | 방식 |
|---|---|---|
| 그래프 템플릿 필드(템플릿 기반) | 예, 저장 시 | 해당 템플릿 기반의 모든 그래프에 기록 |
| 그래프 템플릿 필드(객체별 독립) | 아니요 | 하위 객체가 자체 값을 유지 |
| 그래프 항목 외형 | 예, 저장 시 | 색상, 투명도, 항목 유형, 선 두께, 점선, CDEF, VDEF, 이동, 통합 함수, 정렬, 텍스트 및 범례 형식 |
| 그래프 항목 추가, 제거 또는 다른 필드로 재지정 | 작업에 따라 다름 | 일치, 추가, 삭제, 재매핑은 서로 다른 경로를 사용함. 결과 로컬 항목 매핑 확인 필요 |
| 데이터 템플릿 필드(템플릿 기반) | 예, 저장 시 | 해당 템플릿 기반의 모든 데이터 소스에 기록 |
| 데이터 템플릿 입력 필드 값 | 템플릿 기반인 경우 | 템플릿 및 하위 플래그, 쿼리 인덱스 필드, 호스트 필드 규칙이 전파를 제한 |
| 데이터 템플릿 스토리지 프로필, 스텝, 아카이브 | 데이터베이스에만 반영 | 기존 파일은 생성 시의 구조를 유지 |
| 데이터 템플릿에 추가된 필드 | 데이터베이스에만 반영 | 기존 물리적 파일에는 저장할 공간이 없음 |
| 디바이스 템플릿 내용 | 별도 동기화 필요 | 연결 설정 수정만으로는 기존의 모든 디바이스가 동기화되지 않음 |

데이터베이스 전파는 저장 경로와 재정의 규칙에 따라 달라집니다. 템플릿 메타데이터를 업데이트한다고 해서 기존 RRD 파일 자체가 자동으로 마이그레이션되지는 않습니다. 파일 관리는 별도의 작업입니다. 사용 중인 데이터 템플릿 편집기에서는 일부 구조적 설정이 읽기 전용입니다. [사용자 정의 템플릿 생성](/ko/guides/create-custom-templates/)을 참조하세요.

## 디바이스 템플릿에는 명시적인 동기화 경로가 존재

디바이스 템플릿의 연결 설정을 편집하면 새 디바이스에 제공되는 항목이 변경됩니다. 기존 디바이스는 별도의 재적용/동기화 작업을 사용합니다. 대량 처리 도구는 호출자가 중지된 디바이스를 명시적으로 포함하지 않는 한 기본적으로 Up 또는 Recovering 상태의 디바이스를 선택합니다. 모든 디바이스가 업데이트되었다고 가정하기 전에 작업 대상 범위를 확인하세요.

동기화 작업은 누락된 그래프 템플릿 연결을 추가하고, 선택한 데이터 쿼리를 새로 고치며, 더 이상 필요하지 않은 미사용 그래프 템플릿 연결을 제거할 수 있습니다. 템플릿이 디바이스 템플릿에서 제거되었다는 이유만으로 기존 그래프를 직접 삭제하지는 않습니다. 또한 자동화 및 플러그인 훅을 호출하므로 구성된 그래프 자동화 규칙이 실행될 수 있습니다.

동기화 후 결과 디바이스 연결 및 그래프를 점검하세요. 적용된 적이 있는 모든 템플릿 버전의 영구적인 합집합을 항상 유지하는 것은 아닙니다.

## 인덱스 및 포트 이동 원인

데이터 쿼리는 검색된 항목이 기존의 어떤 데이터 소스와 일치하는지 결정해야 합니다. 이것이 인덱스입니다. 하드웨어나 설정이 변경된 후 숫자 인덱스가 변경될 수 있습니다. 적절하고 안정적인 필드를 사용하면 식별성을 유지하는 데 도움이 되지만, 인터페이스 이름 역시 변경되거나 재사용될 수 있습니다. 실제 디바이스에서 고유성, 영속성 및 재인덱싱 동작을 확인하세요. 필드 이름 하나만으로 연속성이 보장되지는 않습니다.

이 결정은 내릴 당시에는 사소해 보이지만 잘못되었을 때 많은 대가를 치르게 됩니다. 또한 쿼리 전체에 대해 한 번 수행되는 것이 아니라 실행 시 디바이스별로 수행되므로 동일한 두 스위치가 서로 다른 필드를 기준으로 인덱싱될 수 있습니다. 필드 선택 방식, 인덱스 누락 시 결과, 번호 재지정 감지 비용은 [데이터 쿼리 및 인덱스](/ko/concepts/data-queries-and-indexes/)에서 다룹니다.

## 나중에 템플릿 변경하기

그래프 변경 사항은 관련 저장 및 전파가 완료된 후 후속 렌더링에 영향을 줍니다. 개별 재정의 및 이미지 캐싱이 뷰어에 표시되는 내용에 영향을 줄 수 있으므로 모든 그래프가 즉시 변경된다고 가정하지 마세요. 대표적인 하위 그래프와 해당 항목 매핑을 점검하세요. [그래프 모양 조정](/ko/guides/tune-graph-appearance/)을 참조하세요.

데이터 템플릿을 저장해도 기존 RRD 파일이 자동으로 재구성되지는 않습니다. 파일의 실제 데이터 소스 정의 및 아카이브가 데이터베이스 프로필과 일치하지 않을 수 있습니다. 유지 관리 전에 둘 다 점검하세요. 새 파일 생성은 여러 대안 중 하나일 뿐입니다.

변경 사항에 따라 지원되는 RRDtool 튜닝, 아카이브 크기 조정 또는 제어된 덤프/복원 작업을 통해 기존 기록 데이터의 일부 또는 전부를 보존할 수 있습니다. 이러한 작업에는 한계가 있으며 백업과 검증이 필요합니다. 한 번도 저장되지 않은 데이터를 복원할 수는 없습니다. 파일을 삭제하고 다시 생성하면 기록 데이터가 영구적으로 손실됩니다. [데이터 보존 관리](/ko/guides/manage-data-retention/) 및 [데이터 소스 및 라운드로빈 아카이브](/ko/concepts/data-sources-and-rras/)를 참조하세요.

## 템플릿으로 불리는 기타 요소들

다른 네 가지 객체도 이 명칭을 사용하지만 위에서 설명한 네 가지와는 다르게 작동합니다. 색상 템플릿은 그래프 항목에 적용되는 명명된 팔레트입니다. 집계 템플릿은 여러 그래프를 하나로 결합하는 방법을 설명합니다. 자동화 템플릿은 검색된 디바이스를 디바이스 템플릿에 매칭합니다. 그래프 프리셋 정의는 재사용 가능한 범례 형식을 제공합니다.

이들 중 어느 것도 여기에 설명된 스택에 속하지 않습니다. 검색 결과에서 템플릿이라는 단어가 나올 때 올바른 유형으로 해석할 수 있도록 파악해 두는 것이 유용합니다.
