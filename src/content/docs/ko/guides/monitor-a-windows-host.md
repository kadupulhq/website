SNMP를 통한 Windows는 인터페이스, 프로세서, 스토리지 및 일부 카운터를 제공합니다. 내장 Microsoft 에이전트는 net-snmp UCD 템플릿의 로드, 메모리 및 디스크 개체를 노출하지 않습니다. 에이전트가 노출하는 경우 스토리지 행에서 메모리를 플롯할 수 있습니다. 타사 에이전트는 다른 개체를 제공할 수 있습니다. 템플릿을 선택하기 전에 실제 에이전트를 검사하십시오.

## SNMP 서비스가 제공하는 항목

Windows SNMP 서비스는 더 이상 사용되지 않으며 선택 사항입니다. Windows 10 및 11의 경우 Microsoft는 선택적 기능 또는 Windows 기능을 통한 설치를 문서화합니다. 이전 DISM 기능 이름 오류 자체만으로 이를 사용할 수 없다는 증거는 아닙니다. 사용 중인 Windows 버전에 맞는 지침을 확인하십시오. [Microsoft의 SNMP 설치 가이드](https://learn.microsoft.com/en-us/troubleshoot/windows-client/networking/cannot-install-snmp-wmisnmpprovider)를 참조하십시오.

설치된 에이전트가 노출하는 하위 트리를 확인하십시오.

| 영역 | 하위 트리 | 제공 내용 |
|---|---|---|
| 시스템 | `.1.3.6.1.2.1.1` | 설명, 가동 시간(uptime), 담당자, 이름, 위치 |
| 인터페이스 | `.1.3.6.1.2.1.2` 및 `.1.3.6.1.2.1.31` | 트래픽, 오류, 상태 |
| 호스트 리소스 | `.1.3.6.1.2.1.25` | 프로세서, 스토리지, 프로세스 수, 로그인한 사용자 수 |
| LAN Manager | `.1.3.6.1.4.1.77` | Windows 서비스 및 공유 데이터 |

Kadupul에서 제공하는 Windows 템플릿은 처음 세 개 영역을 읽습니다. 제공된 세트의 어떤 항목도 LAN Manager 하위 트리를 읽지 않습니다.

호스트의 두 가지 구성 항목이 데이터 수신 여부를 결정합니다. 커뮤니티 문자열과 에이전트가 패킷을 수락하는 관리자 목록입니다. 단일 관리자 주소에서만 SNMP를 수락하도록 설정된 호스트는 해당 관리자에게만 응답하고 다른 모든 요청은 삭제합니다.

그래프를 생성하기 전에 폴러 호스트에서 각 영역을 확인하십시오. 예제 호스트와 커뮤니티를 구성된 값으로 대체하십시오. `public`은 설명 목적으로만 제공됩니다.

```bash
snmpget  -v2c -c public win.example.net .1.3.6.1.2.1.1.1.0
snmpwalk -v2c -c public win.example.net .1.3.6.1.2.1.25.3.3.1.2
snmpwalk -v2c -c public win.example.net .1.3.6.1.2.1.25.2.3.1.3
```

두 번째 walk는 프로세서 로드를 읽고, 세 번째 walk는 스토리지 설명 목록을 읽습니다. 첫 번째 명령이 작동하고 다른 두 명령이 아무것도 반환하지 않는 경우 액세스 제한, 에이전트 지원 및 반환된 SNMP 오류를 확인하십시오.

## 장치 추가

템플릿이 누락된 경우 [템플릿 가져오기 및 내보내기](/ko/guides/import-and-export-templates/)에 따라 `install/templates/Windows_Device.xml.gz`를 가져오십시오. Windows 장치 템플릿을 선택하고 쿼리 검색을 확인한 다음 원하는 그래프를 명시적으로 생성하십시오. 패키지에는 세 개의 데이터 쿼리와 관련 그래프 템플릿이 포함되어 있습니다.

| 데이터 쿼리 | 기반 | 읽는 대상 |
|---|---|---|
| SNMP - 인터페이스 통계 | `resource/snmp_queries/interface.xml` | `IF-MIB`, 직접 순회 |
| SNMP - 프로세서 정보 가져오기 | `resource/script_server/host_cpu.xml` | `scripts/ss_host_cpu.php`를 통해 `hrProcessorLoad` |
| SNMP - 마운트 지점 가져오기 | `resource/script_server/host_disk.xml` | `scripts/ss_host_disk.php`를 통해 `hrStorageTable` |

디스크 및 프로세서 쿼리는 이름에도 불구하고 스크립트 서버 쿼리입니다. 이들은 별도의 오래 실행되는 PHP 스크립트 서버 프로세스에서 실행되며 장치 레코드의 자격 증명으로 SNMP 호출을 수행합니다. 인터페이스 쿼리는 순수한 SNMP 쿼리입니다. 실질적인 결과는 실패한 PHP 스크립트 서버가 Windows에서 디스크 및 CPU 수집을 중지하는 반면 인터페이스 그래프는 계속 실행된다는 것입니다.

## 데이터 쿼리 없이 얻을 수 있는 항목

두 개의 그래프 템플릿은 각각 하나의 고정 OID를 읽습니다.

| 그래프 | OID | 저장 형식 |
|---|---|---|
| 호스트 MIB - 프로세스 수 | `.1.3.6.1.2.1.25.1.6.0` | `GAUGE` |
| 호스트 MIB - 로그인한 사용자 수 | `.1.3.6.1.2.1.25.1.5.0` | `GAUGE` |

다른 두 템플릿은 장치에서 아무것도 읽지 않습니다. 가동 시간 및 폴링 시간 그래프는 `scripts/ss_hstats.php`를 호출하고 Kadupul 자체 장치 레코드에서 열을 반환합니다. 가동 시간의 경우 `snmp_sysUpTimeInstance`, 폴링 시간의 경우 기록된 폴링 지속 시간을 반환합니다. 이들은 새로운 실시간 SNMP 응답이 아니라 저장된 측정값을 읽습니다.

## 호스트 리소스 테이블

### 프로세서

`.1.3.6.1.2.1.25.3.3.1.2` 아래의 `hrProcessorLoad`는 에이전트가 노출하는 논리 프로세서당 하나의 항목을 반환합니다. walk는 인덱스를 제공합니다. 행 수가 항상 홍보된 하드웨어 스레드 수와 일치한다고 가정하지 마십시오.

값은 이미 백분율입니다. MIB는 이를 지난 1분 동안의 평균으로 정의합니다. [Host Resources MIB 정의](https://www.rfc-editor.org/rfc/rfc2790.html)를 참조하십시오.

### 스토리지

제공된 스토리지 쿼리는 `.1.3.6.1.2.1.25.2.3.1` 아래의 `hrStorageTable`을 사용합니다. 6개 열을 읽습니다.

| 열 | OID | 방향 |
|---|---|---|
| `hrStorageIndex` | `.1.3.6.1.2.1.25.2.3.1.1` | 인덱스 |
| `hrStorageDescr` | `.1.3.6.1.2.1.25.2.3.1.3` | 인덱스 및 표시된 레이블 |
| `hrStorageAllocationUnits` | `.1.3.6.1.2.1.25.2.3.1.4` | 입력, 승수 |
| `hrStorageSize` | `.1.3.6.1.2.1.25.2.3.1.5` | 출력 |
| `hrStorageUsed` | `.1.3.6.1.2.1.25.2.3.1.6` | 출력 |
| `hrStorageAllocationFailures` | `.1.3.6.1.2.1.25.2.3.1.7` | 출력 |

크기와 사용된 공간은 바이트가 아닌 할당 단위 수입니다. 스크립트는 두 값이 모두 유효할 때 해당 인덱스에 대해 캐시된 할당 단위 크기를 각 값에 곱합니다.

Windows에서는 두 가지 문제가 자주 발생합니다.

**이 테이블은 하드 디스크 목록이 아닙니다.** 에이전트는 스토리지로 간주하는 모든 항목을 보고합니다. 에이전트에 따라 고정 드라이브와 함께 물리적 메모리와 가상 메모리가 나타날 수 있습니다. `C:\`, `D:\`, `Physical Memory`, `Virtual Memory`와 같은 레이블은 예시일 뿐이며 보장된 행이 아닙니다. 그래프로 표시할 행을 선택하십시오.

**크거나 유효하지 않은 스토리지 값은 확인이 필요합니다.** MIB는 크기와 사용량을 음수가 아닌 Integer32로 정의합니다. 음수 값을 반환하는 에이전트는 해당 범위를 벗어납니다. 현재 스크립트는 `(abs(value) + 2147483647) * allocation_units`를 사용하지만 부호 없는 32비트 재해석을 나타내지 않습니다. 영향을 받는 값을 신뢰할 수 없는 것으로 처리하고 검색을 수정한 후 다시 색인화하십시오. [스토리지 변환 결함](https://github.com/kadupulhq/kadupul/issues/243)을 참조하십시오.

## Windows와 Linux의 차이점

| 특징 | net-snmp를 사용하는 Linux | 내장 Windows 에이전트 / 제공된 템플릿 |
|---|---|---|
| 로드 애버리지 | `.1.3.6.1.4.1.2021.10.1.3` | UCD 로드 애버리지 개체 없음 |
| 메모리 | `.1.3.6.1.4.1.2021.4` | 노출된 `hrStorage` 행에서 플롯 가능 |
| CPU | UCD 백분율 또는 `hrProcessorLoad` | `hrProcessorLoad`만 해당 |
| 디스크 목록 | 사용자가 선언한 `dskTable` 또는 `hrStorage` | `hrStorage`만 해당, 필터링되지 않음 |
| 디스크 I/O | `diskIOTable` | 제공된 항목 중 이를 읽는 항목 없음 |
| 인터페이스 이름 | 커널 이름, 짧음 | 긴 어댑터 설명, 중복되는 경우가 많음 |

내장 Microsoft 에이전트는 UCD 하위 트리 `.1.3.6.1.4.1.2021`을 제공하지 않습니다. [누락된 데이터 문제 해결](/ko/guides/troubleshoot-missing-data/)을 참조하십시오.

### 인터페이스

인터페이스 쿼리는 스위치에서 사용하는 쿼리와 동일합니다. 인덱스 선호 순서는 `ifName`, `ifDescr`, `ifHwAddr`, `ifIndex` 순입니다. 검색된 각 인터페이스에서 존재하고 고유한 첫 번째 필드를 선택합니다.

Windows는 이 작업이 가장 자주 실패하는 플랫폼입니다. 동일한 두 NIC가 동일한 `ifDescr`을 반환할 수 있으며 일부 에이전트는 `ifName`을 비워 둡니다. 쿼리가 `ifIndex`로 대체되면 인터페이스 기록은 Windows가 자유롭게 재할당할 수 있는 번호에 연결됩니다.

[스위치 모니터링](/ko/guides/monitor-a-switch/) 및 [데이터 쿼리 및 인덱스](/ko/concepts/data-queries-and-indexes/)를 참조하십시오.

## SNMP를 사용할 수 없을 때

많은 Windows 설치 환경에는 SNMP 서비스가 활성화되어 있지 않습니다. 대체 방법은 스크립트 입력입니다.

두 가지 사실이 스크립트 작성 방법을 결정합니다.

**스크립트는 폴러가 실행 중인 시스템에서 실행됩니다.** Windows 호스트에 도달하는 것은 스크립트의 역할입니다. WinRM, 에이전트, HTTP 끝점, 공유 또는 운영 중인 모든 메커니즘을 사용할 수 있습니다.

**표준 출력으로 측정값을 내보냅니다.** PHP 폴러의 외부 명령 경로는 종료 상태를 측정값으로 사용하지 않습니다. 숫자를 출력하거나 이 주기에 측정값이 없는 경우 `U`를 출력하십시오. 측정이 실패했음을 알리려는 경우 `0`을 출력하지 마십시오.

단일 숫자 대신 인터페이스별, 디스크별 또는 서비스별 값이 필요한 경우 동일한 스크립트 메커니즘이 인덱싱된 형식을 제공합니다. `resource/script_queries/host_cpu.xml`은 스크립트 서버 대신 PHP 스크립트를 호출하는 실용적인 예입니다.

출력 계약 및 명명 제약 조건에 대해서는 [데이터 수집 스크립트 작성](/ko/guides/write-a-data-collection-script/)을 참조하십시오.

## 실패 모드

| 증상 | 흔한 원인 |
|---|---|
| 시스템 설명은 읽히지만 다른 것은 수집되지 않음 | 개체 지원, 액세스 제한 및 특정 SNMP 오류 확인 |
| 온라인 상태인 호스트로부터 전혀 응답이 없음 | 에이전트의 허용된 관리자 목록 또는 UDP 161 포트의 호스트 방화벽 규칙 |
| 파티션 목록에 메모리가 포함됨 | 정상 동작. 에이전트가 메모리를 스토리지로 보고함 |
| 대용량 볼륨이 음수 또는 알 수 없음으로 표시됨 | 잘못된 에이전트 값 또는 오래된 할당 단위. 알려진 버그 확인 |
| 디스크 및 CPU는 중지되고 인터페이스는 계속 실행됨 | 스크립트 서버 오류. 인터페이스 쿼리는 이를 사용하지 않음 |
| Net-snmp 템플릿이 할당되었지만 모든 측정값이 unknown | 선택한 에이전트가 해당 템플릿에 필요한 UCD 개체를 제공하지 않음 |
| 변경 후 인터페이스 기록이 잘못된 어댑터를 추적함 | 이름이 비어 있거나 중복되어 인덱스가 `ifIndex`로 대체됨 |
| 가동 시간이 이전 값을 반복함 | 장치 레코드가 오래되었는지 확인. 도우미는 가동 시간을 외삽하지 않음 |
