:::caution[ব্যবহারের পূর্বে যাচাই করুন]
উৎস কোড উপলব্ধ, তবে কোনো সমর্থিত Kadupul রিলিজ বা মাইগ্রেশন পাথ নেই। এগুলির উপর নির্ভর করার আগে ব্যাকআপ সহ একটি বিচ্ছিন্ন অনুলিপিতে এই পদ্ধতিগুলি পরীক্ষা করুন। [প্রকল্পের অবস্থা](/bn/project/status/) দেখুন।
:::

সরবরাহকৃত ESXi প্যাকেজ হোস্ট পরিমাপ এবং গেস্ট ইনভেন্টরি গণনা সংগ্রহ করে। এটি প্রতি-গেস্ট CPU, মেমরি বা সংঘাত পরিমাপ প্রদান করে না। গ্রাফ নির্বাচন করার আগে আপনার হাইপারভাইজার সংস্করণ দ্বারা উন্মুক্ত অবজেক্টগুলি যাচাই করুন।

## যা সরবরাহ করা হয়

একটি হাইপারভাইজার ডিভাইস টেমপ্লেট সরবরাহ করা হয়েছে: **ESXi Device**। এটি একটি ডিভাইস প্যাকেজ, তাই `install/templates/ESXi_Device.xml.gz`-এ এর স্ক্রিপ্ট এবং ডেটা-কোয়েরি ফাইলগুলি রয়েছে। [টেমপ্লেট আমদানি ও রপ্তানি করুন](/bn/guides/import-and-export-templates/) অনুসরণ করুন এবং ফাইল মোতায়েন সহ আমদানি সম্পন্ন হয়েছে কিনা তা যাচাই করুন। ডিভাইস টেমপ্লেট নির্বাচন করুন, আবিষ্কার পরীক্ষা করুন এবং পছন্দসই গ্রাফগুলি স্পষ্টভাবে তৈরি করুন; কেবল প্যাকেজ আমদানি করা বা একটি ডিভাইস টেমপ্লেট সংযুক্ত করা সেগুলি তৈরি করে না।

| যা সরবরাহ করা হয় | উদ্দেশ্য |
|---|---|
| `resource/snmp_queries/esxi_cpu.xml` | প্রসেসর আবিষ্কার করে এবং প্রতি-প্রসেসর লোড পড়ে |
| `resource/snmp_queries/esxi_hw.xml` | হার্ডওয়্যার উপাদান আবিষ্কার করে এবং তাদের স্থিতি পড়ে |
| `resource/snmp_queries/interface.xml` | স্ট্যান্ডার্ড ইন্টারফেস পরিসংখ্যান কোয়েরি |
| `resource/script_server/host_disk.xml` | Host Resources স্টোরেজ টেবিলের মাধ্যমে মাউন্ট করা পার্টিশন |
| `scripts/ss_esxi_vhosts.php` | `install/templates/ESXi_Device.xml.gz`-এর মধ্যে বান্ডিল করা; গেস্ট সংখ্যা, চালিত গেস্ট এবং গেস্ট টুলের অবস্থা গণনা করে |
| `scripts/ss_multicpu_avg.php` | প্রতি-প্রসেসর লোডকে একটি সংখ্যায় গড় করে |
| `scripts/ss_hstats.php` | ডিভাইসের জন্য Kadupul ইতিমধ্যে ধরে রাখা পোলিং পরিসংখ্যান পড়ে |
| `scripts/ss_host_disk.php` | পার্টিশন কোয়েরি সমর্থন করে |

এই চেকআউটে Hyper-V, KVM/libvirt, Xen বা Proxmox-এর জন্য কোনো ডেডিকেটেড ডিভাইস প্যাকেজ সরবরাহ করা হয় না। জেনেরিক Linux/Windows টেমপ্লেট তাদের এজেন্টদের দ্বারা সমর্থিত হোস্ট মেট্রিক্স কভার করতে পারে; হাইপারভাইজার-নির্দিষ্ট সংগ্রহের জন্য উপযুক্ত টেমপ্লেট এবং সংগ্রাহক প্রয়োজন। [একটি ডেটা সংগ্রহের স্ক্রিপ্ট লিখুন](/bn/guides/write-a-data-collection-script/) দেখুন।

## প্রথমে এজেন্ট চালু করুন

বিদ্যমান এজেন্ট কনফিগারেশন পর্যালোচনা করুন এবং আপনার ESXi সংস্করণের নির্দেশাবলী ব্যবহার করুন। প্যাকেজ নোটগুলির মধ্যে একটি ফ্যাক্টরি রিসেট অন্তর্ভুক্ত রয়েছে; এটি কোনো নিয়মিত পূর্বশর্ত নয় এবং বিদ্যমান SNMP কনফিগারেশন মুছে ফেলবে। একটি কমিউনিটি-ভিত্তিক সেটআপের জন্য, নিম্নলিখিত কমান্ডগুলি এজেন্ট মান সেট করে; উদাহরণগুলি প্রতিস্থাপন করুন এবং কমিউনিটি তালিকা সেট করার সময় যেকোনো প্রয়োজনীয় বিদ্যমান কমিউনিটি সংরক্ষণ করুন।

```bash
esxcli system snmp get
esxcli system snmp set -c YOUR_STRING
esxcli system snmp set -p 161
esxcli system snmp set -L "City, State, Country"
esxcli system snmp set -C noc@example.com
esxcli system snmp set -e yes
```

প্রথম কমান্ডটি কনফিগারেশন প্রদর্শন করে; শেষ কমান্ডটি এজেন্টকে সক্ষম করে। কমিউনিটি বিকল্পটি এর কনফিগার করা তালিকাকে প্রতিস্থাপন করে। পোলার থেকে প্রয়োজনীয় ফায়ারওয়াল অ্যাক্সেস পরীক্ষা করুন এবং [ESXCLI SNMP কমান্ড রেফারেন্স](https://developer.broadcom.com/xapis/esxcli-command-reference/latest/namespace/esxcli_system.html) দেখুন। এই কমান্ডগুলি কমিউনিটি-ভিত্তিক পোলিং কনফিগার করে; সেগুলি SNMPv3 কনফিগার করে না। ডিভাইস যোগ করার আগে পোলার যে মেশিনে চলে সেখান থেকে যাচাই করুন।

```bash
snmpget  -v2c -c YOUR_STRING esxi.example.net .1.3.6.1.2.1.1.1.0
snmpwalk -v2c -c YOUR_STRING esxi.example.net .1.3.6.1.2.1.25.3.3.1.2
snmpwalk -v2c -c YOUR_STRING esxi.example.net .1.3.6.1.4.1.6876.2.1.1.6
```

প্রথমটি কাজ করলে এবং তৃতীয়টি কিছুই না ফেরালে, SNMP ত্রুটি, অ্যাক্সেস নীতি এবং এজেন্ট সমর্থন পরীক্ষা করুন; কেবল একটি খালি ওয়াক কারণ চিহ্নিত করে না। বান্ডিল করা গেস্ট স্ক্রিপ্টটি SNMPv1 ব্যবহার করে, তাই একটি সফল v2c প্রোব এর সংগ্রহ পথকে যাচাই করে না। খালি গেস্ট ওয়াক শূন্য গণনা তৈরি করে, অপরিহার্যভাবে গ্রাফ ফাঁক নয়; [খালি-ফলাফল বাগ](https://github.com/kadupulhq/kadupul/issues/245) দেখুন।

## হোস্ট যা প্রকাশ করে

|---|---|---|
| প্রসেসর | `.1.3.6.1.2.1.25.3.3.1` | এজেন্ট দ্বারা উন্মুক্ত প্রতিটি প্রসেসরের জন্য লোড |
| হার্ডওয়্যার উপাদান | `.1.3.6.1.2.1.25.3.2.1` | উপাদানের সূচক, বিবরণ এবং স্থিতি |
| স্টোরেজ | `.1.3.6.1.2.1.25.2.3.1` | ডেটাস্টোর এবং স্থানীয় ফাইল সিস্টেম, যেভাবে এজেন্ট রিপোর্ট করতে বেছে নেয় |
| ইন্টারফেস | `.1.3.6.1.2.1.2` এবং `.1.3.6.1.2.1.31` | ট্র্যাফিক, ত্রুটি, স্থিতি |
| গেস্ট ইনভেন্টরি | `.1.3.6.1.4.1.6876` | প্রতি-গেস্ট পাওয়ার অবস্থা এবং গেস্ট টুলের অবস্থা |

প্রথম চারটি হলো স্ট্যান্ডার্ড Host Resources এবং ইন্টারফেস টেবিল, যা একটি Linux হোস্টও উত্তর দেয়। সেগুলি কীভাবে আচরণ করে এবং কোন ডিস্ক টেবিলটি পছন্দ করবেন তার জন্য [একটি লিনাক্স সার্ভার পর্যবেক্ষণ করা](/bn/guides/monitor-a-linux-server/) দেখুন।

পঞ্চমটি হলো বিক্রেতার সাবট্রি যা সরবরাহকৃত গেস্ট-গণনা স্ক্রিপ্ট দ্বারা ব্যবহৃত হয়।

## গ্রাফ টেমপ্লেট

| গ্রাফ | উৎস | যা পড়ে |
|---|---|---|
| ESXi - CPU | ডেটা কোয়েরি | একটি আবিষ্কৃত প্রসেসরের লোড |
| ESXi - MultiCPU Average | স্ক্রিপ্ট | প্রতিটি প্রসেসরের লোডের গড় |
| ESXi - Hardware | ডেটা কোয়েরি | একটি আবিষ্কৃত উপাদানের স্থিতি |
| ESXi - VHosts | স্ক্রিপ্ট | গেস্ট সংখ্যা এবং গেস্ট টুলের স্থিতি |
| Host MIB - Processes | নির্দিষ্ট OID | হোস্টে প্রসেসের সংখ্যা |
| Host MIB - Logged in Users | নির্দিষ্ট OID | হোস্টে সেশনের সংখ্যা |
| Device - Uptime | স্ক্রিপ্ট | Kadupul দ্বারা শেষ রেকর্ড করা আপটাইম |
| Device - Polling Time | স্ক্রিপ্ট | এই ডিভাইসটি পোল করতে Kadupul-এর কত সময় লেগেছে |
| ইন্টারফেস গ্রাফ | ডেটা কোয়েরি | প্রতি ইন্টারফেসে ট্র্যাফিক, ত্রুটি, প্যাকেট, স্থিতি |

প্রসেসর কোয়েরি প্রতি আবিষ্কৃত এন্ট্রির লোড পড়ে। ধরে নেবেন না যে এর সারির সংখ্যা হোস্টের হার্ডওয়্যার থ্রেড গণনার সাথে মেলে: প্যাকেজ করা সূচক প্যাটার্ন শুধুমাত্র এক বা দুই অঙ্কের সূচক গ্রহণ করে এবং 100 বা তার বেশি প্রত্যাখ্যান করে, এমনকি কয়েকটি CPU সহ হোস্টে। আবিষ্কারকে র ওয়াকের সাথে তুলনা করুন; [CPU-সূচক বাগ](https://github.com/kadupulhq/kadupul/issues/246) দেখুন। গড় স্ক্রিপ্ট স্বাধীনভাবে প্রসেসর লোড স্ক্যান করে এবং প্রত্যাবর্তিত সারিগুলি গড় করে।

Device - Uptime এবং Device - Polling Time Kadupul-এর সংরক্ষিত ডিভাইস রেকর্ড পড়ে। আপটাইম হেল্পার অতিবাহিত সময় অনুমান না করে সংরক্ষিত SNMP আপটাইম ফেরত দেয়; পোলিং সময় Kadupul-এর সংগ্রহের কাজকে বর্ণনা করে। একটি পুরানো সংরক্ষিত মান বর্তমান নাগালযোগ্যতা প্রমাণ করে না। সংগ্রহ বন্ধ হলে এই সহায়কগুলি নতুন নমুনা তৈরি করে না।

## গণনার সমস্যা

এই অংশটি ভার্চুয়ালাইজেশনকে একটি ফিজিক্যাল সার্ভার থেকে আলাদা করে তোলে, এবং এর কোনোটিই একটি গ্রাফ টেমপ্লেট দ্বারা সমাধান করা যায় না।

**গেস্ট স্থানান্তরিত হয়।** অন্য হোস্টে স্থানান্তরিত হওয়া একটি গেস্ট প্রথম হোস্টের ইনভেন্টরি থেকে অদৃশ্য হয়ে যায় এবং দ্বিতীয় হোস্টে উপস্থিত হয়। স্বাধীনভাবে সময়যুক্ত নমুনাগুলি সাময়িকভাবে সেই গেস্টকে দ্বিগুণ গণনা করতে পারে বা বাদ দিতে পারে। একা গণনা পরিবর্তন মাইগ্রেশন প্রমাণ করে না: তাদের ব্যাখ্যা করতে হাইপারভাইজার ইনভেন্টরি পরিচয় এবং ইভেন্টগুলি ব্যবহার করুন।

**সম্পদ ভাগ করা হয়, তাই প্রতি-গেস্ট বণ্টন একটি অনুমান।** হোস্ট ফিজিক্যাল প্রসেসরের লোড রিপোর্ট করে। এটি রিপোর্ট করে না কোন গেস্ট এটি সৃষ্টি করেছে। হোস্ট CPU-কে গেস্ট সংখ্যা দ্বারা ভাগ করলে এমন একটি সংখ্যা তৈরি হয় যা গাণিতিকভাবে সঠিক এবং কেউ জিজ্ঞাসা করেনি এমন প্রশ্নের উত্তর দেয়।

**ওভারকমিট বরাদ্দ এবং ব্যবহারকে ভিন্ন পরিমাণে পরিণত করে।** নির্ধারিত ভার্চুয়াল CPU ইচ্ছাকৃতভাবে ফিজিক্যাল কোর অতিক্রম করতে পারে এবং নির্ধারিত মেমরি ইচ্ছাকৃতভাবে ফিজিক্যাল মেমরি অতিক্রম করতে পারে। নির্ধারিত সম্পদের একটি গ্রাফ পরিমাপ করা চাহিদার পরিবর্তে বরাদ্দকে বর্ণনা করে। এটিকে শারীরিক ক্ষমতা, কনফিগার করা সীমা এবং প্রকৃত ব্যবহারের সাথে তুলনা করুন।

**এই টেবিলগুলিতে সংঘাত (Contention) প্রদর্শিত হয় না।** পরিমাপ যা আপনাকে বলে যে একটি গেস্ট ক্ষুধার্ত, ফিজিক্যাল প্রসেসরের জন্য অপেক্ষার সময় এবং হোস্ট তার কাছ থেকে পুনরুদ্ধার করা মেমরি, এই টেমপ্লেট যা সংগ্রহ করে তার মধ্যে নেই। তীব্র সংঘাতের গেস্ট সহ 60 শতাংশ CPU-র একটি হোস্ট সুখী গেস্ট সহ 60 শতাংশ CPU-র একটি হোস্টের মতোই এখানে অভিন্ন দেখায়।

**গেস্ট এবং হোস্ট পরিমাপ বিভিন্ন প্রশ্নের উত্তর দেয়।** শুধুমাত্র গেস্ট ব্যবহার হোস্টের সময় নির্ধারণের বিলম্ব ব্যাখ্যা করতে নাও পারে। হোস্ট লোড থেকে বণ্টন অর্জন করার পরিবর্তে হাইপারভাইজার সংঘাত মেট্রিক্সের সাথে গেস্ট/অ্যাপ্লিকেশন পরিমাপের সম্পর্কযুক্ত করুন।

### বিকল্প পদক্ষেপ

| প্রশ্ন | উত্তর যেখানে রয়েছে |
|---|---|
| হোস্ট কি সম্পৃক্ত | হোস্ট প্রসেসর লোড, হোস্ট থেকে |
| গেস্ট কি সম্পৃক্ত | গেস্টের ভিতরে, সাথে হাইপারভাইজারের সংঘাত মেট্রিক |
| কতগুলি গেস্ট চলছে | হোস্ট গেস্ট ইনভেন্টরি, গণনা হিসাবে |
| এস্টেট কি ক্ষমতার বাইরে | এই গ্রাফ থেকে নয়। এটির জন্য প্লেসমেন্ট ডেটা প্রয়োজন যা হোস্ট প্রকাশ করে না |
| গেস্ট কি স্থানান্তরিত হয়েছে | হাইপারভাইজার ইনভেন্টরি পরিচয় এবং মাইগ্রেশন ইভেন্ট; একা গণনা পদক্ষেপ যথেষ্ট নয় |

গেস্ট সম্পর্কিত যেকোনো কিছুর জন্য গেস্টকে তাদের নিজস্ব ডিভাইস হিসাবে পর্যবেক্ষণ করুন এবং হোস্টের যেকোনো কিছুর জন্য হোস্টকে পর্যবেক্ষণ করুন। হোস্ট-স্তরের সংখ্যা থেকে প্রতি-গেস্ট গ্রাফ তৈরি করা প্রতিরোধ করুন: সেগুলি উদ্ভূত, সেগুলি প্রামাণিক মনে হয়, এবং সেগুলি এমনভাবে ভুল যা পরে কেউ ধরতে পারে না।

## সরবরাহকৃত গেস্ট গণনার ফাঁদ

গেস্ট ইনভেন্টরি স্ক্রিপ্টের আউটপুটের উপর নির্ভর করার আগে এটি বোঝা মূল্যবান।

**এটি কেবল SNMP সংস্করণ 1 এবং কমিউনিটি স্ট্রিং দিয়ে স্ক্যান করে।** সংস্করণটি স্ক্রিপ্টে নির্ধারিত এবং ডিভাইসের v3 শংসাপত্র পাস করা হয় না। v3-এর জন্য কনফিগার করা একটি ডিভাইস অন্যান্য পাথের মাধ্যমে সংগ্রহ করতে পারে যখন গেস্ট সংগ্রহ ব্যর্থ হয়। গেস্ট সংগ্রহ এখনও সফল হতে পারে যদি সেই এজেন্ট স্বাধীনভাবে v1-এ সংরক্ষিত কমিউনিটি গ্রহণ করে; ডিভাইসে v3 নির্বাচন করা নিজেই ফলাফল নির্ধারণ করে না। খালি গেস্ট ওয়াক শূন্য হিসাবে ফেরত দেওয়া হয়। সহায়ককে সামঞ্জস্য করার জন্য এজেন্টের নিরাপত্তা নীতি ডাউনগ্রেড না করে এই প্রোটোকল অমিল পরীক্ষা করুন।

**গণনা পাওয়ার স্থিতি টেবিল থেকে আসে।** গেস্ট মোট হিসাবে রিপোর্ট করা সংখ্যাটি পাওয়ার স্টেট সাবট্রির একটি ওয়াক দ্বারা প্রত্যাবর্তিত এন্ট্রি সংখ্যা, কোনো পৃথক ইনভেন্টরি অবজেক্টের নয়। একটি গেস্ট যা হোস্ট তালিকাভুক্ত করে কিন্তু যার কোনো পাওয়ার স্টেট এন্ট্রি নেই তা গণনা করা হয় না।

**পাওয়ার্ড-অন স্থিতির টেক্সটের সাথে মিলানো হয়।** ট্রিম এবং ছোট হাতের অক্ষরে রূপান্তরের পরে, শুধুমাত্র `powered on` এবং `poweredon` চলমান গণনা বৃদ্ধি করে। অন্যান্য উপস্থাপনা তা করে না; শূন্য ব্যাখ্যা করার আগে এজেন্টের অপরিবর্তিত প্রতিক্রিয়া তুলনা করুন।

**গেস্ট টুলস শ্রেণিবিন্যাসে একটি নিশ্চিত ত্রুটি রয়েছে।** আক্ষরিক `not installed` চলমান হিসাবে গণনা করা হয় কারণ এর মিল অফসেট শূন্য থেকে শুরু হয়। অচেনা টেক্সটও চলমান অবস্থায় পড়ে। সেই গণনাটিকে সুস্থ টুলের প্রমাণ হিসাবে বিবেচনা করবেন না; [টুলস-স্থিতি বাগ](https://github.com/kadupulhq/kadupul/issues/244) দেখুন।

**এটি প্রতি কলে তিনবার ওয়াক করে।** এটি পাওয়ার-স্টেট টেবিল দুবার পড়ে, তারপর টুলস টেবিল, তাই এর নিজস্ব গণনাও একটি পারমাণবিক ইনভেন্টরি স্ন্যাপশট নয়। অনেক গেস্ট সহ হোস্টে, সেই সংগ্রহের খরচ পরিমাপ করুন। যদি পোলার কঠোর চাপে থাকে, তবে থ্রেড বাড়ানোর আগে এটি একটি দীর্ঘ ব্যবধানের প্রার্থী। [পোলার স্কেল করুন](/bn/guides/scale-the-poller/) দেখুন।

স্ক্রিপ্টটি সাধারণত খালি ওয়াকের জন্য শূন্য সহ পাঁচটি নামযুক্ত মান নির্গত করে। একটি ব্যর্থ ওয়াক তাই সিনট্যাক্সগতভাবে সম্পূর্ণ কিন্তু বিভ্রান্তিকর নমুনা তৈরি করতে পারে। অসম্পূর্ণ আউটপুটের জন্য, PHP আউটপুট প্রসেসর সংশ্লিষ্ট ডেটা উৎসের প্রয়োজনীয় ক্ষেত্রগুলি পরীক্ষা করে এবং অসম্পূর্ণ টাইমস্ট্যাম্প গোষ্ঠী আটকে রাখে; এটি অপরিহার্যভাবে তাৎক্ষণিকভাবে তাদের বাতিল করে না। [পোলার ক্যাশ](/bn/concepts/the-poller-cache/) দেখুন।

## বাকি অংশের ফাঁদ

**প্রসেসর গড় ভারসাম্যহীনতা গোপন করে।** একটি পিন করা কোর এবং 63টি নিষ্ক্রিয় কোর সহ একটি হোস্টের গড় কম থাকে। যেখানে এটি গুরুত্বপূর্ণ সেখানে যাচাইকৃত প্রতি-প্রসেসর গ্রাফ রাখুন। গড় সহায়ক খালি ওয়াকের জন্য `load:0` ফেরত দেয়, যা পরিমাপ করা নিষ্ক্রিয় CPU থেকে আলাদা করা যায় না; সংগ্রহের অবস্থা এবং পরিচিত খালি-ফলাফল বাগের সাথে এটি সম্পর্কযুক্ত করুন।

**প্রসেসর সূচকগুলি অবস্থানগত।** সেগুলি প্রসেসর টেবিল স্ক্যান করে আবিষ্কৃত হয়। এজেন্টের সূচক পরিবর্তন হলে, ধারাবাহিকতা বিশ্বাস করার আগে পরিচয়ের ম্যাপিং যাচাই করুন। প্যাকেজ করা এক/দুই অঙ্কের সীমাবদ্ধতা একটি পৃথক আবিষ্কারের ত্রুটি।

**স্টোরেজ এন্ট্রি হলো এজেন্ট যাকে স্টোরেজ বলে।** এমন বরাদ্দ ইউনিটে অবাঞ্ছিত জিনিসের সাথে মিশ্রিত ডেটাস্টোর প্রত্যাশা করুন যা গুণ করা প্রয়োজন। এটি Host Resources-এর আচরণ, কোনো ESXi খামখেয়ালী নয়। বাইট ব্যাখ্যা করার আগে ক্যাশ করা বরাদ্দ ইউনিট যাচাই করুন; অবৈধ ঋণাত্মক নমুনা বা অনুপস্থিত গুণকের জন্য শেয়ার্ড স্ক্রিপ্টে একটি [পরিচিত রূপান্তর ত্রুটি](https://github.com/kadupulhq/kadupul/issues/243) রয়েছে।

**হাইপারভাইজারে ইন্টারফেসের নাম স্থিতিশীল থাকে যতক্ষণ না সেগুলি পরিবর্তিত হয়।** একটি ড্রাইভার আপডেট বা একটি পুনর্গঠন সেগুলিকে পুনরায় নম্বর দিতে পারে। সূচক কীভাবে বেছে নেওয়া হয় এবং কেন এটি গুরুত্বপূর্ণ তার জন্য [একটি সুইচ পর্যবেক্ষণ করা](/bn/guides/monitor-a-switch/) দেখুন।

**স্ক্রিপ্টগুলি পোলার হোস্টে চলে।** সেগুলি ক্যাশ করা কমান্ড দ্বারা পাস করা ডিভাইস ID ব্যবহার করে নিজেরাই হাইপারভাইজারে পৌঁছায়। গেস্ট এবং CPU-গড় সহায়ক প্রতিটি কলে বর্তমান ডিভাইস সারি আনে; একটি কমিউনিটি পরিবর্তনের জন্য সেই কমান্ডের যুক্তি পুনর্নির্মাণের প্রয়োজন হয় না। অন্যান্য সংগ্রাহক তাদের কাজের আইটেমে শংসাপত্র এম্বেড করতে পারে। [পোলার ক্যাশ](/bn/concepts/the-poller-cache/) দেখুন।
