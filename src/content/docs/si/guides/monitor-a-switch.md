ප්‍රභව කේතය ලබා ගත හැකි නමුත් සහය දක්වන Kadupul නිකුතුවක් හෝ සංක්‍රමණ මාර්ගයක් නොමැත. මේවා මත විශ්වාසය තැබීමට පෙර උපස්ථ සහිත හුදකලා පිටපතක මෙම ක්‍රියා පටිපාටි පරීක්ෂා කරන්න. [ව්‍යාපෘති තත්ත්වය](/si/project/status/) බලන්න.
:::

ස්විචය යනු දත්ත විමසුම් සඳහා සම්භාව්‍ය භාවිත අවස්ථාවයි. කොපමණ පෝට් ප්‍රමාණයක් තිබේදැයි ඔබ කලින් නොදනී, ගණන වෙනස් විය හැකි අතර සෑම පෝට් එකකටම තමන්ගේම දත්ත ප්‍රභවයක් අවශ්‍ය වේ. දත්ත විමසුම් ක්‍රියා කරන ආකාරය සඳහා [සැකිලි](/si/concepts/templates/) බලන්න; මෙම පිටුව නිවැරදි සැකසුම ගැන සාකච්ඡා කරයි.

## ඔබ ආරම්භ කිරීමට පෙර

වඩාත් සුදුසු වන්නේ poller පරිශීලකයා යටතේ, පවරා ඇති එකතුකරන්නාගෙන් උපාංගය ප්‍රතිචාර දක්වන බවට සහතික වන්න. ඔබගේ වින්‍යාසගත කියවීමට පමණක් ඇති අක්තපත්‍ර භාවිතා කරන්න. සංඛ්‍යාත්මක OID දේශීයව ස්ථාපිත MIB නම් මත යැපීම වළක්වයි.

```bash
snmpwalk -v2c -c 'your-read-only-community' switch.example.net .1.3.6.1.2.1.31.1.1.1.1
```

SNMP v2c හෝ v3 භාවිතා කරන්න. 64-බිට් අතුරුමුහුණත් ගණක යනු SMIv2 වස්තු වන අතර ඒවා v1 හරහා විමසිය නොහැක. v1 උපාංගයක් ඔබට ලබා දෙන්නේ 32-බිට් ගණක පමණක් වන අතර වෙන කිසිවක් නොවේ.

## උපාංග සැකිල්ලක් තෝරා ගැනීම

ඔබ උපාංගය එක් කරන විට පිරිනමනු ලබන දත්ත විමසුම් සහ ප්‍රස්ථාර සැකිලි මොනවාදැයි උපාංග සැකිල්ල මඟින් තීරණය කරයි. Kadupul සාමාන්‍ය SNMP උපාංග සැකිල්ලක් සහ විකුණුම්කරුට විශේෂිත වූ සැකිලි කට්ටලයක් ඇතුළත් Cacti විසින් සපයන ලද සැකිලි කට්ටලය උරුම කර ගනී.

ඔබ කුමක් තෝරා ගත්තද පෝට් සොයා ගැනීම පැමිණෙන්නේ එකම මූලාශ්‍රයකිනි: `resource/snmp_queries/interface.xml` හි අර්ථ දක්වා ඇති අතුරුමුහුණත් දත්ත විමසුම. කිසිදු සැකිල්ලක් ඔබේ දෘඩාංගයට නොගැලපේ නම්, සාමාන්‍ය සැකිල්ල තෝරා අතුරුමුහුණත් විමසුම එයට සම්බන්ධ කරන්න.

## දත්ත විමසුම ක්‍රියාත්මක කිරීම

විමසුම පෝට් සෙවීම සඳහා `ifIndex` හරහා ගමන් කරන අතර, කොපමණ ප්‍රමාණයක් අපේක්ෂා කළ යුතු දැයි දැන ගැනීමට `ifNumber` කියවයි. ඉන්පසු එය පෝට් එකකට ක්ෂේත්‍ර කට්ටලයක් එකතු කරයි.

| ක්ෂේත්‍රය | OID | මේ සඳහා භාවිතා වේ |
|---|---|---|
| `ifIndex` | `.1.3.6.1.2.1.2.2.1.1` | SNMP වගුවේ පිහිටීම |
| `ifName` | `.1.3.6.1.2.1.31.1.1.1.1` | කෙටි පෝට් නම, `Gi1/0/3` |
| `ifDescr` | `.1.3.6.1.2.1.2.2.1.2` | දිගු විස්තරය |
| `ifAlias` | `.1.3.6.1.2.1.31.1.1.1.18` | ඔබ වින්‍යාස කරන අතුරුමුහුණත් විස්තරය |
| `ifHwAddr` | `.1.3.6.1.2.1.2.2.1.6` | පෝට් MAC ලිපිනය |
| `ifSpeed` | `.1.3.6.1.2.1.2.2.1.5` | තත්පරයට බිටු වේගය, 32-බිට් |
| `ifHighSpeed` | `.1.3.6.1.2.1.31.1.1.1.15` | තත්පරයට Mbits වේගය |
| `ifOperStatus` | `.1.3.6.1.2.1.2.2.1.8` | Up හෝ Down |
| `ifInOctets` / `ifOutOctets` | `.1.3.6.1.2.1.2.2.1.10` / `.16` | 32-බිට් බයිට් ගණක |
| `ifHCInOctets` / `ifHCOutOctets` | `.1.3.6.1.2.1.31.1.1.1.6` / `.10` | 64-බිට් බයිට් ගණක |

උපාංගය මත එක් වරක් විමසුම ක්‍රියාත්මක කරන්න. එය සොයාගත් පෝට් වල වගුවක් ලබා දෙනු ඇත. ප්‍රස්ථාර සෑදීමට පෙර මෙම වගුව කියවන්න, මන්ද එය පසුකාලීන සෑම තීරණයකටම පදනම සපයයි.

## 64-බිට් ගණක තෝරා ගැනීම

අතුරුමුහුණත් විමසුම රථවාහන ප්‍රස්ථාර සැකිලි කිහිපයක් ඉදිරිපත් කරයි. ප්‍රධාන ඒවා:

| ප්‍රස්ථාර සැකිල්ල | කියවන්නේ |
|---|---|
| In/Out Bits | `ifInOctets`, `ifOutOctets` |
| In/Out Bits (64-bit) | `ifHCInOctets`, `ifHCOutOctets` |
| In/Out Bits (64-bit, 95th) | එකම, 95 වන ප්‍රතිශතක රේඛාවක් සහිතව |
| In/Out Bits (64-bit, BW) | එකම, අතුරුමුහුණත් වේගයට සාපේක්ෂව |
| Status (Up/Down) | `ifOperStatus` |
| In/Out (Errors/Discards) | `ifInErrors`, `ifInDiscards`, `ifOutDiscards`, `ifOutErrors` |

එසේ නොකිරීමට ඔබට නිශ්චිත හේතුවක් නොමැති නම් 64-බිට් සැකිල්ලක් භාවිතා කරන්න. 32-බිට් ඔක්ටෙට් ගණකයක් 4294967295 දී සීමා වේ. පූර්ණ භාරයක් යටතේ ඇති ගිගාබිට් පෝට් එකක් තත්පර 34 කින් පමණ එය පුරවයි. තත්පර 300 ක පියවරකදී, එක් පිටාර ගැලීමක් පිටාර ගැලීම් හතකින් වෙන්කර හඳුනා ගැනීමට poller හට නොහැකි වන අතර, `COUNTER` මඟින් නිවැරදි කරන්නේ සාම්පල දෙකක් අතර තනි පිටාර ගැලීමක් පමණි. ප්‍රස්ථාරය කැඩී ඇති බවක් නොපෙනේ; එය සදහටම ඉතා අඩු අගයන් පෙන්වයි.

සිය ගණනක් ප්‍රස්ථාර සෑදීමට පෙර ගණක සැබවින්ම පිරී ඇත්දැයි තහවුරු කරන්න.

```bash
snmpwalk -v2c -c 'your-read-only-community' switch.example.net .1.3.6.1.2.1.31.1.1.1.6
```

හිස් හෝ අසමත් වූ walk එකක් විමර්ශනය අවශ්‍ය වේ: වාර්තා වූ දෝෂය, ප්‍රවේශ දසුන සහ නියෝජිත සහාය පරීක්ෂා කරන්න.

## වේග වෙනස්වීම් වලින් පසු ගබඩා කර ඇති උපරිමය පරීක්ෂා කිරීම

දත්ත ප්‍රභවය විමසුම් වේගය මත පදනම්ව උපරිමයක් භාවිතා කරන විට, නිර්මාණය මඟින් හැඹිලිගත සොයාගැනීමේ දත්ත වලින් වේගය ලබා ගනී. `ifHighSpeed` වඩාත් කැමති වේ, පළමුවැන්න නොමැති නම් `ifSpeed` භාවිතා වන අතර දෙකම ශුන්‍ය නම් වින්‍යාසගත පෙරනිමිය අදාළ වේ.

එම අගය ගොනුවට ලියනු ලැබේ. 100 Mbps වේගයෙන් සොයාගෙන පසුව ඉහළ සාකච්ඡා කරන ලද පෝට් එකක් එහි සැබෑ ගමනාගමනයට වඩා අඩු සීමාවක් රඳවා ගත හැකි අතර, RRDtool එම සීමාවට වඩා වැඩි අනුපාත නොදන්නා ලෙස සටහන් කරයි. `rrdtool info` සමඟ හැඹිලිගත වේගය, දත්ත ප්‍රභව අර්ථ දැක්වීම සහ සැබෑ ගොනුව සංසන්දනය කරන්න.

## දර්ශක තීරණය

වැරදීමක් සිදු වූ විට ඉතිහාසය නැති වන්නේ මෙතැනදීය.

සෑම දත්ත ප්‍රභවයක්ම එහි පෝට් එක ගැන කරුණු දෙකක් ගබඩා කරයි: එය හඳුනා ගන්නේ කුමන ක්ෂේත්‍රයද (දර්ශක වර්ගය) සහ එම ක්ෂේත්‍රයේ අගය. එක් එක් නැවත සුචිගත කිරීමේදී, එම ක්ෂේත්‍රයේ දැනට එම අගය ඇත්තේ කුමන SNMP දර්ශකයටදැයි විමසීමෙන් එය නැවත පෝට් එක සොයා ගනී. දත්ත ප්‍රභවය අගය අනුගමනය කරයි, වගු පිහිටීම නොවේ.

එබැවින් ප්‍රශ්නය වන්නේ අගය දරන්නේ කුමන ක්ෂේත්‍රයද යන්නයි.

අතුරුමුහුණත් විමසුම මනාප අනුපිළිවෙලක් ප්‍රකාශ කරයි: `ifName`, පසුව `ifDescr`, පසුව `ifHwAddr`, පසුව `ifIndex`. Kadupul සාමාන්‍යයෙන් ප්‍රමාණවත් තරම් වෙනස් අගයන් සහිත සහ අනුපිටපත් නොමැති අපේක්ෂකයින් අතරින් තෝරා ගනී.

| ක්ෂේත්‍රය | නොනැසී පවතින්නේ | අසමත් වන්නේ |
|---|---|---|
| `ifName` | නැවත පණගැන්වීම්, කාඩ්පත් ප්‍රතිස්ථාපනය, නැවත අංකනය | නියෝජිතයා එය හිස්ව තබයි හෝ ස්ටැක් සාමාජිකයින් අතර පුනරාවර්තනය කරයි |
| `ifDescr` | ස්විච් දෘඩාංග මත සාමාන්‍යයෙන් ස්ථායී වේ | සේවාදායකයන්හි වෙනස් වීමට යටත් වන කර්නල් නමකි |
| `ifHwAddr` | නැවත පණගැන්වීම් | ප්‍රතිස්ථාපනය කරන ලද කාඩ්පතක නව MAC ඇත, එය ඔබ ආරක්ෂා කිරීමට බලාපොරොත්තු වූ අවස්ථාවයි |
| `ifIndex` | විශ්වාසදායක කිසිවක් නැත | කාඩ්පත් හුවමාරුවක්, නැවත පණගැන්වීමක් හෝ ෆර්ම්වෙයාර් වෙනසක් වගුව නැවත අංකනය කරයි |

විමසුම `ifIndex` වෙත ආපසු ගියහොත්, එය සාමාන්‍ය ප්‍රතිඵලයක් නොව සොයා ගැනීමක් ලෙස සලකන්න. ඔබගේ පෝට් ඉතිහාසය එවිට ස්විචයට නිදහසේ නැවත පැවරිය හැකි අංකයකට බැඳී ඇත.

## නැවත සුචිගත කිරීමේ ක්‍රමය (reindex method)

දත්ත විමසුමකට එක් උපාංගයකට සකසා ඇත. Kadupul දර්ශක ක්ෂේත්‍ර නැවත කියවන්නේ කවදාද යන්න එය තීරණය කරයි.

| ක්‍රමය | ක්‍රියාත්මක වන්නේ | පිරිවැය |
|---|---|---|
| None | කිසිවක් නැත; අතින් හෝ ස්ක්‍රිප්ට් පමණි | නැත |
| Uptime | උපාංගයේ SNMP ක්‍රියාකාරී කාලය පසුපසට යාම | චක්‍රයකට එක් සංසන්දනයක් |
| Index Count | සොයාගත් දර්ශක ගණනේ වෙනසක් | චක්‍රයකට එක් ගණනයක් |
| Verify All | හැඹිලිගත අනන්‍යතා පරීක්ෂාවක් අසමත් වීම | ඡන්ද විමසීමේදී දන්නා දර්ශක විමසයි |

Uptime පෙරනිමි වන අතර බොහෝ ස්විචයන් සඳහා ගැලපේ, මන්ද නැවත පණගැන්වීම යනු දර්ශක නැවත අංකනය කරන සිදුවීමයි. Index Count මඟින් නැවත පණගැන්වීමකින් තොරව එකතු කරන ලද හෝ ඉවත් කරන ලද කාඩ්පත් ග්‍රහණය කරයි. Verify All මඟින් දන්නා දර්ශකවල වෙනස් වූ අනන්‍යතා හඳුනාගත හැකි නමුත් නව පෝට් සොයා ගැනීම සහතික නොකරයි.

තෝරාගත් උපාංගයක් සහ විමසුමක් නැවත ධාවනය කිරීමට, හැඳුනුම්පත් දෙකම ස්ථාපිත හැඳුනුම්පත් සමඟ ප්‍රතිස්ථාපනය කරන්න. එම උපාංගය සඳහා සියලුම විමසුම් නැවත ධාවනය කිරීමට `--qid` මඟ හරින්න:

```bash
php cli/poller_reindex_hosts.php --id=42 --qid=16
```

`--id=all` සක්‍රීය කර ඇති සියලුම උපාංග වෙත ක්‍රියාත්මක කිරීම දීර්ඝ කරයි. අතිච්ඡාදනය වන නැවත සුචිගත කිරීම් ක්‍රියාත්මක කිරීමෙන් වළකින්න. `--force` ක්‍රියාවලි ලියාපදිංචිය මඟහැර මාතෘකා හැඹිලි නැවුම් කරයි.

## පෝට් එකක් අතුරුදහන් වූ විට

නැතිවූ පෝට් එකක් ස්වයංක්‍රීයව එකතු කිරීම නවත්වන බව උපකල්පනය නොකරන්න. අනන්‍යතාවයක් නොවිසඳී ඇති විට සහ කිසිදු මූලාශ්‍රයක් දර්ශකය වෙනස් නොකරන විට වත්මන් නැවත සුචිගත කිරීමේ කේතයට අනාථ ධජයක් නැවත සැකසිය හැකි අතර පැරණි ඡන්ද විමසීම් OID රඳවා තබා ගත හැක. ගබඩා කර ඇති අනන්‍යතාවය නව සොයාගැනීමේ හැඹිලිය සමඟ සංසන්දනය කර ගැලපීම තහවුරු වන තෙක් බලපෑමට ලක් වූ මූලාශ්‍රයක් අබල කරන්න. [දත්ත විමසුම් සහ දර්ශක](/si/concepts/data-queries-and-indexes/) බලන්න.

## විශාල චැසි (large chassis)

පෝට් ගණන වැඩි වූ විට එක් උපාංගයකට සැකසුම් දෙකක් වැදගත් වේ: එක් SNMP ඉල්ලීමකට වින්‍යාස කර ඇති OID සහ එක් උපාංගයකට ත්‍රෙඩ් ගණන පරීක්ෂා කරන්න. කාණ්ඩගත කිරීමේ සහාය සහ ඵලදායී සමාන්තරභාවය එකතු කරන්නා සහ නියෝජිතයා මත රඳා පවතී; PHP `cmd.php` සහ Spine එකම ත්‍රෙඩ් හැසිරීමක් ලබා නොදේ.

වරකට එක් සැකසුමක් පමණක් වෙනස් කර poller චක්‍රයේ කාලසීමාව නිරීක්ෂණය කරන්න.
