일반적인 이미지 요청은 그래프 구성에서 RRDtool 명령을 조합하고 참조된 RRD 파일을 읽을 수 있습니다. 유효한 캐시 이미지도 요청을 처리할 수 있으며, 온디맨드 Boost 처리를 통해 렌더링 전에 파일을 업데이트할 수 있습니다. 데이터 최신성 한계는 [대용량 쓰기](/ko/concepts/high-volume-writes/)를 참조하세요.

## 작업 순서

명령 생성으로 진행되는 요청의 경우:

1. 요청된 시간 창과 그래프 구성을 확인합니다.
2. 데이터베이스 프로필에서 해상도를 추정하고 통합 함수를 선택합니다.
3. 필요한 필드와 함수에 대해 중복이 제거된 `DEF` 참조를 출력합니다.
4. 참조된 `CDEF` 및 `VDEF` 식을 출력합니다.
5. 적용 가능한 옵션 및 플러그인 변경 사항과 함께 구성된 순서대로 그리기 및 인쇄 항목을 출력합니다.
6. RRDtool이 실제 파일을 읽고 결과를 렌더링하도록 합니다.

## 아카이브 선택

Kadupul은 아카이브 범위와 그래프 옵션을 계산할 때 데이터베이스 프로필 행을 참조합니다. 자동 추정은 스텝 시간 곱하기 스텝 수 곱하기 행 수, 요청된 범위 및 아카이브 스텝 수를 고려합니다. 명시적인 아카이브 선택은 별도의 경로를 따릅니다. 이러한 프로필 계산은 모든 파일의 모든 실제 물리적 아카이브를 검사하지 않으므로 프로필 변경 후 기존 파일과 불일치할 수 있습니다.

생성된 `DEF` 는 파일, 데이터 소스 이름 및 통합 함수를 지정합니다. RRDtool은 적절한 해상도에서 사용 가능한 아카이브를 선택하고 그래프 너비와 시간 창에 맞춰 데이터를 추가로 통합할 수 있습니다. 애플리케이션의 추정치가 특정 물리적 아카이브를 읽는다는 보장은 아닙니다. 업스트림 [RRDtool 데이터 정의 문서](https://oss.oetiker.ch/rrdtool/doc/rrdgraph_data.en.html)를 참조하세요.

시간 창을 넓히거나 이미지 너비를 변경하면 표시되는 해상도가 달라질 수 있습니다. 더 정밀한 아카이브에 여전히 스파이크가 포함되어 있더라도 평균 기반의 거친 계열에서는 스파이크가 숨겨질 수 있습니다. 프로필뿐만 아니라 실제 파일 레이아웃과 명령을 비교하세요. [데이터 소스 및 라운드로빈 아카이브](/ko/concepts/data-sources-and-rras/)를 참조하세요.

호출자가 종료 시간을 제공하지 않으면 일반 렌더러는 처음에 현재 시점 기준 메인 폴러의 마지막 실행 오프셋을 사용하며, 해당 값을 사용할 수 없거나 미래인 경우 폴링 간격으로 대체합니다. 이후 코드에는 통합 간격 대체 기능도 있지만 보편적인 기본값은 아닙니다. 명시적인 종료 시간은 이 초기화를 재정의합니다. 현재 시점 이전으로 끝나는 그래프 자체가 선택된 아카이브를 증명하거나 최신 샘플이 기록되었음을 증명하지는 않습니다.

## 그래프 항목

그래프는 순서가 지정된 항목 목록입니다. 명령 생성 시 항목을 생략하거나 정의를 재사용하거나 항목을 여러 명령어로 확장할 수 있습니다. 그리기 순서는 단순한 레이아웃 이상의 의미를 가집니다.

| 항목 | 그리기 동작 | 비고 |
|---|---|---|
| `AREA` | 축에서 값까지 채워진 영역 | 이후 영역이 이전 영역 위에 겹쳐 그려짐 |
| `STACK` | 이전 항목의 상단에서 시작하는 채워진 영역 | 스택 플래그가 있는 영역으로 출력됨 |
| `LINE1`, `LINE2`, `LINE3` | 1, 2, 3픽셀 두께의 선 | 점선으로 표시 가능 |
| `LINE:STACK` | 누적 스택 총합 위에 그려지는 선 | |
| `TICK` | 플롯 가장자리를 따른 눈금 표시 | 크기가 아닌 상태 표시에 유용 |
| `GPRINT` | 그리기 없음. 범례에 숫자 하나 출력 | |
| `COMMENT` | 그리기 없음. 범례에 리터럴 텍스트 출력 | 긴 설명은 줄 바꿈됨 |
| `HRULE` | 고정값 위치의 수평선 | |
| `VRULE` | 고정 시간 위치의 수직선 | |
| `TEXTALIGN` | 그리기 없음. 이후 범례 텍스트의 정렬 설정 | |

각 유형에 적용되는 구성 열을 포함한 전체 목록은 [그래프 항목](/ko/reference/graph-items/)에 있습니다.

`AREA` 와 `STACK` 은 가장 혼동하기 쉬운 조합입니다. 영역은 0에서 시작하므로 두 영역이 겹치면 더 높은 영역이 더 낮은 영역을 가립니다. 스택은 이전 항목이 끝난 위치에서 시작하므로 두 번째 밴드의 가시적인 높이는 자체 값을 나타내지만 상단 가장자리는 총합을 나타냅니다. 누적 그래프는 Y축 위치가 아니라 밴드 높이로 읽어야 하며, 그렇지 않으면 맨 아래 계열을 제외한 모든 계열을 잘못 해석하게 됩니다.

`HRULE` 은 템플릿 대체 변수를 포함할 수 있는 값을 사용합니다. 숫자가 아닌 문자는 결과에서 제거되며, 숫자가 남아있지 않으면 렌더링이 실패하는 대신 0 위치에 선이 그려집니다. 0 위치의 선은 의도된 것일 수도 있고 대체 실패의 결과일 수도 있습니다. 판단하기 전에 변환된 명령을 검사하세요. 숫자 필터는 단위나 지원되지 않는 숫자 표기법이 포함된 문자열을 변경할 수도 있습니다.

`VRULE` 은 Unix 타임스탬프 또는 `hours:minutes` 쌍을 허용합니다. 음수 시간 값은 시계 시간이 아니라 현재로부터 과거로의 오프셋으로 해석됩니다.

## 두 가지 작업, 하나의 단어

통합 함수라는 용어는 두 가지 서로 다른 목적으로 사용되며, 동일한 네 가지 이름인 `AVERAGE`, `MIN`, `MAX`, `LAST` 가 두 곳 모두에 나타납니다.

첫 번째 작업은 아카이브 선택입니다. `DEF` 는 파일, 파일 내부의 데이터 소스 및 통합 함수를 지정합니다. 이 함수는 요청된 아카이브 패밀리를 제한합니다. `MAX` 를 요청하면 아래에 설명된 애플리케이션 대체 및 해상도 선택에 따라 RRDtool에 일치하는 저장된 통합 데이터가 필요합니다.

두 번째 작업은 범례 연산입니다. `GPRINT` 는 그려진 전체 창을 하나의 출력된 숫자로 축소하며, 해당 함수가 연산 방식을 결정합니다. 이 축소는 이미 읽은 계열에 대해 발생하며, 이는 표현을 위한 집계이지 물리적 저장이 아닙니다.

따라서 `AVERAGE` 로 읽은 `DEF` 에 대해 `MAX` 를 표시하는 `GPRINT` 는 렌더링된 창에서 해당 평균 기반 계열의 최대값을 출력하며, 반드시 원시 샘플의 최대값인 것은 아닙니다. 5분은 예시일 뿐이며 유효 해상도는 달라집니다. 이 둘은 서로 다른 숫자이며 사용량이 많은 회선에서는 매우 큰 차이를 보입니다. 두 판독값 모두 타당합니다. 단지 한 가지만이 원래 의도했던 값일 가능성이 높습니다.

## 암시적 대체 동작

최적 함수 도우미를 사용하는 항목 유형의 경우 Kadupul은 파일의 통합 함수를 읽고 요청된 함수가 있으면 이를 사용하고, 그렇지 않으면 처음 보고된 함수를 사용합니다. 유효한 로컬 데이터 소스에 대해 함수를 얻지 못하면 도우미는 AVERAGE로 대체합니다. 고정된 GPRINT 변형은 별도의 경로를 따르며 이 도우미를 사용하지 않으므로, 누락된 모든 함수가 복구된다는 보장은 아닙니다.

따라서 `MAX` 를 요청하는 그리기 항목은 파일에 AVERAGE 아카이브만 포함된 경우 결국 평균을 읽게 될 수 있습니다. 생성된 `DEF` 및 `rrdtool info` 출력을 검사하세요. 아카이브 유지 관리를 통해 기존 레이아웃을 변경할 수 있지만, 아카이브를 추가한다고 해서 이전 평균화로 인해 버려진 과거의 피크를 재구성할 수는 없습니다. [데이터 보존 관리](/ko/guides/manage-data-retention/)를 참조하세요.

## GPRINT는 인접 항목의 아카이브를 차용함

일반 `GPRINT` 는 자체 아카이브를 갖지 않습니다. 데이터 소스 이름과 로컬 템플릿 필드 ID를 기준으로 가장 최근에 일치하는 `AREA`, `STACK`, 선 또는 `TICK` 항목의 통합 함수를 재사용합니다. 이전 일치 항목이 없는 경우 자체 구성된 함수와 함께 최적 함수 도우미를 사용합니다. 고정 변형은 자체 구성된 함수를 직접 사용합니다.

즉, 그래프 템플릿에서 항목 순서를 변경하면 아무도 범례를 건드리지 않아도 범례에 보고되는 내용이 변경될 수 있습니다. `GPRINT` 블록 위에 `MAX` 를 읽는 `LINE` 을 배치하면 일치하는 범례가 최대값을 요약할 수 있습니다. 아래로 이동하면 이전 일치 항목이나 대체 항목이 입력 계열을 결정합니다. 관련 없는 템플릿 편집 후 범례의 숫자가 변경되면 먼저 항목 순서를 확인하세요.

## CDEF와 VDEF

둘 다 그리기 전에 데이터를 변환합니다. 둘은 서로 호환되지 않습니다.

| | CDEF | VDEF |
|---|---|---|
| 생성 결과 | 시계열 데이터(타임슬롯당 하나의 값) | 스칼라 값 및 일부 함수의 경우 관련 시간 |
| 선 또는 면으로 그리기 가능 여부 | 예 | 스칼라로 일정한 수준선 제공 가능 |
| 구성 요소 | 함수, 산술 연산자, 다른 CDEF, 특수 데이터 소스, 리터럴 | 단일 참조에 적용된 단일 함수 |
| 중첩 | CDEF는 다른 CDEF를 참조할 수 있음 | VDEF는 산술 연산을 포함할 수 없음 |

CDEF는 역폴란드 표기법으로 평가되는 스택 식입니다. 지원 어휘는 방대하며 [그래프 항목](/ko/reference/graph-items/)에 전체 목록이 나와 있습니다. 산술, 비교 및 조건 연산자, 삼각법, 데이터 소스 간 집계, 스택 조작, X축에서 위치를 파악할 수 있는 시간 함수 등이 포함됩니다. `UN` 과 `UNKN` 은 초기에 익혀둘 가치가 있습니다. 알 수 없는 값을 0으로 바꾸면 시각적 끊김을 방지할 수 있지만 누락된 측정을 숨길 수도 있으므로 이러한 표현 방식을 신중히 선택하세요.

CDEF는 고정된 데이터 소스 이름 대신 특수 참조도 읽습니다. 하나는 현재 항목의 데이터 소스로 확인되며, 이를 통해 단일 CDEF를 템플릿의 모든 항목에서 재사용할 수 있습니다. 다른 참조는 그래프의 모든 데이터 소스 또는 중복 여부에 관계없이 유사한 모든 데이터 소스로 확인되어 입력을 개별적으로 지정하지 않고도 총계 선을 만들 수 있습니다.

VDEF는 계열을 스칼라 값으로 축소합니다. 최대값, 최소값, 평균, 표준 편차, 첫 번째 값, 마지막 값, 합계, 백분위수 또는 최소제곱 맞춤의 기울기, 절편 및 상관관계가 이에 해당합니다. RRDtool은 VDEF 내의 산술 연산을 지원하지 않으므로 VDEF에 계산된 입력이 필요할 때 Kadupul은 원시 데이터 소스 대신 항목의 CDEF 위에 이를 구축합니다. 이것이 의도된 계산 경로입니다. CDEF에서 계산을 수행한 다음 VDEF에서 축소합니다.

VDEF를 기반으로 하는 `GPRINT` 는 통합 함수 인수를 사용하지 않습니다. VDEF가 이미 축소 결과를 제공했기 때문입니다. VDEF는 그리기를 위한 스칼라 값을 제공할 수도 있습니다. RRDtool은 VDEF 기반 선을 지원합니다. 업스트림 [그래프 요소 문서](https://oss.oetiker.ch/rrdtool/doc/rrdgraph_graph.en.html)를 참조하세요.

CSV 내보내기는 지원되는 그리기 유형을 계열 열로 선택하며, 범례 항목은 동등한 열로 내보내지지 않습니다. VDEF 기반 그리기 항목은 그래프 이미지에는 계속 렌더링되지만 내보내기에서는 제외됩니다. VDEF는 시계열이 아니라 단일 값이기 때문입니다.

## 동일한 데이터가 다르게 보이는 이유

아래의 모든 항목은 저장된 단일 샘플을 변경하지 않고도 시각적 이미지를 변경합니다.

| 선택 사항 | 효과 |
|---|---|
| 창 길이 및 이미지 너비 | 아카이브 선택 및 추가 통합을 변경할 수 있음 |
| `DEF` 의 통합 함수 | 피크, 밸리, 평균 또는 마지막 값을 읽음 |
| 누락된 통합 함수 | 일부 항목 경로는 다른 함수로 대체되며 일부는 실패할 수 있음 |
| `AREA` 대 `STACK` | 절대 높이 대 누적 높이 |
| 항목 순서 | 겹쳐 그리기, 스택 순서 및 `GPRINT` 가 차용하는 아카이브 |
| 밑수 1000 또는 1024 | 축 레이블을 변경함. 값 자체는 동일함 |
| 자동 배율 모드, 고정 한계, 로그 눈금 | Y축을 변경하여 변화의 시각적 체감 크기를 바꿈 |

그래프가 일치하지 않는 경우 렌더링된 명령, 실제 물리적 파일 식별성 및 레이아웃, 캐시 상태 및 샘플 최신성을 비교하세요. 이러한 표현 방식 확인은 유용한 점검 사항이지만 수집, 저장 또는 매핑 오류를 배제하지는 않습니다. 이에 대한 단계별 안내는 [누락된 데이터 문제 해결](/ko/guides/troubleshoot-missing-data/)을 참조하세요.
