監視システムは、コードの品質とは無関係な3つの理由から、防御が困難な対象です。

監視対象のすべてに対する認証情報を保持しています。SNMP コミュニティ名、v3 ユーザー名およびパスフレーズなど、デバイスが必要とするあらゆる情報が保存されており、ポラーが無人状態でそれらを使用できるようにしています。5分ごとに手動で入力する人間は存在しません。

スケジュールに従って外部コマンドを実行します。SNMP が公開していない値を収集することはスクリプトの実行を意味し、そのスクリプトの定義はデータベースに保存されインターフェースから編集可能な設定情報です。

監視対象のマシンが生成するデータを取り込みます。インターフェースの説明、ディスクのマウントポイント、センサーの名前など、すべてがデバイスから届き、データベース、グラフのタイトル、および他のプログラムに渡される引数に行き着きます。侵害されたスイッチは単なる被害者ではなく、入力源となります。

これらはいずれも欠陥ではありません。監視業務が要求する要件です。以下では、それぞれがアーキテクチャのどこに位置するかを解説します。

## 信頼できない入力が入る場所

オペレーターがそれらをどの程度制御できるかのおおよその順序による4つのエントリポイントです。

| エントリポイント | ソース | 向かう先 |
|---|---|---|
| HTTP パラメータ | Web サーバーに到達できるすべてのユーザー | データベース、ページ出力、および SQL |
| SNMP 値 | ポーリング対象のデバイス | `host_snmp_cache`、グラフタイトル、RRD 境界、スクリプト引数 |
| スクリプト出力 | ローカルスクリプトまたは通信相手 | `poller_output`、その後に RRD ファイル |
| アップロードされたテンプレートとパッケージ | インポートレルムを保持する任意のユーザー | テンプレート行、およびパッケージの場合はディスク上のファイル |

### HTTP パラメータ

リクエストヘルパーは `lib/html_utility.php` にあります。`get_filter_request_var()` はデフォルトで整数検証を行いますが、空、未定義、および正規表現値に対する特別なケースも備えています。呼び出し元は、ある値が必要でありその操作に対して適切であるかどうかを引き続き確認する必要があります。フィルタリングは認可を確立するものではありません。

`set_request_var()` は値を `$_CACTI_REQUEST` にキャッシュし、リクエスト配列に反映します。`get_nfilter_request_var()` はそのキャッシュまたは生のリクエストを読み取り、それ自体で値を検証したり書き込んだりすることはありません。したがって、その後の読み取りでは以前に保存された値が参照される可能性があり、読み取り順序が重要になります。

`log_validation` を有効にすると、`get_request_var()` は特定のキャッシュされていないリクエストの読み取りを記録します。直接のスーパーグローバル読み取りおよび `get_nfilter_request_var()` はすべてがカバーされているわけではありません。これは診断支援であり、完全な検証監査や強制ではありません。

### SNMP 値

データクエリディスカバリは、選択されたインデックス値を `host_snmp_cache` に保存します。通常の SNMP ポーリング結果はサンプルパスに従います。`lib/data_query.php` の `data_query_format_record()` は、保存前に2つの変換を適用します。クエリ定義からのオプションの `rewrite_value` マップ、および `mb_detect_encoding()` がエンコーディングを特定できない任意の値に対する `bin2hex()` です。後者はバイナリオクテット文字列に対するガードであり、敵対的なコンテンツに対する防御ではありません。

そこから値は伝播します。`substitute_snmp_query_data()` を介してグラフに名前を付けます。データテンプレートはその最大値を `|query_ifSpeed|` として宣言できるため、RRD の最大値を設定できます。スクリプトクエリの引数になり、そこでは `get_script_query_path()` が最初に各部分を `cacti_escapeshellarg()` に通します。

エスケープ処理および [RRDtool の統合](/ja/reference/rrdtool-integration/) で説明されている RRDtool バリデータがここでの境界となります。デバイスデータは信頼できないものとして扱わなければなりません。検証とエスケープは各呼び出しポイントの属性であり、ヘルパーの存在はすべてのコンシューマーがそれらを正しく使用していることの証明にはなりません。コマンド構造と置換された引数の両方を確認してください。

### スクリプト出力

`exec_poll()` の `popen()` 分岐は `fgets(..., 8192)` で読み取り、最大で 8,191 バイトまたは最初の改行までを返します。その `shell_exec()` フォールバックは異なる出力動作を示し、スクリプトサーバーによる収集は別のパスをたどります。

`prepare_validate_result()` は数値および未知の値、16進数形式、および一部の複数フィールド出力構造を認識します。数値を抽出するためにテキストを取り除くこともできますが、汎用的で厳格なスカラーフィルターではありません。後続の解析と RRDtool の検証も重要です。[データ入力メソッド](/ja/reference/data-input-methods/) を参照してください。

出力チェックは、すでに実行されたスクリプトをサンドボックス化するものではありません。収集を有効にする前に、コマンド、入力許可リスト、およびオペレーティングシステムの権限を確認してください。

### テンプレートとパッケージ

2つの異なるメカニズムが1つのレルムを共有しています。

**テンプレートインポート** は署名のないプレーンな XML です。テンプレート、データクエリ、およびデータ入力メソッドを作成します。データ入力メソッドはコマンドラインであるため、これはアップロードされたファイルからポラーが実行する処理へのパスとなります。`lib/import.php` はインポートされた任意の `input_string` に対して `cacti_input_string_is_safe()` を実行し、シェルメタ文字が含まれている場合はそのメソッドを拒否して次のようにログに記録します。

```
ERROR: Refusing to import data input method '<hash>' - input_string contains shell metacharacters
```

**パッケージインポート** は署名されています。`import_read_package_data()` はパッケージに埋め込まれた公開鍵を読み取り、`lib/import.php` にコンパイルされた3つの鍵（2つの Cacti 鍵と Kadupul 鍵）と比較します。その他の鍵は失敗します。`<publickey>` 要素を持たないパッケージは古い Cacti 鍵を主張していると解釈され、それに対して検証される署名を生成する必要があります。`import_read_package_data()` は検証を試行する前に 2048 ビット未満の鍵を拒否しますが、512 ビットの古い鍵はこの条件を通過できません。含まれる各ファイルは独自の署名を保持し、個別に検証されます。

パッケージは選択されたファイルを書き込むことができます。受け入れられる名前は `scripts/` または `resource/` で始まり、オプションで有効な `plugins/<name>/` プレフィックスの下に配置されます。インポーターは NUL バイト、ディレクトリトラバーサル、絶対パスを拒否し、インストールルート配下の包含関係を解決します。単にディレクトリ名を含んでいるだけでは不十分です。保存先の書き込み可能性も書き込みが成功するかどうかを制御します。検証に合格したパッケージは、設計上実行可能な PHP をツリーに書き込みます。署名検証は受け入れられた署名者の身元と整合性を確認するものであり、コードが無害であることを示すものではありません。レルム認可、パスの包含性、選択されたファイル、ファイルシステムの権限、およびコマンド許可リストのポリシーも重要です。

両方のメカニズムはレルム 17 の背後にあります。標準のテンプレート編集者ロールはレルム 17 とレルム 2（データ入力メソッド）を保持しています。これらの権限を持つアカウントは、検証と許可リスト処理に従って収集コマンドを定義できます。それがこのロールの目的であり、付与する前に知っておく価値があります。検証されたワークフローと既知の制限事項については、[テンプレートのインポートとエクスポート](/ja/guides/import-and-export-templates/) を参照してください。

## 何がどの権限で実行されるか

| プロセス | 起動元 | 実行ユーザー | 役割 |
|---|---|---|---|
| Web インターフェース | Web サーバー | Web サーバーユーザー | データベースの読み書き、RRDtool によるグラフ描画、オンデマンドでの RRD ファイル書き込み、インポート時のパッケージファイル書き込み |
| `poller.php` | 設定されたスケジューラーまたはサービス | スケジューラー/サービスアカウント | ポラーキャッシュの読み取り、コレクターの起動、RRD ファイルの書き込み |
| `cmd.php` | ポラーまたはリアルタイム収集パス | 起動アカウント | SNMP get および収集コマンドの実行 |
| `script_server.php` | コレクター | 起動アカウント | PHP ファイルをインクルードし、自身のプロセス内で関数を呼び出す |
| RRDtool | Web プロセスまたはポラー | 呼び出した側のプロセス | `rra/` 配下のファイルの読み書き |

これらの中の2つについて、より詳しく確認する必要があります。

**スクリプトサーバーはサンドボックスではありません。** 対象ファイルを長時間実行される PHP プロセスにインクルードし、その中の関数を呼び出します。その関数はプロセス、そのメモリ、およびデータベース接続を共有します。`script_server.php` 内のチェックは呼び出しが発生するかどうかを決定します。インクルードファイルの `realpath()` が `$config['base_path']` または `$config['scripts_path']` 配下で解決される必要があり、インクルード後に関数が存在する必要があり、`ReflectionFunction::isInternal()` が false である必要があり、関数を定義するファイルも許可されたルート配下にある必要があります。これらを通過すると、コードはポラーの完全な特権で実行されます。スクリプトサーバーメソッドは、Kadupul の*内部*で PHP を実行する方法であり、その*隣*で実行する方法ではありません。

**Web プロセスは RRD ファイルを書き込むことができます。** グラフのリクエストにより、オンデマンドの Boost 更新やファイル作成がトリガーされる場合があります。あるディレクトリ作成パスをポラーに委任するという警告は、Web の書き込みアクセスが全体として任意であることを意味しません。ストレージの事前確認とメンテナンス調整でも、アカウントアクセスと信頼された数値 UID/GID 設定がチェックされます。root 権限での作成はストレージの所有権に合わせようとしますが、失敗が記録される場合があります。[安全なアップグレード](/ja/guides/upgrade-safely/) を参照してください。

Web アカウントとスケジュールされたポラーのアカウントは異なる場合があります。Web リクエストから起動されたリアルタイム収集は Web アカウントを継承する可能性があるため、コマンド実行はスケジュールされたポラーのIDに制限されません。継承された Spine 統合では、実際のバイナリに対する個別の検証が必要です。このページはサポートされるビルドを規定するものではありません。

## データベースアカウントに必要なもの

同じデータベース設定を使用するプロセスは通常、そのアカウントを共有します。リモートコレクターは個別のローカル認証情報と中央認証情報を持つことができます。デプロイ固有の設定は異なる場合があります。設定されているすべてのアカウントについて、実際の権限付与を確認してください。

| 要件 | 理由 |
|---|---|
| Kadupul スキーマに対する完全な DML | 通常の運用 |
| Kadupul スキーマに対する DDL | アップグレード、および Boost テーブルのローテーション、一時テーブル、プラグインのライフサイクル変更などの実行時操作 |
| `mysql.time_zone_name` に対する `SELECT` | サイトおよびデータコレクターのタイムゾーンリストがそのテーブルを直接読み取る |

アップグレードのみに必要であるという想定で DDL 権限を削除しないでください。アプリケーションは個別の移行用 ID に一律に切り替わるわけではありません。アカウントの分離には、影響を受けるすべての実行時パスに対するデプロイ固有の検証が必要です。

`include/config.php` にはデータベースの認証情報が含まれており、リモートコレクターは中央の `$rdatabase_*` 認証情報も保持できます。ファイルシステムの権限、HTTP アクセスルール、PHP ハンドラー設定、およびバックアップ保護のすべてが重要です。PHP は通常、ソースコードを提供するのではなくファイルを実行しますが、それは直接の開示から保護することの代用にはなりません。[インターネットに公開されたインストールのセキュリティ確保](/ja/guides/secure-an-internet-facing-install/) を参照してください。

デバイスの認証情報も同様に保存されます。`host.snmp_community`、`host.snmp_password`、および `host.snmp_priv_passphrase` は通常の列であり、暗号化ステップなしで `form_input_validate()` を通じて `api_device_save()` によって書き込まれ、ポラーが読み取るために `poller_item` 行にコピーされます。関連するテーブルへの読み取りアクセスは保存された認証情報を公開する可能性がありますが、考えられるすべての外部認証情報ソースへのアクセスを意味するわけではありません。ユーザーパスワードは例外です。`compat_password_hash()` は `PASSWORD_DEFAULT` を指定した PHP の `password_hash()` を使用し、引き続き検証可能なレガシー MD5 ハッシュは次回のログイン時に再ハッシュされます。

## コードによる強制と単なる慣例

これは変更について考察する際に最も重要な区別です。

### コードメカニズムとその適用範囲

| 境界 | メカニズム |
|---|---|
| 認証 | 一般的なインターフェースページは `include/auth.php` を使用。特殊なエンドポイントには独自の処理が存在 |
| CSRF | 共有 Web ブートストラップがトークン処理を構成。不正な形式のトークン配列は拒否。一律の適用を想定せず各エンドポイントを確認 |
| CLI 専用スクリプト | SAPI が `cli` でない場合、`include/cli_check.php` は `404` を返して終了 |
| データクエリ XML の場所 | `<base_path>/resource` に対して `cacti_path_is_within()` を実行し、満たさない場合は記録して拒否 |
| パッケージの信頼性 | 組み込み鍵に対する署名検証、最小 2048 ビット、ファイルごとの個別署名 |
| パッケージファイルの配置 | 無効な名前は拒否。許可された scripts/resource プレフィックスと解決されたルート包含関係を確認 |
| スクリプトサーバーの呼び出し対象 | `realpath()` による包含制限、および上記の関数チェック |
| シェル引数 | 適用されている場所でのエスケープ、構造化コマンドヘルパー、およびバリデータ。実際の呼び出しポイントを確認 |
| RRDtool 引数 | `lib/functions.php` 内の制御文字および構造のバリデータ |
| SQL | プリペアドヘルパーによる値のバインド。動的 SQL、識別子、および非プリペアド呼び出しは引き続き確認が必要 |
| リモートエージェントの呼び出し元 | 送信元アドレスが `poller` 内の有効な行と一致する必要があり、正確な IP または確認済み逆引きによる |

### デプロイおよび呼び出しポイントの責任

| 境界 | なぜ強制されないのか |
|---|---|
| リクエストフィルタリング | ページが `get_filter_request_var()` を選択するかどうかによる。`log_validation` は報告するだけでブロックはしない |
| 出力エスケープ | `html_escape()` および `html_purify()` は呼び出しポイントごとに適用される |
| ページごとの認可 | レルムチェックはファイル名をキーとする `$user_auth_realm_filenames` を使用。マップされていないページはそのマップからだけでは認可を得られない。追加のチェックが適用される場合がある。プラグインページは独自のポリシーを登録・適用する必要がある |
| ディレクトリ拒否 | `cli/`、`log/`、`rra/`、`scripts/`、`contrib/`、`mibs/`、および `cache/*` 配下の `.htaccess` は Apache ディレクティブ。nginx や `AllowOverride` が無効な Apache では適用されない |
| 静的ファイルのセキュリティヘッダー | `.htaccess.dist` は名前変更されずに出荷される。PHP ヘッダーの送出はレスポンスパスと設定に依存し、静的レスポンスはサーバー/プロキシ設定に依存 |
| Web とポラーのユーザー分離 | 慣例であり、必須要件ではない |
| `include/config.php` のパーミッション | インストールした者によって設定される |

`resource/` およびそのサブディレクトリ内の `index.php` リダイレクトスタブはディレクトリ一覧の表示を阻止します。これらはアクセス制御ではなく、指定されたファイルへの直接リクエストを阻止するものではありません。

## 認証前に応答するエンドポイント

これらは特殊なエントリポイントの例であり、公開エンドポイントの網羅的な一覧ではありません。共通インクルードが存在しないことは、リクエストパスの他の場所での認証や認可の不在を証明するものではありません。

| ファイル | 動作 |
|---|---|
| `auth_login.php`, `auth_changepassword.php` | ログイン画面自体 |
| `csp_report.php` | ブラウザの CSP 違反レポートを受信 |
| `service_check.php` | `version` に対する1つのクエリの後に `success` または `fail` を応答。認証のない生存確認プローブ |
| `link.php` | 外部リンク行をロードし、自身で `is_realm_allowed($page['id'] + 10000)` をチェック |
| `remote_agent.php` | データコレクター RPC、送信元アドレスによって認可 |

`remote_agent.php` は熟考すべき対象です。その認可は `remote_client_authorized()` であり、`get_client_addr()` を `poller` テーブル内のホスト名およびアドレスと比較します。共有シークレットはありません。アドレスが有効なデータコレクター行と一致する呼び出し元は、エージェントのアクションを呼び出すことができます。データのポーリング、データクエリの実行、デバイスへの Ping、SNMP get/walk の実行、グラフデータのリクエスト、ネットワークディスカバリの実行などです。2つの保護がこれを形作っています。第1に、有効なコレクター行が高々1つしか返されない場合、関数は直接 false を返すため、その場合は拒否されます。第2に、正確な IP ではなくホスト名で一致する場合、逆引き結果が正引きによって確認された後に初めて受け入れられます。

`include/config.php` で `$proxy_headers` が設定されていない限り、`get_client_addr()` は `REMOTE_ADDR` のみを読み取ります。出荷時のデフォルトは `null` です。サポートされているプロキシヘッダーを有効にすると、有効なクライアントアドレスが選択される順序付けられたソースが変更されます。信頼された入力プロキシによって制御されるヘッダーのみを使用し、クライアントがそれらの値をバイパスまたは自己申告できないようにしてください。これはリモートエージェントの認可やログに記録されるアドレスを含め、システム内のあらゆるアドレスベースの決定の意味を最も大きく変える単一の設定行です。

## ゲストアクセス

`guest_user` 設定は、ログインなしでグラフページに使用される権限を持つアカウントを指定します。デフォルトではユーザーなしであり、グラフの表示には他のすべてと同様に認証が必要になります。これを設定すると、そのアカウントが見ることができるすべての内容が、Web サーバーにアクセスできるすべての人に公開されます。それがこの機能の意図です。アカウントは依然としてユーザーレコードに存在します。ゲスト設定とは、通常ログインなしでその適用可能なグラフ権限を使用可能にするものです。設定されたアカウント名だけでなく、実際のリクエストとオブジェクト権限を確認してください。

## 変更について考察する方法

次の3つの質問を順番に行ってください。

どのプロセスが、どのユーザーとしてこれを実行するのか？ データ入力メソッドに対する答えは通常、起動するコレクターの OS アカウントです。Web を契機とする収集はスケジュールされた収集と異なる場合があります。

データはその通過経路で何に触れるのか？ デバイスから取得され RRD ファイルにのみ到達する値は、1つの境界を越えています。グラフタイトル内の同じ値は2つの境界を越えており、スクリプト引数内の値は3つの境界を越えています。

依存している境界は強制されているのか、それとも単なる慣例なのか？ 単なる慣例である場合、あなたが書いているコードこそがその強制機構となります。
