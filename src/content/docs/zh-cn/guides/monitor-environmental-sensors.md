温度、湿度和瞬时功率是测量值，通常存储为 `GAUGE`。累积能量或事件总量可能需要计数器类型。在选择模板之前，请检查每个对象的单位、标识和语义。

在编写任何内容之前，请先检查已随附的内容。

## 随附内容

在代码库自身的查询目录中仅存在四个数据查询定义，且没有一个是针对环境传感器的。

| 随附的 SNMP 查询 | 涵盖范围 |
|---|---|
| `interface.xml` | 网络接口 |
| `host_disk.xml` | Host Resources 存储 |
| `net-snmp_disk.xml` | UCD 声明的分区 |
| `net-snmp_devio.xml` | UCD 块设备 I/O |

传感器覆盖通过另外两种途径提供。

**脚本服务器查询，捆绑在 Net-SNMP 设备软件包中。** 导入 `install/templates/NetSNMP_Device.xml.gz` 以在 `resource/script_server/` 下部署其三个 lmSensors 查询 XML 文件。助手脚本 `scripts/ss_netsnmp_lmsensors.php` 也存在于源码检出中。

| 查询 | 表 |
|---|---|
| Net-SNMP - Sensors - Get Thermal Sensors | `.1.3.6.1.4.1.2021.13.16.2.1` |
| Net-SNMP - Sensors - Get Fan Sensors | `.1.3.6.1.4.1.2021.13.16.3.1` |
| Net-SNMP - Sensors - Get Voltage Sensors | `.1.3.6.1.4.1.2021.13.16.4.1` |

该助手使用索引、名称和读数列。该查询基于数值 `sensorDevice` 建立索引；`sensorName` 提供助手截断为 18 个字符的显示名称。名称不能保证是唯一的传感器标识。

正常的 `get sensorReading` 路径返回原始值：传统温度对象为毫度，电压为毫伏，风扇为 RPM。温度图表应用了 `Divide by 1000` CDEF。尽管标有 Volts 标签，电压图表却没有 CDEF，这是一个[已确认的缩放缺陷](https://github.com/kadupulhq/kadupul/issues/247)。

单独的 `query sensorReading` 路径缩放温度和电压，并尝试使用不正确的常数 4294967294 进行有符号电压转换。它还可能[在不可用的读数上抛出异常](https://github.com/kadupulhq/kadupul/issues/248)。不要从这个发现输出中推断存储单位。

助手仍在使用传统温度列 `.2.1.3`。当前上游 [LM-SENSORS-MIB](https://raw.githubusercontent.com/net-snmp/net-snmp/master/mibs/LM-SENSORS-MIB.txt) 废弃了该无符号对象，推荐使用有符号列 `.2.1.4`；在调整模板之前，请在实际代理上验证支持情况和负温行为。

**设备软件包，作为可导入归档提供。** 其中若干个携带自己的查询 XML，并在导入时将其写入查询目录。与此处相关的软件包包括：

| 软件包 | 带来 |
|---|---|
| SNMP UPS | UPS-MIB 输入和输出线路查询，以及用于电池、运行时间、温度和告警的固定 OID 模板 |
| AKCP Device | 用于温度、湿度、气流和 4-20 mA 传感器的脚本查询 |
| APC InfraStruXure PDU | 用于断路器和相位统计的查询 |
| APC InfraStruXure InRow CRAC | 用于机组和群组统计的查询，包括温度、湿度、气流和风扇转速 |
| BayTech PDU | 插座查询和三相电路查询，带有电流、电压、功率和温度 |

在手工编写查询之前，请检查匹配的软件包。遵循[导入和导出模板](/zh-cn/guides/import-and-export-templates/)，验证文件部署和发现，然后显式创建所需的图表。软件包的存在不能证明设备兼容性或正确的缩放比例；下面的 UPS 和 lmSensors 缺陷需要引起注意。

## 传感器的两种形态

对于 SNMP 收集，区分标量对象与已索引的表格实例。

**固定 OID。** 一个地址处的一个标量值，在该类型的每台设备上都是相同的地址。电池温度。总输出功率。使用固定 OID 数据源：针对字面 OID 的 SNMP get，每个读数对应一个数据源。

**表格。** 每台设备发现的读数数量未知。机架探针、插座排、分相测量。使用数据查询，它会遍历表格，了解索引，并允许您挑选哪些行生成图表。

随附的 UPS 软件包同时使用了这两种形态。遵循 MIB 的对象结构：仅有一个电流探头的设备仍可能将其暴露为索引表行。

| UPS 读数 | 形态 | OID |
|---|---|---|
| 电池温度 | 固定 | `.1.3.6.1.2.1.33.1.2.7.0` |
| 预计剩余运行时间 | 固定 | `.1.3.6.1.2.1.33.1.2.3.0` |
| 电池供电时间 | 固定 | `.1.3.6.1.2.1.33.1.2.2.0` |
| 电池电压 | 固定 | `.1.3.6.1.2.1.33.1.2.5.0` |
| 存在的告警 | 固定 | `.1.3.6.1.2.1.33.1.6.1.0` |
| 输入电压、电流、功率、频率 | 查询 | `.1.3.6.1.2.1.33.1.3.3.1` |
| 输出电压、电流、功率、负载 | 查询 | `.1.3.6.1.2.1.33.1.4.4.1` |

这些数据源中的每一个都是 `GAUGE`。没有一个是计数器。随附的模板归档声明了 60 秒的步长和 600 秒的心跳，最小值为零，没有最大值，但温度没有最小值。检查导入的配置文件和实际的 RRD 配置；这些声明并不能确定运行中的轮询节奏。有效的负读数还需要一个显示它的图表轴。

## 寻找 OID

在编写任何内容之前遍历设备。您要寻找三样东西：读数表、平行的标签表以及供应商选择的任何乘数，加上可用时的有效性/状态对象。

```bash
snmpwalk -v2c -c public probe.example.net .1.3.6.1.2.1.33
# Replace this example enterprise number with the vendor's actual number.
vendor_oid='.1.3.6.1.4.1.318'
snmpwalk -v2c -c public probe.example.net "$vendor_oid"
```

将示例主机和共同体替换为配置的值，并从轮询器运行探测。加载匹配的 MIB 及其依赖项以检查名称、单位和语义；供应商对象文档也可以解释数字 OID。附近的阈值或状态码不能与测量值互换。

```bash
snmptranslate -m +UPS-MIB -Td -OS .1.3.6.1.2.1.33.1.2.7
```

MIB 定义是记录缩放比例的地方。报告十分之一度的供应商将在对象的描述或单位子句中以及关联的供应商文档中进行说明。从单次读数猜测可能会将 23.5 度变成 235 度的图表。

标准 MIB 涵盖的范围超出了人们的预期。位于 `.1.3.6.1.2.1.33` 的 UPS-MIB 在各个供应商之间是通用的。ENTITY-SENSOR-MIB 提供了传感器值，并在其旁边附带了自己的缩放比例和精度字段。在寻求企业子树之前，请先检查这些内容。

在测试安装中对比具有代表性的重启和探针更换前后的发现。两次未改变的 walk 本身不能证明索引的稳定性。在创建长期图表之前，记录稳定的传感器标识（如果有）。

## 构建固定 OID 数据源

固定 OID 传感器需要一个使用 SNMP get 数据输入的数据模板，其中 OID 作为字面值，并包含一个数据源项目。将类型设置为 `GAUGE`，仅当传感器确实无法低于该值时才为最小值赋予实际值，并且除非供应商记录了上限，否则将最大值保留为未定义。

超出 RRD 数据源边界的值将变成未知。在存储的原始单位中设置这些边界，而不是在图表的转换单位中；否则，有效读数可能会在应用显示 CDEF 之前丢失。

## 构建数据查询

查询需要一个索引 OID、一种将每个遍历到的 OID 转换为索引的方法，以及所需的每列一个字段。

UPS 输出查询是一个简短的现成示例。它在输出线路上建立索引，使用正则表达式从每个返回的 OID 末尾解析出索引，并声明一个用于索引的输入字段和四个用于电压、电流、功率和负载的输出字段。输出定义包括方法、来源、方向和列 OID。列 OID 可以是有效的索引遍历根；匹配查询的解析器与实际返回的 OID 才是关键。有关如何选择和存储索引，请参见[数据查询和索引](/zh-cn/concepts/data-queries-and-indexes/)。

审慎选择重新索引方法。选项包括无、正常运行时间倒退时、索引计数更改时以及验证所有字段。传感器表是较弱方法失效的典型场景：从机架单元上拔下一个探针并插入另一个探针，计数可能不会更改，而索引背后的每个读数现在都属于不同的传感器。完全验证会在每个周期消耗 SNMP 开销。验证查询可以检查哪些标识字段：未改变的数字索引或重复/截断的标签不能证明物理探针是同一个。更换后刷新发现并检查图表关联。

## 缩放数值

决定在何处进行转换，并且只将其放在一个地方。

| 位置 | 何时使用 |
|---|---|
| 在收集脚本中 | 使用记录的收集器约定；lmSensors get 当前返回原始单位 |
| 在图表项的 CDEF 中 | 原始值值得存储，且显示单位是呈现选择 |

CDEF 是处理供应商乘数的通常方案。随附的软件包携带诸如 `Divide By 10` 之类的定义，它由当前数据源、`10` 和除法构建而成。仅将它们应用于具有相应原始单位的对象。

UPS 软件包具有[不正确的功率和时间 CDEF](https://github.com/kadupulhq/kadupul/issues/249)：其 On Battery 系列将秒除以 6000 而不是 60，而输入/输出 Watts 系列将瓦特除以 10。对于合规的代理，600 秒应显示为 10 分钟，1000 瓦应显示为 1000 瓦。电池电压和线路电流确实需要除以 10；预计剩余运行时间已经是分钟。参见 [RFC 1628 的 UPS 对象单位](https://www.rfc-editor.org/rfc/rfc1628.html)。

存储原始读数并在图表上进行除法运算可以保持 RRD 文件的真实性，并允许您在不重写原始历史记录的情况下更正显示乘数，前提是样本在数据源边界和保留期中幸存下来。收集器端转换会更改存储的单位并可能丢弃精度；请记录它。未解释的原始读数不应作为经过验证的工程单位呈现。

不要重复应用转换。在脚本已经缩放了数值的图表上使用 CDEF 可能会产生看似合理但不正确的读数。

## 提供适合测量值的图表设置

为测量值选择设置，而不是盲目照搬流量默认值。

| 设置 | 流量 | 传感器 |
|---|---|---|
| 数据源类型 | `COUNTER` | `GAUGE` |
| 基数值 | 1000，以便坐标轴以 k 和 M 为单位读取 | 仍为 1000，但在度数上前缀毫无意义 |
| 自动缩放 | 需要，因为范围未知 | 通常不需要，因为范围已知 |
| 上限和下限 | 取决于自动缩放模式 | 选择有用的可见范围 |

设置显式的上限和下限，以及命名实际单位的垂直标签。随附的 UPS 温度图表就是这样做的：下限为 0，上限为 100，垂直标签为 `C`。

自动缩放选项是一组选择，而不是一个开关。随附的温度图表所使用的选项传递带有 `--alt-autoscale-max` 的下限；它不传递存储的上限 100。没有刚性边界时，超出范围的读数可以扩展传递的限制。配置的限制不会自动固定。选择保留您关心的边界的变体：

| 选项 | 效果 |
|---|---|
| 忽略限制的自动缩放 | 两端浮动。在对范围一无所知时使用 |
| 接受下限的自动缩放 | 传递下限；最大值跟随数据 |
| 接受上限的自动缩放 | 传递上限；最小值跟随数据 |
| 接受双重限制的自动缩放 | 传递双重限制；扩展仍取决于刚性模式 |

还有一个刚性边界选项，当数值落在您设置的限制之外时，它会阻止坐标轴扩展。当固定坐标轴比观察偏移更重要时开启它，而在不重要时保持关闭，因为刚性图表可以剪裁显示范围之外的偏移。这不会删除存储的样本。参见 [RRDtool 图表限制参考](https://rrdtool.org/rrdtool/doc/rrdgraph.en.html)。

对于使用 SI 前缀会使读者困惑的度数或百分比，请考虑将单位指数设为 0。基数 1000 控制前缀阶梯；它本身并不禁用前缀或转换测量单位。

### 合并在此处比在流量上更重要

在接口计数器上一小时内的平均值仍能大致告诉您发生了什么。在温度上一小时内的平均值则掩盖了至关重要的十分钟偏移。确保这些数据源背后的存储配置文件保留 `MAX` 归档，并将绘制的系列配置为读取适当的 `MAX` 合并。在 `AVERAGE` 系列上的图例最大值无法恢复原始峰值。

即使是 MAX 归档也只能保留收集到的样本中体现的峰值；它无法恢复轮询之间的偏移或存储前被拒绝的值。参见[管理数据保留](/zh-cn/guides/manage-data-retention/)和[数据源和归档](/zh-cn/concepts/data-sources-and-rras/)。

## 没有值得使用的 MIB 时

大量环境设备使用 Modbus、串行协议或 HTTP API，其 SNMP 代理没有暴露任何有用的内容。这些设备需要脚本数据输入。脚本在轮询器主机上运行，而不是在设备上运行，访问设备是脚本的问题。有关输出约定，请参见[编写数据收集脚本](/zh-cn/guides/write-a-data-collection-script/)。

当传感器不可达时返回 `U` 而不是 `0`。掉线的探头并不是读数为零度的探头。

## 故障模式

| 现象 | 常见原因 |
|---|---|
| 温度绘制为大十倍或百倍的数字 | 未通过除法排除供应商乘数 |
| 温度绘制为小十倍的数字 | 双重除法，一次在脚本中，一次在 CDEF 中 |
| 电压轨读数为数十亿 | 未经纠正的持有负值的无符号 SNMP 整数 |
| 更换探头后传感器图表变平 | 表格重新建立了索引，数据源现在指向不同的传感器 |
| 高于阈值的读数显示为断层 | 数据源上设置了最大值，实际值超过了该值 |
| 刻度在度数读数上标记为 k 或 M | 从流量模板继承的基数值和单位设置 |
| 偏移在周视图中不可见 | 检查所选的合并、保留的分辨率、轮询间隔和拒绝的样本 |
| 查询不返回索引 | 检查返回的 OID、解析器匹配、访问限制和对象支持；列根可以是有效的 |
| lmSensors 查询在 Linux 主机上未发现任何内容 | 检查代理支持、访问权限、暴露的传感器行和确切的 SNMP 错误 |
