Comunique as vulnerabilidades de forma privada, incluindo as que afetam código ainda não publicado. Não abra um relato público nem publique uma correção antes da avaliação privada.

Esta página é um resumo. Consulte a página completa em inglês para obter mais informações. [English](/project/security/)

[Política de segurança do repositório](https://github.com/kadupulhq/kadupul/blob/main/SECURITY.md)

## Comunicar uma vulnerabilidade de forma privada

Inclua a versão ou o commit, os passos para reproduzir o problema, a configuração necessária e se é exigida autenticação. Os responsáveis procuram confirmar o recebimento no prazo de três dias úteis; não se trata de uma data de correção garantida.

[Comunicar uma vulnerabilidade de forma privada](https://github.com/kadupulhq/kadupul/security/advisories/new)

As vulnerabilidades em código compartilhado exigem uma divulgação coordenada com os outros projetos afetados antes da publicação. Combine a atribuição de crédito e o calendário durante a avaliação privada.

A política abrange o aplicativo, o coletor, o instalador e a criação de pacotes. Exclui extensões de terceiros, RRDtool, Net-SNMP, o servidor web, o banco de dados e situações que exijam que um administrador aja contra a própria instalação.
