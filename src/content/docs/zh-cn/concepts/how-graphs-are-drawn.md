常规的图像请求可以根据图表配置拼装 RRDtool 命令并读取引用的 RRD 文件。有效的缓存图像也可以直接满足请求，而按需执行的 Boost 处理可以在渲染前更新文件。关于数据新鲜度限制，请参见[大容量写入](/zh-cn/concepts/high-volume-writes/)。

## 操作的先后顺序

对于进入命令生成阶段的请求：

1. 解析所请求的时间窗口与图表配置。
2. 根据数据库配置文件估算分辨率并选择整合函数。
3. 为所需的字段和函数输出去重后的 `DEF` 引用。
4. 输出所引用的 `CDEF` 与 `VDEF` 表达式。
5. 按配置好的顺序输出绘图与打印项，并应用相关选项及插件调整。
6. 让 RRDtool 读取实际文件并渲染最终结果。

## 选择归档

Kadupul 在计算归档跨度与图表选项时会查阅数据库配置行。其自动估算综合考量步长乘以步数乘以行数、所请求的时间跨度以及归档步数；显式归档选择则走独立路径。这些配置计算并不会检查每个文件中的每个物理归档，并且在修改配置文件后可能会与既有物理文件产生出入。

生成的 `DEF` 会指明文件、数据源名称及整合函数。RRDtool 会在合适的分辨率下选择可用的归档，并可能根据图表宽度和时间窗口进一步合并数据。应用程序的估算并不保证一定会读取特定的物理归档。参见上游的 [RRDtool 数据定义文档](https://oss.oetiker.ch/rrdtool/doc/rrdgraph_data.en.html)。

放宽时间窗口或调整图像宽度都可能改变展示的分辨率。基于平均值的粗粒度序列可能会掩盖短暂的峰值，即使更细致的归档中仍然保存着该峰值。请比对物理文件的实际布局与执行命令，而不仅仅参考配置文件。参见[数据源与轮询归档](/zh-cn/concepts/data-sources-and-rras/)。

当调用者未提供结束时间时，常规渲染器初始会采用主采集器上次运行相对于当前时刻的偏移量；若该值不可用或位于未来，则回退为轮询间隔。后续代码也具备针对合并间隔的回退机制，但这不是普遍通用的默认行为。显式指定的结束时间会覆盖此默认初始化；图表结束于当前时刻之前本身既不能确定选中的归档，也不能证明最新样本已经写入。

## 图表项

图表是一个有序的项列表。命令生成过程可以忽略某些项、复用定义，或将单个项展开为多条指令。绘制顺序的作用远不止决定视觉布局。

| 项 | 绘制内容 | 说明 |
|---|---|---|
| `AREA` | 从坐标轴到数值之间的填充区域 | 后绘制的区域会覆盖先绘制的区域 |
| `STACK` | 从前一项顶部开始绘制的填充区域 | 作为带有堆叠标志的面积图输出 |
| `LINE1`、`LINE2`、`LINE3` | 宽度为一、二或三个像素的线条 | 可以设定为虚线 |
| `LINE:STACK` | 绘制在当前累计堆叠总量顶部的线条 | |
| `TICK` | 沿图表边缘绘制的刻度标记 | 适用于状态标记，而非量级展示 |
| `GPRINT` | 无绘制。在图例中打印一个数值 | |
| `COMMENT` | 无绘制。在图例中打印字面文本 | 较长的注释文本会自动换行 |
| `HRULE` | 固定数值处的水平标线 | |
| `VRULE` | 固定时间点处的垂直标线 | |
| `TEXTALIGN` | 无绘制。设置其后图例文字的对齐方式 | |

完整列表以及各配置列适用的类型说明，请参见[图表项](/zh-cn/reference/graph-items/)。

`AREA` 与 `STACK` 是最容易让人混淆的一对组合。面积图从零刻度起算，因此两个面积图会相互重叠，较高的面积会遮盖较低的面积。堆叠图从前一项结束的位置起算，因此第二层的可见高度代表其自身数值，但其顶边缘指示的是累计总量。请将堆叠图解读为色带的厚度，而不是其在 Y 轴上的绝对高度坐标，否则除了最底层的序列之外，其他序列都会被误读。

`HRULE` 接受一个可包含模板替换变量的数值。非数字字符会从最终结果中剥离；如果剥离后没有剩余任何数字，该标线会在零刻度处绘制，而不是导致整个渲染失败。位于零刻度的水平线可能是刻意为之，也可能是变量替换失败的结果。在下结论前请先审查解析后的具体命令。数字过滤器还可能改变包含单位或非标准数字表示法的字符串。

`VRULE` 接受 Unix 时间戳或 `hours:minutes` 时间对。负数小时分量会被解析为相对于当前时刻向后倒退的时间偏移，而不是具体钟表时间。

## 两个任务，同一词汇

整合函数这一术语用于两种截然不同的用途，并且相同的四个名称——`AVERAGE`、`MIN`、`MAX` 和 `LAST`——同时出现在这两个场景中。

第一个任务是归档选择。一条 `DEF` 会指定文件、其中的数据源以及整合函数。该函数限定了所请求的归档族。若请求 `MAX`，RRDtool 就需要匹配已存储的整合数据，具体取决于下文所述的应用程序回退逻辑及分辨率选择。

第二个任务是图例运算。一条 `GPRINT` 会将绘制的整个时间窗口压缩为一个打印出来的数字，其函数决定了计算方式。这种规约是在已读取的序列数据上完成的；它是用于呈现的聚合，而不是物理存储。

因此，在通过 `AVERAGE` 读取的 `DEF` 上使用显示 `MAX` 的 `GPRINT`，打印出的是该均值序列在渲染窗口内的最大值，而不一定是原始采样的绝对峰值。五分钟只是一个例子；实际有效分辨率各有不同。这是完全不同的两个数字，在繁忙的链路上其差异极其显著。这两种读数在逻辑上都是合法的。但通常只有其中一种符合您的真实意图。

## 隐式回退机制

对于使用最佳函数辅助逻辑的项类型，Kadupul 会读取文件支持的整合函数，若存在所请求的函数则直接使用，否则采用列表报告的首个函数。如果对一个合法的本地数据源未能获取到任何函数，该辅助逻辑会回退到 AVERAGE。固定格式的 GPRINT 变体走单独路径且不使用该辅助逻辑，因此这并不构成修复所有缺失函数的绝对承诺。

因此，请求 `MAX` 的绘图项在其物理文件仅包含 AVERAGE 归档时，最终可能会读取均值数据。请检查生成的 `DEF` 以及 `rrdtool info` 的输出。归档维护操作可以修改现有布局，但追加新归档无法找回早期因均值计算而被丢弃的历史峰值。参见[管理数据保留期](/zh-cn/guides/manage-data-retention/)。

## GPRINT 借用邻近项的归档

普通的 `GPRINT` 本身没有专属于自己的归档。它会复用最近的匹配项（`AREA`、`STACK`、线条或 `TICK`）所使用的整合函数，匹配依据为数据源名称及本地模板字段标识。如果没有前置匹配项，它将使用最佳函数辅助逻辑以及自身配置的函数。固定格式的变体则直接采用其自身配置的函数。

这意味着在图表模板中调整项的排列顺序，可能会在无人改动图例的情况下直接改变图例显示的数据。如果在 `GPRINT` 块上方放置一个读取 `MAX` 的 `LINE`，匹配的图例就会汇总最大值。若将其移动到下方，则前置匹配项或无匹配回退机制将决定输入的序列。如果图例中的数字在对模板进行无关修改后发生改变，请首先核对各项的顺序。

## CDEF 与 VDEF

两者都在数据绘制前对数据进行转换。它们之间不可互换。

| | CDEF | VDEF |
|---|---|---|
| 生成结果 | 数据序列，每个时隙一个数值 | 标量数值，特定函数下还会附带关联时间 |
| 绘制形态 | 可绘制为线条或面积 | 标量可用于提供固定水平参考线 |
| 构成要素 | 函数、算术运算符、其他 CDEF、特殊数据源、字面量 | 作用于单一引用的单个函数 |
| 嵌套支持 | CDEF 可以引用另一个 CDEF | VDEF 内部不能包含算术运算 |

CDEF 是采用逆波兰表示法计算的堆栈表达式。其操作符词汇非常丰富，详见[图表项](/zh-cn/reference/graph-items/)：算术运算、比较与条件运算符、三角函数、跨数据源聚合、堆栈操作以及用于获取 X 轴位置的时间函数。`UN` 与 `UNKN` 值得尽早掌握。用零替代未知值虽然可以消除图表视觉上的断层，但也会掩盖数据缺失的真实情况；请权衡并明确这种呈现取舍。

CDEF 还可以读取特殊引用而不是固定的数据源名称。其中一个会解析为当前项的数据源，这使得单个 CDEF 可以在模板的所有项之间重复使用。其他引用可解析为图表上的全部数据源或所有同类数据源（可选包含或排除重复项），这就是无需枚举各项输入即可构建总计线条的原理。

VDEF 将序列规约为标量：最大值、最小值、平均值、标准差、首值、末值、总和、百分位数，或是最小二乘法拟合的斜率、截距与相关系数。RRDtool 不支持在 VDEF 内部进行算术运算，因此当 VDEF 需要计算输入时，Kadupul 会将其建立在该项的 CDEF 之上，而不是原始数据源上。这是推荐的计算路径：先在 CDEF 中完成数学运算，然后再通过 VDEF 进行规约。

基于 VDEF 的 `GPRINT` 不需要整合函数参数：VDEF 已经完成了规约计算。VDEF 还可以提供用于绘图的标量值；RRDtool 支持基于 VDEF 绘制线条。参见上游的[图表元素文档](https://oss.oetiker.ch/rrdtool/doc/rrdgraph_graph.en.html)。

CSV 导出功能会将支持的绘图类型作为序列列进行导出；图例项不会作为等价的数据列导出。与早期的描述不同，当前代码通常不会跳过基于 VDEF 的绘图项。它可能会为标量 VDEF 输出非法的 `XPORT` 指令：独立的 RRDtool 测试可以正常渲染 VDEF 线条，但会拒绝此类导出。参见[应用程序缺陷 #273](https://github.com/kadupulhq/kadupul/issues/273)。进行数据导出时请使用基于序列的绘图项，并核验生成的数据列。

## 为什么相同的数据看起来会有差异

以下每一项设置都会在不改变任何底层存储样本的前提下改变最终呈现的图像。

| 选项 | 影响效果 |
|---|---|
| 时间窗口跨度与图像宽度 | 可能改变归档选择并触发额外的合并整合 |
| `DEF` 上的整合函数 | 决定读取的是峰值、谷值、均值还是末值 |
| 整合函数缺失 | 部分项路径会替代为其他函数；其他路径则可能报错 |
| `AREA` 与 `STACK` | 表现为绝对高度与累计递增高度的差异 |
| 项的排列顺序 | 影响绘制遮盖、堆叠层级以及 `GPRINT` 所借用的归档 |
| 基数 1000 或 1024 | 更改坐标轴单位刻度。底层数值完全相同 |
| 自动缩放模式、刚性极限、对数刻度 | 改变 Y 轴比例，从而影响视觉上波动幅度的大小感知 |

当图表呈现不符合预期时，请对比渲染出的具体命令、物理文件的标识与布局、缓存状态以及采样的时效性。这些呈现层面的选项是极佳的排查切入点，但并不排除采集、存储或映射阶段本身存在错误。关于具体的排查步骤，请参见[排查缺失数据](/zh-cn/guides/troubleshoot-missing-data/)。
