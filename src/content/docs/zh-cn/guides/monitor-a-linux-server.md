运行 net-snmp 的 Linux 主机无需编写任何额外代码即可提供大部分所需指标。关键任务在于引导 `snmpd` 暴露正确的子树，并明确您正在查看两个重叠磁盘 MIB 中的哪一个。

## snmpd 需要暴露的内容

Kadupul 轮询四个区域。为监控身份授予所选图表所需的子树权限；并非每个部署都需要所有子树。

| 区域 | 子树 | 提供的内容 |
|---|---|---|
| 系统 | `.1.3.6.1.2.1.1` | 描述、运行时间、联系人、名称、位置 |
| 接口 | `.1.3.6.1.2.1.2` 和 `.1.3.6.1.2.1.31` | 流量、错误、状态 |
| 主机资源 | `.1.3.6.1.2.1.25` | 进程、已登录用户、存储、处理器 |
| UCD / net-snmp | `.1.3.6.1.4.1.2021` | 平均负载、内存、CPU 时间、磁盘 I/O、已声明分区 |

若干 Linux 发行版附带的默认 `snmpd.conf` 仅授予覆盖系统子树的视图。设备能够响应并报告系统描述，但不会采集任何实际指标。这种组合是 Linux 主机上最常见的第一道故障，其表象与模板问题完全一致。

使用设备上配置的相同 SNMP 身份从轮询器主机检查所需区域。这些示例使用说明性团体名（community）；请替换为您配置的实际值。数值 OID 可避免依赖本地符号 MIB 定义。

```bash
snmpget  -v2c -c public server.example.net .1.3.6.1.2.1.1.1.0
snmpwalk -v2c -c public server.example.net .1.3.6.1.4.1.2021.10.1.3
snmpwalk -v2c -c public server.example.net .1.3.6.1.2.1.25.2.3.1.3
```

如果只有第一个命令有效，请深入排查具体响应：受限视图、不可用的代理模块、不同的 SNMP 上下文或空表都可能解释该结果。在修改 Kadupul 模板之前，请核实代理配置与访问权限。

## 添加设备

附带的软件包 `install/templates/NetSNMP_Device.xml.gz` 包含 Net-SNMP 设备模板及其依赖项。如果模板缺失，请先导入，然后在添加设备时予以选择。确认查询索引并显式创建所需图表；选择设备模板并不代表数据采集已正常工作。请参阅[导入模板](/zh-cn/guides/import-and-export-templates/)与[您的第一个图表](/zh-cn/start/first-graph/)。

## 无需数据查询即可获取的内容

这些固定 OID 数据模板已包含在软件包中。一个图表可以组合其中的多个模板；可用性取决于目标代理。它们不需要索引发现。

| 图表 | OID | 存储类型 |
|---|---|---|
| 1 分钟平均负载 | `.1.3.6.1.4.1.2021.10.1.3.1` | `GAUGE` |
| 5 分钟平均负载 | `.1.3.6.1.4.1.2021.10.1.3.2` | `GAUGE` |
| 15 分钟平均负载 | `.1.3.6.1.4.1.2021.10.1.3.3` | `GAUGE` |
| 总内存 | `.1.3.6.1.4.1.2021.4.5.0` | `GAUGE` |
| 可用内存 | `.1.3.6.1.4.1.2021.4.6.0` | `GAUGE` |
| 缓冲内存 | `.1.3.6.1.4.1.2021.4.14.0` | `GAUGE` |
| 缓存内存 | `.1.3.6.1.4.1.2021.4.15.0` | `GAUGE` |
| 用户 CPU | `.1.3.6.1.4.1.2021.11.9.0` | `GAUGE` |
| 系统 CPU | `.1.3.6.1.4.1.2021.11.10.0` | `GAUGE` |
| 空闲 CPU | `.1.3.6.1.4.1.2021.11.11.0` | `GAUGE` |
| 中断 | `.1.3.6.1.4.1.2021.11.7.0` | `GAUGE` |
| 上下文切换 | `.1.3.6.1.4.1.2021.11.8.0` | `GAUGE` |
| 进程数 | `.1.3.6.1.2.1.25.1.6.0` | `GAUGE` |
| 已登录用户数 | `.1.3.6.1.2.1.25.1.5.0` | `GAUGE` |

内存对象以千字节（KB）为单位。附带的内存图表应用了转换，使轴以字节显示。如果您根据这些 OID 构建自己的图表，该转换需由您自行负责。

列出的 CPU 对象是已废弃的百分比，并非累积 CPU 时间计数器。请勿假设仅凭这三项就能涵盖所有处理器状态。Net-SNMP 已废弃它们，转而推荐使用原始计数器；原始计数器需要进行适当的速率和百分比计算，而不是直接代入 gauge 模板。请参阅 [UCD-SNMP-MIB](https://www.net-snmp.org/docs/mibs/ucdavis.html)。

## 需要数据查询的内容

| 查询 | 发现对象 | 支持依据 |
|---|---|---|
| SNMP - 获取挂载点 | 代理称为存储的所有内容 | `hrStorageTable`, `.1.3.6.1.2.1.25.2.3.1` |
| Net-SNMP - 获取监控分区 | 仅限 `snmpd.conf` 中声明的分区 | `dskTable`, `.1.3.6.1.4.1.2021.9.1` |
| SNMP - 获取处理器信息 | 每个 CPU 一个条目 | 主机资源处理器负载 |
| Net-SNMP - 获取设备 I/O | 块设备 | `diskIOTable`, `.1.3.6.1.4.1.2021.13.15.1.1` |
| SNMP - 接口统计信息 | 网络接口 | `IF-MIB` |

### 该使用哪种磁盘查询

它们并非同一数据的两种不同视图。

主机资源查询会遍历代理报告为存储的所有内容。在大多数 Linux 主机上，这会将物理内存、交换分区、tmpfs 挂载和真实文件系统集中在一个列表中。大小以分配单元返回，查询将分配单元大小作为单独字段读取以便图表进行相乘。您无需配置任何内容即可获取所有信息，但也会得到大量不需要的条目。

net-snmp 查询读取 UCD 磁盘表，该表由 `disk` 指令或 `includeAllDisks` 填充。选择显式分区或广泛发现属于不同的策略。

```
disk /      10%
disk /var   10%
```

或者，`includeAllDisks 10%` 会在代理启动时填充发现的磁盘。10% 的值配置的是可用空间阈值；它不是选择过滤器，本身也不配置 Kadupul 警报。重新加载或重启代理，然后复查索引。空查询也可能反映访问权限问题或模块可用性问题。请参阅 [snmpd 配置](https://www.net-snmp.org/docs/man/snmpd.conf.html)。

当您追求完整性并愿意清理无关项时，优先选择主机资源查询。当您需要精准定向的列表时，优先选择带有显式 `disk` 条目的 net-snmp 查询。`includeAllDisks` 会扩大该列表；在代理重启后请重新检查索引。

### 网络接口

服务器上的接口数据查询与交换机上的完全一致，但有一个注意事项：Linux 下的 `ifDescr` 是内核接口名称，重启或驱动程序更新后可能会发生变动。有关索引选择的详细信息，请参阅[监控交换机](/zh-cn/guides/monitor-a-switch/)。

## 当 SNMP 不足时

某些指标缺乏可用的 MIB。队列深度、应用程序计数器或文件中的数字都需要脚本输入。

两项事实决定了您编写脚本的方式：

**脚本运行在执行轮询器的机器上，而不是被监控的主机上。** 到达目标主机是您脚本的职责：SSH、HTTP 调用、专用代理或任何您已部署的机制。

**轮询器只读取标准输出，不读取其他内容。** 退出状态不会被评估。

输出规范契约：

| 输出 | 含义 |
|---|---|
| `42` 或 `3.7` | 单个数据源的单一数值 |
| `U` | 本周期无数值，记录为未知（unknown） |
| `in:1420 out:980` | 多个数值，每个数据源一个 |

对于多值格式，键值对之间用单空格分隔，名称与值之间用冒号分隔。解析器会计算分隔符与空格，因此多余的内部空格可能导致验证失败。PHP 轮询器会去除末尾空白字符。请使用单空格的标准格式输出，并将诊断信息重定向离开 stdout。

模板编辑器接受的内部 RRD 数据源名称符合 `[a-zA-Z0-9_]{1,19}`；此处不接受连字符。脚本输出标签必须与数据输入字段名称匹配，并映射到目标内部元素。整个输出行存储在 512 字符的列中。有关经审核的 PHP 轮询器契约，请参阅[编写数据收集脚本](/zh-cn/guides/write-a-data-collection-script/)。

当无法测量某个值时，请返回 `U` 而不是 `0`。零本身是一个有效测量值，并将以此呈现。请参阅[数据源与 RRA](/zh-cn/concepts/data-sources-and-rras/)了解为何要将两者区分开来。

### 脚本服务器

普通脚本在每个间隔内针对每个数据源执行一次。对于用 PHP 编写的脚本，脚本服务器形式会在一个持久独立的 PHP 进程中调用函数，从而减少解释器启动开销。

### 白名单陷阱

当启用数据输入白名单文件时，轮询器会将每个数据输入的命令字符串与记录的字符串进行比对。未经重新生成白名单而发生变更的命令字符串将停止创建轮询器缓存条目，且数据源将在图表上静默失效而无报错。日志会对此进行报告，但 UI 不会。

```bash
php cli/input_whitelist.php --audit
php cli/input_whitelist.php --update --id=42
```

请将 `42` 替换为经过审核的数据输入方法的 ID，而不是设备 ID。不带 `--id` 的更新将接受整个输入清单中的当前命令字符串。请预先审核更改。更新后，请验证数据源启用状态及有效的轮询器缓存条目。

## 故障模式

| 症状 | 常见原因 |
|---|---|
| 能读取系统描述，无法采集其他数据 | `snmpd` 视图受限于系统子树 |
| Net-SNMP 分区查询未找到索引 | `snmpd.conf` 中缺少 `disk` 或 `includeAllDisks` 行 |
| 主机资源分区包含 RAM 和 tmpfs | 正常现象；代理将它们均报告为存储 |
| 内存图表偏差 1024 倍 | 直接基于原始 OID 构建而未做单位转换 |
| 脚本在命令行返回数值，轮询器记录为 unknown | 输出/映射不匹配、内部定界符错误或无效内部名称 |
| 脚本手动执行正常，但通过轮询器失败 | 运行身份为轮询器用户，环境及权限受其限制 |
