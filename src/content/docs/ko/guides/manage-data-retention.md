:::caution[사용 전 검증 필요]
소스 코드는 공개되어 있지만, 공식적으로 지원되는 Kadupul 릴리스나 마이그레이션 경로는
아직 없습니다. 본 운영 환경에 적용하기 전에 백업이 준비된 격리 환경에서 이 절차를

데이터 보존 정책은 파일 생성 시 설정되며 정상적인 데이터 갱신 과정에서는 변경되지 않습니다. 나중에
프로필을 수정하더라도 다음에 새로 생성되는 파일의 구조만 변경될 뿐 기존 파일은 모두
이전 상태 그대로 유지됩니다. 수만 개의 데이터 소스를 생성하기 전에 이 설정을 올바르게 구성하십시오.
추후 변경하려면 명시적인 파일 유지보수나 데이터 마이그레이션이 필요합니다.

스텝(step), 하트비트(heartbeat), 아카이브, 통합(consolidation)이라는 용어가 아직
생소하다면 [데이터 소스 및 아카이브](/ko/concepts/data-sources-and-rras/)를 먼저 읽어보십시오.

## 프로필이 포함하는 내용

데이터 소스 프로필은 데이터 보존 정책을 정의합니다. 하나의 프로필이 하나의 스토리지 저장 형태를 결정합니다.

| 필드 | 의미 |
|---|---|
| 폴링 주기 (step) | 새로운 데이터 값이 입력될 것으로 예상되는 간격 (초 단위) |
| Heartbeat | 입력 데이터가 '알 수 없음(unknown)'으로 처리되기 전까지 허용되는 최대 갱신 간격 |
| X-Files 팩터 | 통합 값이 알 수 없음으로 처리되기 전까지 통합 윈도우 내에서 허용되는 알 수 없는 값의 최대 비율 |
| 통합 함수 | `AVERAGE`, `MIN`, `MAX`, `LAST` 중 보존할 함수 목록 |
| 아카이브 | 해상도별 레코드 행. 각각 집계 수준과 행 수를 포함 |
| 기본값 | 신규 데이터 소스 생성 시 이 프로필을 기본으로 선택할지 여부 |

스텝은 기본적으로 폴러의 실행 주기와 동일하게 설정됩니다. 폴링 주기보다 더 미세한 스텝을 가진
프로필을 설정하더라도 수집되지 않은 세부 데이터를 복원할 수는 없습니다. 행에
알 수 없는 값이 포함되는지 여부는 하트비트 설정과 RRDtool의 정규화 방식에 따라 결정됩니다.

## 기본 제공 프로필

시스템 설치 시 3가지 기본 프로필이 제공됩니다. 3가지 모두 4가지 통합 함수를 완전히 유지합니다.

| 프로필 | Step | Heartbeat |
|---|---|---|
| 5 Minute Collection | 300s | 600s |
| 1 Minute Collection | 60s | 600s |
| 30 Second Collection | 30s | 1200s |

5분 수집 프로필이 시스템의 기본값입니다.

각 프로필은 4개의 아카이브를 갖습니다. 집계 수준은 스텝 배수로 표현되므로,
실제 해상도는 배수 곱하기 프로필 스텝이 되며, 전체 보존 기간은
해당 해상도 곱하기 행 수가 됩니다.

### 5 Minute Collection

| 아카이브 | 배수 | 행 수 | 해상도 | 보존 기간 |
|---|---|---|---|---|
| Daily | 1 | 600 | 5분 | 약 2일 |
| Weekly | 6 | 700 | 30분 | 약 14일 |
| Monthly | 24 | 775 | 2시간 | 약 64일 |
| Yearly | 288 | 797 | 1일 | 약 2년 2개월 |

### 1 Minute Collection

| 아카이브 | 배수 | 행 수 | 해상도 | 보존 기간 |
|---|---|---|---|---|
| Daily | 1 | 2900 | 1분 | 약 2일 |
| Weekly | 15 | 1440 | 15분 | 15일 |
| Monthly | 60 | 8784 | 1시간 | 약 366일 |
| Yearly | 720 | 7305 | 12시간 | 약 10년 |

### 30 Second Collection

| 아카이브 | 배수 | 행 수 | 해상도 | 보존 기간 |
|---|---|---|---|---|
| Daily | 1 | 2900 | 30초 | 약 1일 |
| Weekly | 30 | 1346 | 15분 | 약 14일 |
| Monthly | 120 | 1445 | 1시간 | 약 60일 |
| Yearly | 480 | 4380 | 4시간 | 2년 |

이름은 단순한 식별 라벨일 뿐 특정 동작을 강제하지 않습니다. "Yearly"라는 이름의 아카이브가
정확히 1년 치 데이터를 보존하도록 강제하는 제약 조건은 없습니다.

## 프로필이 파일로 변환되는 방식

파일 생성 시 프로필의 아카이브 및 통합 함수 설정을 읽어
create 명령어로 변환합니다. 스텝은 데이터 소스에 저장된 `rrd_step`
값에서 가져오며, 대개 해당 프로필에서 자동으로 채워집니다. 포함된 각 데이터 소스 항목은 이름,
타입, 하트비트, 최솟값, 최댓값을 담은 정의 라인을 생성합니다. 각 아카이브는
통합 함수마다 한 줄씩 함수명, X-Files 팩터, 배수, 행 수를 담은 정의를 추가합니다.

4개의 아카이브에 4개의 통합 함수를 적용하면 파일 내부에는 총 16개의 아카이브 정의가 생성됩니다.
이러한 곱셈 연산이 디스크 공간을 실질적으로 소모하는 원인이 됩니다.

파일이 이미 존재하는 경우 일반적인 생성 경로는 파일을 덮어쓰지 않고 중단됩니다.
프로필을 수정해도 기존 파일이 자동으로 마이그레이션되지는 않습니다. 명시적인 유지보수 도구를
사용한 작업은 아래에서 설명하는 별도의 절차입니다.

## 정책 선택

다음 3가지 질문을 순서대로 검토하십시오.

**요구되는 가장 세밀한 데이터 질의 단위는 무엇입니까?** 이것이 스텝을 결정합니다.
30초 스텝은 "90초 동안 발생한 일시적 이상 현상 동안 무슨 일이 있었는지"에 답할 수 있습니다. 5분 스텝은
그 아래에서 생성된 파일에 대해 어떠한 경우에도 이에 답할 수 없습니다. 스텝이 미세할수록 매 주기마다 폴러의
연산 부하가 증가하고 디스크 공간이 더 많이 소모됩니다.

**그 세밀한 데이터를 얼마나 먼 과거까지 조회할 것입니까?** 이것이 일일 아카이브의 행 수를 결정합니다.
대부분의 환경에서는 며칠 정도만 최고 해상도로 유지하고, 그 이후의 과거 데이터는
더 거친 집계 데이터로 만족합니다.

**통합 과정을 거친 후에도 살아남아야 하는 질문은 무엇입니까?** 이것이 통합 함수를 결정합니다.
`AVERAGE`는 일반적인 상태가 어떠했는지 답합니다. `MAX`는 가장 심각했던 피크가 얼마였는지 답합니다.
`MIN`은 일시적인 중단이나 급락이 있었는지 답합니다. `LAST`는 해당 윈도우의 마지막 값이 얼마였는지 답하며,
이는 변화율이 아닌 상태를 나타내는 지표에서 필수적입니다.

4개의 통합 함수 중 하나를 제외하면 모든 해상도에서 신규 파일의
저장 용량을 4분의 1 줄일 수 있습니다. 그러나 이는 관리자가 나중에 가장 자주 후회하는 결정이기도 합니다.
피크 데이터에 대해 묻는 사람이 아무도 없을 것이라 확신하지 않는 한 `MAX`를 반드시 유지하십시오.

## 디스크 용량 산정

단일 파일의 크기는 선택한 수치로부터 직접 도출됩니다. 인터페이스에서 사용하는
계산 수식은 다음과 같습니다.

```
file size = 284 + (data sources x (300 + total rows x 8 x consolidation functions))
```

인터페이스는 고정 오버헤드 추정치로 284바이트와 300바이트를 사용합니다.
이를 모든 RRDtool 파일 형식에 대한 엄격한 정의가 아닌 용량 계획을 위한 근사치로 취급하십시오.
저장되는 각 데이터 값은 8바이트를 차지하며, 총 행 수는 통합 함수를 곱하기 전 프로필의 모든 아카이브 정의에 포함된 행 수의 합입니다.
스토리지 크기를 확정하기 전에 설치된 RRDtool 환경에서 대표적인 파일을 직접 측정하십시오.

4개의 통합 함수를 모두 갖춘 단일 데이터 소스 파일의 경우:

| 프로필 | 총 행 수 | 대략적인 파일 크기 |
|---|---|---|
| 5 Minute Collection | 2872 | 92 KB |
| 30 Second Collection | 10,071 | 323 KB |
| 1 Minute Collection | 20,429 | 654 KB |

그래프 수가 아니라 예상되는 데이터 소스의 총수를 곱하십시오. 하나의
그래프가 하나 또는 여러 파일의 필드를 결합하여 렌더링될 수 있습니다. 실제 RRD 파일의 개수와
각 파일 내부에 포함된 데이터 소스 항목 수를 직접 집계하십시오.

기본 프로필 기준으로 데이터 소스 2만 개는 약 1.8 GB를 차지합니다. 동일한 2만 개를
1분 프로필로 운영하면 약 13 GB가 필요합니다. 이 비율은 단순한 스텝 차이뿐만 아니라
프로필 간의 서로 다른 보존 기간을 함께 반영합니다.
수집 주기를 촘촘하게 설정하면 디스크 쓰기 빈도 또한 급격히 증가합니다. 대규모 환경에서 세밀한 스텝을 선택하기 전에
[대용량 쓰기](/ko/concepts/high-volume-writes/)를 검토하십시오.

프로필 편집기와 아카이브 편집기는 숫자를 조정할 때마다 계산된 용량을 실시간으로 보여줍니다.
이를 적극 활용하십시오. 이러한 산술 계산에서는 자칫 4배의 오차가 쉽게 발생할 수 있습니다.

## 프로필 변경 시 적용되는 사항과 적용되지 않는 사항

이 동작을 혼동하여 과거 데이터를 잃어버리는 경우가 자주 발생합니다.

| 변경 작업 | 신규 파일에 미치는 영향 | 기존 파일에 미치는 영향 |
|---|---|---|
| 아카이브 추가 또는 삭제 | 적용됨 | 없음 |
| 행 수 수정 | 적용됨 | 없음 |
| 집계 수준 수정 | 적용됨 | 없음 |
| 통합 함수 추가 또는 삭제 | 적용됨 | 없음 |
| 스텝 변경 | 신규 데이터 소스가 상속받으며, 생성 시 저장된 스텝 사용 | 기존 파일은 자동 마이그레이션되지 않음 |
| 하트비트 변경 | 생성 시 저장된 데이터 소스 항목 메타데이터 사용(아래 참조) | 기존 파일은 자동 튜닝되지 않음 |
| 프로필 삭제 | 템플릿이나 데이터 소스가 참조 중인 경우 및 기본 프로필인 경우 거부됨 | 없음 |

**사용 중인 프로필의 하트비트를 변경하면 메타데이터만 갱신됩니다.** 새로운
하트비트를 저장하면 해당 프로필과 그 프로필을 사용하는 템플릿 및
로컬 데이터 소스의 항목에 값이 반영되지만, 다른 템플릿은 변경되지 않습니다.

저장 동작이 기존 RRD 파일을 자동으로 튜닝하지는 않습니다. 파일뿐만 아니라 메타데이터도 함께 백업하고,
하트비트 유지보수 작업 후 프로필, 템플릿 항목, 로컬 데이터 소스 항목 및 실제
`rrdtool info` 출력을 반드시 대조 검증하십시오.

메인 데이터 수집기의 `cli/update_heartbeat.php` 유틸리티를 사용하면 기존 파일을 튜닝하고
메타데이터를 갱신할 수 있습니다. 먼저 `--help`, `--list-heartbeats`,
`--list-data-templates`, `--list-profiles`를 실행해 보십시오. 새 하트비트 값은 시스템에서 지원되어야 하며
구성된 폴러 주기의 최소 2배 이상이어야 합니다. 대상 범위를 좁히려면 `--data-template-id`를 사용하십시오.
이 유틸리티에는 드라이런(dry-run) 옵션이 없습니다.

`--force` 옵션을 지정하지 않으면 선택한 프로필이 이미 요청된 하트비트 값을
가지고 있어야 합니다. `--force`를 사용하면 공유 프로필의 값도 변경되므로 진행하기 전에
해당 프로필을 사용하는 모든 대상을 확인하십시오. `--prev-heartbeat`는 각 RRD 파일에서 읽어온 값이 아니라
데이터베이스의 값을 필터링합니다. 웹에서 부분 저장한 후 이전 파일 값을 지정하면 아무것도 매칭되지 않을 수 있습니다.
선택 대상을 검증하고 처리 결과를 꼼꼼히 점검하십시오. 격리된 테스트 환경에서는
프로필 메타데이터를 정렬한 후 기존 파일을 600에서 900으로 성공적으로 튜닝했습니다.

이와 관련하여 두 가지 주의사항이 더 있습니다.

**프로필이 사용 중인 상태가 되면 편집기에서 구조적 변경이 제한됩니다.** 실제
데이터 소스가 프로필에 하나라도 연결되면 편집기 내에서 스텝, X-Files 팩터, 통합 함수,
아카이브 행 수, 집계 수준이 읽기 전용으로 전환되며 아카이브 추가/삭제 제어 버튼도 숨겨집니다.
프로필을 복제한 후 복제본을 편집하십시오. 이러한 인터페이스 수준의 제약이 제출된 요청에 대한
서버 측 검증을 대신하는 것은 아닙니다.

**프로필을 삭제하기 전에 참조 관계를 먼저 재할당하십시오.** 템플릿이나
로컬 데이터 소스가 프로필을 사용 중인 경우 목록에서 선택이 비활성화되며,
참조가 남아 있는 프로필에 대해 서버는 삭제를 거부합니다.

## 프로필 간 데이터 소스 이동

데이터 템플릿에는 프로필을 일괄 변경하는 작업이 제공됩니다. 이 작업은 템플릿에
기록된 프로필, 스텝, 하트비트를 다시 작성하지만, 대상은 의도적으로 템플릿 레코드 자체에만 국한됩니다.
기존에 생성되어 있는 데이터 소스는 포함되지 않습니다.

따라서 실제 마이그레이션의 올바른 순서는 다음과 같습니다.

1. 새 프로필을 생성하고 계산된 크기를 검토합니다.
2. 데이터 템플릿이 새 프로필을 가리키도록 설정합니다.
3. 지금부터 새로 생성되는 모든 데이터 소스가 새 구조를 채택한다는 점을 인지합니다.
4. 이미 존재하는 파일들을 어떻게 처리할지 별도로 결정합니다.

네 번째 단계에는 변경 사항과 설치된 RRDtool 버전에 따라 몇 가지 옵션이 있습니다.

**그대로 유지하기.** 서로 다른 보존 구조를 가진 파일들이 문제없이 공존할 수 있습니다. 각 기존
데이터 소스의 폴링 메타데이터를 해당 파일과 일치하도록 유지하십시오. 데이터베이스의 프로필 참조만 변경한다고 해서
스텝, 필드, 아카이브가 자동으로 변환되지는 않습니다.

**재구축하기.** 데이터 소스를 삭제하고 다시 생성합니다. 빠르게 처리되지만 이전 이력 데이터는 완전히 사라집니다.

**접합(Splice).** 커맨드라인 splice 유틸리티는 이전 파일의 데이터를 새 파일로 병합하며,
새 파일에 이미 올바른 스텝이 구성되어 있는 경우 해상도 변경도 수행할 수 있습니다. 드라이런 모드가 지원됩니다.
중요한 데이터에 적용하기 전에 반드시 복사본에서 먼저 테스트하십시오.

**RRDtool 네이티브 유지보수.** 설치된 버전 및 원하는 변경 사항에 따라
[rrdtool tune](https://oss.oetiker.ch/rrdtool/doc/rrdtune.en.html) 또는
[rrdtool resize](https://oss.oetiker.ch/rrdtool/doc/rrdresize.en.html)를 사용하여
저장된 데이터를 보존하면서 기존 파일을 변경할 수 있습니다. 동시 쓰기 프로세스를 중지하고, 백업을 확보한 후,
복사본에서 결과를 확인하십시오. 이러한 작업으로도 과거 통합 처리로 인해 이미 폐기된 세부 데이터를 되살릴 수는 없습니다.

## 외부 프로필

데이터 소스에 스텝 값을 0으로 기록하는 외부 프로필을 지정할 수 있습니다.
이는 해당 파일이 일반적인 수집 파이프라인 외부에서 관리됨을 나타내며, 데이터 소스 목록에서도
주기를 표기하는 대신 '외부'로 표시됩니다. 다른 외부 프로세스가 쓰는 파일에 사용하십시오.
보존 기간은 파일이 처음 생성되었을 때의 구조를 그대로 유지하므로 "보존 정책 없음"이라는 의미로 오용하지 마십시오.
단지 관리 화면에 구조 정보가 노출되지 않을 뿐입니다.

## 장애 모드

| 증상 | 흔한 원인 |
|---|---|
| 프로필을 편집해도 아무런 변화가 없음 | 정상적인 동작입니다. 기존 파일은 생성 당시의 구조를 그대로 유지합니다 |
| 행 수와 집계 수준을 편집할 수 없음 | 해당 프로필이 최소 하나 이상의 데이터 소스에서 사용 중입니다. 프로필을 복제하십시오 |
| 인터페이스에 표시되는 하트비트와 실제 파일 동작이 불일치함 | 프로필의 하트비트만 변경하고 실제 파일 튜닝을 수행하지 않았습니다 |
| 신규 데이터 소스 생성에 실패하고 아카이브 미할당 로그가 남음 | 데이터 소스가 프로필을 여전히 참조하고 있는 상태에서 프로필이 삭제되었습니다 |
| 가장 정밀한 아카이브가 알 수 없는 값(unknown)으로 가득 참 | 누락된 업데이트, 하트비트 설정값, 통합 규칙을 확인하십시오 |
| 주간 그래프에서 몇 시간마다 주기적으로 데이터 공백이 발생함 | 지연이 발생하는 폴러 환경에서 하트비트가 스텝 주기와 너무 가깝게 설정되었습니다 |
| 어제 확인되던 피크가 월간 뷰에서 사라짐 | `AVERAGE`만 보존되거나, 공간 절약을 위해 `MAX` 아카이브가 삭제되었습니다 |
| 디스크 사용량이 예상보다 4배 빠르게 증가함 | 산정 시 아카이브 개수만 계산하고 통합 함수의 곱셈을 누락했습니다 |
| 새 아카이브 드롭다운에 원하는 해상도가 표시되지 않음 | 편집기는 프로필 스텝 해상도를 제공한 후 기존 아카이브보다 거친 선택지만 제공합니다 |
