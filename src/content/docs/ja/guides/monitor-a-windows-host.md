:::caution[使用前に検証してください]
ソースコードは利用可能ですが、サポートされている Kadupul のリリースや移行パスはありません。本番環境で信頼する前に、バックアップを備えた隔離されたコピーでこれらの手順をテストしてください。[プロジェクトのステータス](/ja/project/status/)を参照してください。
:::

SNMP 経由の Windows は、インターフェース、プロセッサ、ストレージ、および一部のカウンターを提供します。組み込みの Microsoft エージェントは、net-snmp UCD テンプレートの負荷、メモリ、およびディスクオブジェクトを公開しません。ただし、エージェントが公開していれば、ストレージ行からメモリをプロットできます。サードパーティのエージェントは他のオブジェクトを提供する場合があります。テンプレートを選択する前に実際のエージェントを確認してください。

## SNMP サービスが提供するもの

Windows SNMP サービスは非推奨であり、オプションです。Windows 10 および 11 の場合、Microsoft はオプション機能または Windows の機能によるインストールを文書化しています。古い DISM 機能名エラーだけでは、利用できないことの証明にはなりません。ご使用の Windows エディションに応じた手順を確認してください。[Microsoft の SNMP インストールガイド](https://learn.microsoft.com/en-us/troubleshoot/windows-client/networking/cannot-install-snmp-wmisnmpprovider)を参照してください。

インストールされたエージェントが公開しているサブツリーを確認します。

| 領域 | サブツリー | 提供内容 |
|---|---|---|
| システム | `.1.3.6.1.2.1.1` | 説明、稼働時間、連絡先、名前、場所 |
| インターフェース | `.1.3.6.1.2.1.2` および `.1.3.6.1.2.1.31` | トラフィック、エラー、状態 |
| ホストリソース | `.1.3.6.1.2.1.25` | プロセッサ、ストレージ、プロセス数、ログインユーザー数 |
| LAN Manager | `.1.3.6.1.4.1.77` | Windows サービスおよび共有データ |

Kadupul に付属の Windows テンプレートは、最初の 3 つの領域を読み取ります。同梱のセットでは、LAN Manager サブツリーを読み取るものはありません。

ホスト上の 2 つの設定項目がデータを受信できるかどうかを決定します。コミュニティ文字列と、エージェントがパケットを受け入れるマネージャーのリストです。単一のマネージャーアドレスからのみ SNMP を受け入れるように設定されたホストは、そのマネージャーにのみ応答し、他のすべてを破棄します。

グラフを作成する前に、ポーラーホストから各領域を確認してください。サンプルのホストとコミュニティを設定した値に置き換えます。`public` は説明のみを目的としています。

```bash
snmpget  -v2c -c public win.example.net .1.3.6.1.2.1.1.1.0
snmpwalk -v2c -c public win.example.net .1.3.6.1.2.1.25.3.3.1.2
snmpwalk -v2c -c public win.example.net .1.3.6.1.2.1.25.2.3.1.3
```

2 番目の walk はプロセッサ負荷を読み取り、3 番目の walk はストレージ説明リストを読み取ります。最初のコマンドが機能し、他の 2 つが何も返さない場合は、アクセス制限、エージェントのサポート、および返された SNMP エラーを確認してください。

## デバイスの追加

テンプレートがない場合は、[テンプレートのインポートとエクスポート](/ja/guides/import-and-export-templates/)に従って `install/templates/Windows_Device.xml.gz` をインポートします。Windows デバイステンプレートを選択し、クエリの検出を確認してから、目的のグラフを明示的に作成します。パッケージには、3 つのデータクエリとそれに関連するグラフテンプレートが含まれています。

| データクエリ | 支援元 | 読み取り内容 |
|---|---|---|
| SNMP - インターフェース統計 | `resource/snmp_queries/interface.xml` | `IF-MIB`、直接走査 |
| SNMP - プロセッサ情報の取得 | `resource/script_server/host_cpu.xml` | `scripts/ss_host_cpu.php` 経由で `hrProcessorLoad` |
| SNMP - マウントポイントの取得 | `resource/script_server/host_disk.xml` | `scripts/ss_host_disk.php` 経由で `hrStorageTable` |

ディスクおよびプロセッサクエリは、その名前に反してスクリプトサーバークエリです。これらは個別の存続期間の長い PHP スクリプトサーバープロセスで実行され、デバイスレコードの資格情報を使用して SNMP 呼び出しを行います。インターフェースクエリは純粋な SNMP クエリです。実用上の結果として、障害が発生した PHP スクリプトサーバーは Windows 上のディスクと CPU の収集を停止しますが、インターフェースグラフは実行を継続します。

## データクエリなしで取得できるもの

2 つのグラフテンプレートは、それぞれ 1 つの固定 OID を読み取ります。

| グラフ | OID | 保存形式 |
|---|---|---|
| ホスト MIB - プロセス数 | `.1.3.6.1.2.1.25.1.6.0` | `GAUGE` |
| ホスト MIB - ログインユーザー数 | `.1.3.6.1.2.1.25.1.5.0` | `GAUGE` |

他の 2 つはデバイスから何も読み取りません。稼働時間グラフとポーリング時間グラフは `scripts/ss_hstats.php` を呼び出し、Kadupul 自身のデバイスレコードから列を返します。稼働時間には `snmp_sysUpTimeInstance`、ポーリング時間には記録されたポーリング期間を返します。これらは保存された測定値を読み取るものであり、最新の SNMP 応答ではありません。

## ホストリソーステーブル

### プロセッサ

`.1.3.6.1.2.1.25.3.3.1.2` の下の `hrProcessorLoad` は、エージェントが公開する論理プロセッサごとに 1 つのエントリを返します。walk はインデックスを提供します。行数が常に公称ハードウェアスレッド数と一致するとは見なさないでください。

この値はすでにパーセンテージです。MIB は過去 1 分間の平均として定義しています。[Host Resources MIB 定義](https://www.rfc-editor.org/rfc/rfc2790.html)を参照してください。

### ストレージ

付属のストレージクエリは、`.1.3.6.1.2.1.25.2.3.1` の下の `hrStorageTable` を使用します。6 つの列を読み取ります。

| 列 | OID | 方向 |
|---|---|---|
| `hrStorageIndex` | `.1.3.6.1.2.1.25.2.3.1.1` | インデックス |
| `hrStorageDescr` | `.1.3.6.1.2.1.25.2.3.1.3` | インデックスおよび表示ラベル |
| `hrStorageAllocationUnits` | `.1.3.6.1.2.1.25.2.3.1.4` | 入力、乗数 |
| `hrStorageSize` | `.1.3.6.1.2.1.25.2.3.1.5` | 出力 |
| `hrStorageUsed` | `.1.3.6.1.2.1.25.2.3.1.6` | 出力 |
| `hrStorageAllocationFailures` | `.1.3.6.1.2.1.25.2.3.1.7` | 出力 |

サイズと使用済み容量はバイトではなく、アロケーションユニットのカウントです。両方の値が有効な場合、スクリプトは各値にそのインデックス用にキャッシュされたアロケーションユニットサイズを乗算します。

Windows では 2 つの点が頻繁に問題を引き起こします。

**このテーブルはハードディスクのリストではありません。** エージェントはストレージとみなすすべてのものを報告します。エージェントによっては、固定ドライブの横に物理メモリと仮想メモリが表示される場合があります。`C:\`, `D:\`, `Physical Memory`, `Virtual Memory` などのラベルは例であり、保証された行ではありません。グラフ化する行を選択してください。

**大きなストレージ値や無効なストレージ値は検証が必要です。** MIB はサイズと使用量を非負の Integer32 として定義しています。負の値を返すエージェントはその範囲外です。現在のスクリプトは `(abs(value) + 2147483647) * allocation_units` を使用していますが、これは符号なし 32 ビットの再解釈を表すものではありません。影響を受ける値は信頼できないものとして扱い、検出を修正した後に再インデックスを行ってください。[ストレージ変換の欠陥](https://github.com/kadupulhq/kadupul/issues/243)を参照してください。

## Windows と Linux の違い

| 特徴 | net-snmp を備えた Linux | 組み込み Windows エージェント / 付属テンプレート |
|---|---|---|
| ロードアベレージ | `.1.3.6.1.4.1.2021.10.1.3` | UCD ロードアベレージオブジェクトなし |
| メモリ | `.1.3.6.1.4.1.2021.4` | 公開された `hrStorage` 行からプロット可能 |
| CPU | UCD パーセンテージまたは `hrProcessorLoad` | `hrProcessorLoad` のみ |
| ディスクリスト | 宣言された `dskTable` または `hrStorage` | `hrStorage` のみ、フィルターなし |
| ディスク I/O | `diskIOTable` | 付属のものはこれを読み取らない |
| インターフェース名 | カーネル名、短い | 長いアダプターの説明、重複することが多い |

組み込みの Microsoft エージェントは、UCD サブツリー `.1.3.6.1.4.1.2021` を提供しません。[欠落データのトラブルシューティング](/ja/guides/troubleshoot-missing-data/)を参照してください。

### インターフェース

インターフェースクエリは、スイッチで使用されるものと同じです。インデックスの優先順位は、`ifName`、`ifDescr`、`ifHwAddr`、`ifIndex` の順です。検出された各インターフェース上で存在し、一意である最初のフィールドが選択されます。

Windows はこれが最も頻繁に失敗するプラットフォームです。2 つの同一の NIC が同じ `ifDescr` を返すことがあり、一部のエージェントは `ifName` を空のままにします。クエリが `ifIndex` にフォールバックすると、インターフェースの履歴は Windows が自由に再割り当てできる番号に関連付けられます。

[スイッチの監視](/ja/guides/monitor-a-switch/)および[データクエリとインデックス](/ja/concepts/data-queries-and-indexes/)を参照してください。

## SNMP が利用できない場合

多くの Windows インストールでは、SNMP サービスが有効になっていません。代替手段はスクリプト入力です。

2 つの事実がスクリプトの作成方法を決定します。

**スクリプトは、ポーラーが実行されているマシン上で実行されます。** Windows ホストへの到達は、WinRM、エージェント、HTTP エンドポイント、共有、または運用しているメカニズムなど、スクリプトの役割です。

**標準出力に測定値を出力します。** PHP ポーラーの外部コマンドパスは、終了ステータスを測定値として使用しません。数値を生成するか、このサイクルで測定値がない場合は `U` を出力します。測定が失敗したことを通知するために `0` を出力しないでください。

単一の数値ではなく、インターフェースごと、ディスクごと、またはサービスごとの値が必要な場合、同じスクリプトメカニズムによってインデックス付きの形式が提供されます。`resource/script_queries/host_cpu.xml` は、スクリプトサーバーの代わりに PHP スクリプトを呼び出す実用的な例です。

出力規約と名前の制約については、[データ収集スクリプトの作成](/ja/guides/write-a-data-collection-script/)を参照してください。

## 障害モード

| 症状 | 一般的な原因 |
|---|---|
| システム説明は読み取られるが、他には何も収集されない | オブジェクトのサポート、アクセス制限、特定の SNMP エラーを確認 |
| オンラインのホストからまったく応答がない | エージェントの受け入れマネージャーリストまたは UDP 161 上のホストファイアウォールルール |
| パーティションリストにメモリが含まれている | 想定通り。エージェントはメモリをストレージとして報告する |
| 大きなボリュームが負または不明として表示される | 無効なエージェント値または古いアロケーションユニット。既知のバグを確認 |
| ディスクと CPU が停止し、インターフェースが継続する | スクリプトサーバーの障害。インターフェースクエリはそれを使用しない |
| Net-snmp テンプレートが割り当てられ、すべての測定値が unknown | 選択したエージェントがこれらのテンプレートに必要な UCD オブジェクトを提供していない |
| 変更後にインターフェース履歴が誤ったアダプターを追跡する | 名前が空または重複していたため、インデックスが `ifIndex` にフォールバックした |
| 稼働時間が古い値を繰り返す | デバイスレコードが古いかどうかを確認。ヘルパーは稼働時間を外挿しない |
