:::caution[使用前に検証してください]
ソースコードは公開されていますが、サポートされている Kadupul のリリースや移行パスはまだ存在しません。本運用で依存する前に、バックアップを備えた隔離された環境でこれらの手順をテストしてください。[プロジェクトのステータス](/ja/project/status/)を参照してください。
:::

この手順を順番に一度通して実行してください。各ステップの最後には確認手順が用意されています。次に進む前に必ず確認を行ってください。ここに記載されている不具合は、今なら容易に特定できますが、ポーラーが1週間稼働した後に特定しようとすると多大なコストがかかります。

ホスト固有の前提条件については、[Windows 上の Linux](/ja/guides/install-on-windows/) と [FreeBSD](/ja/guides/install-on-freebsd/) を参照してください。これらの手順は、エンドツーエンドの検証に合格したことを示すものではありません。

## 最初に必要なもの

Kadupul は、MySQL または MariaDB に設定を保存し、ディスク上の RRD ファイルに測定値を保存する PHP アプリケーションです。このページでは、アップグレードやアーカイブされた LTS 系列ではなく、現在の `main` ソースコードからの新規メインサーバーのインストールについて説明します。実行する前に、4つの要素が揃っている必要があります。

| コンポーネント | 必要な理由 |
|---|---|
| PHP 8.4 以降（セキュリティサポート対象のリリース） | Web インターフェースおよびポーラーを実行するため |
| MySQL または MariaDB | デバイス、テンプレート、ユーザー、およびポーラーキャッシュを保持するため |
| RRDtool | ラウンドロビンアーカイブを作成・更新し、グラフを描画するため |
| net-snmp | デバイスの照会に使用するクライアントツールとライブラリを提供するため |

PHP には、`pdo_mysql`、`gd`、`sockets`、`gmp`、`intl`、`ldap`、`mbstring`、`pcntl`、`posix`、および `sqlite3` を含む、[アプリケーションマニフェスト](https://github.com/kadupulhq/kadupul/blob/main/composer.json)で要求される拡張モジュールも必要です。コマンドライン用と Web ランタイム用の両方にこれらをインストールしてください。[システム要件](/ja/reference/requirements/)では、Composer の要件とインストーラーによる個別のチェックの違いについて説明しています。

## 手順 1: ランタイムのインストール

ディストリビューションのパッケージから、必要な拡張モジュールを含む PHP、データベースサーバー、RRDtool、および net-snmp をインストールします。

**確認します。**

```bash
php -v
php -m | sort
rrdtool --version
snmpget --version
```

`php -m` で必要な拡張モジュールが一覧表示される必要があります。net-snmp のコマンドラインツールが利用可能な場合、PHP の `snmp` 拡張モジュールは任意です。Composer は依存関係のインストール時に自身に必要な拡張モジュールをチェックします。Web インストーラーには個別の拡張モジュールチェックがあります。ランタイムのフォールバックが存在しても、Composer の要件が免除されるわけではありません。

コマンドラインと Web サーバーの PHP 設定は異なる場合があります。両方を確認してください。インストーラーは、少なくとも 400M の `memory_limit` と、少なくとも 60 秒の `max_execution_time` を推奨しています。また、それぞれ無制限の値（`-1` および `0`）も許容されます。これらの推奨値を下回ると警告が表示され、`date.timezone` が未設定の場合はエラーとなります。`UTC` などの明示的なタイムゾーンを設定し、`php --ini` を使用してコマンドライン設定を特定してください。

## 手順 2: データベースとユーザーの作成

空のデータベースを1つ作成し、そのデータベースに対する権限を持つユーザーを1人作成します。ローカルデータベースの場合は、データベース管理者としてこの SQL を実行し、使用前にサンプルのパスワードを置き換えてください。

```sql
CREATE DATABASE kadupul CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'kadupul'@'localhost' IDENTIFIED BY 'replace-with-a-unique-password';
GRANT ALL PRIVILEGES ON kadupul.* TO 'kadupul'@'localhost';
```

PHP が別のマシンから接続する場合は、対応するデータベースアカウントのホストを使用してください。

データベースサーバーにはタイムゾーンテーブルも投入されている必要があり、Kadupul ユーザーは `mysql` データベース内のそれらのテーブルに対する読み取り権限を必要とします。これは、自身のスキーマ外で付与される唯一の権限です。監視システムのセットアップにおいてこの要件は一見見落とされがちですが、必須であり、これがないと以下のチェックが失敗します。

```bash
# Populate the tables, then grant the one extra read the installer needs.
mysql_tzinfo_to_sql /usr/share/zoneinfo | mysql -u root -p mysql
mysql -u root -p -e "GRANT SELECT ON mysql.time_zone_name TO 'kadupul'@'localhost';"
```

**確認します。** Kadupul データベースユーザーとしてログインし、以下を実行します。

```sql
SELECT COUNT(*) FROM mysql.time_zone_name;
```

権限エラーなしでゼロ以外のカウントが返されれば正常です。ゼロの場合はテーブルがロードされていないことを意味し、エラーの場合はユーザーがテーブルを読み取れないことを意味します。どちらの場合もインストーラーは停止します。

サーバー自体の設定のうち、今すぐ修正しておくべき重要な項目が4つあります。

| 設定項目 | 希望する設定値 | 理由 |
|---|---|---|
| `max_allowed_packet` | 16M 以上 | メインサーバーとリモートコレクター間の大規模な同期 |
| `character_set_server`, `collation_server` | `utf8mb4`, `utf8mb4_unicode_ci` | デバイス説明にマルチバイト文字が含まれるため |
| `innodb_file_per_table` | On | テーブルスペースを個別に管理しやすく保つため |
| `innodb_buffer_pool_size` | システムメモリの約4分の1 | ワーキングセットをメモリ内に保持するため |

インストーラーはこれらの独自判定を報告し、不足しているものにフラグを立てるため、この表を盲信する心配はありません。実際に負荷がかかった後の調整については、[データベースパフォーマンスの調整](/ja/guides/tune-database-performance/)でさらに詳しく説明しています。

## 手順 3: 展開、所有権の修正、および公開設定

Web サーバーが公開できる場所にアプリケーションを配置し、それを所有するシステムユーザーを決定します。その決定は配置場所よりも重要です。ここには2つのプロセスが書き込みを行います。Web サーバーと、ポーラーをスケジュールするプロセスです。両方を同一のユーザーとして実行してください。ポーラーは非特権で実行し、両方のプロセスに必要なアクセス権を与えます。所有権やパーミッションモードが正しくないと、グラフが描画されていても後の更新が妨げられる可能性があります。

### リリースを展開するのではなくリポジトリをクローンした場合

Git チェックアウトでは、PHP の依存関係と生成されるブラウザアセットの両方が必要です。リポジトリの `mise.toml` ランタイムをインストールした状態で、リポジトリルートから以下を実行します。

```bash
mise exec -- php "$(command -v composer)" install --no-dev --optimize-autoloader
mise exec -- npm ci --ignore-scripts
mise exec -- npm run build
mise exec -- php bin/console asset-map:compile
mise exec -- php bin/console about
```

Composer は `include/vendor/` に依存関係を配置し、固定された互換性ファイルを復元します。npm ビルドは `include/js/`、`include/fa/`、および `include/vendor/flag-icons/` の下にアセットを作成します。ソースからのインストールでは、Composer 単体だけでは不十分です。

依存関係を完備したオフラインバンドルは個別のビルドアセットです。一般的な GitHub ソースアーカイブはそのバンドルではありません。ターゲットホストにインターネットアクセスがない場合は、[オフラインビルドおよび検証手順](https://github.com/kadupulhq/kadupul/blob/main/docs/symfony-migration.md#offline-installation)に従ってください。

依存関係のインストール後、書き込み可能なパスを準備します。

| グループ | ディレクトリ | 書き込み可能にするタイミング |
|---|---|---|
| インストール時 | `resource/snmp_queries`, `resource/script_server`, `resource/script_queries`, `scripts` | インストール時またはアップグレード時のみ |
| インストール時 | `include/vendor/csrf/`、または設定された `path_csrf_secret` の場所 | インストーラーがインストール固有のシークレットを作成する必要があるため。完了後も保持します |
| 常時 | `log`, `cache/boost`, `cache/mibcache`, `cache/purifier`, `cache/realtime`, `cache/spikekill`, システム一時ディレクトリ | インストールの稼働期間全体 |
| Symfony ランタイム | `var/cache`、およびファイルログが設定されている場合は `var/log` | PHP ランタイムおよびキャッシュウォーミングユーザー用 |

RRD ディレクトリも、インストールの稼働期間全体にわたって書き込み可能である必要があります。履歴が保持される場所であるため、データベースディレクトリと同等の配慮を払ってください。

現在の移行段階では、従来のログイン、インストーラー、およびプラグインのルートが引き続き必要です。この複合インストールの場合は、プライベートディレクトリ、設定、依存関係、およびランタイム状態へのアクセスを明示的に拒否するルールを設けてリポジトリルートを公開してください。インストール全体を `public/` に切り替えないでください。現在も使用されている従来のルートが削除されてしまいます。Symfony の個別のエンドポイントには異なるルーティングがあります。[移行手順書](https://github.com/kadupulhq/kadupul/blob/main/docs/symfony-migration.md)を参照してください。

Nginx については、リポジトリの [Nginx の location ルール](https://github.com/kadupulhq/kadupul/blob/main/tests/e2e/nginx.conf) をベースとし、root と PHP-FPM アップストリームを調整してください。汎用的な PHP 処理の前に deny ルールを配置し、`/app.php/...` の PATH_INFO を維持してください。Nginx は `.htaccess` を読み取りません。RRD ファイル、ログ、シークレットには HTTP 経由でアクセスできないようにしてください。ファイルパーミッションが公開を防いでいると思い込まず、実際のサーバー設定を検証してください。

**確認します。** ポーラーユーザーになり、常時グループの各ディレクトリにファイルを書き込み、削除します。`ls -l` で正しく見える権限であっても、SELinux や AppArmor によって拒否される場合があり、ファイルを実際に書き込むことがそれを確認する唯一のチェックです。次に、HTTP 経由で log ディレクトリ配下のファイルをリクエストします。アクセス拒否となることを確認してください。

## 手順 4: 設定ファイルの作成

新規インストールの場合は、同梱されている設定ファイルをコピーします。

```bash
cp include/config.php.dist include/config.php
```

既存のインストールの設定を上書きしないでください。手順 2 で設定したデータベースのホスト、名前、ユーザー、パスワードを設定します。初回インストール時には、さらに2つの値が重要になります。先頭と末尾にスラッシュを付けたアプリケーションの公開パスである `url_path` と、メインサーバーでは `1` でありリモートコレクターでのみ異なる値となる `poller_id` です。

リモートコレクターのブロックはコメントアウトしたままにしておきます。まだ作成していません。必要になった際には[リモートデータ収集](/ja/concepts/remote-data-collection/)で説明されています。その他の設定にはすべて機能するデフォルト値があるため、変更を加える前に[設定](/ja/reference/configuration/)をお読みください。

それを使用する Symfony 機能のために、PHP プロセス環境でデプロイ固有の `APP_SECRET` を設定してください。ブートストラップのデフォルトは `APP_ENV=prod` および `APP_DEBUG=0` であり、`.env` ファイルはロードされません。これはレガシーインストーラーの CSRF シークレットとは別物です。

**確認します。** 認証情報を表示せずに構文をチェックします。

```bash
php -l include/config.php
```

ブラウザでインストーラーを開く前に、次のステップでスキーマをインポートしてください。

## 手順 5: スキーマのインポート

インストーラーは、テーブルがすでに存在していることを前提とします。同梱されているスキーマを作成したデータベースに読み込みます。

```bash
mysql -u kadupul -p kadupul < cacti.sql
```

これは空のデータベースに対して一度だけ実行してください。これはアップグレードスクリプトではありません。データが存在するデータベースにインポートすると、失敗したり、競合する不完全なデータが残ったりする可能性があります。

## 手順 6: インストーラーの実行

ブラウザでサイトを開き、順を追って進めます。インストーラーは固定された順序で進行し、各ステップが次のステップの前提条件となります。

1. ようこそ画面とライセンス。
2. 依存関係のチェック: PHP のバージョンと拡張モジュール、手順 1 のコマンドラインと Web サーバー双方の PHP 設定、タイムゾーンテーブル、および手順 2 のデータベース設定。エラーがあると次へ進むボタンがブロックされます。警告はブロックされませんが、内容を確認してください。
3. インストールタイプ: 新規メインサーバー、またはリモートコレクター。
4. 権限チェック: 手順 3 のディレクトリへの書き込みテスト。
5. バイナリの場所: PHP、RRDtool、および net-snmp ツールのパス。
6. データソースプロファイルとランチャー間隔。
7. テンプレートの選択: 読み込むデバイステンプレート。
8. テーブル変換、確認、そしてインストール自体の実行。

そのリストの中で元に戻すのが困難な項目は 6 番です。選択したプロファイルによって、それ以降に作成されるすべての RRD ファイルに書き込まれるステップとアーカイブセットが決定され、プロファイルを編集しても既存のファイルは移行されません。データ保持期間の変更には個別の検証済み移行手順が必要です。必ずしも履歴を破棄する必要があるとは限りません。ピーク値が重要な場合は、プロファイルが平均値だけでなく最大値も保持していることを確認してください。先へ進む前に[データソースとラウンドロビンアーカイブ](/ja/concepts/data-sources-and-rras/)をお読みください。提示されるランチャー間隔は 1 分または 5 分です。データソースプロファイルによって収集間隔が設定されます。ランチャーとプロファイルは整合性を保って設定する必要があります。

## 手順 7: デフォルトの認証情報の変更

同梱のスキーマには、ユーザー名 `admin`、パスワード `admin` の管理者アカウントがあらかじめ登録されており、初回ログイン時にパスワードの変更が強制されるように設定されています。また、無効化されたゲストアカウントも登録されています。インスタンスが他のユーザーから到達可能になる前、つまり他のユーザーがルーティングできるネットワークに接続する前に、パスワードを変更してください。

## 手順 8: ポーラーのスケジューリング

ポーラーは外部から起動する必要があります。収集間隔とランチャー間隔を整合性を保って設定してください。ポーラーは 1 分または 5 分のランチャー間隔をサポートし、通常の実行が早すぎるタイミングで開始されるのを防ぐガードを備えています。1 分のランチャーの場合は、非特権のポーラーユーザーの crontab に次のエントリを追加し、`php` とアプリケーションパスをそれぞれの絶対パスに置き換えてください。

```
* * * * * php -q /path/to/kadupul/poller.php > /dev/null 2>&1
```

または、インストールパスと非特権ユーザーに合わせて調整した `service/cactid.service` を使用して、同梱の `cactid.php` デーモンを実行します。ランチャーは1つだけ使用してください。デーモンを使用する場合は cron ジョブまたはタイマーを無効にします。

実際のスケジュールを設定されたランチャー間隔と一致させてください。1分未満の収集プロファイルの場合、起動されたポーラーはその間隔内で収集サイクルを実行します。この cron エントリで1分未満の間隔を指定しようとしないでください。

**確認します。** ポーラーユーザーとして手動で1サイクル実行します。

```bash
php -q /path/to/kadupul/poller.php --force --debug
```

`--force` は、実行間隔の早期実行防止ガードをスキップします。スケジュールされた実行と重複しないように、スケジューラーを停止した状態でこの手動チェックを行ってください。その他のメンテナンスタスクや安全チェックはバイパスされません。サマリー行が出力されて正常に終了することを確認します。その後、スケジューラーを有効にして2サイクル放置し、手動介入なしで次の実行が行われたことを確認してください。

## トラブルシューティング

以下は、初回のインストールで実際に遭遇しやすい問題です。

| 症状 | 原因 | 確認すべき場所 |
|---|---|---|
| 正しく見える PHP 設定でインストーラーがブロックされる | Web サーバーとコマンドラインで異なる `php.ini` ファイルが読み込まれている | `php --ini`、および Web SAPI が報告するファイル |
| タイムゾーンの確認でインストーラーがブロックされる | タイムゾーンテーブルがロードされていないか、Kadupul ユーザーが読み取れない | `SELECT COUNT(*) FROM mysql.time_zone_name` |
| 書き込み可能に見えるディレクトリで権限ステップが失敗する | 所有者が誤っているか、SELinux や AppArmor による制限 | ポーラーユーザーとしてファイルを書き込んでみる |
| インストールは完了したが、データが届かない | ポーラーがスケジュールされていない | 手動で `poller.php --force --debug` を実行する |
| 数サイクル分はデータがあるが、その後停止する | 誤ったユーザーでポーラーが実行され、Web ユーザーが更新できないファイルが残されている | RRD ディレクトリ内のファイルの所有者 |
| グラフに細かい隙間（抜け）が多数ある | スケジュールされた間隔と設定された間隔が一致していない | 設定された間隔に対する crontab の設定 |
| Composer がインストールを拒否する | PHP が 8.4 未満であるか、マニフェストで要求される拡張モジュールが不足している | `php -v`、`php -m`、および Composer のエラー出力 |
| ポーラーが複数のプロセスを実行できない | `pcntl` または `posix` が不足している | `php -m` |

[ロギング](/ja/reference/logging/)では、各コンポーネントがどこにログを記録するかを説明しています。[欠落データのトラブルシューティング](/ja/guides/troubleshoot-missing-data/)では、インストール自体は正常だが特定のデバイスに問題がある場合について説明しています。

## 外部へ公開する前に

ポーラーはシステムユーザーとして実行され、RRDtool や収集スクリプトを実行します。このインストール環境は実際にコマンドを実行するものであるため、その前提で扱ってください。

- TLS 経由で公開してください。
- デフォルトの管理者パスワードは、一時的であってもそのままにしないでください。
- データベースユーザーの権限は、自身のデータベースのみに制限してください。
- RRD ディレクトリとログディレクトリは、ドキュメントルートの外に配置してください。
- 別途決定しない限り、ゲストアカウントは無効のままにしてください。
