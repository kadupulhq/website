## চালানোর পরিবেশ বেছে নিন

বর্তমান `main`-এর জন্য PHP 8.4+, `pcntl` ও `posix` প্রয়োজন; নেটিভ Windows PHP এই Unix প্রয়োজন মেটাতে পারে না। Composer-এর প্ল্যাটফর্ম পরীক্ষা এড়াবেন না। Linux VM ব্যবহার করুন অথবা Microsoft-সমর্থিত Windows-এ WSL 2 মূল্যায়ন করুন। এগুলো Windows-এ হোস্ট করা Linux ইনস্টলেশন, যাচাইকৃত নেটিভ IIS স্থাপনা নয়। PHP-এর প্ল্যাটফর্ম সীমা দেখুন।

## Linux তৈরি করে ইনস্টল করুন

WSL-এর জন্য প্রশাসক PowerShell-এ এগুলো চালান এবং বলা হলে পুনরায় চালু করুন:

```powershell
wsl --install -d Ubuntu
wsl --list --verbose
```

সংস্করণ 2 নিশ্চিত করুন। Linux অ্যাকাউন্ট তৈরি করে Linux-এর ভেতরে ইনস্টলেশন অনুসরণ করুন: ডেটাবেস, PHP এক্সটেনশন, উপকরণ, ওয়েব সার্ভার ও সময়সূচি ব্যবস্থা। কোড ও RRD Linux ফাইল সিস্টেমে রাখুন, `/mnt/c/`-এর নিচে নয়। Microsoft-এর WSL ও ফাইল সিস্টেম নির্দেশিকা দেখুন।

## জীবনচক্র ও পুনরুদ্ধার দেখুন

আলাদা বিশেষাধিকারহীন অ্যাকাউন্ট ও একটি সংগ্রহ চালুর ব্যবস্থা ব্যবহার করুন। হোস্ট পুনরায় চালু বা WSL বন্ধ হওয়ার পরে স্টোরেজের আস্থা, পোলিং, গ্রাফ টাইমস্ট্যাম্প ও পুনরায় শুরুর আচরণ যাচাই করুন। ডেস্কটপ সেশন সংগ্রহ চালু রাখবে ধরে নেবেন না। ডেটাবেস, কনফিগারেশন ও RRD একসঙ্গে ব্যাকআপ নিন। নেটিভ Windows-এ ধ্বংসাত্মক RRD রক্ষণাবেক্ষণ ও স্বয়ংক্রিয় স্থানীয় মুছে ফেলা/আর্কাইভ করা এখনো নেই; Linux-এর আচরণ এগুলো যাচাই করে না। প্রয়োজনীয়তা ও ব্যাকআপ দেখুন।
